## 1. 做了什么

| # | 内容 | 用户看到的变化 |
| --- | --- | --- |
| 1 | 统计面板 | 番茄钟页面底部多一张「专注统计」卡片：累计、日均、连续天数、专注次数 |
| 2 | 区间切换 | 日 / 周 / 月 / 年 四个按钮，标题随区间变（如「10 月 26 日 – 11 月 1 日」） |

| 4 | 下钻 | 点扇区或图例，下方展开该类内部各任务；「占比 / 时长」切换；再点收起 |
| 5 | 导出 / 导入 | 导出 JSON 备份；导入只补不改，重复记录不重复计 |

## 2. 为什么做

对应需求 **R3**：「累计学习时间、日/周/月/年、按大类饼图、大类下钻」，
以及第 8 节的交互定稿（点扇区 → 下方展开 → 占比/时长可切换）。

再加一条现实理由：**B6 云同步还没上线，而浏览器缓存和 `data/` 都可能一夜之间没了**。
导出/导入是同步做出来之前用户唯一的退路 —— 它在验收清单里排在「可选」，
但按 `docs/06` 7.5 的风险 1（SQLite 与服务器绑定、项目无定时备份），我把它当成必做项。

## 3. 改动明细

### 新增 `logic/focusExport.ts`（139 行）

`buildExport` / `exportFileName` / `parseExport` / `mergeImport` + 类型 `FocusExport` / `ImportOutcome`。

| 决策 | 内容 |
| --- | --- |
| 文件格式 | `{ kind: "campus.focus", version: 1, exportedAt, tasks, sessions }`，`kind` 用来拒绝「随便一个 JSON」 |
| 拒绝路径 | `empty` / `not-json` / `wrong-kind` / `no-data`，每种都给一句具体的说明 |
| 清洗 | 复用读取 localStorage 时的 `sanitizeTasks` / `sanitizeSessions`，不新造一套规则 |
| 失败返回 | 失败也返回 `tasks: []` / `sessions: []`，调用方可以无条件解构 |

### 新增 `tools/pomodoro/PieChart.tsx`（160 行）

SVG 环形图，导出 `sectorPath(from, to)` 便于单测几何。

- 单类时画整环（起止角重合，扇形会退化成一个点）；
- 最后一片强制兜到 360°，避免浮点误差在 12 点方向留一条细缝；
- 展开某一类时其余扇区压暗到 42%，不是隐藏 —— 位置和比例仍是参照；
- 圆心显示当前选中类名与合计时长。

### 新增 `tools/pomodoro/StatsPanel.tsx`（263 行）

区间、数字、饼图、下钻、导入导出都在这里。所有聚合调用 `logic/focus.ts`，面板内**零求和**。

`logic/focus.ts` 新增两个纯函数：

| 函数 | 说明 |
| --- | --- |
| `averageSecondsPerDay` | 日均，分母是**区间内已过的天数** |
| `rangeLabel` | 区间标题（日/周跨月/月/年） |

### 改 `PomodoroTool.tsx`（+19 行）

`handleImport`：导入结果落库（任务 + 会话均 `save`），统计立即反映新数据；

六色色值放在 CSS 变量里，深色主题用 `.dark` 覆盖同一批变量，JS 里只有一份色表。

「饼图合计 = 明细合计」这一条在实现上是被结构保证的：面板只有一份 `summarize` 结果，
饼图用 `summary.categories`，下钻用 `drillDown(summary, category)`，两处都没有第二次求和。

### 手工验收步骤

1. 先专注一轮（≥30 秒）让当天有数据，滚到「专注统计」
2. 切「日 / 周 / 月 / 年」→ 标题与数字应跟着变；日均在月初不应被「除以整月」压得很小
3. 点饼图某个扇区 → 下方展开该类任务；再点同一下 → 收起；点另一类 → 直接切换
4. 切「占比 / 时长」→ 右侧数值变化，行顺序不变（始终按秒数降序）
5. 点「导出备份」→ 应下载 `campus-focus-YYYY-MM-DD.json`；打开文件能看到 `kind: "campus.focus"`
6. 点「导入备份」选刚才那个文件 → 提示「完全重复，没有新增」，条数不变
7. 选一个非备份的 JSON（比如随便一个 `.json`）→ 应提示「这不是校园工具集导出的备份文件」

## 5. 风险与未做的事

- **手工验收覆盖不到自动化**：本轮没有引入 DOM 测试环境（项目原本没有测试框架，装 jsdom
  属于引入新依赖，超出这一批的范围）。所以「点扇区 → 展开」这一步是**通过 `PieChart` 传入
  `selected` 渲染 + `drillDown` 纯函数结果验证的**，`StatsPanel` 内部那个 `setSelected` 的接线
  靠上面第 3、4 步手工点。这一点必须让负责人知道，不能算「已自动化验证」。
- **饼图未验证真机像素**：深色主题的对比度是按调色板经验选的（`.dark` 一组更亮的色），
  没有逐像素测对比度。建议验收时切深色看一眼扇区间是否还能分辨。
- **导入没有「覆盖」选项**：只补不改。如果有人想要「用备份还原到某天」，那需要另做一个危险操作
  （二次确认 + 自动先导出一份当前数据），本轮不做。
- **导出不含设置**：音色、时长偏好不在备份里，只有任务与会话。理由：设置是设备偏好，
  换设备后未必想沿用；但这也意味着换设备要重设一次音色。
- **`StatsPanel` 默认区间是「周」**：不是「日」。周更能看出趋势，日往往只有一条记录，饼图只有一片。
  如果负责人觉得应该默认「日」，是一行改动。
- **本批没做**：B6 云同步（下一步）。
