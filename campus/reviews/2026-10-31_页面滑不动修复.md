## 1. 起因

两句话，第二句把问题说死了：

> 「我无法向下滑动。」
> 「我无法向下滑动更多来预览我想要的功能，被钉死了。」

一开始我以为是预览页（`previews/dual.html`）的问题 —— 那一版为了防「滚轮被 iframe 吃掉」，
把整页设成了 `overflow: hidden`，确实是我自己钉死的。但改回正常滚动之后，用 CDP 量了一下
`http://localhost:3000/tools` 本身：

```
页面可滚: scrollH=640 clientH=640  → 需要滚动=false
scrollTo(0,600) 后 scrollY=0       → FAIL 滚不动
overflow: html=hidden body=hidden
```

**应用页面自己就滚不动**，跟预览页无关。

## 2. 根因

`src/app/styles/base.css`：

```css
html, body {
  height: 100%;
  /* 应用外壳固定视口：滚动都发生在内部容器里 */
  overflow: hidden;
  overscroll-behavior: none;
}
```

这是主站工作台的设计：外壳是桌面隐喻，整页不滚，滚动交给内部容器（`main.workbench-main`）。
但 `/tools` 是**独立路由**，页面结构是 `CampusToolsHub → <main class="campus-shell">`，
外面没有 `workbench-main` 那一层 —— 于是：

- `html/body` 不允许滚；
- 这一页也没有自己的滚动容器；
- 内容比视口高 → **直接被裁掉，而且没有任何滚动条提示**。

`campus-shell` 只有 `padding: 28px 16px 72px`，高度由内容撑开，所以 DOM 里内容是全的、
`scrollHeight` 也就等于视口高 —— 看起来「页面就这么多」，实际上下面全被裁了。

**为什么以前没发现**：GPA 页内容短，一屏放得下。番茄钟在 B4（专注统计）和 B6（云同步）之后
变长到 1300px 以上，「我的任务 / 专属统计 / 导入导出」整块掉到视口外，用户点不到、也看不到。

## 3. 改成什么

给板块加一层滚动容器，不给全局样式动刀：

```css
.campus-scroll {
  height: 100vh;
  height: 100dvh;
  overflow-x: hidden;
  overflow-y: auto;
  overscroll-behavior: contain;
  -webkit-overflow-scrolling: touch;
}
```

`CampusToolsHub` 的返回值外面包一个 `<div className="campus-scroll">`，`<main class="campus-shell">` 原样不动。

三点取舍：

| 选择 | 为什么 |
| --- | --- |
| 不改 `base.css` | 主站工作台依赖 `overflow: hidden`（`main.workbench-main` 有自己的滚动），动全局会波及全站 |
| 滚动容器放最外层，不放在 `.campus-shell` 上 | `.campus-shell` 是 `max-width: 880px` 的居中栏，滚动条会卡在栏目边而不是视口边 |
| `100dvh` 而不是 `100%` | 手机浏览器地址栏收放时 `100vh` 会被算错，底部最后一段被挡住 |
| `overscroll-behavior: contain` | 滚到底不再把滚动接力给外层；嵌在预览 iframe 里时不会再弹一下 |

## 5. 顺带修掉的：预览页把用户钉死

`previews/dual.html` 上一版为了防止「滚轮停在画面上时被 iframe 吃掉」，把整页设成
`overflow: hidden + 100dvh`。防是防住了，但也把页面钉死了 —— **用一个新的坑盖住旧的坑**。

改成：

- 页面恢复普通文档流，`html/body` 不设固定高度、不锁 `overflow`、不留 `sticky`；
- 每个画面上盖一层 `.veil`「点击开始操作」，同时 `iframe { pointer-events: none }`；
- 点遮罩 → 该侧 `data-armed="1"`，遮罩撤掉、iframe 接收指针，这时才进「操作」；
- Esc、点页面空白、点「操作中 · 点此退出」→ 退回「只看」状态。

实测（CDP 打真实鼠标事件）：

```
初始:       { armed: null, iframe pointer-events: none, veil: flex }
点遮罩后:   { armed: "1",  iframe pointer-events: auto, veil: none }
点空白后:   { armed: null, iframe pointer-events: none, veil: flex }
页面可滚:   scrollY 300 / 内容 1106 / 视口 768  → 滚得动
```

于是滚轮永远是「先滚这页」，想看画面里的内容也只需要多点一下 —— 不再存在「页面被画面卡住」。

## 6. 没做 / 需要知道的

- **只在 Chromium 上量过**。Safari 的 `-webkit-overflow-scrolling` 是老属性，iOS 13+ 已经忽略，
  留着只是为了不出错，不依赖它。
- 深色主题下滚动条用的是浏览器默认样式，没有单独配色；要统一得写 `::-webkit-scrollbar`，
  这次没做。
- `npm run build` 仍然欠着（本轮为 2 个文件的小改动，风险低，合入前统一补跑）。
