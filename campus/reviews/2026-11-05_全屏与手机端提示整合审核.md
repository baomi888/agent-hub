## 1. 改动一：全屏一次点击 + 手机整屏（0.5.8）

**现象**：电脑上点「全屏」第一次什么都不会发生，得再点一次；手机上那颗按钮直接不出现。

**根因**（两条，同一处设计）：

1. 计时卡上的「全屏」只做 `setStageOpen(true)`，真正发 `requestFullscreen` 的是视图里的**另一颗同名按钮**。
   而 `requestFullscreen` 必须在点击的同一段任务里同步发出，晚一帧手势就过期 ——
   拿「要等渲染才存在」的视图当请求目标，天生只能等到第二次点击。
2. 视图里那颗按钮挂在 `Boolean(document.fullscreenEnabled)` 后面。iPhone Safari 至今不支持元素全屏，
   这个值为假 → 按钮整颗不渲染。用户看到的是「手机没有全屏」，而不是「点了没反应」。

**改法**：

- 加一个**始终存在**的宿主节点 `.campus-stage-host`（收起时高度为 0），专注视图渲染在它里面；
  点「全屏」时对宿主直接请求全屏，一步到位。
- 按钮**一直渲染**；真全屏失败就退到**页内全屏**（`position: fixed` + `100dvh` + 安全区），
  视觉与真全屏一致，只少一层系统 UI。
- 真全屏成功 + 粗指针 + 当前竖屏这三个条件同时成立时才试 `orientation.lock("landscape")`；
  退出时补 `unlockOrientation()`，不把用户屏幕锁在横屏。
- 完成弹窗移入宿主内部（z-index 70 > 整屏层 60）—— 浏览器全屏只渲染全屏元素及其后代，
  挂在外面等于到点静默。
- 手机竖屏整屏的顶栏改两行（任务名一行、时刻与按钮一行），大钟按 `min(vw, vh)` 放大。

**关键实测**：桌面首次点击后 `document.fullscreenElement = campus-stage-host`，视图铺满 1440×900，
钟 180px；iPhone 模拟（`requestFullscreen` 直接 reject）下 `campus-stage is-full is-immersive`，
390×844 铺满并锁背景滚动；换 844×390 视口后左右两栏、钟 132.6px。

## 2. 改动二：手机端去掉键盘操作提示（0.5.9）

**现象**：手机界面上写着「按 Esc 收起」「点击卡片（或按空格）翻转」「空格 翻转 · → 认识 · ← 不认识」。

**为什么是问题**：这些键手机上根本不存在，等于指路指到一个不存在的按钮 —— 用户会低头找键，
找不到就以为功能坏了；单词卡那行 `kbd` 还白占一行高度。

**改法**（一句话写两版，按设备切换，**删的是提示不是能力**）：

| 位置 | 电脑 | 手机 |
| --- | --- | --- |
| 专注视图 · 整屏 | 点「退出全屏」回到页面；按 Esc 也行，计时不会中断。 | 点「退出全屏」回到页面，计时不会中断。 |
| 专注视图 · 页内 | 随时可以切到别的标签；按 Esc 收起。 | 点「收起」回到计时卡；切去别处，计时也不会停。 |
| 单词卡提示 | 点击卡片（或按空格）翻转看释义 | 点击卡片翻转看释义 |
| 单词卡底部 `kbd` 行 | 照旧 | 整行不渲染，连高度都不占 |

- 实现是一对工具类 `.campus-desktop-only` / `.campus-touch-only`，
  只在 `@media (hover: hover) and (pointer: fine)`（电脑 + 精确指针）翻转。
  **没有用 JS 判设备**：`/tools` 首屏是服务端渲染，JS 判断会让手机先闪一版桌面文案；
  媒体查询首帧就成立，也没有 hydration 前后两套 DOM 的问题。
- 反向修了一处：**「横过来更沉浸」不再出现在电脑上**，它原来按「竖屏 + 整屏」显示，
  把电脑窗口竖着拉窄也会冒出来，而电脑转不了屏。
- 键盘监听一行没删：iPad / Android 平板接物理键盘时 Esc、空格真能用。

**关键实测**：手机 390×844（CDP 触摸模拟）下 `document.body.innerText` 中 **0 个 `Esc`**、
「空格」0 次、`kbd` 行 `display: none`；六个标签页全扫一遍同样为零。桌面竖窗口 820×1100 下
Esc 提示仍在，`rotateDisplay = none`。

## 5. 风险与未做的事

**已知限制**

- iPhone 没有 `screen.orientation.lock`，无法程序化转横屏：页内全屏只能提示「横过来更沉浸」，
  转不转由用户决定。这是平台限制，不是实现取舍。
- 页内全屏少了浏览器那层系统 UI（地址栏、状态栏还在）。它让 iPhone 从「完全没有全屏」
  变成「有整屏」，这是「没有 API 就只能这样」的天花板。
- 设备判定用 `(hover: hover) and (pointer: fine)`：iPad 接触控板时会走桌面版 —— 那种设备确实有 Esc 键，属正确结果。
- `display: revert` 需 Chrome 84+ / Safari 13.1+ / Firefox 67+，与板块其他特性（`100dvh`、`color-mix`）同一基线；
  万一不支持会回落到「文字仍可见」，不会弄坏电脑端。

**本次没做（但相关）**

- `tests/test_focus_sync.py` 13 个接口级用例（无 pytest）。这两条改动没碰后端。
- 真机未测：Android Chrome 的 `orientation.lock` 实际旋转、iOS 页内全屏的安全区表现、
  iPhone / Android 的 `hover / pointer` 实际取值（规范上恒为 `none / coarse`，风险低）。
- 主站 `ChatArea.tsx` 的「Enter 发送 · ↑ 上一条 · Esc 清空」，以及 `FeedbackModal` /
  `FilePreviewModal` 的 `title="关闭（Esc 也行）"`。前者属桌面工作台，后两者是 `title`（触屏本就不显示）。

**可能的回归点**

1. **整屏层级**：页内全屏 `z-index: 60`、完成弹窗 70，顺序反了会让到点提醒被盖住 —— 已实测。
2. **宿主与卡片相邻规则**：`.campus-card + .campus-card` 靠相邻选择器给间距，插入宿主后两卡仍相邻，
   页高实测一致（收起桌面 1105 / 手机 1292）。
3. **`.campus-stage-hint` 的横屏规则**（≥760px 整块 `display:none`）没被改动 ——
   0.5.9 只在里面包了两个 `span`，外层 `p` 一行没碰。
4. **切去别的工具**：组件卸载时兜底 `exitFullscreen` + `unlockOrientation`，否则会停在「没有地址栏且横着」。

## 6. 回归点清单（审核时值得亲手点的 4 个点）

1. 电脑：建任务 → 点「全屏」→ **一次**就整屏；再点「退出全屏」→ 回到页内、计时没断。
2. 电脑：手机尺寸窗口（或手机）点「全屏」→ 整屏后点「收起」→ 视图收起、页面能继续滚。
3. 手机：专注视图底部提示里**不该出现 Esc**；单词卡底部**不该有那行键盘说明**；
   整屏竖着时应看到「横过来更沉浸」。
4. 整屏中等到倒计时走完 → 提醒弹窗要出现（这是 0.5.8 修的那个静默失败）。
