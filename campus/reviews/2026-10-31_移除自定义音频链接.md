## 1. 做了什么

把 0.3.2 里的「自定义音频链接 / 连接歌单」整块删掉，提示音只保留 6 个按钮：晨钟、木琴、八音盒、风铃、水滴、静音。

用户看到的变化：

| 之前 | 现在 |
| --- | --- |
| 6 个音色 + 1 个「自定义」按钮 | 6 个音色按钮（两行三列，正好整齐） |
| 一个链接输入框 + 「用这个」按钮 | 无 |

| 面板底部两段说明文字 | 一行：「音色由浏览器实时合成，不下载音频文件，断网也能响。」 |

## 2. 为什么撤

原话：「可以选择链接歌单，自行连接设计这个部分取消吧」

技术上这条路的真实边界：能播的只是**音频文件直链**（`https://…/x.mp3`）；
使用者真正想要的是**连自己的歌单**，而歌单页是脚本渲染的网页，`<audio>` 取不到里面的音频流。
这不是实现难度问题，是平台不开放。

所以这个入口的最可能结局是：用户粘上歌单链接 → 看到「这是歌单页面，不是音频文件」 → 放弃。
留一个大概率失败的入口，比不提供更消耗信任。**按你的判断撤掉。**

## 4. 老数据怎么处理

这是删除功能时唯一有风险的地方，做法是**不写迁移，靠清洗兜住**：

存量里可能有 `{ "chime": "custom", "volume": 0.3, "customUrl": "https://…/a.mp3" }`

1. `isChimeId("custom")` 现在返回 `false` → 回落默认音色「晨钟」；
2. `volume: 0.3` 原样保留（音量是用户调过的，不该跟着丢）；
3. `customUrl` 不解构、不转发；`saveSoundPrefs` 只写两个字段，**下次任何一次改设置都会把它冲掉**；
4. 即便用户从不改设置，这个字段也只是躺在 localStorage 里，不参与任何逻辑。

结果：老用户升级后听到的是「晨钟 @ 30%」，不是静音、也不是空态。

| 项 | 命令 / 方式 | 结果 |

**自检覆盖的关键断言**

- 预设：数量 6、id 顺序固定、低通为正、只用 sine/triangle（不用方波锯齿）、单音增益 < 0.25、起音 ≥ 0
- 兼容：`custom` 判无效、旧数据回落为 `{chime:"bell", volume:0.3}`、**不留 `customUrl`**
- 兜底：音量越界夹取、非数字回落 0.6、`null` / 数组 / 字符串 / 坏 JSON / SSR（无 `window`）都回默认
- 落库：故意传入带 `customUrl` 的对象，写盘后只有 `{chime, volume}` 两个键

**渲染冒烟覆盖**

- 在：面板容器、`提示音 ·`、5 个音色名、静音、音量标签、试听按钮、`type="range"`
- 不在（逐项断言为 0）：`自定义`、`用这个`、`type="url"`、`alarm.mp3`、`歌单`、`campus-sound-url`、`campus-sound-error`
- 音色按钮数 = **6**

**没做的**

- 仍**未跑 `npm run build`**：dev server 占着 `.next`，跑了会打断预览；合入前补。
- 未做真机验证（音色听感、iOS 音量）—— 需要你在手机上听一遍。
