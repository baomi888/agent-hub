## 0. 给审核人的三分钟版

昨天到今天一共做了 **16 条需求**、**16 个版本**。核心是：番茄钟从「一个计时器」变成「能长期用的专注记录器」，
然后按你的反馈把界面形态返工了七次（0.5.1 – 0.5.7）。

**必须先知道的三个结论：**

1. **`npm run build` 的欠账已还清**（2026-11-02 补跑）：0.3.1–0.5.7 一次性过，
   Next.js 16.3.5 编译 4.8s、15 个页面全部预渲染。原本这是放行前唯一的硬性前置条件。
2. **`tests/test_focus_sync.py` 的 13 个接口级用例仍没跑过**（本机无 fastapi / pytest）。
   服务层用真实 SQLite 验了 40 项，但鉴权、400、404、尾斜杠这些 HTTP 行为只有静态校验。
3. **有 4 份报告被后续版本覆盖**，实际交付以最新为准：0.3.2 → **0.3.3**、0.4.0 → **0.5.1**、
   0.5.4 → **0.5.5** → **0.5.6**（覆盖关系见附录 A 末尾）。

> **为什么合成一份**：`reviews/README.md` 定的规则是「一份功能交付 = 一份报告」。本文件不推翻它 ——
> 16 份分项报告原样保留、仍可逐条回溯（附录 A 有索引）；这一份是给负责人**一次性看完全部**的合集，

### 会直接影响你看到的数字的七条口径

审核时若发现「数字和我预期不一样」，先看这张表 —— 都是主动定的，不是算错：

| 口径 | 定义 | 为什么 |
| --- | --- | --- |
| 暂停不计时长 | 跑 10 秒 → 停 100 秒 → 跑 5 秒 = **15 秒** | 否则「好像学了两小时」会真算成两小时 |
| 30 秒门槛 | 中途结束不足 30 秒不写记录（自然完成不受限） | 点开又点掉的误触不该进统计 |
| 同名不重复建 | 忽略大小写与首尾空白；重新添加已归档的同名任务 = 恢复 | 历史统计始终归在一个任务名下 |
| 日均分母 | 区间内**已过**的天数，不是区间总天数 | 本月 3 号看月统计除以 31，数字小得离谱 |
| 导入只补不改 | 同 id 保留本地版本 | 备份可能是上周的，用旧的盖新的等于删掉这一周 |
| 零时长会话 | 计入条数，不计时长 | 避免「今天练了 3 次」变成 0 次 |
| 饼图分片 | 超过 6 类合并「其他」，合并后重新降序 | 否则图例比饼图还长 |

## 3. 交互返工：七轮

七轮全部来自「做出来才发现不是想要的样子」。把「我判断错在哪」写出来，是因为这一类错误会重复发生。

| 版本 | 你的原话 | 我判断错在哪 | 改法 | 实测 |
| --- | --- | --- | --- | --- |
| 0.5.1 | 不要锁定我的预览画面 | 一开专注视图就 `requestFullscreen` + 锁横屏 + 锁 body，等于抢走整页 | 改页内区域，全屏变手动按钮，常亮收紧 | SSR 冒烟 9 项 |
| 0.5.2 | 我要体验双端具体是怎样的界面 | 一直用截图汇报，把汇报材料当成了产品本身 | 双真 iframe 预览页 + 修 6 处双端问题 | 三种宽度截图 |
| 0.5.3 | 无法向下滑动，被钉死 | 先怀疑预览页，把整页设 `overflow:hidden`，用新坑盖旧坑。真因是 `/tools` 没有滚动容器 | 加 `.campus-scroll`，六工具共用 | 可滚距离 GPA 260/377、番茄钟 677/816 |
| 0.5.4 | 收成按键，节约占比 | 做成了弹窗，盖住正在跑的计时 | 入口按钮 + 数字 | 页高 1317 → 975（−26%） |
| 0.5.5 | 页内展开，不要弹窗，加淡入 | 展开用整块做滚动锚点，600px 的统计面板把刚点的按钮顶出屏幕 | 锚点改标题行（34px） | 滚动增量 0 |
| 0.5.6 | 要上下，不要并列；展开不影响 | 并排时右侧长值压字；竖排若让内容跟行，点上面那行会推走下面那行 | 展开区固定在整个组下方 | 两次点击按钮 y 都是 661.4 / 727.4 |
| 0.5.7 | 两个功能区别贴太紧；做区分度；小框双端都不对 | 两行挤同一张卡只隔 1px，像同一张表的两个表头；三块卡底色边框阴影完全一样 | 拆两张独立卡 + 图形标记 + 间距 16 + 卡片头底线 + 控件双端分档 | 见 5.2 |

> **结论（已写进 `docs/06` 第 4 节）**：凡是「界面怎么呈现」，先给最小可点版本再往下做。
> 七轮里有六轮是形态问题，与技术实现无关。

### 通道异常：`github.com:443` 走不通，改走 API

本机出口代理拒绝到 `github.com:443` 的 CONNECT（`502 Bad Gateway`），`git fetch/push` 直接失败；
`api.github.com` 正常。SSH（`github.com:22` / `ssh.github.com:443`）能连通但账号没有登记公钥，
而令牌只有 `repo` 权限、加不了密钥。

因此改用 **Git Data API** 完成等价推送：按 commit 逐个 `POST /git/blobs` → `POST /git/trees`（带 `base_tree`）
→ `POST /git/commits` → 最后一次 `PATCH /git/refs/heads/school-tools`。共 63 个 blob、8 个 commit、79 次请求。

**副作用已处理**：GitHub 建 commit 时会去掉 message 末尾的空行，所以 API 产生的 sha 与本地不同。
两边分叉会让将来的 `git push` 被判 non-fast-forward，因此按远端元数据把本地对象重建了一遍
（tree 相同、message 与日期对齐，sha 本身就是校验和），现在**本地 `HEAD` 与远端 `school-tools` 完全相同**。

下次在这台机器上推送仍需先解决 `github.com:443` 的连通性，否则只能继续走 API。
