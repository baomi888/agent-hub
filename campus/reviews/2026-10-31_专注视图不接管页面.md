## 1. 起因

测试时反馈一句话：

> 「不要锁定我的预览画面，我要真实体验。」

打开专注视图之后，整块页面被接管：标签栏看不见了、统计看不了、连预览窗都被顶掉，
只能按 Esc 或点「退出全屏」才能回到正常页面。这不是「专注」，这是「被关起来」。

## 2. 问题定位

三处叠加，才造成「页面被锁住」：

| # | 位置 | 原来做了什么 | 后果 |
| --- | --- | --- | --- |
| 1 | `PomodoroTool.tsx` 的 `stageOpen` 副作用 | 挂载后立刻 `enterFullscreen()`，成功后再 `tryLockLandscape()` | 视图一开就抢走整屏，且自动转横屏 |
| 2 | `.campus-stage` 的样式 | `position: fixed; inset: 0; z-index: 80` | 盖住标签栏和整页内容，页面无法滚动 |
| 3 | `FocusStage.tsx` 的挂载副作用 | `document.body.style.overflow = "hidden"` | 连滚动都被锁死，像页面卡住了 |

三件事单独看都「为了沉浸」，合起来就是用户说的「锁定」。

## 3. 改成什么

### 3.1 默认长在页面里

`.campus-stage` 从 `position: fixed` 改为普通块级区域（`section`，`margin-bottom: var(--campus-gap)`），
`min-height: clamp(320px, 56dvh, 520px)`。

于是：视图跟着页面滚、标签栏可点、统计和任务列表随时能看。**「专心」不再等于「被锁住」。**

### 3.2 全屏变成一次显式选择

- 视图头部多一个「全屏」按钮，点一下进、再点一下出；
- 全屏请求仍必须在点击事件里发出（浏览器要求用户手势），所以不做任何自动重试；
- 进不去就静静留在页面内，不弹错、不打断计时；
- `document.fullscreenEnabled` 为 false 时（部分 iOS / 嵌入式 WebView）**不显示这个按钮** ——
  摆一个按了没反应的按钮比没有更糟。

### 3.3 常亮只在真全屏时申请

`requestWakeLock` 的前置条件从「视图打开」收紧为「视图打开 **且** 已在全屏」。
页面内看计时没必要拦着锁屏。

### 3.4 Esc 的语义

| 状态 | 按 Esc |
| --- | --- |
| 已在全屏 | 交给浏览器退全屏（不 `preventDefault`），视图留着 |
| 不在全屏 | 收起专注视图 |

### 3.5 关掉「同屏两个计时」

视图展开时把「专注计时」卡片收起（`{!(stageOpen && timer) && ...}`）——
否则同一屏上摆着两个一模一样的 25:00，看着像出了 bug。音色设置在卡片里，
收起期间不可见，但计时中本来也不该去调这个。

### 3.6 全屏状态从哪来

容器不再自己 `useState` 一份「我是不是全屏」再去 effect 里追 —— 那样会在 effect 里同步 setState，
React 官方明确不建议（lint 也会报 `react-hooks/set-state-in-effect`）。
改成 `useSyncExternalStore(subscribeFullscreen, isFullscreenSnapshot)`：
浏览器就是那个「外部系统」，状态由它说了算，服务端快照恒为 `false`。
为此在 `logic/fullscreen.ts` 里加了 `subscribeFullscreen` / `isFullscreenSnapshot` 两个函数，
原有的 `enterFullscreen` / `exitFullscreen` / `watchFullscreen` 一行未动。

### 3.7 排版

- 大钟字号 `clamp(52px, 12vmin, 128px)`；只有 `:fullscreen` 才放开到 `clamp(56px, 18vmin, 190px)`
  （卡片里用 18vmin 会直接撑爆）；
- 头部按钮区允许换行（`flex-wrap`），窄屏上「当前时刻 / 全屏 / 收起」不会挤成一坨；
- 「横过来更沉浸」只在真全屏 + 竖屏时出现 —— 页面内本来就是竖着看的，提示没有道理。

## 4. 为什么保留「全屏」

反馈针对的是「默认被接管」，不是「不想要全屏」。把手机架在桌上、专心写两小时的人，
确实需要整屏 + 常亮 + 横屏。所以做法是**把决定权交回去**：默认不打扰，需要时一键进。
