一句话：**深色模式下九个分类终于能一眼分开；日历格子从「扁表格」改回接近方形；点某一天只弹那一天的事；在日历上就能把不想看的收走；第一次进来会看到一页使用说明。**

## 5. 深色模式：问题在算法，不在配色

### 5.1 根因

第一版的深色格底是这一行算出来的：

```css
/* 第一版 */
.dark .campus-ev-cell.is-tinted {
  background: color-mix(in srgb, var(--ev-c1-dark) 24%, var(--card-bg));
}
```

卡片底是 `#292217`（一个很暗的暖褐）。把九个分类色按 24% 混进去，结果是这样：

| 分类 | 第一版 24% mix | 现在 `cellDark` |
| --- | --- | --- |
| 创新创业 | `rgb(85, 59, 40)` | `#5C3823` |
| 计算机与 AI | `rgb(58, 70, 65)` | `#294A63` |
| 电子信息 | `rgb(87, 69, 36)` | `#64501E` |
| 数理基础 | `rgb(66, 68, 41)` | `#3A5424` |
| 语言与人文 | `rgb(71, 57, 44)` | `#55302B` |
| 经管与商科 | `rgb(70, 61, 67)` | `#55406E` |
| 设计与建筑 | `rgb(58, 68, 56)` | `#26504B` |
| 综合与其他 | `rgb(73, 66, 54)` | `#464238` |
| 升学就业 | `rgb(63, 61, 60)` | `#3A4666` |

左列九个值全部落在 **RGB 57–87** 这个窄带里，任意两色的单通道差只有 10–30。
**不是九个分类色选得不好** —— 它们色相跨度足够；是 `mix` 这个算法把结果明度交给了那个很暗的卡片底，
九个色被同一个低频底拉平，色相再远也只剩「偏红的暗褐 / 偏蓝的暗褐」。

### 5.2 为什么不能靠提浓救

把混合比例从 24% 提到 45%，色相确实出来了，但格子里 11px 的小字被压掉。
浅色模式 22% 就是实测上限，同一个约束在深色下换了方向又撞一次 —— 浓度与可读性是零和的。

### 5.3 改法：每个分类单独配一支深色格底

`CategoryMeta` 加 `cellDark` 字段，原则是「色相明确 + 明度比卡片高一档」。
蓝、靛、紫这三支色相本来就挨得近，再靠明度拉开一档。

字段注释里写明了约束，防止后来者随手改：

> 这里按「色相明确 + 明度比卡片高一档」单独配一组：蓝紫三兄弟靠明度再拉一档，其余靠色相区分。数值是实测调过的，改之前先截图比对九色同屏。

配完实测：**九色格内的纸白字对比度 5.9–8.7:1**（WCAG AA 门槛 4.5），既分得开又读得清。

### 5.4 三处配套改动（同一个原因）

| 项 | 原来 | 现在 | 为什么 |
| --- | --- | --- | --- |
| 格子顶边 | 3px，用 `--ev-c1`（浅色版） | **4px**，用 `--ev-c1-dark` | 3px 在暗底上细得看不出是「分类色条」；浅色版压在暗底上更暗 |
| 彩色格内文字 | `--text-2` | `--ink`（最亮档） | 11px 小字压在彩色底上最先糊 |
| 格内色点 | 分类原色 | 深色用 `--dot-d`（提亮版） | 原色压在**同色相**的深色格底上等于没有色点；手机格子里只剩色点，认不出点就是认不出分类 |

最后一条是这次最不显眼但最要命的：桌面还能靠文字认，手机上格子只有色点，色点隐身等于分类信息整个丢失。

## 7. 三处交互收紧

### 7.1 点日期只弹当天

上一版弹层是两段：当天的事 + 「本月其余 N 件（只有月份精度）」。

问题在于 **11 月没有一条核实到日**，于是点 11 月的**任意**一天，都会倒出二十多件跟那天无关的东西 ——
用户点的是「12 号」，看到的是整个 11 月。那不是回答问题，只是把日历又抄了一遍。

月份精度的事从来没有核实到「哪一天」，把它塞进某一天的窗口里**本身就是假精确**。

现在弹层只有一段：当天已核实的事；没有就直说没有。

配套的空状态也重写了：

| | 文案 |
| --- | --- |
| 原来 | 「这一天没有确切日期的安排，这个月也没有其他窗口期赛事。」 |
| 现在 | 「这一天没有已核实的安排。」+「只有月份精度的事留在本月清单里，不按天拆。」 |

原句读起来像在解释另一件事；新句把「空」和「漏了」区分开。

**顺带清掉四处死样式**：`.campus-ev-daysheet-hint` / `-group` / `-dot` / `-num` —— 弹层不再分组，这些选择器已无对应 DOM。

### 7.2 「不感兴趣」搬到日历上

之前只有详情弹层底部一个入口：一天撞三件事，要**进出六次**才能收完。

现在两个新入口：

| 位置 | 形态 | 理由 |
| --- | --- | --- |
| 右栏本月清单 | 每行 26px 圆形「×」 | 一屏能扫完整月，收一条不用离开日历 |
| 当天弹层 | 每行「不感兴趣」文字按钮 | 弹层宽度富余，文字比符号更明确 |

两者走的都是详情的同一条 `marks[id] = "skip"` 通道 —— **没有另开一套「隐藏」字段**。
两套状态立刻会长出两份对不上的清单（一处说已收走、另一处还在），这是这类功能最常见的坏法。

**这里踩了一个坑，值得记一句**：第一版在右栏用了 66px 的文字按钮，实测名称行只剩 176px、
行高从 57px 涨到 75px —— 右栏是「名称独占一整行」的两行排版（§6），横向少 70px 就直接把它压回两行，
等于把刚修好的截断问题又装回去。换成 26px 圆钮后名称行回到 216px、行高回到 57px，
文案退到 `aria-label` 与 `title`。

另外把悬停底色从行按钮挪到整条 `li`，否则右边按钮那一块不上色，看着像没选中。

**回执**：收走后底部弹一句 ——

> 已把「XX」从日历上收走 · 想找回就去「我的」

条目当场消失，没有这句话用户第一反应是「我是不是点坏了」。

### 7.3 首次进入的使用说明

这个工具长得像一份赛事通知，很容易被当成「官方日期 + 点进去就能报名」。所以说明里必须同时讲清
**怎么用**（四条）与**它不做什么**（一段强调）。

四条按「看 → 处置」排序：

1. 有色格子的含义
2. 空格子不代表没事
3. 不想看某一条怎么办
4. 想留提醒怎么置顶

顺序反过来，用户会先看到两个动作按钮，却不知道该对什么点。

**边界那句话是橙子这轮的核心要求**，原文落在说明底部：

> 这里只帮你打破信息差，不是报名服务。名额、资格、具体日期一律以赛事官网和本校教务处 / 团委的通知为准 —— 我们只负责提醒「有这回事」。

`introSeen` 并进 `campus.events.state.v1`，**不另开 storage 键** —— 少一处「清了一个没清另一个」的隐患。
标题右侧常驻「使用说明」按钮，随时能重开。

手机实测：卡片高 629px / 视口 844px，不用滚；「知道了，开始看」按钮在 722px 处可见。

## 10. 风险与未做的事

### 10.1 真正的回归点（请重点看这条）

`EventsState` 新增了 `introSeen`。`normalizeEventsState` 里写的是 `r.introSeen === true`，
所以**已经用过这个工具的人升级后，会再看到一次使用说明**。

这是有意的 —— 老用户也没见过这页说明，而它承载着「这里不是报名入口」这句免责。
但如果负责人认为「升级后突然多一个弹窗」不可接受，改法是把兜底值从 `false` 改成 `true`，
代价是老用户永远看不到这页说明。**默认按「该看」处理，请确认**（§10 待定 3）。

### 10.2 已知限制

- **`cellDark` 需要人工维护**。新增第 10 个分类时，必须同时配 `color` / `dark` / `cellDark` 三支色，
  漏一个深色下就退回暗褐。已在字段注释里写明约束，但没有代码层校验（写一条「九个分类的 cellDark 必须两两不同」的构建期断言成本不高，可以下批补）。
- **「不感兴趣」现在有三个入口**（详情底部、当天弹层、右栏清单），点错了都要回「我的」找回。
  回执只显示约 3 秒，没看见就得自己找 —— 这是 toast 的固有取舍，不打算改成常驻横幅。
- **使用说明只弹一次**，依据是 localStorage。换浏览器、清缓存会再弹一次，属预期行为。
- **深色截图未压缩**（6 张，含两张使用说明深色图）。压缩会压出锯齿色带，宁可多背体积 —— 目录 4.2MB。

### 10.3 本轮没做（但相关）

- **另外 19 份历史报告**（2026-11-06 课表批、11-08 单词卡批等）用的是同一种 HTML 内联图片写法，
  在预览器与微信里都看不到图。本轮已把 Markdown 原生写法写进 `TEMPLATE.md` 与 `docs/05` 闸门 9b，
  但**存量未改**，等橙子一句话。
- **周末列不染色**（§6 末段），是设计决定，需负责人确认口径。
- **数据仍需每年人工核对**。本轮没有碰日期，但 `tools/events/data.ts` 与 `certs.ts` 的时效性没有自动校验。

### 10.4 提交边界（这批怎么落，需要定）

11-20 与 11-22 两批都在同一个未提交的工作区里。`campus.css`、`EventsTool.tsx`、`types.ts` 三个文件**两批都动过**，
所以：

- **能按文件拆的**：`IntroSheet.tsx`（纯新增，必属今日）
- **不能按文件拆的**：`campus.css`（11-20 新增的年历表样式段 + 今天的深色/排版改动混在一个文件里）
