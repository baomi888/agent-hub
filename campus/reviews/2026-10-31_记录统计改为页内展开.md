## 3. 三个设计判断

### 3.1 为什么是「按钮行 + 展开区」而不是让展开区插在两个按钮之间

手机是两个按钮竖排。如果展开区跟着被点的那个按钮走，点上面那个就出现在中间、点下面那个就出现在底部，
同一份内容在两个位置跳动，滚动位置也跟着变。统一放在按钮行**之后**：
不管点哪个，内容都在同一处出现，位置可预期。

### 3.2 淡入怎么做的

```css
.campus-pomo-fold { animation: campus-fold-in 0.2s ease-out; }
@keyframes campus-fold-in {
  from { opacity: 0; transform: translateY(-6px); }
  to   { opacity: 1; transform: translateY(0); }
}
```

- 只动 `opacity` 与 `transform`，**不碰 `height`**：高度动画要读布局、逐帧重排，手机的列表一长就掉帧；
  这两个属性跑在合成层。
- 0.2s + 6px：够看出「这是刚展开的」，又不拖手感。位移方向是**从上往下落**，与「从按钮下面长出来」一致。
- `prefers-reduced-motion: reduce` 下动画与箭头过渡一并 `none`，内容直接出现。
- 每次展开都重播：展开区是条件渲染、不是 `display:none` 切换，重新挂载即重新触发动画。

### 3.3 展开后要不要滚一下

要。入口按钮常在页面底部，展开区一大半在视口外，不滚的话看起来像「点了没反应」。
用 `scrollIntoView({ block: "nearest" })`：只在需要时动，已经可见时一个字都不滚 ——
用 `start` 会把用户正在看的计时盘顶出屏幕。

## 4. 顺带修掉的一个静默失效

0.5.4 的说明里我写了「完成弹窗与浮层共用 `logic/scrollLock.ts`」，**实际没有**。
`FinishDialog` 仍然是老写法：

```ts
const previousOverflow = document.body.style.overflow;
document.body.style.overflow = "hidden";
```

而 0.5.3 之后滚动发生在 `.campus-scroll` 上，`html/body` 本来就 `overflow:hidden`，
改 body 拦不住任何东西 —— 弹窗背后一直能滚。本轮改成 `return lockPageScroll()`，
CSS 侧规则同步为 `body.campus-modal-open .campus-scroll { overflow: hidden }`。

实测：手动加类后 `.campus-scroll` 的 `overflow-y` 由 `auto` 变 `hidden`，移除后复原。

## 6. 遗留

- 没有展开的**收起动画**：目前是瞬间消失。做收起要固定当前高度再过渡到 0，展开中途收起还要处理打断，
  为一个「顺手看一眼」的面板不值得，先不做。
- 展开区没有焦点管理：按 Tab 会从入口按钮顺序走到「收起」，符合常规文档流，不需要额外处理。
- `npm run build` 仍未跑（累计欠账），合入前必须补。
- 真机未测。手机上的淡入与 `scrollIntoView` 在 iOS Safari 的手感需要点一次确认。
