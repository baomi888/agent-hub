## 1. 做了什么

| # | 内容 | 用户看到的变化 |
| --- | --- | --- |
| 1 | 全屏专注 | 计时中点「全屏」，整屏只剩一个大数字、任务名和三个按钮；Esc 或「退出全屏」回来 |
| 2 | 双时间 | 表盘下方常驻一行「已过 12:34 · 剩余 12:26」；正计时显示「已过 12:34 · 不限时」 |
| 3 | 当前时刻 | 全屏右上角显示 `18:05`（全屏后系统状态栏被隐藏，得自己报时） |
| 4 | 防熄屏 | 全屏且计时中申请屏幕常亮；暂停时释放，切走标签页自动重申请 |
| 5 | 横屏优先 | 宽屏横屏版式「大钟居中 + 操作区右侧一列」；竖屏手机上给一句「横过来更沉浸」 |

进出全屏**不影响计时**：计时状态全在容器里，舞台只是同一份状态的另一种画法。

## 2. 为什么做

对应需求 **R1**：「全屏横屏、剩余时间 + 当前时刻、正计时/倒计时」。

拆开看是三个具体问题：

- **手机放桌上专注时，页面上其他六个工具全在视线里**，一屏杂事，专注变成看菜单；
- **倒计时进行到一半，想知道「已经花了多久」得自己减**（25:00 减剩余），减法不该由用户做；
- **全屏后看不到现在几点**，一轮结束抬头不知道是不是该去上课。

## 3. 改动明细

### 新增 `logic/fullscreen.ts`（215 行）

三个浏览器能力统一成「失败返回 false，不抛错」：`enterFullscreen` / `exitFullscreen` /
`watchFullscreen` / `requestWakeLock` / `releaseWakeLock` / `tryLockLandscape` / `formatWallClock`。

前缀兼容（`webkit`、`moz`）全在文件内部消化，组件里看不到任何厂商前缀。

### 新增 `tools/pomodoro/FocusStage.tsx`（157 行）

全屏舞台本身，**不持有任何计时状态**，时间由容器灌进来 —— 这是「进出全屏不丢计时」的实现方式，
也保证任何时候只有一个定时器在跑。

- 挂载即把焦点放到大数字上（`tabIndex={-1}`），键盘用户不用先 Tab 穿过背后的整页；
- 锁 `body` 滚动，滚轮不会把背后的页面带着走；
- 自带 Esc 兜底：全屏被拒绝时（部分 iOS 版本、嵌入式 WebView），浏览器不会响应 Esc，这里关掉舞台。

### 改 `PomodoroTool.tsx`（+62 行）

| 位置 | 改动 |
| --- | --- |
| 状态 | `stageOpen` + `stageRef`；计时状态一处没动 |
| 副作用 1 | 展开时请求全屏 + 尝试锁横屏 + 监听 `fullscreenchange`；**收起时一定退出全屏** |
| 副作用 2 | 常亮锁的申请/释放，挂在 `visibilitychange` 上重申请 |
| 结算 | `finish` / `handleReset` 里收起舞台 —— 一轮结束要先看到完成弹窗 |

### 改 `TimerFace.tsx`（+18 行）

表盘下加双时间行；按钮区在计时中多一个「全屏」（待机时不显示 —— 全屏是拿来专注的，不是拿来看设置的）。

### `styles/campus.css`（+215 行）

字号用 `clamp(56px, 18vmin, 190px)` 跟随**视口短边**：横过来数字自动变小，任何屏幕都不会溢出。
四边补 `env(safe-area-inset-*)`，刘海和 Home 条不吃内容。

### 手工验收步骤（建议照着点一遍）

1. 选任务 → 时长 1 分钟 → 开始 → 点「全屏」
2. 确认大数字在走、下方「已过 / 剩余」两个数相加恒等于 1 分钟、右上角时刻和手机状态栏一致
3. 按 Esc → 应回到普通页面，**计时继续**，不回到 01:00
4. 把手机横过来 → 大钟变大、操作区移到右侧；竖屏时应看到「横过来更沉浸」
5. 等倒计时走完 → 应自动退出全屏并弹出「本轮完成」

## 5. 风险与未做的事

- **全屏必须由点击触发**：这是浏览器规则，没有绕法。若用户用的是「全屏被禁用」的浏览器/WebView，
  舞台仍会铺满视口（`position:fixed`），只是没有隐藏地址栏 —— 功能不丢，观感略差。
- **iOS 不支持锁横屏**：`screen.orientation.lock` 在 iPhone 上不存在，只能提示用户自己转。
  这与 `docs/06` 2.3 的结论一致，不是本批引入的问题。
- **iOS 不支持 Wake Lock**：iPhone 上全屏仍会按系统设置熄屏。Android Chrome / 桌面可用。
  做不到「网页保证不熄屏」，已在文档中标注为权限边界。
- **快速连点「全屏」**：第二次点无效（已在计时中，按钮不重复触发）。全屏请求是异步的，
  失败时静默停在舞台层，不弹错误 —— 这类提示会打断专注，代价大于收益。
- **无障碍已知缺口**：舞台用的是 `role="dialog" aria-modal="true"`，但没有给背后的页面加 `inert`，
  键盘 Tab 理论上仍可能跳到背后的链接。要做完整需要给 `CampusToolsHub` 加 `inert` 透传，
  属跨组件改动，留到后续（不影响鼠标/触屏用户）。
- **本批没做**：R4 三种模式（已暂缓）。会话模型里的 `awayCount` / `awaySeconds` 仍恒为 0，
  将来重启不用改存储结构。
