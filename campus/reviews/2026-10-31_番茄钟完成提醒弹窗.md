## 1. 做了什么

倒计时走到 00:00 时，屏幕中间弹一层「本轮完成」：显示这一轮多久、做的哪个任务、今天累计几段多久，
主按钮「再来一轮」直接接着开下一轮。

## 2. 为什么做

原话：「在倒计时结束后，多加一个弹窗的提醒页面。」

改之前到点只在计时卡片下方换一行灰字（「完成一段「高等数学」，25 分钟」）。这段提示有两个问题：

1. **看不见**：25 分钟里人大概率切到了别的窗口或低头看书，一行灰字出现时没人盯着屏幕；
2. **不敢信**：没有明确的「这轮结束了」的信号，容易以为计时还在跑，或者反过来以为数据没记上。

## 4. 交互规则（请重点看这节）

| 场景 | 行为 | 为什么 |
| --- | --- | --- |
| 倒计时自然走完 | 弹窗 | 到点是无人值守也会发生的事件，需要把人叫回来 |
| 手动点「结束」（倒计时提前收） | **不弹**，只页面内提示 | 这是用户自己的动作，再弹一层会让「结束」变得不敢点 |
| 正计时手动结束 | **不弹** | 正计时没有终点，不存在「到点」 |
| 点「重置」 | **不弹** | 明确丢弃本轮，不需要庆祝 |
| 「再来一轮」 | 同一任务、同一时长立刻开始，弹窗关闭 | 连续做番茄是常态，不该逼人关窗→点开始两步 |
| 「先歇会」/ Esc / 点遮罩 | 关闭弹窗，表盘停在 00:00 | 不自动进入休息计时，避免「以为没在计时」 |

### 4.1 弹窗不承担写入

会话记录在弹窗出现**之前**就已经写进 `localStorage` 了。关掉弹窗不会丢数据，也不会重复记录一次。
这一点是刻意设计的：如果写入挂在「关弹窗」上，用户直接关标签页就会丢这一轮。

### 4.2 后台标签提醒

到点时如果页面不可见，标签标题会变成「⏰ 专注完成 · 校园工具集 · 知穗」，切回来自动还原。
不加这个的话，人在别的窗口时弹窗等于没弹。

### 4.3 文案按时段变

深夜 23–4、清晨 5–7、上午 8–11、中午 12–13、下午 14–17、晚上 18–22 各一句。
「深夜的一段，早点睡比多熬一小时更值。」这类话对着上午 9 点说会很怪，所以按时段分开。

## 附：评审时怎么试

```bash
cd frontend
npm run dev
# http://localhost:3000/tools → 点「番茄钟」
```

1. 选一个任务，把时长改成 **1 分钟**（最短就是这个值），点开始；
2. **切到别的标签页**，等 60 秒 —— 标签标题应变成「⏰ 专注完成 · …」；
3. 切回来 —— 应看到弹窗，显示「1 分钟」、任务名 + 大类、今日累计；
4. 点「再来一轮」—— 弹窗关闭且立刻重新开始计时，不用再点开始；
5. 再跑完一轮，这次按 **Esc** —— 弹窗关闭，表盘停在 00:00，「最近记录」里两条都在；
6. 反例：开始后 10 秒点「结束」—— **不应**弹窗，只出现「已结束并记下…」的页面内提示。
