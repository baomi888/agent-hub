## [0.5.7] - 2026-11-01

整页层级重排：三块功能区各自成立，两个入口不再是「一张表的两行」，控件尺寸按双端分开定。
顺带清掉 0.5.1–0.5.5 留下的代码债。

### 变更

- **两个入口拆成两张独立卡**：不再是同一张卡里靠 1px 分隔线分出的上下两行。
  挤在一起时那两行看起来像同一张表的两个表头，既分不清是哪两个去处，又显得贴得太死。
  现在各自有底色、边框、圆角，中间 10px。展开区仍固定在两张卡之后 ——
  点哪个按钮，内容都出现在同一处，两个按钮的坐标一个字不动（实测连点两次都是 661.4 / 727.4）。
- **入口加图形标记**：左起一个表盘（最近记录）、一个饼图（专注统计）。
  两行一样的字挨在一起时只能靠读，形状不同就能扫出来。画法与导航图标一致（24 网格、描边 currentColor）。
- **入口卡比内容卡轻一档**：填色底、无阴影；展开出来的内容才是纸白卡 + 阴影。
  浅色下是「轻入口 → 实内容」，深色下 `fill-3` 只有 5% 亮度差、会沉进卡片底，
  所以深色单独提一档到 `fill-2`（9%）。展开态深色不换底，靠金边 + 左条 + 阴影表示打开。
- **卡片间距 12 → 16（仅本面板）**：用 `#campus-panel-pomodoro { --pomo-gap }` 收口，
  `.campus-pomo-entries` 也吃这个值 —— 它原来不是 `.campus-card`，吃不到 `+` 相邻规则，
  于是比卡片之间还挤。其他五个工具仍是 12px，没有一起动。
- **每张卡的头一行加底线**：标题和内容原来只靠字号分层，三块摆一起时像三段连续文字。
- **时长框两端各归各的**：
  桌面 64×30 → 72×39（和旁边按钮同高，`开始` 也从 44×32 撑到 120×40，不再孤悬在全行最右）；
  手机从 `flex: 1 1 0` 撑满两半（实测 136px 宽）→ 固定 64×44，靠左排，数字和自己的单位贴在一起读。
- **触控尺寸双端分开定**：快捷芯片 30 → 手机 40；分段控件（倒计时/正计时）30 → 手机 40；
  入口卡 54 → 手机 56。
- **手机同步条 112 → 58px**：原来文字占满一行、按钮被挤到第二行，一条「数据在哪」的说明
  吃掉首屏八分之一。「去登录」还因此被拆成「去登 / 录」两行。
  现在并排、文字按行内流连续折行（「仅本机」不再独占一行），链接 `nowrap`。
- **深色下压在 fill-3 底上的小字提一档**：`--text-3` 是按纸白卡底调的，
  压在更亮的 fill-3 上只有 4.22:1。涉及空状态说明与统计数字旁的标签，改 `--text-2`。

### 修复（代码）

- **收起展开区后焦点掉到 body**：`EntryFold` 卸载时「收起」按钮一起消失，焦点无处可去。
  现在按 `aria-controls` 反查入口按钮并归还（只在焦点已掉到 body 时）。
- **关闭完成弹窗后焦点掉到 body**：同理。原按钮已卸载时退到计时区第一个按钮（也就是「开始」）。
- **退出专注视图后焦点掉到 body**：钟是聚焦目标，视图收掉它就没。改还回「全屏」按钮。
  三处都是同一个毛病：条件渲染的整块消失后，焦点没人接。
- **删 `fullscreen.ts` 的 `watchFullscreen`**：0.5.1 之前 FocusStage 用的回调版订阅，
  已被 `subscribeFullscreen` + `useSyncExternalStore` 取代，全仓无调用方。同一事件留两条订阅路径迟早不一致。
- **两处无效的 `event.stopPropagation()`**：`EntryFold` 与 `FinishDialog` 的 Esc 监听都挂在 window 上，
  同目标的多个监听不会因为冒泡被拦掉，要拦得用 `stopImmediatePropagation` —— 而那会把对方的 Esc 一起废掉。
- **删 `EntryFold` 里无样式的 `.campus-pomo-fold-body`** 包层；注释里「浮层」的旧说法一并改掉。

### 验收工具

- `previews/dual.html` 支持 `?theme=dark`：把主题参数带进两边 iframe，深浅两套对比度一起看。
  「刷新」改用 `location.reload`（重设相同 src 在部分浏览器不重载）。

### 效果

- 页面高度：收起 桌面 1023 → 1105、手机 1246 → 1292；展开（统计）桌面 1418 → 1499、手机 1771 → 1856。
  高出来的部分是间距与卡片头底线，手机那条同步条自己省回了 54px。
- 深浅 × 双端 × 展开态的对比度检查：可读性提示 0 条（改前深色 5 处 4.22:1）。

### 文档

- 新增 **整批整合审核** `reviews/2026-11-01_番茄钟整批整合审核.md`：
  把 0.2.0 → 0.5.7 的 16 个版本、16 条需求合成一份，签章针对整批是否放行。
  分项的 16 份报告原样保留 —— 整合版是「一次看完」，不是替代。
- `reviews/README.md` 补一条仓库状态提醒：0.3.0 起的改动目前只在工作区，没有本地 commit。

### 发布（2026-11-02）

- **审核通过**，0.2.0 → 0.5.7 共 16 个版本一次性推送到 `school-tools`。
- **构建欠账还清**：停 dev → `rm -rf .next` → `npm run build` 通过，
  Next.js 16.3.5 编译 4.8s、15 个页面全部预渲染。0.3.1 起的欠账到此为止。
- 推送切成 4 组 commit（0.2.0 遗留 5 个 + 云同步 + 逻辑层 + 界面），文档单独一个。
- **通道说明**：本机出口代理拒绝 `github.com:443`（CONNECT 502），改走 Git Data API 完成等价推送；
  API 建 commit 会去掉 message 末尾空行导致 sha 变化，已按远端元数据重建本地对象对齐，
  现在本地 `HEAD` 与远端分支头一致。细节见整合审核文档第 8 节。

## [0.5.6] - 2026-11-01

两个入口从并排改成**上下排列**，展开时不动任何已有元素。
（跨零点提交，接在 0.5.5 之后，属于同一轮反馈。）

### 变更

- **入口改为上下分组**：两块并排改成一块卡片里的两行（中间一条分隔线），
  行内左边说是什么、右边给当下的数字、末尾箭头。
  并排在 880px 栏宽下本来就有问题：「专注统计 + 今日 1 小时 30 分」这种长值会挤到换行；
  上下之后每行都有整栏宽度，值再长也不会压字。
- **展开不再影响任何元素的位置**：展开区固定在整个入口组的**下方**，
  不跟着被点的那一行走。点第一行或第二行，内容都出现在同一处，
  两个按钮的坐标一个字都不动（实测展开前后滚动增量 0、按钮 y 完全一致）。
  若让内容跟行，就会出现「点上面那个，下面那个被顶下去」的跳动。
- **展开态标记**：行底色压深一档 + 左侧 3px 强调条 + 箭头转 90° 朝下。
- **滚动锚点从整块改为标题行**：上一版对整块用 `scrollIntoView({ block: "nearest" })`，
  统计面板 600px+ 比视口还高，nearest 会把页面滚很远、把刚点的按钮顶出屏幕。
  现在只把 34px 的标题行带进视口，实测滚动增量为 0。

### 结构

`PomodoroTool.tsx` 的 `.campus-pomo-entry-row`（两列 grid）→ `.campus-pomo-entry-group`（单列块）。
按钮自身的边框 / 圆角 / 阴影移到分组上，首尾行各拿自己的圆角，中间那条用 `inset 0 1px 0` 当分隔线
（不会把组撑高 1px）。

## [0.5.5] - 2026-10-31

「最近记录」「专注统计」从弹窗改成**页面内展开**，并加淡入；顺手修掉一个一直静默失效的滚动锁。

### 变更

- **改为页内展开**：点入口按钮，内容在按钮正下方长出来，前面是标题行 + 「收起」。
  不弹窗、不遮罩、不锁滚动，计时盘和任务列表原地留着。
  再点一次按钮 / 点「收起」/ 按 Esc 三种方式都能收回。两个展开区互斥，开一个自动关另一个。
- **淡入**：`campus-fold-in`，0.2s，只动 `opacity` + `translateY(-6px)`，不碰 `height`。
  入口箭头同时转 90°「朝下」，形状本身说明内容在下面。
  `prefers-reduced-motion` 下动画与箭头过渡一并关掉。
- **`EntryFold.tsx`（新增）** 替代 `PanelSheet.tsx`（删除）：不再有 `role="dialog"`、
  `aria-modal`、焦点转移和滚动锁 —— 它是页面的一部分，不是浮层。
  语义用 `role`（section）+ `aria-labelledby`，按钮侧 `aria-expanded` / `aria-controls` 指向区域 id。
- **展开后自动滚到可见**：`scrollIntoView({ block: "nearest" })`，只在需要时动，
  已可见时一个字都不滚，不会把正在看的计时盘顶走。

### 修复

- **「本轮完成」弹窗的滚动锁一直是失效的**：它改的是 `document.body.style.overflow`，
  但 0.5.3 之后滚动发生在 `.campus-scroll` 上、`html/body` 本来就被设成 `overflow:hidden`，
  改 body 完全拦不住。现在改用 `lockPageScroll()`，CSS 侧类名同步为 `body.campus-modal-open`。
  0.5.4 的说明里写了「完成弹窗与浮层共用一套」，实际只有浮层接了 —— 这次才是真的接上。

### 数据

页面高度与展开态一致（内容没少，只是换了位置）：桌面收起 975 / 展开 1161–1370；
手机收起 1256 / 展开 1469–1781。收起后高度与 0.5.4 完全相同。

## [0.5.0] - 2026-10-31

换设备不用再导 JSON 了：登录同一个账号，数据自己跟过来。

### 新增（后端 · 板块外文件，需单独评审）

- **两张表**（`service/focus.py`）：`focus_sessions`（追加型）与 `focus_tasks`（可改，带 `updated_at`），
  懒建、幂等、不在导入期写库，全部强制 `WHERE owner_id = ?`。
- **5 个端点**（`api/focus.py`，前缀 `/api/campus/focus`）：
  `POST/GET sessions`、`GET/POST tasks`、`PATCH tasks/{id}`。
  全部挂 `Depends(get_current_user)`；`core/api_labels.py` 同步登记中文名（看板断言要求）。

### 新增（前端）

- **同步编排**（`logic/focusSync.ts`）：先推后拉。先推是为了让拉回来的那份带上服务端写的
  `syncedAt`，本地「待同步」标记因此自动清掉，不必另写一套标记逻辑。
- **游客并入账户**（`tools/pomodoro/SyncBar.tsx`）：未登录时显示「仅本机」，功能完整；
  登录后下一次同步会把本机所有没有 `syncedAt` 的记录整批上报 —— 这就是游客数据合并，
  不需要单独的迁移接口。
- **触发时机**：首屏、联网恢复、页面重新可见、手动「立即同步」、每轮结束之后。

### 技术说明

- **会话用 `INSERT OR IGNORE`**：一条记录生成后不再修改，按 id 幂等即天然无冲突，
  断网重试、两台设备各推一次都不会重复计数。
- **任务用「后写胜」**：`ON CONFLICT ... WHERE excluded.updated_at > focus_tasks.updated_at`，
  并且条件里带 `owner_id` —— 别人用同 id 写入也改不掉你的行。
- **`FocusTask` 新增 `updatedAt`**：改名 / 归档 / 改大类 / 记一次使用都会顶它。
  老数据没有这个字段，`taskUpdatedAt()` 退回 `lastUsedAt`，避免老任务第一次同步时
  被当成「1970 年更新的」而输给云端。
- **服务端也做一遍清洗**：客户端校验可以被绕过，脏数据一旦进库，前端每次读取都得兜它一辈子。

### 验证

- 服务层 + 路由登记自检 **40 项**（幂等、脏行、owner 隔离、区间、后写胜、PATCH 白名单、
  归一化、表结构、中文名齐全）。
- 前端同步流程自检 **62 项**（假 fetch 跑通游客 / 离线 / 成功 / 失败 / 分片 / 合并 / 状态条五态）。
