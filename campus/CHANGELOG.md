## [0.6.3] - 2026-11-06

课表 B3.1：**把日期写全**。内测反馈原话是「日期好像不明确，缺少月份」，
补一句「我只需要把日期变详细」—— 这一版只解决这一件事，没有别的改动。

### 修改

- **列头每列写「月/日」**：原来是裸日号（`24`、`25`），一周跨月时是「29 30 1 2」，
  1 号是十月还是十一月只能靠猜。现在写「周一 9/28」「周四 10/1」。
  日期字号 12 → 11px、列头间距 4 → 2px，让跨月那列还塞得下「休 / 班」徽标。
- **表格上方常显本周日期区间**：`9月28日 – 10月4日`。
  这一行原来只在有假期时出现，且只写「5–7 号」；现在平常周也显示，两端都带月份。
- **放假提示带月份**：`国庆节 · 10月1–4日放假`（原「1–4 号放假」）。
- **全屏标题给完整区间**：`第 7 周 · 10月5日 – 10月11日`（原「10月5日 起」）。
- **学期 chip 改中文写法**：`第 1 周 8月24日起 · 共 20 周`（原 `8/24`）。

### 修复

- **跨月假期被算成不连续**：`dayRangeText` 原来收「日号数组」，
  跨月的假期（如 9/30–10/2）会排成「30、1、2 号」—— 既读不出月份，
  连号判断也会在 30 → 1 处断掉，本该是「放假三天」被写成三个零散日子。
  现在参数改成 `Date[]`，连续判断走「前一天 + 1 天」，跨月跨年都成立。

## [0.6.2] - 2026-11-06

课表优化的第三批（B3）：**跟日历对上**（需求 4.4 / 4.5 / 4.6 / 4.7 + A05 / A06）。
唯一依赖外部数据的一批：节假日来自国务院办公厅通知，写进常量表随版本发布。

### 新增

- **节假日常量表** `logic/holidays.ts`：内置 2026、2027 两年安排，含放假日（元旦 3 天、
  春节 9 天、清明 3 天、劳动节 5 天、端午、中秋、国庆 7 天）与调休上班日。
  模块加载时展开成逐日索引，查询 O(1)。数据来源与发布文号写在文件头，
  2028 年及以后没有数据时会降级为「只标数据范围，不做判断」。
- **「休 / 班」列头徽标**（4.6）：放假那天列头出现「休」，调休上班日出现「班」，
  10px 单字 + 灰/橙两色，`title` 里写明节日名和「放假，不用上课 / 调休上班，要上课」。
  只有字、没有长文案，是因为列头宽度撑不住 —— B4 把每列压到 45px 后也放得下。
- **放假那天的课块变暗**（4.5）：底色和边框由课程色换成灰，课名加删除线。
  调休上班日不变暗（那天真要上课）。
- **今天要上的课块加深描边**（4.4）：在原有「今天整列淡底」之上，给今天那列的课块
  加 2px 主题色描边。翻到别周时两者一起消失。
- **节日名提示**（4.7）：页面内在课表右上角显示「本周 国庆节 · 5–7 号放假，课不用上」，
  全屏时挪到顶栏标题旁，右上角留给「退出全屏」。

### 修改

- **变暗不再用 `opacity`**：先按「整块不透明度 45%」做过，实测课名只剩 **2.51:1**（浅色），
  比 4.5 差了一半 —— 想确认「那天本来是哪门课」就读不出来。改成语义更准的「彩色变灰」：
  底色边框转灰、课名降到 `--text-2` 并加删除线，实测 **8:1**。变暗是为了表达状态，
  不是为了让人看不见。
- **日期列头的 `opacity: .75` 去掉**：叠加父级 `--text-2` 后实测只有 **4.17:1**，
  而「今天几号」是认日期的主要依据，不该是全表最淡的字。去掉后 **8:1**。
- **提示文案写清哪几天**：国庆跨两周，第 6 周只有周四到周日放假，只说「本周国庆节放假」
  会让人以为整周都不用去。现在算出一周内放假的日期：连号收成区间（`1–4 号`），
  断号照实列（`1、3、5 号`）。
- **没设学期时的说明**：四条日历联动全部静默跳过（D2 降级），但页面要说清原因，
  并给一个「设一下」的入口 —— 否则用户会以为这个功能没做。

### 验证

- `npx tsc --noEmit` exit 0；`npx eslint src/campus --max-warnings=0` 零问题；
  `npm run build` 通过（15/15 页静态预渲染）。
- **第 7 周（10/5–10/11，国庆后 3 天 + 10/10 调休）**：周一/二/三标「休」，周六标「班」，
  周四 10/8、周五 10/9、周日 10/11 无标；高等数学、数据结构、大学英语变灰划线，
  马克思、体育、选修·摄影保持彩色；提示「国庆节 · 5–7 号放假，课不用上」。
- **第 6 周（9/28–10/4，跨节）**：周四–周日标「休」，提示「1–4 号放假」，
  周一到周三的课保持彩色 —— 证明「一周里有几天放假」是逐日算的，不是整周一刀切。
- **第 11 周（今天所在周，11/2–11/8）**：无徽标、无提示行，`today` 列 = 4（周五），
  只有体育块带 2px 描边；翻到第 7 周后 `today` 列变 −1，描边全部消失。
- **全屏**：标题旁「国庆节 · 5–7 号放假」；**没设学期**：无日期、无徽标，
  提示「还没设学期，所以不标今天和节假日 —— 设一下」。
- **对比度（浅 / 深，桌面与手机一致）**：休徽标 **5.87 / 4.78**、班徽标 **5.7 / 6.93**、
  假期提示 **5.7 / 6.93**、变灰课名 **8 / 7.83**、日期列头 **8 / 7.83**、正常课名 **12.43 / 12.03**
  —— 全部 ≥ 4.5:1。

## [0.6.0] - 2026-11-06

课表优化的第一批（B1）：**只动结构与交互，不动数据**。
进来先看到的是「我的课表」而不是一堆输入框；加课要点了才展开；改一门课不用删了重加。

### 新增

- **课程详情弹窗**：点课块不再是「直接删除」，而是打开详情（课名/星期/节次/起止时间/教室/老师/周次），
  里面可**编辑**或删除。原来改一个教室要「删掉重加」，是从旧版一直带过来的缺口。
- **空状态引导**：首访不再塞三门示例课（高数/英语/数据结构），改为「还没有课表」+ 两个入口
  （导入课表 / 手动添加）+ 一句「JSON 从哪来」。塞示例课的代价是新人以为那是自己的课表。
- **「添加课程」页内展开面板**：从第二张常驻卡片收成头部按钮，点了在卡片内展开，0.2s 淡入，
  再点「收起」/「取消」回去。沿用番茄钟 0.5.5–0.5.6 那套页内展开，不用弹窗。
- **学期 chip**：原来独占一行的「第 1 周从 … 开始，共 20 周」收成周次条右端一枚虚线小按钮，
  点开仍是学期弹窗 —— 省一行，且入口更靠近周次本身。

### 修改

- **课程表单按 CSS Grid 重排**（需求 3.1）：6 个字段带标签，桌面 6 列两行（课名 3 格 / 星期 1 格 /
  节次 2 格，教室 2 格 / 老师 2 格 / 周次 2 格），手机 2 列四行。原来是 `flex: 1.4 1 140px` 硬凑，
  宽度随视口乱变，就是「不整齐」的来源。实测两行右边缘都落在 1112px，左边缘 328px。
- **「本学期设置」弹窗排布**（需求 5.1）：420px 宽，开学日期与总周数并排，「或者」分隔线下面
  才是「今天是第几周」，配一句「填了开学日期就自动算」。原来 440px 的框里竖着躺三个窄输入，
  上下都是空白。
- **「清空课表」降级**：从主按钮收成页脚文字按钮，与「共 N 门课，存在这台设备上」同一行。
- **导入成功即收工**：导入弹窗在成功后自动关闭，结果写到页面提示行；首次导入紧接着弹学期设置
  （不设学期，「今天」「节假日」都算不出来）。学期弹窗本来就有「稍后再说」，可直接跳过。

### 验证

- `npx tsc --noEmit` exit 0；`npx eslint src/campus --max-warnings=0` 零问题；
  `npm run build` 通过（15/15 页静态预渲染）。
- 双端实测（桌面 1440×900 / 手机 390×844 触屏模拟）：点课块 5 块 → 5 块且详情打开（不再误删）；
  改名「高等数学（下）」后页面与 localStorage 同步；桌面面板高 **986px**（上一版 1105px），
  课表页**只剩 1 张卡片**（原来 2 张）。

## [0.5.9] - 2026-11-05

手机上没有 Esc、没有空格、没有方向键，界面上却写着「按 Esc 收起」「按空格翻转」。
这一版把这类提示**按设备分两版**：电脑看到按键，手机只看到「点哪里」。

### 修复

- **专注视图的提示带「按 Esc」**：整屏态写「电脑上按 Esc 也行」，页内态写「按 Esc 收起」。
  触屏用户看到的是一个永远按不到的键。现在两处各写两版：电脑保留键盘说法，
  手机整屏态改成「点「退出全屏」回到页面，计时不会中断」、页内态改成
  「点「收起」回到计时卡；切去别处，计时也不会停」。
- **单词卡的「（或按空格）」**：卡片上的提示原为「点击卡片（或按空格）翻转看释义」，
  手机上括号里那句是废话。现在只在电脑上出现，手机上读作「点击卡片翻转看释义」。
- **单词卡底部的 `kbd` 快捷键行**（空格 / → / ←）：整行只在电脑上渲染，手机上不占位也不留空白。
- **「横过来更沉浸」在电脑上不出现**：这句只对能转的手机有意义，但它是按「竖屏 + 整屏」显示的，
  把电脑窗口竖着拉窄也会冒出来。现在加了 `(hover: hover) and (pointer: fine)` 的反向收口，
  电脑上看不到，手机上照旧。

### 变更

- **新增设备能力工具类** `.campus-desktop-only` / `.campus-touch-only`（`campus.css` 顶部「设备能力」一节）：
  默认给触屏看，只有 `@media (hover: hover) and (pointer: fine)`（电脑 + 精确指针）才切成桌面版。
  用 CSS 而不是 JS 判设备 —— 首屏是服务端渲染，那一刻拿不到设备信息，JS 判断会让手机
  先闪一版桌面文案再换掉；媒体查询首帧就成立，也不存在 hydration 前后两套 DOM。
- **`display: revert` 而不是 `inline` / `block`**：包在 `span` 上回到 `inline`、包在 `p` 上回到 `block`，
  让元素自己问 UA 要默认值，以后换标签不用再补规则。
- **键盘监听全部保留**：iPad / Android 平板接物理键盘时 Esc、空格是真能用的，
  这层不占界面、不影响触屏。这一次改的是「看不看得见」，不是「能不能用」。

### 验收

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| 桌面 1440×900 | 显示键盘版提示 | `hover:hover / pointer:fine` 为真；整屏态提示为键盘版；单词卡有「（或按空格）」与 `kbd` 行 |
| 桌面竖窗口 820×1100（能看到这行提示的形态） | 有 Esc、无「横过来」 | 整屏「点「退出全屏」回到页面；按 Esc 也行…」，页内「随时可以切到别的标签；按 Esc 收起。」；`.campus-stage-rotate` 为 `none` |
| 手机 390×844（触屏模拟） | 不出现任何键盘字样 | `pointer:coarse` 为真；整屏提示只剩触屏版，`document.body.innerText` 无 `Esc` |
| 手机 · 退出全屏后（页内） | 触屏版收起提示 | 「点「收起」回到计时卡；切去别处，计时也不会停。」 |
| 手机 · 竖屏整屏 | 「横过来更沉浸」保留 | `.campus-stage-rotate` 计算值 `block` |
| 手机 · 单词卡 | 隐藏 `kbd` 行、去掉「按空格」 | `.campus-words-keys` 计算值 `display:none`；卡片提示「点击卡片翻转看释义」 |
| 桌面 · 单词卡 | 一切照旧 | `kbd` 行可见，卡片提示保留「（或按空格）」 |
| 暂停态 | 两版同文案 | 「已暂停，继续时会接着算。」（不含按键） |
| 构建 | 先停 dev、清 `.next` 再 `npm run build` | 通过：编译 4.9s、15/15 静态页预渲染（0.5.8 的构建欠账一并还清） |

### 欠账

- **主站对话输入框的「Enter 发送 · ↑ 上一条 · Esc 清空」**（`ChatArea.tsx`）未动：
  那是桌面工作台的一部分，不在手机场景里；校园工具集才是手机上要用的入口。
  如果以后工作台也要上手机，这条得一起处理。
- 真机未测（本轮只在桌面 + 触屏模拟里验）：iPhone Safari、Android Chrome 的实际
  `hover / pointer` 取值。按规范这两项在手机上恒为 `none / coarse`，风险低。

## [0.5.8] - 2026-11-05

「全屏」这颗按钮以前要点两次，手机上还根本按不出全屏。这一版把它做成**一次点击、双端都有**：
桌面直接进浏览器全屏，iPhone 进不去的用页内全屏顶上，手机竖着点时自动横过来。

### 修复

- **桌面点两次才进全屏**：计时卡上的「全屏」只做 `setStageOpen(true)`，真正的
  `requestFullscreen` 在视图里的另一颗同名按钮上。根因是**请求目标要等视图挂载才有**，
  而全屏必须在点击的同一段任务里同步发出（晚一帧手势就过期）。
  改法：加一个**始终存在的宿主节点** `.campus-stage-host`，视图渲染在它里面；
  点击时对宿主直接请求全屏，一步到位。实测第一次点击后 `document.fullscreenElement`
  就是 `campus-stage-host`，视图铺满 1440×900。
- **iPhone 上没有任何办法全屏**：`canFullscreen = Boolean(document.fullscreenEnabled)`，
  而 iPhone Safari 的元素全屏至今为假 —— 那颗按钮被整颗隐藏，用户看到的是「手机没有全屏」。
  改法：按钮**一直渲染**，真全屏请求失败就退到**页内全屏**（`position: fixed` + `100dvh` + 安全区），
  视觉结果与真全屏一致，只是少了浏览器那层系统 UI。
- **手机竖着点全屏不会横过来**：`tryLockLandscape` 只在「真全屏成功 + 粗指针 + 当前竖屏」
  三个条件同时成立时调用（Android Chrome 要求文档已全屏才给锁）；退出时补 `unlockOrientation()`，
  不再把用户的屏幕一直锁在横屏。
- **全屏时到点提醒会消失**：浏览器全屏只渲染全屏元素及其后代，而完成弹窗挂在宿主**外面** ——
  整屏专注跑完一轮，到点是静默的。现在弹窗挂进宿主内部（z-index 70 > 整屏层 60），
  并且在结算 / 重置时连同全屏一起退出，避免「视图收了、全屏还挂在一个空盒子上」。
- **预览页 iframe 不允许全屏**：`previews/dual.html` 的 iframe 少了 `allow="fullscreen"`，
  在里面点全屏会被权限策略拒掉，`fullscreenEnabled` 也是 false —— 双端预览因此永远测不出全屏。

### 变更

- **手机竖屏整屏的顶栏改两行**：任务名一行，时刻与「退出全屏 / 收起」一行。
  一行塞满的后果是任务名被压成「高等数学·…」—— 整屏时最该看清的信息反倒唯一被省略。
- **大钟按 `min(vw, vh)` 放大**：原来 `clamp(56px, 18vmin, 190px)`，竖屏受宽度限制只有 70px、
  横屏受高度限制同样偏小。现在竖屏 109px、横屏手机 132px、桌面 180px。
- **整屏时按钮与进度条各放大一档**：按钮 52px 高（原本 32px，在 180px 的字旁边像缩了），
  进度条 6×520 → 8×640。
- **竖屏整屏的「横过来更沉浸」单独一行**：它原来靠 `margin-left: auto` 挤在按钮右边，
  把「暂停 / 结束」整组顶离屏幕中线，单手拇指落在底部正中反而点不到主操作。

### 验收

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| 桌面首次点「全屏」 | 一次点击即整屏 | `fullscreenElement = campus-stage-host`，视图 1440×900，钟 180px |
| 再点「退出全屏」 | 退回页内视图，不收起 | `fullscreenElement = null`，`.campus-stage` 仍在，848×504 |
| iPhone（模拟无全屏 API） | 页内全屏铺满 | `is-full is-immersive`，390×844，`body.campus-modal-open` 已加 |
| 手机竖屏 → 横屏视口 | 左右两栏 | `sideBySide = true`，主区 664 / 操作区贴右，钟 132.6px |
| 整屏中到点 | 弹窗可见、退出整屏 | 60s 时弹窗 1440×900 可见；`fs = null`、视图已收 |
| 回归：完成弹窗焦点 | 关闭后回「开始」 | 通过；滚动锁正常释放 |

### 欠账

- `tests/test_focus_sync.py` 13 个接口级用例仍未跑（本机无 fastapi/pytest），与本次改动无关。
- 真机未测：Android Chrome 的 `orientation.lock` 实际旋转、iOS 上页内全屏的安全区表现。
  这两条只能在真机验，桌面模拟器里 `screen.orientation.lock` 一定失败。

## [0.5.7] - 2026-11-01

整页层级重排：三块功能区各自成立，两个入口不再是「一张表的两行」，控件尺寸按双端分开定。
顺带清掉 0.5.1–0.5.5 留下的代码债。

### 变更

- **两个入口拆成两张独立卡**：不再是同一张卡里靠 1px 分隔线分出的上下两行。
  挤在一起时那两行看起来像同一张表的两个表头，既分不清是哪两个去处，又显得贴得太死。
  现在各自有底色、边框、圆角，中间 10px。展开区仍固定在两张卡之后 ——
  点哪个按钮，内容都出现在同一处，两个按钮的坐标一个字不动（实测连点两次都是 661.4 / 727.4）。
- **入口加图形标记**：左起一个表盘（最近记录）、一个饼图（专注统计）。
  两行一样的字挨在一起时只能靠读，形状不同就能扫出来。画法与导航图标一致（24 网格、描边 currentColor）。
- **入口卡比内容卡轻一档**：填色底、无阴影；展开出来的内容才是纸白卡 + 阴影。
  浅色下是「轻入口 → 实内容」，深色下 `fill-3` 只有 5% 亮度差、会沉进卡片底，
  所以深色单独提一档到 `fill-2`（9%）。展开态深色不换底，靠金边 + 左条 + 阴影表示打开。
- **卡片间距 12 → 16（仅本面板）**：用 `#campus-panel-pomodoro { --pomo-gap }` 收口，
  `.campus-pomo-entries` 也吃这个值 —— 它原来不是 `.campus-card`，吃不到 `+` 相邻规则，
  于是比卡片之间还挤。其他五个工具仍是 12px，没有一起动。
- **每张卡的头一行加底线**：标题和内容原来只靠字号分层，三块摆一起时像三段连续文字。
- **时长框两端各归各的**：
  桌面 64×30 → 72×39（和旁边按钮同高，`开始` 也从 44×32 撑到 120×40，不再孤悬在全行最右）；
  手机从 `flex: 1 1 0` 撑满两半（实测 136px 宽）→ 固定 64×44，靠左排，数字和自己的单位贴在一起读。
- **触控尺寸双端分开定**：快捷芯片 30 → 手机 40；分段控件（倒计时/正计时）30 → 手机 40；
  入口卡 54 → 手机 56。
- **手机同步条 112 → 58px**：原来文字占满一行、按钮被挤到第二行，一条「数据在哪」的说明
  吃掉首屏八分之一。「去登录」还因此被拆成「去登 / 录」两行。
  现在并排、文字按行内流连续折行（「仅本机」不再独占一行），链接 `nowrap`。
- **深色下压在 fill-3 底上的小字提一档**：`--text-3` 是按纸白卡底调的，
  压在更亮的 fill-3 上只有 4.22:1。涉及空状态说明与统计数字旁的标签，改 `--text-2`。

### 修复（代码）

- **收起展开区后焦点掉到 body**：`EntryFold` 卸载时「收起」按钮一起消失，焦点无处可去。
  现在按 `aria-controls` 反查入口按钮并归还（只在焦点已掉到 body 时）。
- **关闭完成弹窗后焦点掉到 body**：同理。原按钮已卸载时退到计时区第一个按钮（也就是「开始」）。
- **退出专注视图后焦点掉到 body**：钟是聚焦目标，视图收掉它就没。改还回「全屏」按钮。
  三处都是同一个毛病：条件渲染的整块消失后，焦点没人接。
- **删 `fullscreen.ts` 的 `watchFullscreen`**：0.5.1 之前 FocusStage 用的回调版订阅，
  已被 `subscribeFullscreen` + `useSyncExternalStore` 取代，全仓无调用方。同一事件留两条订阅路径迟早不一致。
- **两处无效的 `event.stopPropagation()`**：`EntryFold` 与 `FinishDialog` 的 Esc 监听都挂在 window 上，
  同目标的多个监听不会因为冒泡被拦掉，要拦得用 `stopImmediatePropagation` —— 而那会把对方的 Esc 一起废掉。
- **删 `EntryFold` 里无样式的 `.campus-pomo-fold-body`** 包层；注释里「浮层」的旧说法一并改掉。

### 验收工具

- `previews/dual.html` 支持 `?theme=dark`：把主题参数带进两边 iframe，深浅两套对比度一起看。
  「刷新」改用 `location.reload`（重设相同 src 在部分浏览器不重载）。

### 效果

- 页面高度：收起 桌面 1023 → 1105、手机 1246 → 1292；展开（统计）桌面 1418 → 1499、手机 1771 → 1856。
  高出来的部分是间距与卡片头底线，手机那条同步条自己省回了 54px。
- 深浅 × 双端 × 展开态的对比度检查：可读性提示 0 条（改前深色 5 处 4.22:1）。

### 文档

- 新增 **整批整合审核** `reviews/2026-11-01_番茄钟整批整合审核.md`：
  把 0.2.0 → 0.5.7 的 16 个版本、16 条需求合成一份，签章针对整批是否放行。
  分项的 16 份报告原样保留 —— 整合版是「一次看完」，不是替代。
- `reviews/README.md` 补一条仓库状态提醒：0.3.0 起的改动目前只在工作区，没有本地 commit。

### 发布（2026-11-02）

- **构建欠账还清**：停 dev → `rm -rf .next` → `npm run build` 通过，

## [0.5.6] - 2026-11-01

两个入口从并排改成**上下排列**，展开时不动任何已有元素。
（跨零点提交，接在 0.5.5 之后，属于同一轮反馈。）

### 变更

- **入口改为上下分组**：两块并排改成一块卡片里的两行（中间一条分隔线），
  行内左边说是什么、右边给当下的数字、末尾箭头。
  并排在 880px 栏宽下本来就有问题：「专注统计 + 今日 1 小时 30 分」这种长值会挤到换行；
  上下之后每行都有整栏宽度，值再长也不会压字。
- **展开不再影响任何元素的位置**：展开区固定在整个入口组的**下方**，
  不跟着被点的那一行走。点第一行或第二行，内容都出现在同一处，
  两个按钮的坐标一个字都不动（实测展开前后滚动增量 0、按钮 y 完全一致）。
  若让内容跟行，就会出现「点上面那个，下面那个被顶下去」的跳动。
- **展开态标记**：行底色压深一档 + 左侧 3px 强调条 + 箭头转 90° 朝下。
- **滚动锚点从整块改为标题行**：上一版对整块用 `scrollIntoView({ block: "nearest" })`，
  统计面板 600px+ 比视口还高，nearest 会把页面滚很远、把刚点的按钮顶出屏幕。
  现在只把 34px 的标题行带进视口，实测滚动增量为 0。

### 结构

`PomodoroTool.tsx` 的 `.campus-pomo-entry-row`（两列 grid）→ `.campus-pomo-entry-group`（单列块）。
按钮自身的边框 / 圆角 / 阴影移到分组上，首尾行各拿自己的圆角，中间那条用 `inset 0 1px 0` 当分隔线
（不会把组撑高 1px）。

- **同步编排**（`logic/focusSync.ts`）：先推后拉。先推是为了让拉回来的那份带上服务端写的
  `syncedAt`，本地「待同步」标记因此自动清掉，不必另写一套标记逻辑。
