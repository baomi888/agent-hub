## 1. 这个板块是什么

给大学生用的**免登录、纯前端、离线可用**小工具集合。它不属于「登录后的工作台」，而是
"发消息之前顺手用一下"的入口，所以**不依赖后端、不依赖账号体系**——这一点是刻意设计，
不要为了统一架构把它改成必须登录。

当前包含 6 个工具：

| # | 工具 | 核心能力 | 数据是否落盘 |
| --- | --- | --- | --- |
| 1 | GPA 分析 | 录入课程成绩，实时算加权 GPA / 均分 / 学分，支持标准 4.0 与北大 4.0 两套绩点 | localStorage |
| 2 | 番茄钟 | 25 分钟专注计时，开始 / 暂停 / 重置 | 不落盘（会话级） |
| 3 | 课程表 | 周视图课表，支持手动录入与 JSON 导入，含课程冲突检测 | localStorage |
| 4 | 四六级单词卡 | 翻转词卡，认识 / 不认识分流入复习堆 | localStorage |
| 5 | Deadline 倒计时 | 记录截止日期并按剩余时间排序 | localStorage |
| 6 | 群抽签 | 名单随机抽取，支持多人中签 | 不落盘（会话级） |

**已知遗留问题**（来自 `docs/内测反馈_2026-10-27/问题清单与优先级.md`）：

1. `tools.html` 是纯静态页，**整页只有浅色一套变量**，深色模式下打开会一片白。

3. 没有构建产物、没有类型检查、没有测试，回归全靠手点。

以上三条，正是本分区要解决的问题。

## 3. 分区结构（代码到底在哪）

采用「**治理集中、代码集中、路由留壳**」三层：

```
campus/                                  ← 治理区：文档 / 版本 / 审核，只看这里
├── README.md                            本文件
├── VERSION                              板块独立版本号（与根 package.json 无关）
├── CHANGELOG.md                         板块独立变更记录
├── ROADMAP.md                           迭代计划与优先级
├── docs/
│   ├── 01_板块边界与架构.md              能改什么、不能改什么、和主站怎么对接
│   ├── 02_数据与本地存储契约.md          localStorage 的键名、结构、迁移规则
│   ├── 03_审核与验收清单.md              ★ 负责人按这份清单评审
│   └── 04_开发与提交流程.md              分支、提交、发布步骤
└── prototypes/                          原型快照，只读归档

frontend/src/campus/                     ← 代码区：板块全部实现集中在此
├── index.ts                             对外统一导出（外部只从这里 import）
├── types.ts                             板块内共享类型
├── storage/                             本地存储封装（带命名空间与版本迁移）
├── logic/                               纯函数：GPA 计算 / 课表周次 / 抽签
├── components/                          板块级公共组件（导航外壳等）
├── tools/<工具名>/                      各工具独立目录，一个工具一个文件夹
└── styles/campus.css                    板块样式（复用全局令牌，含深色）

frontend/src/app/(campus)/tools/page.tsx ← 路由薄壳：只做挂载，不写业务
```

**为什么路由要单独留一个壳**：Next.js App Router 要求页面必须落在 `src/app/` 下。
薄壳只做「引入 + 渲染」，业务逻辑全部在 `frontend/src/campus/`，这样板块可整体迁移，
而不用满仓库找文件。

## 4. 独立迭代怎么走

> **分支：`school-tools`（长期主线，名字不能带空格——Git 会拒绝）。**
> **推送前必须过审核闸门：开发完成 → 自测 → 写审核报告 → 负责人通过 → 开发者说「上传」→ 才推。**
> 细则见 `docs/05_审核闸门与分支策略.md`。没有负责人通过 + 开发者明确指令，代码不上远端。

### 4.1 版本号规则

`campus/VERSION` 是板块自己的版本，**与主站版本解耦**，语义化版本：

- `0.x.y`：尚未替换线上 `tools.html`，属于重构期
- `1.0.0`：新实现替换 `/tools.html` 并全量上线
- 之后：新增工具 = minor，修 bug = patch，破坏存储结构 = major（必须写迁移）

每次合并进 `dev` 前，同步更新 `VERSION` 与 `CHANGELOG.md`。

### 4.2 迭代节奏

见 `ROADMAP.md`。原则：**先修体验债，再加新工具**。深色主题和模块拆分排在
新工具之前，否则新工具会继续堆进那个 132 KB 的单文件里。

### 4.3 发布

板块不单独发部署包，跟随主站前端一起构建。切换线上入口是一次**独立提交**，
便于回滚（见 `docs/04_开发与提交流程.md` 第 4 节）。

## 5. 边界：这个板块不做什么

明确写下来，避免评审时扯皮：

- ❌ 不引入后端接口。需要跨设备同步时，先提方案评审，不要直接加 `/api/campus/*`。
- ❌ 不接登录态。免登录是产品决定，不是偷懒。
- ❌ 不改主站全局样式令牌（`src/app/styles/tokens.css`）。板块差异写在 `campus.css` 内。
- ❌ 不动 `frontend/public/tools.html` 以外的公共文件（入口常量除外，且需在 PR 说明）。

需要动以上任何一条，先在 PR 描述里单独列出，由负责人裁定。

## 6. 快速开始

```bash
# 1) 装依赖（首次）
cd frontend && npm install

# 2) 起开发服务
npm run dev
#    新实现：http://localhost:3000/tools
#    线上旧版：http://localhost:3000/tools.html

# 3) 类型检查与构建校验
npx tsc --noEmit
npm run build
```

后端不是必需的——本板块纯前端，起不起 FastAPI 都能开发。

## 7. 审核入口

负责人评审时按 `docs/03_审核与验收清单.md` 逐条过。那份清单分三块：
**功能正确性 / 体验与合规 / 工程规范**，每条都可勾选，不留"感觉还行"的模糊项。

每次功能交付另附一份审核报告，放在 `campus/reviews/`（命名 `YYYY-MM-DD_主题.md`），
模板见 `campus/reviews/TEMPLATE.md`。报告结论只有三种：通过 / 有条件通过 / 打回。
