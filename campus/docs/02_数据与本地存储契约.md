# 02 · 数据与本地存储契约

> 本板块**没有后端**，所有用户数据在浏览器 `localStorage`。
> 存储结构一旦发布就是契约：改动必须带版本号与迁移函数，否则老用户数据直接丢。
>
> 本文是迁移实现的唯一依据，写新工具前先读一遍。

---

## 1. 现有键名（线上 `tools.html` 实际使用）

键名用的是**下划线**（`baomi_tools_gpa_v1`），和主站点号风格（`baomi.reportDays`）
不是一套。这是历史遗留，新代码统一用 `campus.*`，但**必须兼容读取旧键**。

| 键名 | 承载工具 | 根结构版本 | 数据形态 |
| --- | --- | --- | --- |
| `baomi_tools_gpa_v1` | GPA 分析 | `v:1` | 对象 `{v, algo, rows}` |
| `baomi_tools_sched_v1` | 课程表 | `v:2` | 对象 `{v, cseq, sample, updated, courses}` |
| `baomi_tools_week_v1` | 课表周次 | `v:1` | 对象 `{v, cur, mode, ...}` |
| `baomi_tools_term_v1` | 学期起始 | `v:1` | 对象 `{v, start, ...}` |
| `baomi_words_v2` | 单词卡 | 无 `v` 字段 | 对象 `WP`（词卡进度） |
| `baomi_deadline_v1` | Deadline 倒计时 | 无 `v` 字段 | 数组 `[{name, date}]` |

## 2. 结构定义

### 2.1 GPA · `baomi_tools_gpa_v1`

```jsonc
{
  "v": 1,
  "algo": "std4",        // "std4" | "pku" | "wavg"
  "rows": [
    { "n": "高等数学", "c": "4", "s": "88" }
  ]
}
```

> ⚠️ **字段名是缩写，且是字符串**：`n` = 课程名、`c` = 学分、`s` = 成绩。
> 三者全部 `string`（旧版直接取 `input.value` 存进去，未转数字），空行存 `""`。
> 迁移到新结构时建议转成 `{ name, credit: number, score: number | null }`，
> 但**读取旧数据必须按字符串解析**，不要假设是 number。

- `algo` 三选一：`std4` 标准 4.0、`pku` 北大 4.0、`wavg` 加权均分。
- `credit` 允许 0.5 步长；`score` 为 0–100 百分制。
- 空行（`s` 为空）不计入统计；`credit` 解析失败按 0 处理。
- 换算表（与旧版必须逐条一致，已核对 `tools.html` 第 826–836 行）：

```js
std4: [[90,4.0],[85,3.7],[82,3.3],[78,3.0],[75,2.7],[72,2.3],[68,2.0],[64,1.5],[60,1.0],[0,0.0]]
pku:  [[90,4.0],[85,3.7],[83,3.3],[80,3.0],[77,2.7],[73,2.3],[70,2.0],[67,1.5],[63,1.0],[60,1.0],[0,0.0]]
```

换算规则：分数**大于等于**阈值取对应绩点（从高到低第一个命中）；`wavg` 不折算，直接用原始分参与加权。

### 2.2 课程表 · `baomi_tools_sched_v1`

```jsonc
{
  "v": 2,
  "cseq": 0,
  "sample": false,
  "updated": 1761811200000,
  "courses": [
    {
      "id": "c_1",
      "name": "线性代数",
      "color": "#7C9A54",
      "day": 0,                      // 0=周一 … 6=周日
      "sections": [1, 2],            // 节次，1 起
      "teacher": "",
      "classroom": "教三-201",
      "weeks": [1, 2, 3, 4, 5, 6, 7, 8],
      "notes": ""
    }
  ]
}
```

> ⚠️ **迁移必读 · `day` 的坑**
> `v:1` 时代 `day` 写成 `dayOfWeek % 7`（周一=1），`v:2` 改为 `(dayOfWeek - 1) % 7`（周一=0）。
> 读 `v:1` 数据时**必须把 `day` 减 1**（负数回绕到 6），否则整张课表错位一天。
> 原作者已在 `loadSched()` 里实现回拨，迁移时不要重复回拨，也不要漏掉。

### 2.3 倒计时 · `baomi_deadline_v1`

```jsonc
[ { "name": "计组实验报告", "date": 1762416000000 } ]
```

- `date` 是**毫秒时间戳**，不是日期字符串。
- 逾期判断按自然日：`Math.ceil((date - today) / 86400000)`，`<0` 为逾期。

### 2.4 单词卡 · `baomi_words_v2`

`WP` 是词卡进度对象，键为词条，值为认识 / 待复习状态。结构在演进中，
**迁移时以现网 `tools.html` 的 `loadWk` / `saveWk` 实现为准**，不要凭本文件猜。

### 2.5 其余两个键

`baomi_tools_week_v1`（当前周次、周模式）与 `baomi_tools_term_v1`（学期起始日）
都是小对象，跟随课表使用。迁移时按字段原样搬运，不改语义。

## 3. 新代码的存储规则

### 3.1 键名规范

```
campus.<tool>.<purpose>.<version>
例：
campus.gpa.rows.v1
campus.schedule.courses.v2
campus.deadline.items.v1
```

- 一律点号分层，小写，工具名用英文短名（`gpa` / `schedule` / `words` / `deadline` / `pomodoro` / `draw`）。
- 版本号写在键名**末尾**，与结构内 `v` 字段保持一致，两处都要写，便于肉眼排查。

### 3.2 读取顺序（兼容旧数据）

```ts
// 概念示意，实际实现见 frontend/src/campus/storage/index.ts
read<T>(newKey, oldKeys, migrate): T | null
// 1) 先读新键 campus.*
// 2) 新键没有 → 依次尝试旧键 baomi_tools_*
// 3) 命中旧键 → 过 migrate 转换 → 写回新键（旧键保留一个版本周期，不主动删）
// 4) 全都没有 → 返回 null，由调用方决定用示例数据还是空态
```

**不要主动删除旧键**。用户可能回滚到旧版 `tools.html`，删了就等于清空他的数据。

### 3.3 写入容错

隐私模式、存储配额满都会让 `setItem` 抛异常。现有代码的做法是 `try/catch` 静默失败，
保留这个行为：**存不下可以记不住，但不能让页面崩**。

新实现统一走 `storage/index.ts` 的封装，不要在工具里直接调 `localStorage`。

### 3.4 禁止存储的内容

- ❌ 学号、身份证号、手机号等身份信息
- ❌ 成绩单原文截图或 OCR 文本（若未来做该功能，需先过隐私评审）
- ❌ 任何密钥、token

本板块数据**只在本机浏览器**，一旦写入上述内容就等于把隐私摊在公共电脑上。

## 4. 版本升级检查单

改存储结构时，PR 必须回答：

- [ ] 旧结构读出来会怎样？有没有默认值兜底？
- [ ] `migrate` 函数是否处理了「字段缺失」「类型不符」「数组为空」三种脏数据？
- [ ] 迁移是否幂等？（重复执行结果一致）
- [ ] 旧键是否保留未删？
- [ ] 是否在 `CHANGELOG.md` 标注了结构变更？
- [ ] 版本号是否按 major 递增（破坏性变更）？

**漏掉任何一条，评审直接打回。** 存储迁移出问题，用户的课程表和成绩是找不回来的。
