## 2. 能力边界

### 2.1 沉浸式「阻止其他 app / 屏蔽推送」——做不到

网页没有任何 API 能拦住用户切到微信、屏蔽系统通知、锁住手机。
真做到需要原生 App（Android 无障碍/设备管理员；iOS Screen Time API，个人开发者通常拿不到授权）。

网页只能做「记录 + 提醒」：全屏 + 屏幕常亮、监听 `visibilitychange` 记中断次数、
标题变「⚠️ 已中断 3 次」、统计里显示专注度。

### 2.2 严格模式「不可取消退出」——半能做

页面内可以不给退出按钮、退出需长按 + 二次确认、放弃留痕；
但**关标签页 / 刷新 / 杀进程无法阻止**，这是浏览器底线。

### 2.3 横屏

全屏可做；自动转横屏仅 Android Chrome 支持，iOS Safari 不支持，只能提示用户自行旋转。

### 2.4 为什么暂缓 R4

1. **预期落差最大**：你要的「阻止其他 app」在网页里无法交付；
2. **依赖最多**：要读中断字段、改全屏层，链路最长；
3. **价值待验证**：先看统计你是否真用得惯，再决定要不要加约束层。

> 会话模型里的 `awayCount` / `pausedCount` 字段照样保留（现在恒为 0），
> 将来重启 R4 不用改表结构。

## 3. 数据模型

### 3.1 核心类型（已落地于 `types.ts`）

```ts
interface FocusTask {
  id: string;
  name: string;
  category: string;    // 大类，饼图按它聚合
  color: string;
  archived: boolean;   // 归档不删除，保住历史归属
  createdAt: number;
  lastUsedAt: number;
}

interface FocusSession {
  id: string;          // 前端生成，服务端按它幂等
  taskId: string;
  taskName: string;    // 冗余：任务改名后历史仍按当时名字统计
  category: string;    // 冗余：改大类不追溯改历史
  startedAt: number;
  endedAt: number;
  seconds: number;         // 有效秒数，已扣暂停
  plannedSeconds: number;  // 正计时为 0
  direction: "countdown" | "countup";
  mode: "normal" | "immersive" | "strict";
  pausedCount: number;
  awayCount: number;
  awaySeconds: number;
  endReason: "finished" | "early" | "abandoned" | "stopped";
  syncedAt?: number;       // 已同步时间；undefined 表示待同步
}
```

聚合结果类型：`PeriodSummary` / `CategoryStat` / `TaskStat` / `DayStat` /
`CategoryDrilldown` / `DrilldownTask`（下钻的 `ratio` 是**类内占比**，与 `TaskStat.ratio`
的「占全区间」语义不同，所以单独定义，不复用）。

### 3.2 统计口径（`logic/focus.ts`）

| 口径 | 定义 |
| --- | --- |
| 会话归属 | 按**开始时刻**归属日期。23:50 开始、00:20 结束算前一天 |
| 区间 | 左闭右开 `[from, to)`，终点取下一周期本地零点（不用 +86400000，避开时区/夏令时） |
| 周起点 | **周一**，与课表 day 口径一致 |
| 零时长会话 | 计入条数，不计时长（避免「今天练了 3 次」变 0 次） |
| 连续天数 | 今天没学则从昨天数起，避免早上打开显示「连续 0 天」 |
| 饼图分片 | 超过 6 类合并「其他」，合并后重新降序排序 |

### 3.3 大类归类（`logic/focusCategory.ts`）

| 层 | 规则 |
| --- | --- |
| 手动 | 用户选了就一律听用户的，不再猜 |
| 自动 | 扫关键词表，第一个命中的大类胜出，都没命中为「未分类」 |

关键词表的内置大类：数学 / 英语 / 政治 / 物理 / 化学 / 生物 / 计算机 / 语文 / 论文 / 实验。
刻意保持短——靠「常见叫法」而非穷举；猜错可手改，猜太激进反而增加纠正成本。

**B2 定下的三条口径**（会影响你看到的数字）：

- **暂停时间不算专注时长**。跑 10 秒 → 暂停 100 秒 → 再跑 5 秒，记 15 秒。长暂停不会把「好像学了 2 小时」算进去。
- **不足 30 秒的中途结束不写记录**（正常完成的番茄不受限）。点开又点掉的误触不该出现在统计里，否则条数和连续天数都不可信。
- **同名任务不重复建**：名字忽略大小写与首尾空白，重新添加已归档的同名任务等于「恢复」，历史统计仍归在这一个任务名下。

**文件拆分**：旧版番茄钟是 184 行单文件，B2 后若继续堆会到 600+。现已拆成「状态机 / 任务库 / 存储 / 表盘 / 任务面板 / 容器」六块，B3 全屏会复用同一个 `TimerFace`，不再叠加第二套计时逻辑。

**为什么不给「手动结束」也弹窗**：到点这件事没人看着也会发生，需要把人叫回来；

| 验证 | 提示音自检 **39 项**、渲染冒烟 **15 项**（均为撤回自定义链接后的口径）；`tsc --noEmit` 零错误；eslint 0 error / 0 warning |

**为什么提示音要自己合成**：五个音色不到 1 KB 代码，mp3 至少几百 KB 且要处理缓存与跨域；
合成音不涉及采样版权；音量、时长、泛音都能按参数调 —— 手机外放和耳机需要的亮度不一样。

**决策记录：自定义音频链接已撤回（0.3.3）**
最初做过一版「粘音频直链」的入口，能播 `.mp3` / `.m4a` / `.ogg` / `.wav`，并对歌单页给出原因提示。
但实际诉求是「连自己的歌单」—— 歌单页是脚本渲染的网页，`<audio>` 取不到音频流，这是平台限制。
入口大概率走向失败，反而消耗信任，因此按需求方确认整块移除：`ChimeId` 去掉 `custom`、
`SoundPrefs` 去掉 `customUrl`、`checkAudioUrl` 与 `<audio>` 播放路径一并删除。
存量数据读取时 `custom` 判无效回落默认音色，音量保留。真要做歌单需各平台开放 API + 授权，属新立项。

### ✅ B2.7 · 任务改名 + 时分时长（已完成）

| | |
| --- | --- |
| 来源 | 反馈：「任务可以设置成改名，然后选择倒计时，可以多一个选择，就是 xx 小时 xx 分钟，方便用户快速定时」 |
| 产出 | `logic/focusTask.ts`（+`renameTask`，190）、`TaskPicker.tsx`（+行内编辑，215）、`TimerFace.tsx`（+时分双输入与芯片，250）、`logic/pomodoro.ts`（+`splitDuration`/`joinDuration`/`formatDurationLabel`/`MAX_HOURS`，125）、`campus.css` +85 |
| 改名 | 行内编辑：Enter 保存、Esc 取消；空名/重名被拒并贴着输入框说明；颜色不变；自动大类跟着新名字重猜，手动大类保留 |
| 时长 | 「__ 小时 __ 分钟」双输入 + 4 个快捷芯片（25 分 / 45 分 / 1 小时 / 1 小时 30 分）；上限 120 分钟 → 12 小时 |
| 表盘 | 满 1 小时才出现小时位（`1:30:00`），不到一小时仍是 `25:00` |
| 验证 | 纯函数自检 **60 项**、渲染冒烟 **27 项**；`tsc --noEmit` 零错误；eslint 0 error / 0 warning |

**为什么改名用行内编辑而不是弹窗**：改一个名字弹一层遮罩，视线要跳两次、手指要够两次；
列表本来就长在这里，就地换行输入是最短路径。

**为什么分钟框不自动进位**：写 90 时若悄悄变成「1 小时 30 分」，输入到一半数字自己跳走，
用户会以为自己打错了。宁可当成 59，让他去小时框补。

**已知边界**：手动选的大类若恰好等于自动识别结果，逻辑层无法与"自动"区分，改名后会跟着重猜。
这是启发式的代价，已写进 `renameTask` 的注释与自检用例，避免以后被当成 bug。

**双时间行是追加的**：R1 原文是「剩余时间 + 当前时刻」，实际做成了三处时间 ——
主数字（剩余或已过）、下方「已过 · 剩余」双时间行、右上角当前时刻。
理由是倒计时到一半想知道「已经花了多久」得心算减法，而减法不该由用户做。

**三个 API 的统一约定**：全屏、屏幕常亮、锁横屏都「失败返回 false，不抛错」。
任何一项不支持，功能打折但不整块不可用 —— 这是网页端唯一诚实的做法。

## 7. 云同步方案（已确认）

### 7.1 一个必须说清的事实

**「换设备数据一致」= 必须登录。** 现在 `/tools` 是匿名可用的（`(campus)` 路由组，无 middleware），
一旦要跨设备同步，账号就是前提，躲不掉。

所以采用**游客模式 + 登录后合并**，而不是强制登录：

| 状态 | 行为 |
| --- | --- |
| 未登录 | 纯本地，功能完整，统计照算，提示「登录后可跨设备同步」 |
| 首次登录 | **把本地已有会话与任务批量上报并入账户**，一条不丢 |
| 已登录 | 会话结束即落本地 + 标记待同步；联网后批量上报，服务端按 `id` upsert |
| 换设备 | 登录后拉取，按 `id` 合并，本地已有的不覆盖 |
| 断网 | 一切照常，积压记录不丢，恢复后补传 |

**游客数据合并是硬要求**：多数人先试用再注册，如果登录时把试用期数据丢了，
等于惩罚了最认真使用的用户。

### 7.2 冲突策略

| 数据 | 特性 | 策略 |
| --- | --- | --- |
| `FocusSession` | **追加型，生成后不再修改** | 按 `id` 幂等 upsert，天然无冲突 |
| `FocusTask` | 会被改名/改大类/归档 | 加 `updatedAt`，按「后写胜」 |

会话是追加型这一点非常有利——云同步最麻烦的冲突合并，在这里基本不存在。

### 7.3 表

```sql
CREATE TABLE IF NOT EXISTS focus_sessions (
  id TEXT PRIMARY KEY, owner_id TEXT NOT NULL,
  task_id TEXT NOT NULL, task_name TEXT NOT NULL,
  category TEXT NOT NULL DEFAULT '未分类',
  started_at INTEGER NOT NULL, ended_at INTEGER NOT NULL,
  seconds INTEGER NOT NULL, planned_seconds INTEGER NOT NULL DEFAULT 0,
  direction TEXT NOT NULL, mode TEXT NOT NULL DEFAULT 'normal',
  end_reason TEXT NOT NULL, created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_focus_owner_time ON focus_sessions(owner_id, started_at DESC);

CREATE TABLE IF NOT EXISTS focus_tasks (
  id TEXT PRIMARY KEY, owner_id TEXT NOT NULL,
  name TEXT NOT NULL, category TEXT NOT NULL DEFAULT '未分类',
  color TEXT, archived INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL, last_used_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_focus_task_owner ON focus_tasks(owner_id, archived);
```

### 7.4 接口

| 接口 | 作用 |
| --- | --- |
| `POST /api/campus/focus/sessions` | 批量上报（按 id 幂等） |
| `GET /api/campus/focus/sessions?from=&to=` | 拉取区间 |
| `GET /api/campus/focus/tasks` / `POST` / `PATCH` | 任务库同步 |
| `GET /api/campus/focus/summary?range=` | 服务端聚合（可选，前端也能算） |

全部挂 `Depends(get_current_user)`，只读写自己的 `owner_id`。

### 7.5 风险

| # | 风险 | 说明 |
| --- | --- | --- |
| 1 | **SQLite 与服务器绑定** | 数据在 `data/sessions.db`，服务器重装/磁盘故障就没了。**项目目前没有定时备份**，上云 ≠ 不丢 |
| 2 | **隐私** | 学习记录是个人数据，`api/admin.py` 若不显式排除可能被统计进去 |
| 3 | **演示型部署** | `core/account.py` 自述「课堂 demo 型部署」，无邮件服务、无找回密码。数据上云后用户会当正式服务 |
| 4 | 单点 | SQLite 无连接池、无多实例能力，并发写靠 `busy_timeout` 排队 |

> 缓解：B4 先做「导出 / 导入 JSON」。即使 B6 还没上线，用户换设备也能手动搬数据。

## 8. 饼图下钻交互（R3 补充）

### 8.1 交互

```
┌─────────────────────────┐
│    ●  大类饼图（6 片）    │   点扇区或图例 → 选中并向下展开
│  数学 42%  英语 28% ...  │
└─────────────────────────┘
┌─────────────────────────┐
│ 数学 · 合计 4 小时 12 分  │   点第二下收起
│ ─────────────────────── │
│ 高等数学    ▓▓▓▓▓▓ 62%   │   ← 类内占比
│ 线性代数    ▓▓▓ 28%      │
│ 概率论      ▓ 10%        │
│                         │
│ 视图：[占比] [时长]       │   ← 切换后：2 小时 36 分 / 1 小时 11 分
└─────────────────────────┘
```

### 8.2 规则

| 项 | 定义 |
| --- | --- |
| 触发 | 点扇区 或 点图例，两者等价 |
| 展开位置 | 饼图**下方**，不弹窗（避免遮挡饼图本身） |
| 收起 | 再点同一类收起；点另一类直接切换 |
| 默认视图 | 占比 |
| 视图切换 | 占比 ↔ 时长，切换只换右侧数值，不重排 |
| 排序 | 类内按秒数降序 |
| 空态 | 该大类只有一个任务时，仍显示（占比 100%），并标注「这一类下只有一个任务」 |
| 无障碍 | 扇区用 `<button>`，`aria-expanded` 标识展开态，键盘可 Tab 到 |

### 8.3 数据

直接用 `drillDown(summary, category)`，已实现并通过 9 项自检。
`ratio` 是类内占比，`ratioOfAll` 是占全区间比例，两者都可用于展示。
