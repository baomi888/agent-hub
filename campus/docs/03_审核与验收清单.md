# 03 · 审核与验收清单

> 给项目负责人（@baomi888）用。**照单勾，不靠感觉。**
> 每条都写成可验证的动作，勾完即可合并；有任一条不通过，PR 打回并注明条目号。

---

## 0. 审核分两级，别搞混

| 级别 | 触发时机 | 用时 | 用哪部分清单 |
| --- | --- | --- | --- |
| **L1 · PR 级** | 每次提 PR | 5–10 分钟 | 第 1、2 节（按改动范围选勾） |
| **L2 · 版本级** | 合并进 `dev`、切换线上入口 | 30–60 分钟 | 全部四节 |

> 只改文档、只改样式变量的 PR，可只走第 2 节相关条目，并在 PR 描述注明「文档类」。

## 1. 功能正确性（L1 / L2 必查）

### 1.1 通用

- [ ] 改动涉及的工具，逐项手动操作一遍，结果与预期一致
- [ ] 刷新页面后数据仍在（涉及存储的改动）
- [ ] 清空 localStorage 后首次打开不报错，呈现空态而非白屏
- [ ] 浏览器控制台无 error（warning 需说明原因）
- [ ] 移动端（≤ 400px 宽）打开，无横向滚动、无元素重叠

### 1.2 GPA 分析

- [ ] 标准 4.0 与北大 4.0 两种算法的换算结果与旧版 `tools.html` **逐条一致**
- [ ] 加权均分计算正确（学分 × 成绩 / 总学分）
- [ ] 空行不计入统计；学分填 0 不导致除零
- [ ] 删除某门课后统计实时更新

### 1.3 课程表

- [ ] 周视图节次高度按课程块自动拉伸，与旧版视觉一致
- [ ] JSON 导入兼容旧格式，导入后课程落在正确的星期与节次
- [ ] **迁移旧数据时 `day` 回拨一天**（见 `docs/02` §2.2），抽一门周一课验证不错位
- [ ] 课程冲突检测能正确提示冲突课程
- [ ] 清空课表后无残留渲染

### 1.4 单词卡

- [ ] 复习队列不会卡死（内测 8.2 的原始问题不能复现）
- [ ] 「不认识」的词进入复习堆，一轮后优先重练
- [ ] 词库从 `frontend/public/data/words/` 读取，未内联进 JS
- [ ] 键盘操作仅在词卡可见时生效，不抢占其他工具的按键

### 1.5 番茄钟 / 倒计时 / 抽签

- [ ] 番茄钟计时误差 ≤ 1 秒，切到其他标签页再回来仍准确
- [ ] 倒计时跨天排序正确，逾期项有视觉区分
- [ ] 抽签多人中签不重复；人数超过名单长度有提示而非静默失败

## 2. 体验与合规（L1 / L2 必查）

### 2.1 免登录底线

- [ ] 未登录状态下可直接访问 `/tools` 全部功能
- [ ] 未引入任何 `/api/*` 请求（开发者工具 Network 面板确认）
- [ ] 未新增登录拦截、未读取用户身份

> 这三条是产品定位，任何一条不满足直接打回，不看功能多好。

### 2.2 深色主题

- [ ] 开启深色模式后，无白底卡片、无浅色文字压深色底
- [ ] 正文对比度 ≥ 4.5:1（可用浏览器 Lighthouse 或对比度工具抽查关键文本）
- [ ] 切换主题不闪烁、不需要刷新

### 2.3 视觉一致性

- [ ] 使用全局令牌（`--bg-canvas` / `--card-bg` / `--ink` / `--accent` / `--line`），未自造色板
- [ ] 图标使用 `CornIcon`，未引入 emoji 或第三方图标库
- [ ] 字号层级与主站一致（不出现比主站标题更大的文字）

### 2.4 可访问性

- [ ] 所有可点击元素有 `aria-label` 或可见文本
- [ ] 表单输入有 `<label>` 或 `aria-label`
- [ ] Tab 键可走完主要操作路径
- [ ] 焦点可见（不出现 `outline: none` 且无替代样式）

## 3. 工程规范（L1 / L2 必查）

- [ ] 新增代码全部落在 `frontend/src/campus/` 与 `frontend/src/app/(campus)/` 内
- [ ] 路由文件（薄壳）≤ 30 行，无业务逻辑
- [ ] 未修改 `tokens.css`、`CornIcon.tsx` 等公共文件（除入口常量，且 PR 已说明）
- [ ] `logic/` 与 `storage/` 未 import React
- [ ] 工具之间无横向 import（`tools/a` 不引用 `tools/b`）
- [ ] `npx tsc --noEmit` 通过，无 `any` 滥用（确有必要需注释说明）
- [ ] `npm run lint` 通过
- [ ] `npm run build` 通过
- [ ] `logic/` 下的计算改动，已与旧版 `tools.html` **逐值比对**（至少覆盖边界分：59/60/63/64/67/68/85/90）
- [ ] 提交信息符合 `规范/03_流程规范.md`（`feat(campus): ...` 格式，中文简述 ≤ 50 字）
- [ ] 一个 PR 只做一件事，未混杂无关改动

> **关于单测**：仓库当前没有前端测试框架（`package.json` 无 vitest / jest）。
> 迁移期用「与旧版逐值比对 + 手工回归」代替自动测试，**不要为了跑测试私自加
> devDependency** —— 那会改动 `frontend/package.json`（板块外文件），需单独提 PR 评审。
> 引入 vitest 的建议时机：S1 阶段拆分完成后，一次性补 `logic/` 的全量单测。

## 5. 审核结论怎么给

PR 评论里只用这三种结论，避免模糊表述：

| 结论 | 含义 | 后续动作 |
| --- | --- | --- |
| ✅ **通过** | 全部必查项通过 | 合并 |
| 🔧 **有条件通过** | 仅剩非阻塞项（如文案、注释） | 作者改完直接合，无需二次评审 |
| ❌ **打回** | 有必查项不通过 | 注明条目号（如「2.1 免登录底线」），改完重新提 |

**打回必须写条目号**，不要写「感觉不太对」。作者按条目改，下轮只看该条目。

---

## 6. 常见打回原因（提前避坑）

按经验，这几条最容易出事：

1. **迁移旧数据时重复回拨 `day`** —— 课表整体错一天，且只在老用户身上出现。
2. **在工具组件里直接调 `localStorage`** —— 绕过版本迁移，后续改结构必炸。
3. **把词库 import 进组件** —— 6661 词直接进首屏包，页面卡死。
4. **深色模式只改了卡片背景，忘了文字色** —— 灰字压深灰底，看着像没加载完。
5. **顺手"优化"了别人的文件** —— PR 里混入无关改动，评审无法聚焦。
