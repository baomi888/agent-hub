# 04 · 开发与提交流程

> 板块独立迭代，但**流程跟着团队走**（`规范/03_流程规范.md`）。
> 本文只写本板块的差异部分，其余照团队规范执行。
>
> ⚠️ **分支与推送以 `05_审核闸门与分支策略.md` 为准**：分支固定为 `school-tools`，
> 且**未经负责人审核通过、未经开发者明确指令，不得推送**。

---

## 1. 分支

> 本节描述按功能临时开分支的写法。板块主线固定是 `school-tools`，
> 长期存在、不删除，见 `05` §1。小改动直接在 `school-tools` 上做即可。

### 1.1 命名

团队规范的模块名取值原本是 `frontend / kb / agent / api / core / deploy`。
本板块新增模块名 **`campus`**，已在 `规范/03_流程规范.md` 登记。

```
feat/campus-<简述>-<日期>       新功能
fix/campus-<简述>-<日期>        修复
refactor/campus-<简述>-<日期>   重构（不改行为）
docs/campus-<简述>-<日期>       仅文档
```

例：

```bash
git checkout dev && git pull origin dev
git checkout -b feat/campus-dark-theme-20261102
```

### 1.2 生命周期

- 从 **`dev`** 切出，**不从 `main`**。
- 生命周期 ≤ 5 天。超过就说明拆得不够细。
- 合并后删除远端分支。

### 1.3 并行开发约定

同时有两条 campus 分支时，**按工具划分**，不要按"层"划（一个人改 6 个工具的 storage，
另一个人改 6 个工具的组件，必冲突）：

| 分支 | 范围 |
| --- | --- |
| `feat/campus-gpa-xxx` | 只动 `tools/gpa/` |
| `feat/campus-schedule-xxx` | 只动 `tools/schedule/` |

公共层（`storage/`、`logic/`、`components/`）的改动**单独开一个小 PR 先合**，
不要在功能分支里顺手改公共层。

---

## 2. 提交

格式照团队规范，作用域固定用 `campus`：

```
feat(campus): 单词卡复习队列改为按记忆强度排序
fix(campus): 课表迁移时 day 重复回拨导致错位一天
refactor(campus): GPA 计算抽到 logic/gpa.ts 并补单测
docs(campus): 补充本地存储迁移检查单
```

要点：

- 简述中文、≤ 50 字、结尾不加句号。
- 一个提交只做一件事。**迁移和加功能不要混在一个提交里**，出问题无法单独回滚。

## 3. PR

### 3.1 目标分支

一律提 **`dev`**。`dev → main` 由负责人按节奏合。

### 3.2 PR 描述模板

```markdown
## 改动

（一句话说清做了什么）

## 对应需求 / 问题

（关联 ROADMAP 条目，或内测反馈编号，如「内测 8.2 单词卡复习队列」）

## 影响面

- [ ] 涉及存储结构变更（若是，附迁移说明）
- [ ] 修改了板块外的文件（若是，列出文件与理由）
- [ ] 影响线上入口（若是，说明是否可独立回滚）

## 自查

- [ ] `npx tsc --noEmit` 通过
- [ ] `npm run lint` / `npm run build` 通过
- [ ] 已对照 `docs/03_审核与验收清单.md` 第 1–3 节自查
- [ ] `campus/VERSION` 与 `CHANGELOG.md` 已更新（发版 PR 必填）

## 截图 / 录屏

（视觉改动必附，浅色 + 深色各一张）
```

### 3.3 评审

- 评审人：`@baomi888`（CODEOWNERS 已配置，会自动请求）。
- 评审依据：`docs/03_审核与验收清单.md`。
- 结论只有 `✅ 通过` / `🔧 有条件通过` / `❌ 打回（附条目号）` 三种。

## 4. 发布与回滚

### 4.1 发布

板块不单独打包，跟主站前端一起构建。切换线上入口是一次**独立提交**：

```ts
// frontend/src/components/chat/constants.tsx
export const TOOLS_URL = "/tools";        // 原为 "/tools.html"
```

这次提交必须：

- 单独成一个 commit（`feat(campus): 校园工具集切换到 /tools 新实现`）
- 在 PR 描述里写明回滚方式
- 合并后观察一周再删除 `public/tools.html`

### 4.2 回滚

```ts
export const TOOLS_URL = "/tools.html";   // 一行还原
```

不需要回滚整包。这是选择"薄壳 + 保留旧版"而不是直接替换文件的原因。

## 5. 边界约束的自动化（建议，待负责人批准后启用）

`docs/01` 里说板块边界靠目录和评审约束。如果能加一条 ESLint 规则，就能在 CI 阶段
拦住越界导入。配置片段（加到 `frontend/eslint.config.mjs` 的 rules）：

```js
// 板块内文件不允许反向依赖外部业务代码
{
  files: ["src/campus/**/*.{ts,tsx}"],
  rules: {
    "no-restricted-imports": ["error", {
      patterns: [
        { group: ["@/components/*", "@/lib/*", "@/app/*"],
          message: "校园工具集不得依赖主站业务代码，公共能力请自建到 src/campus/" },
      ],
    }],
  },
},
// 纯逻辑层不允许引入 React
{
  files: ["src/campus/{logic,storage}/**/*.ts"],
  rules: {
    "no-restricted-imports": ["error", { patterns: ["react", "next/*"] }],
  },
},
```

> ⚠️ 这会修改 `frontend/eslint.config.mjs`（板块外文件），需负责人批准后单独提 PR。
> 批准前靠评审人工把关，清单第 3 节已覆盖。

## 6. 本地开发速查

```bash
cd frontend
npm install                 # 首次
npm run dev                 # http://localhost:3000/tools

npx tsc --noEmit            # 类型
npm run lint                # 规范
npm run build               # 构建（发版前必跑）
```

调试本地存储：浏览器开发者工具 → Application → Local Storage →
筛 `campus.`（新）或 `baomi_tools_`（旧）。清空数据前先确认不需要保留。
