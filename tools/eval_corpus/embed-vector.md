# 向量检索与 embedding 笔记

## embedding 模型的一致性

知识库里的所有向量必须用同一个 embedding 模型生成。
换了模型之后，新查询向量落在另一个语义空间里，
余弦相似度在数学上照样算得出来，但数值不再可比，
检索排序会接近随机。用户看到的现象是答非所问，日志里没有任何报错。
所以每个向量库要写入指纹：模型名、服务主机名、向量维度。
检索前先比对指纹，不一致直接拒绝并提示重建索引，
而不是自动重建——自动重建会触发一次未预期的批量计费。

## 相似度换算

向量库默认使用平方 L2 距离。在归一化单位向量上，
平方 L2 距离与余弦相似度有确定换算关系：相似度等于一减去距离的一半。
距离的合法值域是零到四，对应相似度从一到负一。
判定阈值只看 top1 的相似度，不用平均分：
一条强相关配几条噪声不该被判成检索质量差。

## 切片与混合检索

文档先切成几百字的片段再入库，片段之间保留一定重叠，
避免一句话被切在边界上。检索时先按向量多捞几倍候选，
丢掉明显不相关的，再用最大边际相关算法去掉互相重复的片段。
开启混合检索时，向量候选会并上关键词候选，
用倒数排名融合，专有名词和编号靠关键词通道补召回。

## 检索结果缓存

相同问题的检索结果按库缓存，命中时省掉一次向量查询。
查询向量本身也有缓存，同一个问题不同的返回条数可以复用向量。
缓存键里包含用户标识，避免不同用户的画像偏置串结果。
