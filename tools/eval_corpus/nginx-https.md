# nginx 反向代理与 HTTPS 部署笔记

## 为什么需要反向代理

生产环境只对外暴露一个端口。nginx 监听 443 端口做 TLS 终结，
再把请求按路径分流：根路径转发给前端服务（127.0.0.1:3000），
/api 前缀转发给后端服务（127.0.0.1:8000）。
后端 uvicorn 绑定回环地址，不直接对公网开放，
这样防火墙只需要放行 443 一个端口，攻击面最小。

## 证书申请与续期

证书使用 Let's Encrypt，通过 certbot 申请。
申请前必须完成两件事：域名 ICP 备案通过、DNS 解析已指向服务器。
Let's Encrypt 不会给裸 IP 签发证书，这是硬约束。
certbot 的 systemd timer 会每天检查两次，证书剩余 30 天内自动续期，
续期成功后自动 reload nginx，全程不需要人工介入。

## SSE 长连接的坑

问答接口是 SSE 流式响应。nginx 默认会缓冲上游响应，
必须在该 location 里关掉代理缓冲（proxy_buffering off），
否则前端会收不到逐字输出，变成整段一次性到达。
另外要关掉 gzip 对该 location 的影响，并把读超时调大，
避免长回答生成过程中连接被 nginx 提前切断。
