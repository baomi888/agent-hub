# UI 第三批 · 浅色主题复查 + 手机底部导航

日期：2026-11-13
范围：浅色主题全站复查（6 个页面 × 2 个视口）、手机底部导航改造、导航图标、待办页添加入口合并

## 一、浅色复查：怎么量的

前两批的度量全部跑在深色主题上，浅色一直是空白。这一轮先补基线：

- 方法沿用 oil-ui 的「先测量再判断」：CDP 驱动 Edge，逐页取每个文字节点的
  `getComputedStyle`，按 WCAG 算对比度；同时统计字号分布、< 40px 触控目标数、金色元素数、
  首屏第一块真内容的 y 坐标。
- 主题靠 `?theme=light` 强制（`app/layout.tsx` 的内联脚本优先读这个参数），
  不依赖 localStorage 或系统偏好 —— 两轮跑的是同一份口径。

**度量脚本同一个 bug 先修了**：`bgOf()` 原来在半透明层叠加时用一个写死的深色当底，
浅色下会把每处对比度都算错。改成"先往下找到真正的不透明底，再从外往内叠"。

### 改前数据（浅色）

| 页面 | 1440 对比度不达标 | 390 对比度不达标 |
|---|---|---|
| 对话 `/` | 1 | 1 |
| 待办 `/reminders` | 1 | 1 |
| 提醒设置 | 1 | 1 |
| 四六级 `/cet` | 1 | 1 |
| 打卡 `/checkin` | 1 | 1 |
| 看板 `/dashboard` | 0 | 0 |

只有两条，但每页都有：

1. **导航选中态 4.33:1**（`--accent-ink` 压在 `--accent-soft` 上）。
   这是全站唯一的系统性不达标 —— 每个页面都有一条。
2. **对话页头像首字 3.86:1**（`--accent-ink` 压在 `--accent-tint` 上）。
   18% 的金比 10% 的金更深，字反而更难读。

### 改了什么

| 改动 | 位置 | 理由 |
|---|---|---|
| `--accent-ink` `#875B10` → `#7A510D` | tokens.css | 原值只在"纸底"上够用（4.68:1），压到金色自己的底上就掉到 4.33 / 3.86。新值在侧栏纸上 5.62:1、在 `--accent-tint` 上 5.59:1 |
| 新增 `--knob-shadow` | tokens.css | 开关关闭态的轨道是 `--fill-1`、滑块是 `--step-2`，两个都约等于纸色，只差一圈 1px 的线 —— 浅色下关着的开关看起来像"这条设置没有控件" |
| 开关滑块改用 `--knob-shadow` | console.css | 同上 |
| 「每天几点」的说明句改为单独一行 | reminders/page.tsx | 并排时 390px 下留给它的是不到 190px 的窄柱，"还没设置过 · 现在按默认的 20:00" 被折成四行 |

### 改后数据（浅色）

六个页面、两个视口，**对比度不达标 = 0**。

### 一处诚实的不改

浅色下卡片和页面底的对比是 **1.09:1**，分隔线 **1.19:1**（深色是 1.13 / 1.28，一样弱）。
也就是说卡片主要靠"更白一点点 + 一圈几乎看不见的线"浮起来，这是这套纸质底色的既定做法，
不是这一轮引入的问题。改它会牵动全站每一张卡，且要把 `--line` 从 0.10 提到 0.14 以上
才开始看得出来（会同时让所有分隔线变重）。**这一轮不动，记在这里。**

## 二、手机底部导航

### 改前

手机上是一套 3 列 × 3 行的导航网格，9 个入口铺在内容上面：

- 占掉首屏 **216px** —— 每次打开待办都要先滑过一遍导航；
- 它是"每次打开都要付一次"的固定成本，而手机上一屏只有 844px。

### 改后

底部一条固定 tab，5 格：**对话 / 知识库 / 待办 / 每日委托 / 更多**。

- 前 4 项进 tab，其余 6 项进「更多」面板（3 列网格）。
- ★ 前四项 **直接 `slice(0, 4)` 自同一份清单**（`lib/nav.ts`），
  所以手机的前四项恒等于桌面侧栏的前四项，两边不会各自漂移。
- 「更多」面板：遮罩 + 从底部升起，Esc 关闭、换页自动收起、打开时焦点移进面板。

### 顺带修掉的三处耦合

1. **tab 高度只有一个来源** `--tabbar-h`。三处要"让"出这个高度：
   内容区 `padding-bottom`、最短页高 `min-height`、首页工作台 `height`。
   写三个数字的话，改高 tab 一档就会有一处忘跟。
2. **首页也挂同一条 tab**。首页不走 ConsoleLayout，只挂在外壳里的话，
   从待办点「对话」回首页，底部那条当场消失 —— 这是手机上每天走十几次的路径。
3. **首页工作台的高度规则在 `fx.css` 的 899px 断点里**，不在 `base.css`。
   先在 base.css 改过一次，实测高度还是 828px（被 fx.css 整条覆盖）——
   `mainBottom` 836 > `tabTop` 783，输入区被压住 53px。

## 三、导航图标改单色

`CornIcon` 是双色插画（金实块 + 纸白挖空 + 墨描边），40px 以上很可爱，但导航里要的是 19px。
那个尺寸下金块和挖空糊成一坨，四个固有色互相打架。

新增 `components/NavIcon.tsx`：24 网格、1.85 描边、只用 `currentColor`、零填充、13 个形状。

几个形状是"试出来"的，不是一次画对：

- **知识库**：最早画成"左右两页各带一条竖边"，缩到 19px 就只剩两根竖线。
  改成摊开的一本书（单轮廓 + 中缝）—— 小尺寸靠**外轮廓**认，不靠内部细节。
- **设置**：齿轮在 24 网格里画 8 个齿，19px 下糊成一颗太阳。改成三条滑杆 + 三个错开的旋钮。
- 图标颜色从写死的 `--text-3` 改成 `currentColor`：原来整列图标比旁边的字暗一截，
  看起来像"这几个功能不可用"。

## 四、待办页：三个添加入口并成一条

改前这一页有三个入口，散在三个位置：

1. 页头「+ 新建」→ 表单抽屉（精确控制：优先级、图标、清单、提醒）
2. 列表上方那条大的「一句话添加」→ AI 拆分抽屉
3. 列表**最底下**一行输入框 → 直接加一条

后两个说的是同一件事（"说一句就行"），却一个在顶上、一个要滚到底才看得见；
空列表时那句引导文案指向的输入框，恰恰在屏幕外。

现在合成一条：**输入框 + 「添加」+「整理」**，放在列表上方（永远先看到）。
回车/添加 = 直接记一条；「整理」= 把一整段话拆成多条（原 AI 抽屉，能力一点没少）。
页头「+ 新建」保留 —— 它管的是"我要精确设字段"，和"先记下来"是两件事。

空态文案同步改成「在上面那行直接写」，测试钉住了它必须跟着布局一起改。

## 五、验证

- 全量 **1656 passed / 0 failed**。
- 新增 `tests/test_console_nav.py`（9 条），钉三类"页面看起来正常、接口全 200、不会报错"的坏：
  让位高度、格数与切片数一致、桌面不出现第二条导航。
- 反证累计 11 次，其中 **3 次抓到假绿**，都直接改了断言：
  1. "规则里出现过 `display:none`" → 同段再写一句 `display:flex !important` 照样绿。
     改成取"浏览器实际采用的值"（有 `!important` 的优先，否则最后一条）。
  2. 首页断言的是"`ConsoleTabBar` 这个字符串在文件里" → 只留 import 不渲染也是绿。
     改成断言 `<ConsoleTabBar`。
  3. "规则里出现过 `var(--tabbar-h)`" → 回退写法有两行 `height`，只扣一行也是绿。
     改成"该属性的每一条声明都必须扣"。
- 还发现反证样本本身选错两次（改在 `display:none` 之前插一句，被后面的覆盖 →
  浏览器根本没坏，绿是**正确**的）。换成"直接把 none 改成 block"才验证到位。

### 没验到的

- 还是 Edge headless、浅色 / 深色两套都截了，但**没有真机**。
  iPhone 上 `env(safe-area-inset-bottom)` 只在有 home 条的机型上生效，
  模拟器里恒为 0，所以"tab 抬高 34px"这一段没有真实数据。
- 「更多」面板的拖拽手势没做（只有点击遮罩和 Esc 关闭）。
- 面板打开时锁了底层滚动，但**没有做焦点循环**（Tab 走到最后一个会跳出去）。
- 平板区间（900–1024）没单独看：tab 在 900 以上不出现，侧栏在 900 以下不出现，
  900 这个断点两侧都是"只有一套导航"，但没截图确认。
