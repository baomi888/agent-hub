## 二、反馈格式（让他们照抄）

```
设备：iPhone 13
系统：iOS 17.4
深色模式：是 / 否
哪一步：③ 点学习路径
现象：页面空白了两秒才出来
截图：（附图）
```

**为什么必须写型号和系统版本**：安全区、启动屏、状态栏这三件事全部按机型和 iOS 版本分支。同样是「顶部被挡」，iPhone 14 Pro 的灵动岛和 SE 的刘海是高不同的值，修法也不一样。

## 三、问题分级（我这边用）

| 级别 | 判据 | 处理时限 |
|---|---|---|
| **P0 阻断** | 打不开 / 登不上 / 白屏 / 数据错乱 | 当天修，修完当晚部署 |
| **P1 难看** | 被遮挡、错位、颜色不对、闪一下 | 2 天内，攒一批一起部署 |
| **P2 建议** | "希望能 XX"、"这个按钮不好找" | 记下来，内测结束后统一评估 |

**判定原则**：只要用户还能完成那件事，就不是 P0。比如「论坛发图按钮太小」是 P1，不是 P0；但「发了图帖子是空的」是 P0。

## 四、这一轮重点要盯的四件事（都是刚改、没上过真机的）

改完只验到了「HTML 里有这个标签」，**没有一台真机看过效果**。这四条优先级最高：

1. **黑透状态栏有没有把内容压住**
   这次把 `statusBarStyle` 从 `default` 改成了 `black-translucent`，六个整屏容器都补了
   `env(safe-area-inset-top)`（控制台 / 论坛顶栏 / 首页 / 安装页 / 登录页 / 资料库顶栏）。
   任何一页顶部被挡，就是漏了那个容器 —— 报给我时**说清是哪一页**，我按页定位。

2. **深色模式下状态栏文字看不看得见**
   这是改这个的唯一目的。如果深色下还是看不见，说明 `black-translucent` 在你们这代机型上
   行为不一样，要换方案（改用固定 `black`，或按主题动态下发）。

3. **底部 tab 有没有被 Home 指示条压住**
   这是 `viewport-fit=cover` 是否真生效的直接证据。压住了 = 那一步没成功。

4. **启动屏闪不闪白**
   9 张图按机型 media 命中。如果某一代还是闪白，多半是没命中（尺寸表缺那款），
   把型号告诉我，加一行就行。

## 五、每天怎么收

- **固定时间**：每晚 21:00 在群里问一句「今天有遇到问题吗」，比等人主动报有效得多。
- **当天闭环**：当天的问题当天回一句「收到了，明天修」，哪怕还没修 —— 没有回音的反馈，
  第二天就没人再报了。
- **部署节奏**：修完就部署。PWA 的好处是用户下次打开自动是新版，不用重装；
  坏处是**改了不部署，他们看到的永远是旧的**，同一个问题会被报第二遍。

## 六、一条纪律

**任何时候都不要让 App 成为唯一入口。**

`myzhisui.cn` 在手机浏览器里必须始终功能完整。这样哪怕内测期间某个版本改坏了，
他们换回 Safari 就能继续用 —— 你的进度是「加分项」，不是「生死线」。
