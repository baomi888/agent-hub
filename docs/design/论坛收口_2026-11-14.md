# 论坛收口：只剩一套皮肤（2026-11-14）

> 承「辅助标签」第 4 批留下的那项欠账：论坛有 `fm-*` 与 `tb-*` 两套皮肤并存。
> 并发会话第 17–19 轮把列表页、详情页都换成了 `tb-*`，`fm-*` 那套就再没人碰过。
> 这一批把它删掉，并把"删了看不见"的地方逐条钉住。

## 一、死皮肤不是"看起来没用"，是能证的

删之前做了四步核对，缺一步都只是"我觉得它没用了"：

1. **类名零引用**：`src` 里（排除 `_backup/`）搜 `fm-`，只剩 `forum/page.tsx`
   注释里的一处说明文字。列表页 111 个唯一类名全是 `tb-`，详情页 42 个也全是。
2. **选择器全前缀**：把 `forum.css` 的注释剥掉，逐个逗号拆开，**162 份选择器
   全部以 `.fm-` 开头**，没有一条像 `.kb-post` 那样的全局覆盖 —— 这一条最关键，
   有的话删了就会连带改掉别人的样式。
3. **keyframes 无跨文件引用**：`fm-drop` / `fm-rise` 只被它自己的 `animation` 引用，
   `forum-tb.css` 用的是 `tb-spin` / `tb-breathe`。
4. **删前删后各拍一次截图，md5 比对**：

   | 视口 | 删前 | 删后 | 结果 |
   |---|---|---|---|
   | 390 列表 | `46cd6e7c…` | `46cd6e7c…` | 逐字节相同 |
   | 1440 列表 | `24fbb25e…` | `24fbb25e…` | 逐字节相同 |

   这比上面三步加起来更硬：它直接证明"渲染结果没变"。产物 CSS 从
   **446.8 KB → 433.3 KB（−13.5 KB，−3.0%）**，全站每个页面都少下这一份。

## 二、比删文件更容易漏的是测试

`tests/test_forum_ui.py` 有 4 条断言挂在 `forum.css` 上。其中 3 条删文件时会直接
抛 `FileNotFoundError`（运气好，立刻发现），但第 4 条是这样的：

```python
assert "fm-solve" not in _read(FORUM_CSS)
```

**文件不在了，它永远绿。** 这条断言原本守的是"已解决功能下线后不留样式"，
删皮肤之后它守的是空气 —— 而下一个人看到它是绿的，会以为有人在看。

4 条全部改写：

| 原断言 | 改后 |
|---|---|
| `forum.css` 排在 `library.css` 之后 | `forum-tb.css` 排在 `library.css` 之后（楼层复用 `.kb-post`，覆盖靠后到者赢） |
| `forum.css` 排在 `forum-tb.css` 之前 | 删掉（只剩一套，无顺序可言）→ 换成「只许有一套皮肤」 |
| 两个 CSS 都不许重定义 `.kb-post` | 只查 `forum-tb.css` |
| `forum.css` 里不许有 `fm-solve` | 任何皮肤里都不许有 `.fm-solve` |

## 三、孤儿规则：改名留下的尸体

`forum-tb.css` 里有 5 条 `.tb-re*`（楼中楼预览）和 1 条 `.tb-bye` 已经没有任何元素在用。
第 18 轮把预览从 `tb-re` 改名成 `tb-lzl` 时，页面全改了，CSS 一条没删 ——
页面上看不出任何区别，只是有人下次翻 CSS 时会以为它还在用。

这次不靠人眼找，改成**机器判**：页面用到的每个 `tb-` 类都要在 CSS 里有定义，
CSS 里每个 `.tb-*` 选择器都要有页面在用。

```
定义 131 个 / 使用 131 个 / 差集 []
```

> ★ 两个方向都要判。只判"定义 ⊆ 使用"会漏掉"页面写了 `tb-xxx` 但 CSS 没有"——
> 那种情况元素静默退化成浏览器默认样式（无边框、无内边距），看着"只是朴素了点"。
> 反过来只判"使用 ⊆ 定义"则会漏掉孤儿规则。
>
> ★ 还要配数量下限（`>= 100`）。集合相等在两边都是空集时照样成立 —— 正则一失效，
> 这条断言就成了永真式。第 32 条硬约束的老坑。

## 四、正文行宽：56.4 字 → 40.0 字

详情页版心原来是 `max-width: 900px`。1024 / 1440 / 1920 三档实测**都一样宽**
（因为是 max-width），正文一行 **56.4 个汉字**。

中文长文的舒服区是 30–40 字。超过 45 就开始丢行 —— 读到行尾找不到下一行的开头，
人得用手指点着读。

算式（`可用宽 = 版心 − 容器 48 − 楼层卡片 62 = 版心 − 110`）：

| 版心 | 可用宽 | 字号 | 每行字数 |
|---|---|---|---|
| 900（改前） | 790 | 14px | **56.4** |
| 720（第一版） | 610 | 14px | 43.6 |
| **670（现在）** | **560** | **14px** | **40.0** |

线上三档（1024 / 1440 / 1920）实测全是 `560px / 40.0 字`，390 下是 21.4 字。

### 这里踩了一个"量错对象"的坑

第一版我量的是 `.tb-detail` 的计算字号 = **16px**，据此算出"720 就够、一行约 40 字"。
部署后实测 720 是 **43.6** 字/行，才发现正文其实在 `.kb-post-b` 里，是 **14px**
（`.tb-detail` 继承下来的 16px 只作用于外壳）。

这类错误不会报错、不会红测试，只会让写进注释和提交信息里的结论是错的。
判据是**逐层打印 DOM 的 tag/class/fontSize/clientWidth**，而不是拿外层容器的
computed style 当正文的。

## 五、移动端：同一句话在 40px 内说两遍

顶栏面包屑在手机上原本只留最末一级（当前板块），宽度考虑是对的。但留着之后发现：
顶栏「站务公告」，紧跟着标题下面又一行「站务公告 · 1 条回复」，相隔约 40px。
手机上顶栏的前两级本来不可导航（logo 与「返回列表」都指向 `/forum`），
它剩下的作用只有把同一个词先说一遍 —— 藏掉。

**用 `visibility: hidden` 而不是 `display: none`。** 顶栏是三列栅格
（`1fr minmax(0,460px) 1fr`，对应 logo / 面包屑 / 右侧按钮），`display:none`
会把中间那项从栅格流里摘掉，后面的「返回列表」自动补到第二列（460 那格），
按钮就飘到中间偏左了。`visibility` 保留占位，三个子项各在各列，两侧照样贴边。

实测 390：`crumbVisibility = hidden`、面包屑盒子仍占位（x 79–235）、
「返回列表」右边界 376 = 顶栏内容右边界（390 − padding 14）。

## 七、仍未验
