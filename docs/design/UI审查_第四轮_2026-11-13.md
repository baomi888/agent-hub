# UI 审查 · 第四轮：首页撤掉底部 tab（2026-11-13 18:39 上线）

> 用户原话：「然后主页面下面的 tag 去掉把，影响整体性，其他的就不用」
> —— 「tag」指手机上底部那条导航（`.tabbar`），「其他的」指控制台那 8 个页面。

## 一、为什么首页会有一条 tab

首页 `/` 不走 `(console)` 路由组，它有自己的整屏工作台布局（`main.workbench-main`）。
11-13 第二轮把 tab 压到 50px 时，为了不让「从待办点对话回首页时导航凭空消失」，
在 `app/page.tsx` 里**单独挂了一次** `<ConsoleTabBar>`。

这一轮用户看过真页面后否掉了这个决定：工作台是一整块满屏卡片（`margin: 8px` +
`100dvh`），底部再压一条 50px 的导航，等于把卡片切成"内容 + 一条工具栏"两截。
「整体性」说的就是这个。

## 二、改动两处，必须成对

| 位置 | 改动 |
|---|---|
| `app/page.tsx` | 删 `<ConsoleTabBar ... />` 与 import（组件本身保留，控制台还要用） |
| `app/styles/fx.css` | 窄屏 `main.workbench-main` 高度 `calc(100dvh - 16px - var(--tabbar-h) - env(...))` → `calc(100dvh - 16px)` |

**只删组件不改高度 = 底部空出 50px 白边**，比原来被压住更难看。这是这一轮唯一的真实风险点，
所以测试里把两件事写成同一条断言的两半，删一半就会红。

高度只能在 `fx.css` 改：`base.css` 里那条先加载、会被整条覆盖（第二轮实测）。

`--tabbar-h` 没有废弃：控制台 8 个页面仍靠它让位（`.console-scroll` 的 `padding-bottom`、
`.console-shell` 的 `min-height`）。`/tools` 现在也在 `(console)` 里，属于"其它页面"，照旧有 tab。
