# 知穗 Agent · UI 层审查（oil-ui 第二轮）

> 2026-11-13 · 用 oil-ui 的视觉语言判据 + 浏览器实测数据再过一遍
> 上一轮报告：`UI审查_2026-11-13.md`（tasteskill 判据，逐页找毛病）
> 截图：`oil-ui-2026-11-13/`（1440 与 390 两档，8 张）

## 怎么看的

- **判据**：oil-ui `references/visual-language.md` 的六条 —— 焦点与空间、字体与内容、
  可读性作为交付门槛、色彩与表面、控件与图标、减法。
- **方式**：本地起后端 8000 + 前端 3100，用已有测试账号 `uicheck` 登录，
  在 1440×900 与 390×844 两个视口下**先切视口再量**，量的是浏览器算出来的值，
  不是读 CSS 猜的。四个页面：待办 / 待办·设置 / 对话首页 / 四六级。
- **量了什么**：每个文字节点的字号、颜色、行高、与背景的实际对比度；
  每屏用了多少种字号、各承载多少字；金色（`--accent`）出现在哪些元素上；
  小于 40px 的可点元素；第一块"真内容"离页面顶有多远。
- **限**：深色主题（本机系统深色）、Edge headless、没有真机；
  hover/focus 观感、键盘遍历、读屏顺序、LCP 都没测；
  动效没看（截图判不了）。1440 截图压到 1280 传输，细节判断用原始 PNG 复核过。

---

## 一句话结论

**问题不在"哪一页丑"，在于这个产品没有一张自己的字号表。**

同一个"说明句"，在设置页是 14px、在待办页是 12px、在四六级页是 12px；
而同一条 12–13px 的线上，还压着卡片标题、按钮、时间、标签、正文五种角色。
其余问题（首屏被导航吃掉、金色越界、主操作不像按钮）都是这条的后果：
**当所有字都差不多大时，就只能靠颜色抢，于是金色变成了万能强调色。**

## 一、度量：现在到底长什么样

### 表 1 · 字号分布（按承载的汉字数量排，不是按出现次数）

| 页面 | 12px | 13px | 14px | 12px 占比 |
|---|---|---|---|---|
| 待办 · 桌面 | 274 字 / 52 处 | 135 字 / 26 处 | 53 字 / 8 处 | **56%** |
| 待办 · 手机 | 220 字 / 48 处 | 82 字 / 16 处 | 44 字 / 8 处 | **64%** |
| 四六级 · 桌面 | 281 字 / 25 处 | 69 字 / 11 处 | 10 字 / 2 处 | **76%** |
| 对话 · 桌面 | 244 字 / 32 处 | 26 字 / 7 处 | 36 字 / 7 处 | **72%** |
| 设置 · 桌面 | 80 字 / 8 处 | 55 字 / 11 处 | 386 字 / 27 处 | 15% |

三件事从这张表里直接读出来：

1. **12px 是这几个页面的主力字号**，不是"最小字号"。四六级页 76% 的字、对话页 72% 的字都在 12px。
2. **13px 和 12px 只差 1px**，肉眼分不出层级，等于没有这一档。
3. **设置页是全站唯一按 14px 正文排的页面**（386 字在 14px），它也是四个页面里最好读的一个。

根因在令牌里，两条一起看：

```css
--fs-xs: 0.75rem;  /* 12px 元信息、时间戳、说明句 */
--fs-sm: 0.75rem;  /* 12px 工具条、按钮、标签（与 xs 同档） */
```

**两个不同职责的令牌是同一个值。** 注释自己写着"与 xs 同档"——
说明当初是知道的，只是没拆。后果是拿 xs 和 sm 当"两个层级"用，
实际排出来一模一样。

### 表 2 · 结构与可达性

| 待办 · 手机 | y=647 / 844（**77%**） | 9 | 26 | 1 |

才见到第一条待办；桌面也要 402px，接近半屏。

## 二、问题清单（按影响排）

### 1. 手机上 23–27% 的首屏给了导航，四个页面无一例外

**位置**：待办 / 设置 / 四六级三页顶部 y 0–200（`navH=200`，屏高 844）。
对话页是唯一例外（汉堡收起）。

**观察到**：9–10 个入口排成 3 列网格，"设置"单独占第 4 行、留下两个空洞。
这块固定 200px，加上标题区、两个提示块、tab、排序行，
第一条待办落到 y=647。

**依据**：每屏一个主角；手机是主设备，且这批用户会"添加到主屏幕"当 App 用 ——
一个 App 打开先看到一屏导航，是不能用的。

**怎么改**：< 900px 改底部固定 tab，只放 4 项（对话 / 待办 / 资料库 / 更多），
每项 ≥48px 高、加 `env(safe-area-inset-bottom)`；其余 6 项进「更多」抽屉。
主内容从 y=0 起排，标题区压到 90px 内。

**代价**：每日委托 / 四六级 / 打卡多一次点击；`console.css` 里那段 3 列网格
（`console.css:1178` 附近）要换掉，是这批里唯一动布局的。**0.5–1 天。**

### 2. 12px 在撑整句说明，且 xs 与 sm 同值

**位置**：「每天几点给你做回顾」的说明句、免打扰说明、
「设了提醒时间，到时会通知你；课表、打卡的提醒会自动排好。」、
四六级页 5 句 12px 说明（"选好之后按你的选择生成每日任务…"等）。

**观察到**：这些是**给人读的句子**，不是元信息。同一屏上它们的字号
和「收件箱 · 日常」「2 天」这种真·元信息完全一样。

**依据**：产品界面正文 14–16px，每天长时间使用的高密度工具可以到 13–14px；
不靠 9–12px 的说明营造"精致"。

**怎么改**：

```css
--fs-xs: 0.8125rem;  /* 13px 只给时间戳、角标、单位 */
--fs-sm: 0.875rem;   /* 14px 工具条、按钮、标签 —— 与 xs 拉开 */
--fs-md: 0.9375rem;  /* 15px 卡片标题 */
```

同时定一条硬规则：**超过 15 个字的句子不许用 xs**。
四六级页那 5 句 12px 说明会自然升到 14px，那是它该有的样子。

**代价**：改 3 个令牌 + 巡检 `.hint`、`.rem-*` 里写死 12px 的地方；
改完要在 390 下重看换行（字变大，原来一行的会变两行）。**2–3 小时。**

### 3. 桌面也要滑 45% 才见到第一件事，因为首屏有三块"非内容"

**位置**：待办页 y 157–400 之间依次是「一句话添加」卡、权限警告卡、
tab、排序行。**同屏还有第二个输入框**（"记一条：明天 9 点交作业" + 添加）。

**观察到**：三块都在说"加一条"或"你没开权限"，没有一块在说"你该做什么"。
两个输入框用两个动词（`开始 →` / `添加`），第一次用的人不知道该用哪个。

**依据**：一屏一个主动作；同一件事不要两个入口。

**怎么改**：
① 删掉顶部「一句话添加」卡，只留底部那条（它离列表更近、更像输入框）；
② 警告卡压成一行 `收不到提醒 · 去设置`，且**只在真的设了提醒但没有设备时**出现；
③ 眉题「什么时候做什么」和标题「待办」合并 —— 这一句对老用户是噪音。

**代价**：纯结构，不动数据。**半天。**

### 4. 「日常」标签对比度 3.1:1 —— 令牌用错了，不是色值不够

**位置**：待办卡右下角的优先级标签（`.rem-pritag`，12px）。

**观察到**：`3.1:1`，WCAG AA 对正常字号要求 `4.5:1`。

**根因**（这条值得单独记）：令牌系统里每个语义色都有 fill / ink 两档 ——

```css
--info: #3A72A6;      /* 注释写的是「白字 7.17:1」，即它是**底色** */
--info-ink: #8AB6E0;  /* 浅蓝的**文字**版本 */
```

而 `.rem-pritag[data-p="1"]` 写的是 `color: var(--info)` ——
把一个"当底色用"的深蓝直接拿去当文字色，压在 `--fill-3`（暗棕）上，就是 3.1:1。
`--red` / `--red-ink` 那组是对的，蓝色这组漏了。

**怎么改**：`--info` → `--info-ink`。一行，对比度从 3.1 回到 7 左右。
顺手给 `.rem-pritag[data-p="3"]` 也复核一遍（它用的是 `--red-ink`，是对的）。

**代价**：一行。**5 分钟。**

### 5. 26 个可点元素小于 40px，最小 26×26

**位置**：侧栏导航项 171×37（桌面）/ 109×34（手机）；
「列表 / 设置」分段 48×32；对话页字号档位 38×28、26×28；
「退出」38×26；「收起资料库」25×25。

**观察到**：项目自己的规矩是触控 ≥44px。现在导航项 34px 高，
手指点在两行之间容易点错 —— 而这是每页都要点十几次的地方。

**怎么改**：导航项 `min-height: 44px`（手机 48px）；分段控件高度 32→40，
外层命中区用负 margin 撑到 44（`.rem-pritag::after` 已经有这个手法，照抄即可）；
对话页字号档位从 4 个 chip 收进设置（见第 9 条），问题自然消失。

**代价**：改 CSS，手机导航变高——和第 1 条是同一处，一起做。**1–2 小时。**

### 6. 中文被拆行、被省略号切掉

**位置与证据**：

- 手机待办页警告卡右侧的「去设置」被挤成 **「去设 / 置」**（截图里可见）。
- 手机待办页副标题「…课表、打卡的提醒会自动排**…**」被截断，桌面是完整的。
- 对话页左栏副标题在桌面就截成「知识库 · 多对话 · 智能…」。

**依据**：`visual-language.md`：行末只剩一两个字、或词被拆到两行，都算缺陷；
重要名称不要用固定高度裁。

**怎么改**：`.hint` 允许 2 行、去掉 `nowrap + ellipsis`；
警告卡那句压到 20 字内（「这台设备还没开提醒权限，到点不会通知你。」），
「去设置」改成卡片右下整行按钮；对话页副标题删到「AI 学习助手」。

**代价**：文案 + 2 行 CSS。**半小时。**

### 7. 主操作不是按钮形状，同一动作有三个入口

**位置**：
- 四六级页：「建立我的备考档案」是卡片右下角一行 12px 金字，无底、无框、无高度，
  距最后一个字段 60px 以上，而卡片宽 830px、字段只到 x=540。
  同屏 5 个金色 chip（听力/词汇/阅读/写作翻译/真题）比它重得多。
- 待办页：`+ 新建`（描边按钮）、`开始 →`（金字链）、`添加`（描边按钮）——
  三处都是"新增"，三种形态。

**怎么改**：四六级主按钮改金色实底 + `--ink` 字、14px、高 44px，
贴在最后一行右下 16px；未选的 chip 从"金描边 + 金字"降成 `--line` 描边 + `--text-2`，
让主按钮成为全卡唯一的金色实底。

**代价**：改 chip 与按钮样式，四六级页需要重看一遍。**1 小时。**

### 8. 金色越界：一屏 11 处

**位置（待办桌面，实测 11 个元素）**：`待办`（导航选中）、`什么时候做什么`（眉题）、
`一句话添加`（小标题）、`开始 →`、tab 上的 `2`、`还有 9 小时 16 分`、
`改时间`（描边）、`添加`（描边）、`查看全部`、`2 天`、`3 天`。

**依据**：`tokens.css:47` 的注释写的是「金色留给『这一项是选中的 / 这是主操作』」。
现在"还有多久""2 天""查看全部"这些既不是选中也不是主操作，也用了金。

**怎么改**：三条硬规则 ——
① 一屏内金色**实底**不超过 1 处（主操作）；
② 金色文字只给"当前选中"和"进入 30 分钟内的时间"；
③ 其余一律 `--text-2`。按此执行，待办桌面从 11 处降到 4–5 处。

**代价**：只改 CSS 变量引用，不动结构。**1 小时。**

### 9. 图标在 12px 下读起来像 emoji

**位置**：侧栏导航 10 个图标；对话页左上品牌标。

**要先纠正一个误判**：这些**不是 emoji**，是 `components/CornIcon.tsx` 自绘的 SVG 图标集
（文件头注释写明"替代全站 emoji"），这符合"不用图标库"的约束，方向是对的。

**但代价出现了**：这套图标有四个固有色（玉米金 `#F5B840`、叶绿 `#7C9A54`、
陶橙 `#EF8A56`、纸白 `#FFFDF6`），排到 12–14px 时，**四色 + 白填充在深底上就是 emoji 的观感**，
和"暖纸 + 一点金"的单色体系互相打架。而且 `notes`（对话）与 `calendar`（总结）
都是"白方块 + 顶部一条"，12px 下分不出。

**怎么改**：导航层不要四色 —— 图标描边统一 `currentColor`、去掉绿/橙填充，
只保留选中项的描边转金；`notes` 与 `calendar` 换一个有区分度的形态（如便签折角）。
品牌标和首页大图继续用四色，那里尺寸够大。

**代价**：CornIcon 加一个 `mono` 变体，导航处传 `mono`。**1–2 小时。**

### 10. 设置页同类控件四种形态

**位置**：免打扰用 `type=time`（带时钟图标）×2；
「每天几点给你做回顾」用两个 `select`（20 点 / 00 分）×2；
「每天最多提醒几次」用 number input；开关是 switch。

**依据**：控件是一套语法，圆角、描边、字重、按下位移、选中表达在按钮/输入/标签/开关之间用同一套逻辑。
四种"选时间"并排出现，比配色不一致更容易被看见。

**怎么改**：「每天几点」并进 `type=time`（与免打扰同款），
秒/分下拉只有在真的需要 15 分钟粒度时才用；数量输入加 `−/+` 步进。

**代价**：改一张卡 + 一处 API 读值（`steps` 已经在了）。**2 小时。**

### 11. 界面上的行话（3 处必须改）

| 位置 | 现在 | 改成 |
|---|---|---|
| 对话页顶栏胶囊 | `问答 0/60 · 向量化 0/1000` | 删掉，或「还能问 60 次」 |
| 四六级页卡下注 | `还没有档案时会显示这个配置向导；建档之后在这里随时能改。` | 整句删掉 |
| 设置页 · 邮件提醒 | `服务端还没配好发信账号，这台暂时收不到邮件提醒。` | 「邮箱提醒暂时不可用」 |

另有一处命名分裂：导航叫**知识库**，对话页面板和按钮叫**资料库**，
指的是同一个东西。统一成「资料库」（学生更能懂）。

### 12. 规范内部冲突一处（不是页面问题，但会导致以后反复）

`tokens.css` 深色段把 `--bg-subtle` 重新赋成 `rgba(224,160,58,.09)`（**金色**），
而同一文件开头写的是"填充四级全部用中性暖墨/暖白 alpha，不带金色"。
浅色段它是 `--fill-3`（中性）。**所以深色下凡是拿 `--bg-subtle` 当 hover 底的地方，都偏黄。**
建议深色段改回中性（如 `rgba(237,224,196,.07)`）。

## 三、已经在做对的（改的时候别磨掉）

1. **对话页首屏「早上好，我是知穗」** —— 衬线中文字 + 一条手写感金色下划线 +
   上下两行小字。这是全站唯一"编辑感"真正成立的地方，别换成无衬线粗黑。
2. **待办卡的信息顺序** —— 20:00 大字在前、标题中号、元信息灰小字。扫时间最快。
3. **用完整句子说状态** —— 「还有 9 小时 16 分」「关掉只是不再通知，待办和提醒都还在」
   「免打扰 23:00–07:00，这段时间不会发提醒」。平实、具体，是这套文案最值钱的部分。
4. **提醒权限缺失时给可点的"去设置"并写清后果**，而不是静默失败。
5. **深色下三级纸色分得开**（侧栏 / 画布 / 卡片），卡片靠 `--line` 落脚、不堆阴影。
6. **设置页的字号是全站最健康的**（15% 在 12px）—— 它就是其他页面该照着改的样板。
