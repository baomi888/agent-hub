# 首页评审：一个「字」的字体回退，和这一屏的排版（2026-11-15）

两件事，来自同一次用户反馈：

1. 首页「论坛」卡片的**「坛」字和「论」不一样** —— 判断是字体还是样式问题；
2. 用 oil-ui 对首页整体排版做一轮视觉评审，给可执行的改进方案。

结论先写：**① 不是样式，也不是浏览器渲染 bug，是离线字体子集缺字**（已修，已上线）；
**② 机械检查（对比度 / 小字 / 行高 / 溢出）三端全过，问题集中在"层级与对齐"**，
下面按影响排序列了 11 条，每条带实测数值。

---

## 一、「坛」为什么和「论」不一样

### 结论

`--font-serif` 的第一档是 `LXGW WenKai Screen`（手写体），线上那个 **woff2 是子集，只有 1455 个字形**。
「坛」不在里面，浏览器于是**只把这一个字**回退到后面的 `Noto Serif SC` → `Songti SC` / `SimSun`，
画出一个宋体。同一个词里两种书体、两种字重（手写体只有 400，700 是合成粗；宋体 700 是真的粗），
所以「坛」看着又粗又方。

### 证据（不是推测，是三个独立来源）

**① 子集 cmap 直接查**（`fontTools`）：

```
论 0x8bba → 在子集里
坛 0x575b → 不在子集里
LXGWWenKaiScreen-400.woff2 共 1455 个码位
```

**② 让浏览器自己说**（CDP `CSS.getPlatformFontsForNode`，线上页面 390 宽）：

```
「论坛」这张卡 → 两个字体条目：
   LXGW WenKai Screen  glyphCount: 1
   SimSun              glyphCount: 1
「每日委托」对照组 → 一个条目：
   LXGW WenKai Screen  glyphCount: 4
逐字形再验一次（把两个字拆成两个 span）：
   论 → LXGW WenKai Screen
   坛 → SimSun
```

**③ 像素量**：同一行两个字，「论」39×37 / 412 个暗像素，「坛」39×38 / **651** 个暗像素
—— 多 58% 的墨，正是"手写体 vs 宋体粗体"的差。

### 为什么会缺（两个独立成因）

1. **手写体子集只收源码里出现过的字**（`gb2312=False`），而这份子集是 **2026-10-14** 生成的。
   之后一个月新增的文案（含 11-15 加进首页的「论坛」卡）都没有进来 —— 一共缺 495 个字。
2. **GB2312 兜底本身漏了一整列**：`tools/subset_fonts_project.py` 写的是
   `range(0xA1, 0xFE)`，上界少 1，于是 low 字节为 `0xFE` 的那些字（**威 掐 摸 晓 浸 牺 玄**…）
   从来没进过字符集。Noto Sans 子集也缺这 7 个（正文遇到就落到系统宋体）。

### 修法

| 动作 | 文件 |
|---|---|
| GB2312 上界 `0xFE` → `0xFF` | `tools/subset_fonts_project.py` |
| 重新生成 9 个字重（手写体 345KB → 466KB，Noto 基本不变） | `frontend/public/fonts/*.woff2` |
| 新增 3 条覆盖守卫 | `tests/test_font_subset_coverage.py` |
| 声明工具依赖（不静默跳过） | `requirements.txt`（fonttools / brotli） |

守卫三条：源码字符必须每个都在**全部 9 个字重**里；「论」「坛」必须都在手写体里；
GB2312 每区最后一个字必须在 Noto 里。反证方式是**把断言指回修复前的 woff2**（二进制没法逐字节改），
3/3 真红、修复后 3/3 真绿。

修复后线上复验：`「论坛」→ LXGW WenKai Screen, glyphCount: 2`（单一条目），逐字形 论/坛 同一字族。

> 顺手记一条方法论：这类问题**永远只表现为"某个字长得不对"**，接口、构建、测试全绿。
> 以前没有任何守卫，只能靠看得见的人发现。现在文案引入子集外的字会直接红。

## 二、oil-ui 视觉评审（首页空对话态）

### 评审对象与口径

- 页面：登录后的空对话首页（欢迎页），线上 `https://myzhisui.cn/`，管理员账号（比普通用户多「今天」条与提醒条）。
- 设备：390×844（浅色 + 深色）、768×1024、1440×900；另按 200% 缩放等价视口 720×450 与 1024×600 各看一次。
- 方法：真实截图 + DOM 几何量测 + 四类机械检查（对比度 <3:1 / 可见文字 <11px / 正文行高 <1.4 / 首屏透明态）+ 横向溢出。
- 另派了一位**没有制作历史**的独立评审者只看四张图给意见，下面每条我都用实测数据复核过；
  它有两条与实测不符，已剔除（见第三节）。

**机械检查结果（三端）**：对比度 0 处不达标、<11px 文字 0 处、行高过紧 0 处、
横向溢出 0（`docSW == viewport`，三端）。**4 处文字被截断**（见 P2-1、P2-2）。

### 总评：主角与重心错位

这一屏的视觉主角是「下午好，我是知穗」（手写体 31.9px + 品牌金下划线）和它上面的吉祥物，
重心落在**上部 1/3**。但这一屏的任务是"让人开口提问"——输入框在最底部，
浅色下是全屏最淡的主要控件之一，**深色下与纸底只差 1 个色阶**（见 P0-1）。
重心与任务不一致。

### 问题清单（按影响排序）

#### P0-1 深色下"卡片 / 输入框 / 纸底"三块同色，层级与"可输入"的形体都消失

- **位置**：深色主题整屏，尤其一组卡片与底部输入区。
- **观察**（截图像素取样）：纸底 `rgb(43,36,26)`，一组卡内 `rgb(44,37,26)`（**+1 阶**），
  二组卡内 `rgb(44,38,28)`，输入框内 `rgb(44,37,27)`。浅色对照：纸底 `244,238,223`，
  一组卡内 `253,250,241`（**+9 阶**）。
- **依据**：深浅两套主题讲的是两套层级。深色下"卡片"和"输入框"都不成形，
  只剩 1px 描边——用户第一眼找不到可以打字的地方。
- **建议**：给面板定两档抬升并写进 tokens：`--panel-1`（+4~6 阶）/`--panel-2`（再 +4~6 阶）；
  深色输入框用 `--panel-2` + 内描边 `inset 0 0 0 1px rgba(255,255,255,.08)`。浅色数值不动。

#### P0-2 第二组卡片"降级"后与纸底同色（浅色差 2 阶），读起来像禁用；且与一组共用同一条边框

- **位置**：「常去的地方」那三张卡（待办 / 公开知识库 / 论坛）。
- **观察**：一组 `bg rgb(253,250,242)` + `rgba(80,60,30,.05)` 投影；二组 `bg transparent`
  （卡内 `246,242,228`，纸底 `244,238,223`，差 **2 阶**）、无投影；**边框两者相同**
  `rgba(61,47,26,.1)`；尺寸圆角完全相同（115.3×72.6 / 12px）。
- **依据**：同尺寸、同边框、只差"有没有填充"，在纸纹底上等于"未完成/未启用"。
  深色下更糟：两组都只剩描边，区分彻底消失——同一屏在两个主题下讲了两套层级。
- **建议**：二选一，不要"半边有底 + 同款边框"：
  - (a) 二组保留填充但降一档（`--fill-2`），靠图标底衬与文案色区分；
  - (b) 二组去边框，改成"无框列表项"（左图标 + 文字，仅靠留白分列）。

#### P0-3 分组标题没落在任何一条对齐轴上（文字比卡片左缘恒内缩 36px）

- **位置**：「让知穗每天做点什么」「常去的地方」两行标题。
- **观察**：标题**文字**起点 390 / 768 / 1440 = **50 / 76 / 402**，卡片网格左缘 = **14 / 40 / 366**
  → 恒定内缩 **36px**（`::before` 26px 短线 + 10px 间隙）。同时右侧 `.rule` 长
  141.6 / 467.6 / 467.6，左边只有 26px。
- **依据**：这两个标题是这一屏唯一的分隔信号，它既不对齐卡片、也不对齐页面文字轴；
  左右线长 26 vs 142，像没画完。
- **建议**：删掉 `::before` 那条 26px 短线，标题直接左对齐到 `--chat-px`（与卡片同轴），
  右侧 `.rule` 从文字尾延伸；若一定要装饰线，两边各 12px 且对称，标题仍左对齐。

#### P1-1 首屏上下两块大留白把内容挤成"悬浮带"，而且屏幕越高空得越多

- **位置**：顶栏与吉祥物之间、二组卡片与底部胶囊之间。
- **观察**：390：顶栏底 46 → 吉祥物 150（空 **104**）；二组卡底 645 → 胶囊 742（空 **97**）。
  768：吉祥物 ~190、二组卡底 ~700 → 胶囊 ~895（空 **195**）。1440 吉祥物 161.8。
  原因：`.welcome` 垂直居中。
- **依据**：首屏约 190px（768 上）没有承载任何信息，而真正需要空间的卡片
  （手机 72.6px 高、说明文字被迫 `display:none`）反而最紧。
- **建议**：`.welcome` 改上对齐 + `padding-top: clamp(20px, 5vh, 48px)`；
  省下的空间给卡片（手机 72 → 88，并考虑恢复 `hint`）或加高「今天」条。

#### P1-2 同一行胶囊三种规格（同一个权重，四种长相）

- **位置**：输入框上方 `检索 / 智能联网 / 反馈 / 工具集`。
- **观察**：390 三枚 28 高 / 14px；1440 上 `检索 76×30 fs15`、`智能联网 107×30 fs15`、
  而 `反馈 65×28 fs14`；`工具集` 在另一个容器里（未与前三枚同一套 flex）。
- **依据**：这是同一权重的功能开关，规格不齐一眼看得出。
- **建议**：抽一个 `.cap-chip`：高 30 / fs 13 / `padding 0 10` / `gap 6` / 圆角 999，
  四枚同源，`工具集` 并入同一个 flex 容器（注意它带下拉，单独包一层也保持同一外框尺寸）。

#### P1-3 卡片规格跨断点不连续，h1 甚至非单调

- **位置**：卡片与主标题。
- **观察**：卡片圆角 **12（390）→16（1440）**、图标 **30 →44**、label **14 →16**；
  h1 字号 **31.9（390）→ 36.3（768）→ 31.9（1440）**——平板比桌面还大 4.4px。
- **依据**：断点是"换档"，换档要有方向。中间档比大屏还大，说明那一档是单独拍的数，
  不是同一套 scale 推出来的。
- **建议**：定 3 档并进 tokens：h1 `30 / 34 / 38`；卡片圆角恒定 12（或 12/14/14）；
  图标 `30 / 36 / 44`。

#### P1-4 任务条右侧有四条不同的右端线

- **位置**：「六级今天还剩 5 个任务」那条卡片。
- **观察**：卡右缘 **376**；「去做」右端 **363**；「×」右端 **364**；「打开提醒」右端 **334**。
  三端结构相同。
- **依据**：同一块里三个右端，看起来像手摆的；而「×」最小、最淡，却紧贴「打开提醒」，
  最容易误触。
- **建议**：`去做` / `打开提醒` 统一右内缩 16（→360）；`×` 固定到 368 或移到卡片右上角外侧；
  `×` 描边提到与次要文字同色。

#### P1-5 输入框高度跨断点跳 29%，手机上是全屏最矮的主要控件

- **位置**：底部输入区。
- **观察**：390：`362×56`；768 / 1440：`688×72`。距底 12 / 16 / 51。
  （底部安全区已按 iPhone 单独处理过，见第三节，不是问题。）
- **依据**：输入框是这一屏的核心动作，56px 比卡片（72.6）还矮，触控目标偏小。
- **建议**：`min-height: clamp(60px, 7vh, 72px)`，三端只用这一条。

#### P2-1 顶栏胶囊截断，但右侧空着 149px

- **位置**：顶栏「未绑定资料库 · 点此选择」。
- **观察**：390 上文本 `clientWidth 128 / scrollWidth 149`（截断），容器右缘 241，视口 390。
- **依据**：不是空间不足，是 flex 没让它长。
- **建议**：容器 `flex:1; min-width:0`；或缩成短标签「未绑定」+ `title` 给全称。

#### P2-2 三处文字被截断

- `today-strip` 副标题：390 `scrollWidth 252 / client 228`（「…（每日 10–1…」）→ 允许两行或缩短时间表达。
- 右栏资料库名：`数据采集与·处理·作业·` 在 **1440 也只有 119px**（需 180）→ 名称列给下限或换行。
- 顶栏胶囊同上。

#### P2-3 手写体在 14px 上承担"标签"角色

- **位置**：六张卡片的 label。
- **观察**：label 14px 用 `LXGW WenKai Screen`（手写体），说明 13px 用 `Noto Sans`；
  同一张 115px 卡里两种书体 + 1.85 描边插画图标。
- **依据**：手写体在小字号下笔画细、结构松，辨识度不如正文体；而且它正是这次
  "坛"字事故所在的字体——字号越小、回退越难发现。
- **建议**：label 改 `--font-sans` 600（或手写体只留给 h1 / 品牌句 / 侧栏品牌），
  图标保持现状。

#### P2-4 底部脚注在不同断点"谁在、谁不在、在哪"都不一样

- **位置**：`问完的每一句，都能翻回原文。`
- **观察**：390 `display:none`；768 显示在**卡片下方、居中**；1440 显示在**输入框下方**。
- **建议**：统一到输入框下方一档，三端都留或三端都删。

#### P2-5 空对话页顶栏的「新对话」是"当前页的刷新按钮"

- **观察**：空对话态下页面本身就是一个新对话。
- **建议**：空对话态把它换成「搜索对话」，或隐藏。

### 建议的落地顺序

1. **P0-1 + P0-2**（一次改完 tokens + 卡片材质）：只动颜色令牌与 `.is-soft` 三条规则，
   风险最低、收益最大，深浅两个主题的层级同时修好。
2. **P0-3 + P1-1**（对齐轴 + 上对齐）：动 `.welcome` 的 padding 与 `.welcome-section-head`，
   会改变首屏节奏，需要三端重截。
3. **P1-2 + P1-3 + P1-5**（规格归一）：抽令牌，改动面广但都是数值。
4. **P1-4 + P2-\***（细节）：可以并进任意一批。

## 三、独立评审里被实测否掉的两条（记下来，防止以后照抄）

1. **「输入框距屏幕底只有 11px，会被 Home 指示条压住」** —— 不成立。
   实测 390 上距底 12px、左右 14px（不是它说的 24px）；而且 `chat.css` 里
   `.chat-dock` 早就写成 `max(--chat-dock-pb, env(safe-area-inset-bottom) - --app-edge-y)`，
   iPhone 上实际是 26px 内边距、离屏幕底 34px。**避免把安全区叠两遍**是 11-14 第八批刻意修的。
2. **「分组标题字号只有 12px」** —— 实测 13px / 500 / `letter-spacing 2.6px` / 行高 21.45，
   不是 12px。它确实很轻（颜色 `rgb(111,96,68)` 对纸底约 4.2:1），但"太小"这个描述不准，
   真正的问题是**它没有落在对齐轴上**（P0-3）。

这两条我保留在这里：独立评审的价值在于"不带制作惯性"，但**它的数字要复核**。

## 四、没验 / 已知缺口

- 全部读数来自 headless Chromium（Edge），**没有真机**：OLED 屏上深色的 `rgb(43,36,26)`
  实际观感会比截图更黑，P0-1 的严重程度建议拿手机确认一次。
- **没验横屏**（844×390）。
- 200% 缩放只量了 720×450 / 1024×600 两个等价视口的溢出与遮挡，**没逐块截图复核**。
- 对比度按"逐层合成的纯色底"估算；页面有纸纹/渐变的地方真实对比可能再低 2–5%，
  但三端最差值也在 4:1 以上，不影响结论。
- 「今天」条与提醒条的文案是否该合并成一条（视觉上两者是"同一块的两行"），属于产品决定，本报告只记录。
