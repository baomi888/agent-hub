# 深色第一次实拍：16 张与四次假绿（2026-11-14）

> 前五批的验证全在同一个渠道里：同一台机器、同一个 Chromium 内核、同一批桌面视口。
> 方法本身（md5 前后比对、反证、字数统计）是硬的，但它证明的边界很窄 ——
> **只在浅色 + 桌面 Chromium 里成立**。深色一次没拍过，真机一次没上过。
>
> 这一批什么都不加，只做取证。结论是结构没问题，问题只有一档文字；
> 但比结论更值得记的是，取证脚本自己错了四次、假绿了三次。

## 一、怎么量的

`output/_dark_audit.mjs`，8 个页面 × 2 个视口（1440×900 / 390×844），共 16 张。
深色用三道保险钉住：`Emulation.setEmulatedMedia` 报 dark、`localStorage.theme='dark'`、
`html.classList.add('dark')` —— 少任何一道都可能拍到"深了一点的浅色"。

每页量四件事：

| 问题 | 判据 |
|---|---|
| 有没有横向溢出 | `scrollingElement.scrollWidth − clientWidth` |
| 层次还在不在 | 页面底 / 卡片 / 侧栏三层的计算背景色 |
| 正文够不够亮 | WCAG 相对亮度，正文 4.5:1、大字 3:1 |
| 边框有没有消失 | 描边色与身后背景的比值 < 1.25 |

**跟浅色那几批最大的不同**：这次不只看"有没有错"，还要求数字能复现 ——
1440 和 390 两轮跑出来的低对比度条目必须一致，不一致就说明脚本有随机性。

## 二、结论：结构全过，只有一档文字不够

16 张全部：横向溢出 0、边框消失 0、三层纸面色可分（`#1a1610` / `#211b11` / `#292217`）。

唯一的问题集中在 `--text-3`（当时 `#A08B66`）：

| 位置 | 字号 | 实测 | 底色 |
|---|---|---|---|
| 资料库侧栏「1 份资料 · 6 段」 | 11px | **3.83** | `#3F311B` |
| 论坛列表板块标签「站务公告」 | 11px | 4.15 | `#332D21` |
| 楼层「楼主」标 | 11px | 4.15 | `#5A421D` |
| 帖子时间戳「今天 10:16」 | 11–13px | 4.18 | `#382B16` |
| 设置页提示里的 `code` 片段 | 13px | 4.19 | `#332C20` |

`tokens.css` 原来的注释写着「`#A08B66` 在最亮的卡片底上有 4.78:1」——
那个 4.78 只对 `--step-2`(`#292217`) 成立。**深色实际不止三层**：
选中态、公告条、帖子头、code 片段各自把底抬到比 step-2 更亮的位置，
注释里的前提本身就不成立，值自然也就不够。

这不是"算错了"，是**取样不够**：拿三层里的最亮一层当上界，而实际有五六层。

## 三、修法：一个令牌 + 一处标签 + 一处列宽

1. `--text-3` → `#B49E7E`。按「深色下真实出现过的每一层」取最低值算：
   step-2 6.09 / kbp-read 5.72 / code 5.34 / 帖子头 5.33 / 选中态 4.88。
   最低 4.88 仍有余量，与 `--text-2`(`#c9b58a`) 差 1.29，三级文字没有塌成二级。
2. 「楼主」标不再用「亮金字 + 淡金底」这种同色系组合。浅色是淡金底 + 深棕字（5.5:1），
   换到深色后 `--accent-ink` 变成亮金，底还是金 alpha，成了自己压自己。
   改成一道内描边 + 次级文字色，底色从 `#5A421D` 退回父层 `#382B16`，6.86:1。
   顺带把语义分开：**实心金牌只留给「管理员」那种权限身份**，
   「楼主」是位置标注，不该和权限徽章抢视线。
   用 `inset` 阴影不用 `border` —— 边框会把小药丸撑高 2px，和旁边的标错基线。
3. 底部 tab 列宽 `repeat(5, minmax(0, 1fr))` → `minmax(0, 128px)` + 居中。
   390 下仍是各 76px（不变），但 640–900 这段（大手机横屏、小平板竖屏）
   原本会把五个 tab 摊成各 180px，一条横跨 899px 的底栏，看着不像导航像横幅。
   背景和上边框仍铺满全宽，只有内容居中 —— 整条 `max-width` 会在两侧露出页面底，
   底部那条线突然断掉。

## 四、四次假绿，三次是我自己的

这一节才是这一批真正的产出。**取证脚本比被测代码更容易骗人**，因为它出错时
输出的是"通过"。

1. **用学号签令牌**：`users.id` 是 32 位 hex，不是学号。签出来的令牌被判
   「账号不存在」，8 页里 5 页停在登录页 —— 而登录页同样满足"无溢出、无遮罩"，
   第一轮跑出来**全绿**。假绿的根源不在代码，在身份根本没进去。
   现在每页都断言 `.auth-stage / .auth-card` 不存在，出现就打 `!! GATE`。
2. **`setCookie` 给 `url` 不给 `domain`**：页面还停在 `about:blank` 时，cookie 会
   "成功"写进一个之后用不上的分区。必须先落到站点再写。
3. **`backgroundColor` 透明 ≠ 没有背景**：`.kb-role` 的金色渐变在
   `background-image` 里。第一版据此算出「管理员」标 `1.15:1` 的"严重事故"，
   实际是深墨字压金渐变，约 6:1，和源码注释完全一致。**这是假红，也是假绿的另一面** ——
   如果它恰好算出一个正常值，我就会以为那个位置验过了。
4. **浏览器错误页也会「加载完成」**：第一版 `/dashboard` 拍到的其实是 Edge 的
   「This page couldn't load」，那 3 条低对比度是错误页自己的。现在靠
   「标题里有没有站名」识别，并重导航一次。

还有一个方法上的补充：**半透明背景必须做 alpha 合成**。
`rgba(ink,.06)` 这种叠层如果当成实色，对比度一律算乐观。
修完之后 1440 与 390 两轮的读数逐条一致，才开始信这些数字。

## 五、顺手纠正一条错误记忆

记忆里长期写着「平板 900–1024 无导航」。实测七个宽度
（899/901/960/1024/1100/1279/1281）后发现：

| 宽度 | 控制台 | 论坛 |
|---|---|---|
| 899 | 侧栏 `display:none`，底部 tab 51px | 左栏 200px |
| 901–1279 | 侧栏 `display:block` 196px，13 个链接 | 左栏 200px，右栏隐藏 |
| 1281 | 同上 | 左栏 208px + 右栏 296px |

**900–1024 一直都有导航**，七个宽度横向溢出全是 0。那句话要么是当初记错了页面，
要么把"没专门调过"记成了"没有"。已从 MEMORY 改掉。

真正的问题是那段宽度**没有任何针对性断点**，所以没人验过 ——
顺带就验出了 tab 被拉成 180px 那一条。

## 六、反证时踩到的"假红"

反证脚本第一版用 `returncode != 0` 判红。结果 4/4 全"红"，
但每一条的输出都是 `no tests ran` —— 节点 id 拼成了 `test_test_xxx`，
pytest 找不到测试返回 5，**一样是非零**。

**假红比假绿更危险**，因为它长得就像反证成功。改成必须看到输出里有
`1 failed` 才算红，同时校验三个 CSS 逐字节还原。修正后 4/4 真红。
