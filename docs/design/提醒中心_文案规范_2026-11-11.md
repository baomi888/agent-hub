# 提醒中心 · 用户文案规范（2026-11-11）

> 适用：`frontend/src/app/(console)/reminders/page.tsx`、
> `frontend/src/components/reminders/AiCaptureDrawer.tsx`，以及后续从提醒中心拆出去的待办子产品。
>
> 这份文档只解决一件事：**用户看得懂，并且知道下一步点哪里。**
> 功能边界、数据模型、接口约束仍以 `docs/design/提醒中心_AI整理_v12/README.md` 为准。

---

## 1. 一句话原则

用户不需要理解提醒是怎么发出去的，只需要在三秒内回答：

1. **什么时候提醒我？**
2. **提醒我做什么？**
3. **没提醒时，是为什么、我现在能做什么？**

凡是回答不了这三件事的句子，都是要删的句子。

---

## 2. 用户可见词表

| 用 | 不用 | 原因 |
|---|---|---|
| 提醒 / 提醒你 | 响 / 会响 / 不会响 / 响过 | “响”是闹钟的动作，不是通知的动作 |
| 通知 | 推送 / 送达 / 触发 | “推送”是通道名，“送达”是物流词 |
| 提醒时间 | 什么时候响 / 触发窗口 | 用户只关心几点 |
| 免打扰时间 | 静默时段 | “静默”是系统状态，不是用户状态 |
| 提醒记录 | 送达记录 / 最近送达 | 用户想知道“提醒过没有” |
| 哪些功能会提醒你 | 来源 / 来源已关 | “来源”是数据字段名 |
| 定时提醒 | 日程 / 日程提醒 | 这个模块里的“日程”其实是固定时间提醒 |
| 条（提醒的量词） | 个（提醒的量词） | 和“条待办”统一，避免一会儿条一会儿个 |
| 没发出去 | 发送失败 / 失败 | 说结果，不说系统动作 |
| 当时设备不在线 | 错过触发窗口 | 说用户能理解的原因 |

### 2.1 必须改写的四句话

| 旧写法 | 新写法 |
|---|---|
| 什么时候响？ | 什么时候提醒你？ |
| 到点不会响。 | 到时间不会提醒你。 |
| 最近送达 | 提醒记录 |
| 来源已关 | 这个功能已关闭 |

## 3. 三条写作规则

### 3.1 先写后果，再写原因

- ✅ `只设截止时间，不会收到提醒。想被提醒，请打开「提醒我」。`
- ❌ `截止时间与提醒时间是两个字段。`

用户不是来读数据模型的，是来判断“我会不会收到提醒”。

### 3.2 一句话只出现一个动作

- ✅ `点下方「补上时间」，设好后才会提醒你。`
- ❌ `缺少时间，可补充后重试或取消勾选。`

一句话里给两个动作，用户会先愣一下；愣一下就会退出去。

### 3.3 不写开发者旁白

界面里禁止出现：

- 后端、服务端、接口、字段、落库；
- 触发、调度、窗口、合并策略；
- “这条没有完成语义”“来源只读”这类产品经理解释；
- “我听到 / 我先把 / 我建议”这类人格化旁白。

这些可以留在代码注释里，不能留在用户眼前。

## 5. 验收清单

### 5.1 静态检查

在 `page.tsx` 和 `AiCaptureDrawer.tsx` 的用户可见字符串里搜索，以下词必须为 0：

```text
响   推送   送达   静默   来源   日程   触发   后端   服务端
```

注释里出现不算，但 JSX、`showToast`、`aria-label`、`title`、`placeholder` 里出现就算不通过。

### 5.2 交互检查

- 只设截止时间：保存后卡片上必须能看到 `不提醒`，且不会产生一条提醒。
- 打开「提醒我」：底部预览必须同时出现截止时间和提醒时间。
- 关掉课表 / 打卡等功能：它安排的提醒要一起停；自己建的待办和提醒不受影响。
- 免打扰时间里到点：记录显示 `没提醒 · 免打扰时间`，不能事后补发。
- AI 整理没整理出时间：那一行必须有 `补上时间`，点开能直接选时间。
- AI 整理部分失败：失败项留在原处，不能关抽屉，也不能弹“全部成功”。

### 5.3 布局检查

- 390 / 360 宽度：页面无横向滚动；主按钮文字不溢出、不压住次按钮。
- 390 宽度抽屉：`加入 N 条，并设 M 条提醒` 单行可读；读不全就缩字号前先减字。
- 1440 宽度：设置 tab 的长句不超过卡片宽度，不出现孤字换行。

### 5.4 已有测试

```bash

venv\Scripts\python.exe -m pytest tests/test_reminders_ui.py tests/test_campus_sync_wiring.py -q --junitxml=output/reminders_copy.xml
```

`pytest` 的退出码在本机不可信，必须读 `output/reminders_copy.xml` 的 `tests / failures / errors` 三项。

## 6. 不要动的边界

- `due_at` 与 `remind_at` 仍然是两个字段；只设截止不会提醒。
- 待办 `○` 可以完成；定时提醒 `◇` 不能完成，只能推迟 / 暂停 / 关功能。
- 课表、番茄钟、委托、打卡、四六级、单词、DDL、系统回顾这些联动入口一个都不能删。
- 不做假语音、假进度、假撤销。
