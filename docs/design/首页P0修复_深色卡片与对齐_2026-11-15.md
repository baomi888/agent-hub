# 首页 P0 三条修复（深色卡片层级 / 第二组形态 / 分组标题对齐）

**日期**：2026-11-15　**范围**：`tokens.css`（深色 `--step-2`）、`welcome.css`（两处）
**依据**：`首页评审_字体回退与排版_2026-11-15.md` 的 P0-1 / P0-2 / P0-3
**结论**：三条全部落地，三端实测达标；P0-1 的**原因与评审报告猜的不一样**（不是"没分档"，
是纸面噪点吃掉了整级阶梯），改的是值而不是新造一套令牌。

---

## 一、P0-1 深色「卡片 / 输入框 / 纸底」同色

### 报告说的是什么，实测是什么

报告给的现象是对的：深色下卡内 `rgb(44,37,26)`、纸底 `rgb(43,36,26)`，只差 1 阶。
但它给的原因（"深色只定了三级、相邻档不够"）不成立 —— 深色令牌的阶梯其实和浅色一样宽：

| | 令牌值 | 计算值差 |
|---|---|---|
| 浅色 | step-1 `#F5F0E1` → step-2 `#FDFAF2` | 8/255 |
| 深色 | step-1 `#211B11` → step-2 `#292217` | 8/255 |

真原因是**噪点只加在一层上**：

- `main.workbench-main` 的背景是 `底色 + var(--noise)`；深色那层噪点是**亮暖色**（4% alpha），
  把纸从 `33,27,17` 抬到 `38,32,22`（+5/255）。
- 卡片 / 输入框是不透明色块，**把噪点盖住了**，所以它们是"没被提亮的纸 + 8"。
- 两者相抵，渲染出来只剩 3/255（`ΔL* 0.6`），肉眼就是"只有一条 1px 描边"。
- 浅色没有这个问题：浅色的噪点是**深色** alpha，只把纸压暗 1–2 阶，阶梯反而更明显。

这条差点被当成"令牌没分档"去新造一套 `--panel-1/--panel-2`。造了就成了两套阶梯
（而且新令牌同样会被噪点吃掉，问题不会消失）。

### 改法

`tokens.css` 深色 `--step-2`：`#292217`（L\* 13.7）→ `#362E1D`（L\* 19.3）。

只动一个值、只动深色。所有"抬起的表面"（首页卡、输入框、论坛帖卡、控制台卡、
开关滑块）都吃这一档，不会出现"首页修好了别处还是糊的"。

为什么不干脆把噪点改成深色：那等于把整站深色的纸底压暗 5/255，
观感是"深色变黑"，属于另一个决定了；而"抬起的一层要比纸亮"是这套主题的基本前提，
用令牌保证比用纹理去凑更稳。

### 实测（渲染像素，中位色，三端 × 两主题）

| 视口 | 主题 | 纸底（卡后） | 卡内 | ΔL\*（改前 → 改后） |
|---|---|---|---|---|
| 1440 | 深 | 39,33,23 (L\*13.1) | 54,46,29 (L\*19.3) | **+0.6 → +6.2** |
| 768 | 深 | 39,32,22 (L\*12.7) | 54,46,29 | **+6.6** |
| 390 | 深 | 38,32,22 (L\*12.6) | 54,46,29 | **+6.7** |
| 1440 | 浅 | 244,239,223 (L\*94.4) | 253,250,242 (L\*98.3) | +3.9（未动） |

深色给的差值比浅色大（+6 vs +3.9）：深底上的小差值更难辨，需要多给一点。
`--text-3` 压在新卡片上是 **5.20:1**（AA 4.5），没为了"抬起来"牺牲小字可读性。

## 二、P0-2 第二组「降级」后读成禁用

### 现象

一组：`bg #FDFAF2` + 投影；二组：`bg transparent` + 无投影；**边框两者完全相同**
（`rgba(61,47,26,.1)`），尺寸圆角也完全相同（115.3×72.6 / 12px）。
同框同尺寸只差"有没有填充"，在纸纹底上不读"次要"，读"未启用"。

### 改法：改成"无框平铺"，不是把填充调浅

报告给了 (a) 降一档填充 / (b) 去框列表项两条路，选 (b)：

- (a) 在深色下会失效 —— `--fill-2` 是暖白 9% alpha，铺在深色纸上会抬到和抬起卡几乎一样的亮度，
  两组又糊在一起；
- (b) 的层级由**形态**讲（抬起 vs 平铺），与主题无关，深浅两套都成立。

具体：`.welcome-daily.is-soft .entry-card` 去掉底色、把边框设成 `transparent`
（保留 1px 占位，避免 hover 出现时跳 1px）、去掉投影；图标底衬保留 `--fill-2`
（没有它这一组就只剩三行漂浮的文字）；hover 沿用统一的"金描边 + 淡底"，但**不抬起**
（它本来就贴在纸上）。

三端实测：二组卡内 = 纸底（浅 244,240,225 / 深 38,32,22），不再有"半个卡片"的观感；
一组仍是 253,250,242 / 54,46,29。

## 三、P0-3 分组标题没落在任何一条对齐轴上

改前（1440）：标题文字左缘 **402**，卡片网格左缘 **366**，恒定内缩 **36px**
= `.welcome .eyebrow::before` 的 26px 短线 + 10px gap。那条短线本来是给 Hero 眉题
「苞米地 · 智能体工作台」做页眉装饰的（两侧对称才成立），分区标题里只剩左边一条，
右边接的是 `.rule`，于是左右线长 26 vs 467，"像没画完"。

改法：在 `.welcome-section-head` 这一档把眉题的 `::before/::after` 收掉
（`display: none`），标题直接压在 `--chat-px` 这条轴上，右侧 `.rule` 从文字尾延伸。

改后（三端两主题一致）：标题文字左缘 = 卡片网格左缘（1440：366 = 366），
`.rule` 从 514 起延伸到 1054。

用令牌值会高估 5/255，正是上一版把 `#292217` 判成"够用"的原因。
`DARK_BASES["step-2 卡片"]` 也同步从 `(41,34,23)` 改成 `(54,46,29)` ——
不跟着改，`--text-3` 那条守卫量的就是一个已经不存在的层。

**反证 3/3 真红**（改回旧值后逐条跑，跑完 `shutil.copy2` 还原，sha256 与备份逐字节一致）：

1. `--step-2` 退回 `#292217` → 卡片层级那条红（ΔL\* 0.6 < 5）；
2. 删掉分区标题的 `display:none` 块 → 对齐那条红；
3. 二组恢复 `border-color: transparent` 一行之下的边框 → 形态那条红。

## 五、没验 / 已知缺口

- 全部读数仍是 **headless Chromium**，没有真机。深色噪点的提亮量在不同屏幕亮度下
  主观差异较大，`#362E1D` 建议在手机上再看一眼（如果偏亮，一次只回调 2–3 个 16 进制值，
  别直接退回 `#292217`）。
- 没验横屏（844×390）。
- 二组从"有框卡片"变"无框图标行"，**是可点性的一次权衡**：桌面有右箭头、手机靠图标底衬
  与排布密度提示可点，但触屏上没有 hover 兜底。如果真机上被反馈"不知道能点"，
  回退方案是只给手机档加回 `--fill-3` 淡底（保留无边框）。
- 深色 `--step-2` 是全局值，顺带改了论坛 / 公开知识库 / 每日总结 / 设置四页的卡片亮度；
  已逐页截图确认无溢出、无新糊区，但**只看了这四个页面**，其余控制台页未逐页复核。
