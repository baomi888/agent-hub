# 去 AI 味与引导性验收

> 配套：`README.md`、`视觉基线_v13.md`、`../../提醒中心UI对标与优化方案_2026-11-10.md` §19
> 用途：WorkBuddy 开发 AI 整理时，按这份清单自检；P0 未过，不允许进入确认写库阶段。

---

## 1. 方向纠正

不是“让 AI 更像一个人”，而是：

> **让 AI 变成安静的能力，让界面像一个可靠的整理工具。**

保留：

- 底部一句话输入；
- 自然语言拆成待办/提醒；
- 用户确认后才写库；
- 原话可回看、可改。

去掉：

- AI 头像、聊天气泡、拟人化旁白；
- “我听到 / 我拿不准 / 我在整理 / 我建议”；
- 到处 spark、AI 光晕、机器人感；
- 为了让用户觉得聪明而多问、多解释。

一句话标准：

> 用户不读说明书，也知道现在在哪、整理出了什么、下一步点什么、点下去会发生什么。

### 1.1 用户可见词表（2026-11-11 定稿）

用户面对的是「提醒」，不是调度系统。界面上一律用左边这列，右边这列只许留在代码和注释里：

| 用 | 不用 |
|---|---|
| 提醒 / 提醒你 | 响 / 会响 / 不会响 / 响过 |
| 通知 | 推送 / 送达 / 触发 |
| 提醒时间 | 什么时候响 / 触发窗口 |
| 免打扰时间 | 静默时段 |
| 提醒记录 | 送达记录 / 最近送达 |
| 哪些功能会提醒你 | 来源 / 来源已关 |
| 定时提醒 | 日程 / 日程提醒 |
| 条（提醒的量词） | 个（提醒的量词） |

三条硬规则：

1. **先写后果，再写原因。** 「只设截止时间，不会收到提醒」比「截止不等于提醒」有用。
2. **一句话里只出现一个动作。** 「点下方『补上时间』，设好后才会提醒你」——用户知道下一步点哪。
3. **不写开发者旁白。** 「后端不收」「服务端未配置」「触发窗口」「来源语义」都不许出现在界面上。

## 2. 什么叫“AI 味”

以下都是 AI 味，不是高级感：

- 助手头像 + 气泡尾巴 + “今天想先记什么？”的聊天开场；
- “我在整理成待办…”“我先把听到的排好了”“我听到 4 件事”；
- 每屏都有 spark，每个按钮都像 AI 功能；
- “AI 正在思考”“智能识别”“已为你分析”；
- 假进度、假打字机、假记忆；
- 过度解释“我为什么这样理解”；
- 为了显得聪明，把简单确认做成三段式向导页（顶部一条轻量步骤提示不算）；
- 紫色渐变、蓝紫光晕、玻璃拟态、机器人图标。

去 AI 味不是变冷，而是：

> 少表演，多把事情说清楚。

## 3. 去 AI 味的 6 条规则

### 3.1 去人格化

- 过程叙述不用第一人称。
- 用“已整理 / 正在整理 / 需要确认 / 将加入”，不用“我听到 / 我拿不准”。
- 一屏内“我”最多出现 1 次，而且只在必要的人文提示里，例如“说错也没关系，整理完可以改”。

### 3.2 去聊天气泡

- 保留底部输入，但上方不是“AI 聊天”，而是“整理区”。
- 输入态不要 AI 头像 + 问候气泡；用一块简洁说明：

```text
一句话整理
自动拆成待办和提醒；确认后才会加入。
例：明天交高数作业，周五社团开会，每晚背单词
```

- 用户原话用“你说的”引用卡，不用深墨聊天气泡。
- 结果区用结构化列表，不用“AI 回复气泡”。

### 3.3 去装饰

- 整个抽屉最多 1 个 spark，放在入口按钮上。
- 抽屉内不再重复“AI 整理”字样。
- 不用渐变、光晕、玻璃拟态、机器人头像。
- 不用 emoji 代替图标。

### 3.4 去表演

- 不展示“思考过程”。
- 只展示状态：`正在整理…` / `已整理 4 条` / `正在加入…`。
- 没有真实阶段，就不要做三段式假进度。
- 结果不要逐字打字机，直接出现；最多 40–60ms 的淡入。

### 3.5 去过度承诺

- 不说“我懂你”“我建议”“我猜”。
- 说事实：“整理出 4 条，2 条需要确认。”
- 不确定就写“需要确认”，不写“我拿不准”。
- 没有历史数据，不写“根据你的习惯”。

### 3.6 保留温度，但不谄媚

可以保留：

- `说错也没关系，整理完可以改。`
- `只设截止不会响，要提醒请单独设置。`
- `到点会提醒你。`

不要：

- `太棒了！我已经帮你搞定啦～`
- `放心交给我吧！`
- `我懂你的意思！`

## 4. 引导性的 6 条规则

### 4.1 三步心智模型

抽屉顶部用一条很轻的步骤条：

```text
1 说一句   →   2 确认   →   3 加入
```

- 当前步骤用墨色，其余用 `--text-3`；
- 不要做成大 wizard，不要每步一个页面；
- 它只负责告诉用户“现在在哪、还差几步”。

### 4.2 每个状态只回答三件事

| 问题 | 必须出现在哪里 |
|---|---|
| 我在哪 | 顶部步骤条 + 状态标题 |
| 刚发生了什么 | 状态标题下的一句事实 |
| 下一步做什么 | 一个主按钮 + 一句后果 |

示例：

```text
确认这 4 条
2 条待办、2 条提醒；2 条还要补信息。
[先看 2 条要确认 ↓]       [加入 4 条，并设 3 条提醒]
```

### 4.3 每屏只有一个主行动

| 状态 | 主行动 |
|---|---|
| 输入态 | `整理` |
| 结果态 | `加入 N 条，并设 M 条提醒` |
| 0 条 | `换个说法` |
| 失败 | `再试一次` |
| 部分失败 | `重试失败的 N 条` |

次行动只能是文字级或 ghost，不能和主按钮同样重。

### 4.4 把注意力带到最需要的地方

- 有需要确认的条目时，结果区顶部出现一条可点击提示：
  `先看 2 条要确认 ↓`
- 点它滚到第一条需确认，并展开问题。
- 不要只写“2 条要确认”然后让用户自己找。
- 需确认条目用左侧金色细线 + `需要确认` 标签，不用大面积黄色。

### 4.5 说清楚点下去的后果

- 按钮不能只写 `加入 4 条`。
- 有提醒：`加入 4 条，并设 3 条提醒`。
- 无提醒：`加入 4 条，不提醒`。
- 全不选：按钮 disabled + `至少选一条，才能加入`。
- 只设截止：结果里必须出现 `只设截止时间，不会收到提醒`。
- 加入后：`已加入 4 条，其中 3 条会提醒你。`

### 4.6 每个错误都有出口

| 状态 | 必须给 |
|---|---|
| 解析失败 | `再试一次` + `改用快速添加` + 原文保留 |
| 0 条 | `换个说法` + `先记成一条待办` |
| 部分失败 | `重试失败的 N 条` + 已成功数量 |
| 429 | `约 30 秒后再试` + 原文保留 |
| 401 | 回登录/刷新，不留空白抽屉 |

## 5. v12 → v13 的具体改法

### 5.1 抽屉头

现在：

```text
✦ AI 整理 · 新的一件
说给我听
不用组织语言，说乱了也能拆
```

改成：

```text
一句话整理
自动拆成待办和提醒；确认后才会加入。
1 说一句  →  2 确认  →  3 加入
```

注意：

- 入口按钮仍然可以叫 `AI 整理`，用户需要知道这是 AI 能力；
- 抽屉内部不再反复出现“AI”；
- 不在抽屉里再放头像。

### 5.2 输入态

删掉：

- `.chat-avatar`
- `.chat-bubble`
- 问候语“今天想先记什么？”

换成一块普通说明：

```text
一句话整理
自动拆成待办和提醒；确认后才会加入。

例：明天交高数作业，周五社团开会，每晚背单词
```

底部 composer 保留，但 placeholder 改成具体例句：

```text
输入要做的事，例如：明天下午 3 点交高数作业
```

### 5.3 整理中

现在：

```text
我在整理成待办…
```

改成：

```text
正在整理…
```

- 不要 AI 头像；
- 不要把用户原话做成深墨聊天气泡；
- 用“你说的”引用卡：左侧金色细线 + 原文 + 小字 `刚刚`。

### 5.4 结果态

现在：

```text
✦ AI 整理 · 已排好
我先把听到的排好了
看看有没有听错；确认后才会加入，不会自动提醒。
我听到 4 件事
```

改成：

```text
确认这 4 条
2 条待办、2 个日程；2 条需要补充信息。
[4 条 · 2 条需确认 · 3 个提醒]
[先处理 2 条需确认 ↓]
```

原话卡标题：

```text
你说的
```

不要：

```text
我听到 / 我先把听到的排好了 / 点编号回看原话
```

可以：

```text
点编号查看原句
```

### 5.5 条目状态

每条结果左上角给一个状态：

- `可直接加入`：字段完整，无歧义；
- `需要确认`：时间/周期/对象不确定；
- `缺少时间`：只有标题，没有日期。

不要用“我拿不准”。用“需要确认”。

### 5.6 提交按钮

现在：

```text
加入 4 条
```

改成：

```text
加入 4 条，设 3 个提醒
```

无提醒：

```text
加入 4 条，不设提醒
```

### 5.7 成功反馈

现在：

```text
排好了 4 件，该提醒的到点我会叫你
```

改成：

```text
已加入 4 条，3 个提醒已设置。
下一件：明天 23:59 交高数作业。
```

保留温度，但不要“我会叫你”这种拟人化承诺。

## 6. 状态矩阵（WorkBuddy 必须逐格实现）

| 状态 | 必须出现 | 主行动 | 禁止 |
|---|---|---|---|
| 首次打开 | 一句话说明、具体示例、步骤条、底部输入 | `整理` | AI 头像、问候气泡、空白页 |
| 输入中 | 可编辑、示例可点填、按钮状态清楚 | `整理` | 点示例自动提交 |
| 整理中 | 你说的引用卡、`正在整理…`、输入禁用 | 等待 | 假进度、假阶段、AI 旁白 |

| 解析失败 | 错误说明、原文保留、两种出口 | `再试一次` | 清空输入、静默失败 |
| 提交中 | 按钮 loading、防双击、列表锁定 | 等待 | 重复写库 |
| 部分失败 | `已加入 X 条，Y 条失败`、失败项保留 | `重试失败的 Y 条` | 假装全成功 |
| 成功 | toast 说清条数/提醒数/下一件 | 关闭/看列表 | 只说“操作成功” |
| 全不选 | 按钮 disabled、辅助文案 | 至少选一条 | 允许提交空选择 |

## 8. P0 / P1 / P2

### P0（不过不能进 Phase C）

- 删掉 AI 头像、问候气泡、第一人称旁白。
- 抽屉头改成“一句话整理 + 三步骤 + 一句说明”。
- 结果标题改成“确认这 N 条”，不再用“我先把听到的排好了”。
- 有需确认时，结果区顶部有“先处理 N 条需确认 ↓”。
- 提交按钮写清条数和提醒数。
- 0 条 / 失败 / 部分失败 / 全不选有出口。
- placeholder 是具体例句。
- 整屏“我”最多 1 次，spark 最多 1 个。

### P1（第一版最好有）

- 每条结果的“依据是什么？”默认收起。
- 成功 toast 带“下一件”。
- 示例按意图分组（作业 / 开会 / 每天）。
- 整理中先出现“你说的”引用卡。
- 结果条目 40–60ms 依次淡入，reduced-motion 关闭。

### P2（后续）

- 最近 3 条输入，方便复用（这是工具能力，不是 AI 人格）；
- 提交后引导“要不要顺手设个提醒”；
- 语音转写后的“文字确认”。

## 9. 评分表（WorkBuddy 交付时自评）

每项 0–3 分：

| 维度 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 去人格化 | 满屏“我” | 有头像/气泡 | 偶尔第一人称 | 事实叙述，最多 1 次“我” |
| 状态清晰 | 不知道在哪 | 有标题 | 标题 + 说明 | 标题 + 说明 + 步骤条 |
| 下一步明确 | 要自己找 | 有主按钮 | 主按钮 + 后果 | 主按钮 + 后果 + 注意力路由 |
| 后果清晰 | 只写加入 N 条 | 有条数 | 有条数 + 提醒数 | 还说明只设截止不会响 |
| 异常恢复 | 空白/报错 | 有 toast | 有重试 | 两种出口 + 原文保留 |
| 克制 | 花哨 | 有点多 | 基本克制 | 安静、清楚、有温度 |

通过线：

- 平均 ≥ 2.5；
- 不允许任何一项 0 或 1；
- P0 全部满足。

WorkBuddy 交付时必须附：

1. 11 个状态的截图（覆盖状态矩阵 11 行）；
2. 自评分表；
3. 文案 deck 对照（哪些用了、哪些改了、为什么）；
4. 负向断言结果。

## 10. 审阅时问 WorkBuddy 的 5 个问题

1. 把“AI”两个字删掉，这个界面还成立吗？它像一个正常工具吗？
2. 用户第一次打开，不看文档，能不能在 5 秒内说出下一步？
3. 界面有没有在“表演聪明”？哪一句是多余的？
4. 点“加入 N 条”之前，用户知不知道会设几个提醒？
5. 解析失败/0 条/部分失败时，用户有没有明确的下一步？

答不上来，就还没到“去 AI 味、强引导”。
