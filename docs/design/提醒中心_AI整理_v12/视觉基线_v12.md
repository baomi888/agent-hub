## 1. 这一版解决什么

v10 把“开始整理”做成了一个中央大麦克风表单：用户打开抽屉，先看到一个大圆盘和输入框，像在填表，不像在说话。

v12 改成聊天结构：

1. 上面是已经发生的对话或整理结果；
2. 说话和文字输入永远固定在底部；
3. 用户说完、点发送后，先出现“我说的原话”，再出现“我在整理成待办…”，最后才进入结果态；
4. 结果态是下一步，不是另一个页面，仍然沿用同一个抽屉壳和同一套标题/底栏切换。

一句话：**输入不是页面中央的表单，而是对话底部一直可用的入口。**

## 2. 结构

抽屉分三层：

| 层 | 内容 | 约束 |
|---|---|---|
| 顶部 | `AI 整理 · 新的一件` + 标题 + 副标题 + 关闭 | 固定，不随对话滚动 |
| 对话画布 | 日期分隔、AI 问候、今日上下文、空态提示、用户气泡、整理中气泡 | 独立滚动，底部留出 composer 空间 |
| 底部 dock | 示例句、信任说明、麦克风 + 输入框 + 发送、按住提示 | 固定在抽屉底部，不被对话内容顶走 |

关键选择：

- 标题从“今天想先记什么？”改成“说给我听”，避免和问候气泡重复。
- 问候气泡承担第一句话，不再让标题和气泡说同一件事。
- 对话画布加极淡的横线纸纹，空态不再像一块没加载完的空白。
- 空态中间只放一句 `说完，整理好的安排会出现在这里`，不塞教程卡、模板卡。

## 3. 状态机

```text
打开抽屉 → 输入态
输入态 → 输入文字 / 点示例句 / 按住麦克风
输入文字 → Enter 或点发送 → 用户气泡 + 整理中
按住麦克风 → 松开 → 用户气泡（语音 00:12）+ 整理中
整理中 760ms → 结果态
结果态 → 重新说 → 输入态（清空）
结果态 → 改文字 → 输入态（填入原话）
结果态 → 加入 N 条 → toast + 关闭
再次打开 → 输入态（清空）
```

## 4. 交互细节

### 4.1 文字输入

- 真实 `<input>`，不是占位 div；可以输入、可以回车。
- Enter 触发整理；中文输入法 composing 时不触发。
- 360/390 下 `font-size: 16px`，避免 iOS Safari 聚焦放大。
- 输入框为空时点发送，用示例原话走完整流程，保证空态也能演示。
- 示例句点击只填入输入框并聚焦，不自动提交。

### 4.2 按住说话

- `pointerdown` 进入 `.is-listening`：麦克风变金、输入区出现金色描边、提示改成“正在听… 松开结束”。
- `pointerup` 退出录音态并开始整理。
- 用户气泡 meta 显示 `语音 00:12 · 刚刚`，图标是麦克风。
- 这是效果图状态，不是真实录音/转写；真实实现必须补录音中、转写中、失败、取消四种状态。

### 4.3 发送后的连续性

- 用户原话先以深墨气泡出现在右下，靠近 composer。
- 下方紧跟 AI 的 `我在整理成待办…` 气泡，三点跳动。
- 760ms 后才切到结果态；切换时原话卡、4 条结果、底部确认栏一起出现。
- 用户不会看到“点一下直接跳到另一个表单页”。

### 4.4 结果态

- 继续沿用 v9 的验收结果：原话高亮、编号回看、改口、逐条勾选、追问、底部确认。
- 顶部标题改成 `我先把听到的排好了`，kicker 改成 `AI 整理 · 已排好`。
- 底部由 composer 换成确认栏：`已选 N 条 · N 条会提醒` + `全不选` + `加入 N 条`。

## 5. 响应式

| 宽度 | 结果 |
|---|---|
| 1440 | 抽屉 520px；输入 dock 贴底；对话画布有纸纹和空态提示，不再像空白页 |
| 720 | 抽屉全宽底部结构不变；composer 仍然贴底 |
| 390 | 对话、示例句、composer、提示完整可见；无横向滚动 |
| 360 | 示例句换两行，composer 仍完整；输入字号 16px；无横向滚动 |

实测：

- 1440：`scrollWidth 1440 / innerWidth 1440`，抽屉 `520px`，右边缘 `1440`。
- 390：`scrollWidth 390 / innerWidth 390`，抽屉 `390px`，右边缘 `390`。
- 360：`scrollWidth 360 / innerWidth 360`，抽屉 `360px`，右边缘 `360`。

## 7. 负向断言

- 打开抽屉：只能看到输入态；结果态和底栏必须 `hidden`。
- 发送后 200ms：输入态不能已经消失；必须还能看到用户气泡和“整理中”。
- 760ms 前不能出现结果列表；760ms 后才允许切换。
- 点示例句：只填输入框，不能自动开始整理。
- 点发送但输入为空：必须走完整示例流程，不能停在原地无反馈。
- 结果态取消一条：计数、提醒数、按钮文案必须同时变。
- 全不选：主按钮 `disabled`，点击不能关闭抽屉。
- 重开抽屉：标题必须是 `说给我听`，输入值必须为空，用户气泡必须隐藏。
- 360 下：composer、示例句、底部提示不能横向溢出；输入框字号不能小于 16px。

## 8. 已知边界

- 这是交互效果图，不是真实语音识别；按住/松开只做视觉与状态演示。
- 文字输入会驱动用户气泡和过渡，但结果列表仍是固定样例；真实实现由后端返回解析结果。
- 结果态仍是静态样例数据，编号回看、chips 编辑、勾选计数是交互演示，不写库。
- 关闭抽屉会清空输入；真实产品建议保留草稿或明确提示“已丢弃”。

## 9. 不要做

- 不要再把麦克风做成页面中央的大圆盘；输入必须在底部。
- 不要让标题和问候气泡说同一句话。
- 不要把示例句做成自动提交；用户仍然要能改。
- 不要在空态再塞“最近记录 / 热门模板 / 使用教程”三块卡。
- 不要把结果态做成另一个独立页面；它必须像同一段对话的下一步。
- 不要假装真实语音识别；没有录音状态就不要显示“正在录音”。
- 不要自动写库；AI 只能 propose，用户确认后才 commit。
