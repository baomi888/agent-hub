# 「更多」面板：看板入口与二级导航空旷（2026-11-15 第 10 批）

> 用户报两件事：**管理员账号下「数据面板」再次无法显示**；**「更多」这个二级导航显示过于空旷**。
> 两件是同一个根 —— `lib/nav.ts` 里 `/dashboard` 被标了 `desktopOnly: true`，
> 而 `mobileMoreNav()` 正是靠这个字段过滤的。

## 一、数据面板「无法显示」：页面和接口都是好的，缺的只是一个入口

### 1.1 先排除整条链路（全部实测）

| 怀疑对象 | 怎么验 | 结果 |
| --- | --- | --- |
| 后端挂了 | `GET /api/admin/overview`（管理员 Cookie） | **200** |
| 权限没了 | `GET /api/auth/me` | `"is_admin": true`，`unlimited: true` |
| 管理员配置丢了 | 线上 `.env` + `quota._is_admin(uid)` | `ADMIN_UIDS=9630…5a74a` 在，返回 `True` |
| 账号被停用 | `users.status` | `1`（正常），171 个账号里 uid 对得上 |
| 页面 404 | 390×844 直接开 `/dashboard` | 渲染出「数据看板」，**13 张卡**，横向溢出 **0** |
| 前端构建坏了 | `BUILD_ID` / 服务启动时间 | 都在，静态资源 15 个全 200 |

到这一步只剩一种可能：**进不去**。

### 1.2 根因

`frontend/src/lib/nav.ts`：

```ts
{ href: "/dashboard", icon: "dashboard", label: "看板", adminOnly: true, desktopOnly: true }
```

`mobileMoreNav()` 的实现是 `visibleNav(isAdmin).filter(it => !it.desktopOnly && no mobileTab)`。
`desktopOnly` 的语义在接口注释里写得很清楚：**「桌面有、移动端彻底不出现（连「更多」里也没有）」**。

实测手机「更多」面板（390 宽，管理员身份）只有 4 项：
`资料库 / 待办 / 工具集 / 设置` —— 没有「看板」。

这个决定的出处是我自己写的 `docs/design/iOS内测方案_2026-11-14.md` 第 98 行：

> 恒隐藏 | 工作流 `/flow`、看板 `/dashboard` | 已是 `adminOnly`，手机上永不需要

**「开发者调试面」被当成了「只在桌面看」。** 但管理员恰好在手机上最想瞄一眼今天有没有人用 ——
而且 `/dashboard` 在 390 宽下是能用的（两列卡片、数字可读、零横向溢出），它根本不属于
"窄屏做不了这件事"的那一类。

### 1.3 为什么所有测试都没拦住

`tests/test_console_nav.py` 里有一条专门守"别把入口悄悄移走"的断言
（`test_learning_path_owns_a_mobile_tab_slot`），但只守了 **`/path`** 一条 ——
因为当初的事故是"学习路径没有一级入口"。`/dashboard` 没有任何测试过问。

更讽刺的是同一段注释里写着：

> 有人把 `mobileTab: 2` 删掉、或者顺手把它标成 `desktopOnly`，手机上就再也找不到它，
> **而所有测试照样绿**（拓扑没坏，只是入口消失了）。

这次正是这句话描述的事，只是发生在另一个页面身上。所以补了一条
`test_admin_dashboard_has_a_mobile_entry`，三向锁死：不能 `desktopOnly`、不能 `mobileTab`、必须 `adminOnly`。

### 1.4 修复

```ts
{
  href: "/dashboard",
  icon: "dashboard",
  label: "看板",
  adminOnly: true,
  hint: "用户、调用、失败",
}
```

`/flow` **保持** `desktopOnly`：它的主体是可编辑 JSON 和 UUID 列表，390 宽下只能横向滚，
改坏了还没有撤销 —— 那才是真正"窄屏做不了的事"，两者不能类比。

## 二、二级导航空旷：空洞的不是留白，是格子里的内容

### 2.1 实测（390×844，管理员，改前）

```
面板：top 568 → 844，高 276px
网格：top 634，高 160px  ← 面板里只有 58% 是内容
列宽：114px × 3
排布：3 + 1（第二行只有「设置」一项，右侧空两格）
每格：76px 高，内容 = 图标 20px + 两个字
```

### 2.2 三个具体不足

1. **末行缺角**。4 项 ÷ 3 列 = 3+1，右下角两格空白。这是最直接的空旷感来源，
   而且它对"加一个新入口"极不友好 —— 加到第 5 项变成 3+2，还是缺一角。
2. **格子里的信息量低于格子面积**。114px × 76px 里只有「资料库」三个字。
   而这一层恰恰是用户不知道"点进去有什么"的地方 ——「工具集」到底装 GPA 还是番茄钟？
   名字本身没回答。
3. **横向空间被浪费**。每格 114px 里，两个字只占 42px，剩下 72px 是空气；
   而纵向因为竖排图标又吃掉 76px 的高度。**方向和内容量的分配是反的**。

### 2.3 方案对比

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 保持 3 列，末行居中 | `justify-content: center` | 只是把"右边空"变成"中间孤零零一个"，没解决内容空 |
| B. **2 列 + 每格一句用途**（采用） | 每格 175px，图标左、名称+说明右，58px 高 | 4 项 = 2×2 填满；5 项（管理员）= 2+2+1，末项居中；信息密度翻倍 |
| C. 单列列表行 | 每行 52px，图标+名称+箭头 | 任意项数都不空，但底部 sheet 会变成"设置页"，丢掉入口的方块感 |

选 B：改的是**内容密度**而不是**形态**，风险最小；形态（方块入口 + 底部 sheet）是
iOS 用户已经认识的东西，不需要在这一批里重学。

### 2.4 实施

`console.css`（在 ≤900 的媒体块里）：

```css
.tab-sheet-grid {
  display: flex;
  flex-wrap: wrap;
  justify-content: center;   /* 末行那一项居中，缺角不明显 */
  gap: var(--space-8);
}
.tab-sheet-item {
  flex: 0 0 calc(50% - var(--space-4));
  flex-direction: row;       /* 图标左、文字右 */
  align-items: center;
  min-height: 58px;
  padding: 0 var(--space-12);
  text-align: left;
}
```

用 flex-wrap 而不是 grid：grid 的末行项目只能左对齐，flex 配 `justify-content:center`
才能让最后那一个居中（实测 `设置` 的 left = 108，`(390-175)/2 = 107.5`）。

`nav.ts` 的 `NavItem` 新增可选的 `hint`，只在这一个面板用：

| 入口 | hint |
| --- | --- |
| 资料库 | 课件、笔记、论文 |
| 待办 | 今天要做什么 |
| 工具集 | GPA、番茄钟、课表 |
| 看板（管理员） | 用户、调用、失败 |
| 设置 | 头像、主题、密码 |

写 hint 的两条约束（写进 `NavItem` 的注释里）：

- **只写用途，不复述名字**（「资料库」下面再写「资料库管理」等于白占一行）；
- **不写版本号/状态**（"新功能"三个月后就是谎话）。

字号用 `--fs-xs`(13px) 而不是 11px 的 `--fs-badge` —— 后者的注释写的是
「只放 1–2 个字或数字」，这里一句 6–8 个字，用角标字号读不清。两列 175px 一格，
扣掉图标和内边距还有 121px，13px 放得下 9 个中文字（实测五条 hint 全部未触发省略号）。

## 四、诚实缺口

1. **全程 headless，无真机。** 390×844 + 模拟安全区（top 47 / bottom 34）不等于 iPhone 实机。
2. **没验 5 项时面板在小屏（375×667）上的表现**：两列各 167px，hint 会开始触发省略号。
3. **没验横屏**：横屏宽度够，但高度只有 390，面板 306px 会顶到屏幕上半。
4. 本轮同时发现两条**不属于本批**的线上问题（来自并发会话对 `/dashboard` 的改动，
   已随其 00:16 的构建上线）：
   - `test_layout_explains`：「全量」角标 5 个（约定是 2 个）；
   - 同一个页面文案里引用了仓库文件 `docs/数据看板_2026-10-27/口径与数据字典.md`，
     线上点不开。
   未擅自修改（避免与并发改动冲突），已报给用户。
5. **「更多」面板仍然只是一个 4–5 项的抽屉。** 这次让格子不空了，但"移动端少了很多页面"
   这个产品问题没解决（每日委托 / 总结 / 四六级是按场景主动移出的，不该为了填满而恢复）。
