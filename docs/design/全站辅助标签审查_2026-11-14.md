# 全站「辅助标签 / 说明文案」审查与优化方案

> 需求原话：「检查页面中不必要的辅助标签以及说明，让布局本身发挥解释作用，全站检查，然后给我优化方案」
> 日期：2026-11-14 · 范围：`frontend/src` 全部页面与共享组件（13 个 PageShell 页 + 首页工作台 + 资料库 / 论坛 / 落地页 + 9 个校园工具）

---

## 一、先说判据：一句话决定删不删

**反问：把这句话删掉，用户会不会做一个错误的决定？**
会 → 它承载了布局看不见的信息，留（但要挪到最省的位置）；不会 → 它只是在把屏幕重念一遍，删。

由此拆成三条硬规则：

| 规则 | 内容 | 处置 |
|---|---|---|
| **R1 复述即删** | 句子只是按顺序念出屏幕上的字段 / 按钮 / 数字 / 分区 | 直接删 |
| **R2 规则留下，但要挪位** | 说出布局看不见的东西：口径、限制、后果、代价、隐私边界 | 留，且**一屏只准出现一次**，就近放到它约束的那个控件旁 |
| **R3 功能不碰** | `sr-only`、`role="status"`、`aria-live`、`aria-describedby`、错误提示、法律与隐私告知 | 一律不动 |

**这条原则在本仓库已经成功用过一次**：`app/page.tsx:706` 的注释写着「提示语不再说『定位已开启』：针已经变金色、角标已经出现，再说一遍是重复」——把状态交给视觉，文字只留下用户真正不知道的那件事（「城市用你填的 X」）。本轮就是把这套做法推到全站。

这个判据也对应 design-taste 的两条硬规则：**任何图、渲染、视觉下面不许挂说明**；**标题要命名事物、按钮是动词+宾语**，而不是用一句话解释自己。

## 二、全站盘点（数量与家族）

统计方式：按**精确类名或家族后缀**匹配（`output/_audit_labels.py`，故意不用子串匹配——否则 `rem-cap-dock` 会被 "cap" 命中、`meta` 会混进时间戳）。跑出来 **222 处类命中，其中功能性（`sr-only` / `role="status"`）10 处**。

| 家族 | 数量 | 分布 | 初判 |
|---|---|---|---|
| 页头三层：`eyebrow` + `h2` + `pg-sub` | 13 页 × 3 = 39 | 11 个一级页 + `settings/install` + `settings/reminder` | **重灾区**，见第三节 |
| `.hint` 家族（`hint` / `sd-hint` / `flow-hint` / `kbp-hint` / `rem-sect-hint`） | 69 | settings 15、dashboard 13、其余零散 | 约 4 成是 R1，见第四节 |
| 校园工具卡 `campus-card-note` | 40 | 9 个工具，GPA / 番茄钟最多 | **约一半是"数据/状态"不是说明**，保留；另一半是指示语 |
| 空状态（`lib-empty` / `campus-empty` / `fm-empty` / `kb-board-empty` / `rem-*-empty` / `sd-empty`） | 44 处类命中 ≈ 20 组 | 资料库、论坛、工具、待办 | **多数合格**：标题=状态、说明=原因、按钮=出路，不重复 |
| `.meta` 元信息 | 36 | dashboard 16、settings 9、列表项 | 多为时间戳与口径，保留（dashboard 的括号要合并，见 4.2） |
| 面板 / 弹窗 / 引导提示（`pv-note`、`tour-note`、`tour-step-desc`、`lib-viewer-tip`、`kb-board-tip`） | 16 | 弹窗为主 | 半数属于"第一次用才需要"，应改成**看一次就收** |

> 两个口径要说明：① `pg-sub` 在脚本里只数到 1 处，因为 13 个页面是通过 `<PageShell sub={…}>` 属性传的，类名在组件内部；② `eyebrow` 脚本数到 16 处，比 13 多——多出来的在 `app/library` 等**不走 PageShell 的页面**里，它们自建了小标题，属于同一类问题。

合计约 **200 处**说明性文案；其中 R3（功能性）一律不动。

## 三、页头三层：最该动的地方

每个页面现在是 **眉题（18px 小字）+ 标题 + 一句说明** 三层。而侧栏 / 底部 tab 已经用高亮告诉了用户"你在哪"，标题自己又说了一遍，说明句再解释一遍——同一件事说了三次。

| 页面 | 眉题 | 判 | 理由 |
|---|---|---|---|
| dashboard | 管理 · 内部 | **留** | 标出"这是给管理员看的调试面"，布局无法表达 |
| flow | 管理 · 内部 | **留** | 同上 |
| cet | 专项备考 | 删 | 标题「四六级备考工作区」已说 |
| checkin | 把今天记下来 | 删 | 氛围词，不提供行动线索 |
| delegate | 自动替你干活 | 删 | 氛围词 |
| knowledge | 知识库 | 删 | 与侧栏 label 逐字重复 |
| path | 学习路径 | 删 | 与侧栏 label 逐字重复 |
| reminders | 什么时候做什么 | 删 | 见 4.3，这页还有一个更严重的同名问题 |
| report | 每日总结 | 删 | 标题「今天学了什么」+ 侧栏「总结」已覆盖 |

### 3.2 说明句（pg-sub）13 条：4 条该删、2 条该压、7 条留

| 页面 | 现状 | 判 | 改成 |
|---|---|---|---|
| **settings** | 「账号、外观、检索、隐私、用量，以及知穗现在会哪些工具…」 | **删** | 这一句是把下面 6 个分组标题念了一遍 |

| **path** | 「从『把资料放进来』走到『让它每天替你跑』——走完这 12 关…」 | **压** | 标题已写「12 关」，删掉重复计数，只留"走完才算配成你自己的" |
| **cet** | 「按你的考试日期…生成任务…词卡按遗忘曲线复习，分数画成趋势。」 | **压** | 三个 tab（计划/词汇/分数）自己会说；只留"词卡按遗忘曲线复习"这条规则 |
| **settings/reminder** | 「权限只有一处：待办 → 设置 → 提醒权限。」 | **删路径句** | 页头 actions 里已经有一个跳到 `/reminders?tab=settings` 的按钮——**句子在描述按钮的终点**，删句子、留按钮 |
| checkin | 「…只讲知识结构、不露个人内容…分享出去的是学习笔记」 | 留 | 隐私边界，R2 |
| knowledge | 「课件、笔记、论文都可以放进来。对话时选中它…」 | 留 | 后半是规则 |
| delegate | 两行分句 | 留 | 内容是真规则，但两行偏长，建议压到一行 |
| reminders | 「设了提醒时间，到时会通知你；课表、打卡的提醒会自动排好。」 | 留 | "自动排好"是布局看不出的行为 |
| report | 「聊过的东西容易忘。每天留一份小结，带出处。」 | 留（偏弱） | 可只在首屏空态出现，第二次进来不再显示 |

### 3.3 不建议做的那一步

把页标题（`h2`）本身也去掉、只靠侧栏高亮——**不做**。`h2` 是无障碍地标（screen reader 的 heading 导航）和 SEO 标题，删了是把可读性换成视觉效果，不划算。眉题才是纯装饰层。

## 四、按页面逐个结论

### 4.1 设置页（15 处 hint，最密）
- `page.tsx:251`「密码、昵称、头像都能在这里改。改登录名要验证一次密码。」
  → 前半句是目录（删），后半句是规则（留），改成「改登录名要先验证密码」。
- `:463`「还没有资料库。上传讲义或论文后，在这里能看到它占了多少片段。」
  → 空状态里已经说了同样的意思，两处留一处。
- `:284/:326/:403/:431/:437/:491` 六条 hint 逐条判断，原则同上：**只留"做了会发生什么"，删掉"这里可以做什么"**。

### 4.2 数据看板（8 张指标卡，4 个括号）
`:273`（当前快照，不随筛选变化）、`:298`（不含未登录探测、报告空态）、`:308`（均值，非 p95）、`:322`（全量，不受筛选影响）——**四句话都在说同一类事：这个数是不是跟随筛选、它的统计口径是什么**。

**方案（让布局解释）**：
1. 把"受筛选影响 / 不受影响"变成**视觉分组**：第二排单独加一条细分隔线，或给全量数字加一个小角标（沿用 `--fs-badge`）。
2. 口径说明收成**页头下方一行**：「指标跟随上方筛选；标 · 的为全量口径」。
3. "均值，非 p95"这类无法视觉化的，保留在卡内，但只保留这一条。

一处文字 → 一个视觉规则，省的是一整屏的括号。

### 4.3 待办页（标题与首个分区同名）
- `reminders/page.tsx:3331` 分区标题「待办」，而整页标题也叫「待办」（`:3427`）。
  → DOM 里出现两个同名 `h2`，读屏导航时用户分不清层级。
  → 建议分区改成语义时间段：「今天」「接下来」，页面标题保留「待办」。`rem-sect-n`（条数）已经是布局自带的量化，不需要再写"共 N 条"。
- `:3347`「今天没有安排，这是接下来的：」——这句是对的：它解释了"为什么下面有内容却又是空的"。留。

### 4.4 工具集（同一句事实写了两遍）
- 页头 sub：「数据先存在这台设备上，登录后会同步到云端，换设备也在。」
- `GpaTool.tsx:253`：「数据先存在这台设备的浏览器里，登录后会同步到云端，换设备也在。清理浏览器数据会一并清掉本地那份。」
  → **同一事实、两种措辞**。保留 GPA 卡那句（它多了"清理浏览器会丢"这个后果），页头改为只说价值：「不用连教务，打开就能用」。
- `DrawTool.tsx:69`「写清事由和名额，把参与者名单贴进来（每行一个，模拟群友接龙），点「开奖」随机抽出中签者。」
  → **典型 R1**：下面就是「抽签事由」「参与者名单」「开奖」三个控件，这段在把它们念一遍。删。真要保留的只有「每行一个」这条格式约束——把它挪进输入框的 placeholder。
- `GpaTool.tsx:150` `{activeAlgo.desc}`：算法长解释常驻在 select 下方，切换算法时文字跳变，页面高度跟着抖。建议改成选中项的短标签 + 一处固定说明（或折叠）。

### 4.5 资料库 / 论坛
空状态基本合格，不动。要留意的只有一类：**空状态同时有"标题 + 一句原因 + 一个按钮"时，如果那句原因只是在重复标题，删原因**（目前抽样 4 处都不属于这种情况，属于写得好的样本）。

### 4.6 首页工作台
首页没有页头三层，说明文案主要在：定位提示（已经做过一次去重，见 §1）、建库建议卡、输入框下方快捷键提示。
- `ChatArea.tsx:307` 注释：「每句都控制在 9 字以内」——这条自约束是对的，保持。
- 建议把"示例问题"这类**只在空会话出现一次**的引导，改成"输入框占位符轮播 + 一次展示后收起"，而不是常驻一段话。

## 五、优化方案：四批，按收益/风险排序

### 第 1 批 · 纯删（零风险，1 次提交，收益最大）
1. 删 11 条眉题（保留 dashboard / flow 的「管理 · 内部」）→ `PageShell` 的 `eyebrow` 改成可选。
2. 删 4 条复述型 sub（settings / dashboard / flow / settings/reminder 的路径句）。
3. 删 `DrawTool:69` 整段、`settings:463` 与空状态重复的那句。
4. `path` / `cet` 的 sub 各压到一句。
- 预计净删 300+ 汉字、每页首屏多出 18–20px 纵向空间。
- 风险：`PageShell` 加可选参数要同步改 13 个调用点，测试里有一条断言 PageShell 结构，需要补"eyebrow 可缺省"。

### 第 2 批 · 合并同类项（让布局承担）
1. **看板口径**：4 个括号 → 1 行页头说明 + 数字角标（§4.2）。
2. **待办分区改名**：「今天 / 接下来」，解决同名 h2（§4.3）。
3. **工具集去重**：页头 sub 与 GPA 底部那句只留一处（§4.4）。
4. **弹窗「看一次就收」**：`tour-note` / `lib-viewer-tip` / `kb-board-tip` 共 8 处，改成首次出现、关掉后本地记住。

### 第 3 批 · 把说明变成控件（需要重排，收益最高但最费工）
1. 表单 hint 里的"规则"下沉到控件本身：
   - 密码「至少 8 位。别用生日和学号」→ 输入时实时显示强度/缺失项，静态 hint 删。
   - 用户名「字母、数字、中文、下划线」→ 允许字符集改成输入即校验（输入非法字符直接不给键入）。
2. 空库 / 空列表的"原因"改成**状态行**（图标 + 一句 + 按钮同一行），减少一段文字。
3. GPA 算法说明改成选中项的短标签 + 固定说明区。

### 第 4 批 · 可选，需要你拍板
- 页标题与侧栏 label 重复（`/knowledge` 页标题「我的资料库」vs 侧栏「知识库」）：可以统一措辞，**不建议删标题**（无障碍地标）。
- 论坛页仍是独立页（`app/forum/page.tsx` 自建 `.fm-root` 与头部），和刚并壳的工具集不一致。这属于路由一致性问题，不在本轮范围内，但值得单开一批。

## 六、验证方法（每批都要跑）

1. **文案字数密度**：脚本统计每个页面渲染出的说明性文本总字数，目标「每屏 ≤ 80 字」（design-taste 对 tech 类的上限是 60–80 词/屏）。改前先量一次基线。
2. **反证**：删句前先 grep 该节点是否被 `aria-describedby` / `id` 引用；删完再 grep 一次，确认没有悬空引用。
3. **测试断言**：在 `tests/test_console_nav.py` 加两条——
   - `PageShell` 的 `sub` 长度上限（比如 60 字），超了红；
   - 任何页面不得出现两个同名 `h2`（待办页那条问题的护栏）。
   每条新断言都要故意改坏一次看它变红。
4. **截图对比**：390 / 1440 各拍一批改前改后；重点看"删了说明句之后，页头是否显得空"——如果空，说明还缺一个结构性元素（分区、筛选条），那就补布局而不是把话加回来。

## 七、我不会动的东西（避免误伤）

- `sr-only` 文本、`role="status"` / `aria-live` 播报、错误提示、表单 `label`。
- 隐私与能力边界说明（如打卡页「不露个人内容」、上传页的存储位置说明）——这些是 R2，删了会让人做错误决定。
- 空状态的"原因 + 出路"结构（资料库写得不错，是正面样本）。
- 工具卡里的数据/状态 note（「名单 12 人」「已保存」）——那是数据，不是说明。

### 11.2 换算表：让「说明」和「实现」只剩一个真相

原来那段 `90=4.0、85=3.7……` 是**手写在组件里的字符串**，而真正的阈值表在
`logic/gpa.ts` 的 `TABLES`。两份数据各活各的：改了一个忘了另一个，就会出现
「说明写 85、代码按 84 算」——这类错误用户看不出来，只会觉得"这个 GPA 算错了"。

现在 `gpaScale(algo)` 从 `TABLES` 投影出可读档位，界面只负责渲染：

- 只表达下限（`≥ 90` / `不足 60`），不编造上限。分数可以是 89.5，写成「85–89」
  在 89.5 上就是错的；`score >= min` 的语义用「≥」表达才没有歧义。
- **相邻同绩点合并**到较低下限：北大表 63 与 60 都是 1.0，合成一行 `≥ 60 → 1.0`。
  不改任何输入的結果，只是少一行、少一个看起来像打字错误的重复。

验证方式不是"读代码觉得对"，而是**逐分跑一遍**（`output/_verify_gpa_scale.mjs`）：
0–100 每 0.5 分 × 两套算法 = **402 项**，比「按渲染规则从表里查」与
`scoreToGpa` 的真实返回；另加档位降序、相邻不重复共 **32 项**结构校验。
**434 项全一致**。

|---|---|---|
| （空） | 不显示 | — |
| `abc` | 还差 5 位 | 中性灰 |
| `abcdefgh` | 有四位以上连号，猜的人第一轮就会试。 | warning |
| `12345678` | 纯数字的密码最先被试，加两个字母就稳很多。 | warning |
| `aaaaaaaa` | 整串是同一个字符，等于只有一位。 | warning |
| `a8f2k9x1` | **不显示** | — |

四条设计取舍：

1. **没输入时念规则，等于让人先读一段再动手**。删掉之后，规则由输入触发的差额表达。
2. **「还差 N 位」消失本身就是「够了」的信号**。不再补一行「✓ 符合要求」——
   那是把屏幕又念了一遍。
3. **弱口令只警示、不拦**。硬条件（< 8 位）仍然在 `submit` 里挡；形状判定是
   "换了更安全"的建议，拦下来只会让人把密码写进便签。
4. **`role="status"`**：提示是随输入变化的，读屏需要收到；同时只在有提示时挂
   `aria-describedby`，避免输入框长期指向一个不存在的 id。

实测 6 种输入全部符合，且 `aria-describedby` 在提示消失时一并移除。

### 11.5 空态只改了一处，另外三处**核实后不改**

改的是 GPA 成绩单：原来是虚线框里那句「还没有课程。点「添加课程」手动录入，
或「载入示例」先看看效果。」—— 两个按钮就在上方 20px 处，这句话在念它们的名字。

## 十二、第 4 批执行记录（2026-11-14 下午，已上线）

这一批原本排了两件事：页标题与侧栏 label 措辞统一、论坛两套皮肤收口。执行时变成两件
不一样的事：**论坛那项没做**（另一个会话正在同一批文件里改贴吧三栏，动它必冲突），
换成了用户当场提的**番茄钟同步条**。

### 12.1 同步条：把「状态」还给「后果」

番茄钟顶上原来常显一条：

> ● 已同步 · 刚刚同步 · 已同步，云端共 12 条记录　　[立即同步]

问题不在措辞，在这条信息**本来就不该有人看**：同步有三个自动触发点（进页面、
`online` 事件、`visibilitychange`），成功是默认结果。每天看到十次「已同步」，
用户学到的不是"数据安全"，是"这行字可以无视"。

砍法按第一批同一判据 —— **删掉这句，用户会不会做一个错误的决定？**

| 状态 | 原文 | 判决 |
|---|---|---|
| `synced` | 已同步 · 刚刚同步 · 云端共 N 条 | 删。不会因此做错任何事 |
| `checking` / `syncing` | 检查中 / 同步中（几百毫秒） | 删。为瞬态闪一下反而像出错 |
| `guest` | 仅本机 / 数据存在这台设备上 | **留**。会误以为换设备也能看到 |
| `error` | 未同步 / 计时不受影响，记录不会丢 | **留**。会误以为记录已经没了 |

顺带三件事：

- 按钮从「立即同步」改成只在失败时出现的「重试」，游客态是「去登录」。
  自动同步的产品里，手动同步按钮只在自动失败那一刻有意义。
- `lastSyncedAt` 整个删掉（`PomodoroTool` 的 state 也从三项变两项）——
  「N 分钟前同步」是常显时代才需要的东西。
- CSS 里 `is-synced` / `is-syncing` / `is-checking` 三条圆点规则和
  `@keyframes campus-sync-pulse` 成了死规则，一起删。留着会让后来人以为
  还存在第三种显示态。

### 12.2 一个东西两个名字：资料库

改之前先数了一遍：

| 词 | 界面出现处 | 典型句子 |
|---|---|---|
| 资料库 | 远多于对方 | 我的资料库 / 全部资料库 / 还没有资料库 / 建第一个资料库 / 收起资料库 / 存进资料库 |
| 知识库 | 侧栏 + 一批动作短语 | 导航「知识库」/ 绑定知识库 / 从知识库检索 / 删除知识库 |

后果是三个入口三个说法：侧栏点「知识库」→ 页面标题「我的资料库」→ 另有一个
`/library` 叫「公开知识库」。用户没法判断这是不是同一处。

**改法：界面统一用「资料库」，后端 `kb_*` 命名一个都不动。**

- 侧栏 `nav.ts` 的 label、`/library` 的 h1（公开资料库）、`/knowledge` 的标题
  （我的资料库）、右栏面板、空状态、toast、`layout.tsx` 的 SEO 标题、
  更新公告正文 —— 共 34 处字符串。
- **`lib/chatStatus.ts` 里的正则不动**。那几条 `re` 匹配的是后端 status 帧的原文
  （后端还在发「正在检索知识库(bk_xxx)」），改了正则一条都匹配不上，界面上那行
  状态会永远停在上一条。文件里加了注释，写明"要改先改后端"。
- **论坛页不动**（另一个会话正在改同一批文件），所以 `app/forum/` 里的
  「公开知识库」暂时留着，断言里也有意跳过它 —— 等对方合并后要删掉这条豁免，
  否则论坛里的旧词永远扫不出来。
- 注释里的历史引语不改（"用户原话：点击对话和点击知识库也是一样的跳转"），
  改了就是篡改记录。

**没跟着改的两处，理由是不构成"同名二物"**：

- `/cet` 侧栏「四六级」/ 标题「四六级备考工作区」、`/dashboard`「看板」/「数据看板」、
  `/flow`「工作流」/「工作流与切换规则」—— 简称与全称的关系，点进去一眼能对上。
- `/path` 侧栏「学习路径」/ 标题「12 关，一关一关过」—— 修辞型标题，说的是机制
  （关卡式），不是另一个名字。

### 12.4 一个发现：junit 的 `tests` 属性不可信

本轮 `junit-batch4.xml` 的 `<testsuite tests="1893">`，但里面 `testcase` 节点只有
**1870** 个，而 `pytest --collect-only` 也是 1870。差 23。
