## 一、底部 tab 变矮

### 改了什么

| 项 | 改前 | 改后 | 依据 |
|---|---|---|---|
| `--tabbar-h` | 60px（4+52+4） | **50px**（3+44+3） | 44 是触控下限，再低手指点不准 |
| `.tabbar-item` min-height | 52 | **44** | 同上 |
| tab 字号 | `--fs-xs` 13px | **12px** | 标签只有 2–4 字，12 是可读下限 |
| tab 图标 | 22px | **20px** | 跟着高度收，20 仍能认出轮廓 |
| 上下内边 | 各 4px | 各 3px | 纯留白 |

### 实测（390×844，Edge headless，`mobile: true`）

| 页面 | tab 上沿 | tab 高 | 命中区 | 内容下内边 | 滚到底最后内容 |
|---|---|---|---|---|---|
| `/` 首页 | 793 | 51 | 44 | — | — |
| `/reminders` | 793 | 51 | 44 | 62px | 741（< 793 ✓） |
| `/tools` | 793 | 51 | 44 | 62px | — |
| `/settings` | 793 | 51 | 44 | 62px | **739 → 749** |

- `tab 高 51` = 50 令牌 + 1px 上边框。
- `内容下内边 62px` = 50 + 12 + `env(safe-area-inset-bottom)`（headless 下为 0），
  三页一致 → 让位用的确实是同一个令牌，没有谁掉队。
- 设置页滚到底时最后一块内容的下沿从 739 抬到 **749**，正好多出 10px 可见。

### 诚实结论：10px 的改善很有限

对比图（`docs/design/ui-r7-2026-11-13/对比_tab高度_待办_手机.png`）里两张图
并排看，**肉眼几乎分不出差别**。50px 已经是 iOS 原生 tab bar 的尺寸（49pt），
再往下压只能牺牲标签可读性。

用户在首页看到的「占位置」其实是三段叠加：工具行（检索/智能联网/反馈/工具集）
+ 输入框 + tab 条。这一轮只动了最后一段。要进一步压缩，得动另外两段，
那是另一个量级的设计改动（见文末「还能怎么走」）。

## 二、工具集页挂上底部导航

### 根因

`/tools` 在 `app/(campus)/` 路由组，**不套 ConsoleLayout** ——
`.tabbar` 长在外壳和首页里，这一页两处都不沾。所以从「更多」点进工具集，
底部那条当场消失，想换功能只能点页面顶部「← 回首页」再点一次目标。

### 改法（与首页同一条路）

| 文件 | 改动 |
|---|---|
| `campus/components/CampusTabBar.tsx` | 新增。client 薄壳，`useAuth()` 取 `is_admin` 后交给 `ConsoleTabBar` |
| `app/(campus)/tools/page.tsx` | 渲染 `<CampusTabBar />`，与 `CampusToolsHub` 并列 |
| `campus/styles/campus.css` | ≤900 时给 `.campus-scroll` 加 `padding-bottom: calc(var(--tabbar-h) + env(...) + 12px)`；`body:has(.tab-sheet)` 时锁底层滚动 |

不套 ConsoleLayout 的原因：这一页的 `.campus-scroll` 是 `height:100dvh` 自成一屏，
塞进外壳会出现两层滚动、版心被压两次。

不省掉 `isAdmin` 的原因：省掉的话管理员在待办页「更多」里看到 9 格、
点进工具集变 8 格 —— 同一个面板在不同页面上不一样，比多一次 `/auth/me` 更难解释。

### 实测

`/tools` 打开后：`tabCount=5`、`moreActive=true`（「更多」点亮，因为工具集在这一组里）、
`padding-bottom=62px`、滚到底最后内容不被压。

## 四、没验到的 / 已知缺口

1. **仍然没上真机**。全程 Edge headless。iPhone 的 `env(safe-area-inset-bottom)`
   在模拟器恒为 0，那 34px 的真实效果没有数据。
2. **桌面端工具集仍然没有侧栏**。`/tools` 是独立板块（880px 版心、自己的视觉），
   塞进 ConsoleLayout 会两层滚动。宽屏用户从侧栏进来后仍要点「← 回首页」
   （手机端已由底部 tab 取代，见 6.2 —— 所以那条返回入口只对宽屏保留了）。
3. **10px 的观感提升有限**，见上文。若用户仍觉得「占位置」，需要动输入区那一段。
4. 平板 900–1024 仍未单独确认（上一轮就欠着）：侧栏在 ≤900 隐藏、tab 在 ≤900 出现，
   **1000px 左右可能两边都没有导航**。

## 五、还能怎么走（若要继续压）

按「收益 / 代价」排序：

| 方案 | 收益 | 代价 |
|---|---|---|
| 去掉 tab 文字，只留图标 | 高度可到 ~40px | 5 个图标的辨识度下降，不符合主流习惯 |
| 内容向下滚动时收起 tab | 阅读时长内容占满 | 首页不滚动，对用户抱怨的「主界面」无效 |
| 把工具行 + 输入框 + tab 合成一块底板 | 视觉上从三层变一层 | 动的是首页聊天区的结构，风险最高 |
| 安卓/iOS 各自给不同高度 | 各平台都贴原生 | 多一套分支，验收成本翻倍 |

目前只做了第一列最保守的一行（压到 iOS 标准尺寸）。

## 六、回滚决定与一次减法（同日稍后）

### 6.1 不做「三段合成一块底板」

上一节列了三个方向，用户要了效果图，于是把三个都试了：

| 方向 | 做法 | 结果 |
|---|---|---|
| A 通铺 | 工作台背景转白 | 只换底色，工作台底部仍有 8px 外边距，输入框与 tab 之间露出一条米色缝 —— 比现状更像"两层" |
| B 浮岛 | 输入区做成圆角浮卡 | 卡片缩进、tab 仍全宽，左右对不齐 |
| C 同色 | tab 底改 `--bg-canvas` + 去边框投影；输入框降为 `--fill-4` 无框 | 三块底色收成一块，唯一做得成的；可读性过关（未选中 5.37:1、选中金 6.12:1，均过 AA） |

C 的效果图在 `ui-r7-2026-11-13/对比_底部合成一块_手机.png`。
**用户最终选择保持现状** —— 白底输入框 + 白底 tab 的层次更清楚，不必为"看起来是一块"牺牲它。

留档的理由：这一方案的代价常被低估。它**一个像素也没省**（高度仍 50px），改的只是观感层数；
真正的收益是"不再有三种底色交替"。若以后有人重提"底部太碎"，先看这张图和这几个数字再决定。

### 6.2 工具集页的「← 回首页」在手机上收起

用户要求删掉。但它 2026-11-07 被加进来是有原因的：这一页不套控制台外壳，
PWA 独立窗口（`display: standalone`）里没有浏览器后退键，删掉就等于把人关在页面里。
手机端的前提这轮变了（挂上了底部 tab），宽屏没有 —— `(campus)` 至今没有侧栏。

所以分两半：

```css
/* campus.css */
@media (max-width: 900px) {
  .campus-bar { display: none; }   /* 返回链接 + 品牌字整行收起 */
}
```

DOM 保留（宽屏仍需要）。实测（Edge headless，浅色）：

| 视口 | `.campus-bar` display | 高度 | 标题 top | tab |
|---|---|---|---|---|
| 390×844 | `none` | 0 | **12** | 显示（793，51px） |
| 1440×900 | `flex` | 32 | 68 | 不显示 |

连带删掉 640 断点里两条失效规则（`.campus-back` 的 44px 触控高度、`.campus-bar` 的 2px 外边距）——
整行都 `display:none` 了，它们永远不会生效，留着只会让下一个改这里的人以为手机上有返回键。

**断点为什么用 900 而不是这个文件惯用的 640**：campus.css 自己的手机断点是 640，
但 tab 是 ≤900 出现。若在 640 隐藏，641–900 会出现"既有 tab 又有返回入口"。
立一条约定：有 tab 的地方不再有返回入口。

### 6.3 这轮的坑在工具链，不在产品

Edge 在 11 月 8 日升到 157 之后，原来的截图脚本全线失灵，而且**一声不响**：

1. `Page.enable` / `Runtime.enable` 不应答 → 直接 `Runtime.evaluate`，它本身不需要 enable；
2. 全局 `ws.onmessage` + Map 转发会漏消息（`ws open` 之后才赋值的收不到）
   → 每条命令自己 `addEventListener`，注册与 `send` 之间不隔 `await`；
3. node 里 `spawn` Edge 会让**整条 shell** 收到 SIGTERM，连后面的 `echo` 都不执行、输出全丢
   → Edge 改为外部先起好，脚本只连端口；
4. `--user-data-dir` 不能放在含中文的项目路径下（`E:\项目资料\...`），否则 Edge 起不来。

四条都写进了 `output/_shot_tools_r8.mjs` 的注释。下次换机器或浏览器大版本，先跑
`output/_probe1.mjs` 这个最小探针（它只用 12 行就能区分"CDP 坏了"还是"我的脚本坏了"）。
