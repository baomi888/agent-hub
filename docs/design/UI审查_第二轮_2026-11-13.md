## 一、底部 tab 变矮

### 改了什么

| 项 | 改前 | 改后 | 依据 |
|---|---|---|---|
| `--tabbar-h` | 60px（4+52+4） | **50px**（3+44+3） | 44 是触控下限，再低手指点不准 |
| `.tabbar-item` min-height | 52 | **44** | 同上 |
| tab 字号 | `--fs-xs` 13px | **12px** | 标签只有 2–4 字，12 是可读下限 |
| tab 图标 | 22px | **20px** | 跟着高度收，20 仍能认出轮廓 |
| 上下内边 | 各 4px | 各 3px | 纯留白 |

### 实测（390×844，Edge headless，`mobile: true`）

| 页面 | tab 上沿 | tab 高 | 命中区 | 内容下内边 | 滚到底最后内容 |
|---|---|---|---|---|---|
| `/` 首页 | 793 | 51 | 44 | — | — |
| `/reminders` | 793 | 51 | 44 | 62px | 741（< 793 ✓） |
| `/tools` | 793 | 51 | 44 | 62px | — |
| `/settings` | 793 | 51 | 44 | 62px | **739 → 749** |

- `tab 高 51` = 50 令牌 + 1px 上边框。
- `内容下内边 62px` = 50 + 12 + `env(safe-area-inset-bottom)`（headless 下为 0），
  三页一致 → 让位用的确实是同一个令牌，没有谁掉队。
- 设置页滚到底时最后一块内容的下沿从 739 抬到 **749**，正好多出 10px 可见。

### 诚实结论：10px 的改善很有限

对比图（`docs/design/ui-r7-2026-11-13/对比_tab高度_待办_手机.png`）里两张图
并排看，**肉眼几乎分不出差别**。50px 已经是 iOS 原生 tab bar 的尺寸（49pt），
再往下压只能牺牲标签可读性。

用户在首页看到的「占位置」其实是三段叠加：工具行（检索/智能联网/反馈/工具集）
+ 输入框 + tab 条。这一轮只动了最后一段。要进一步压缩，得动另外两段，
那是另一个量级的设计改动（见文末「还能怎么走」）。

## 二、工具集页挂上底部导航

### 根因

`/tools` 在 `app/(campus)/` 路由组，**不套 ConsoleLayout** ——
`.tabbar` 长在外壳和首页里，这一页两处都不沾。所以从「更多」点进工具集，
底部那条当场消失，想换功能只能点页面顶部「← 回首页」再点一次目标。

### 改法（与首页同一条路）

| 文件 | 改动 |
|---|---|
| `campus/components/CampusTabBar.tsx` | 新增。client 薄壳，`useAuth()` 取 `is_admin` 后交给 `ConsoleTabBar` |
| `app/(campus)/tools/page.tsx` | 渲染 `<CampusTabBar />`，与 `CampusToolsHub` 并列 |
| `campus/styles/campus.css` | ≤900 时给 `.campus-scroll` 加 `padding-bottom: calc(var(--tabbar-h) + env(...) + 12px)`；`body:has(.tab-sheet)` 时锁底层滚动 |

不套 ConsoleLayout 的原因：这一页的 `.campus-scroll` 是 `height:100dvh` 自成一屏，
塞进外壳会出现两层滚动、版心被压两次。

不省掉 `isAdmin` 的原因：省掉的话管理员在待办页「更多」里看到 9 格、
点进工具集变 8 格 —— 同一个面板在不同页面上不一样，比多一次 `/auth/me` 更难解释。

### 实测

`/tools` 打开后：`tabCount=5`、`moreActive=true`（「更多」点亮，因为工具集在这一组里）、
`padding-bottom=62px`、滚到底最后内容不被压。

## 三、验证

| 手段 | 结果 |
|---|---|
| 新增/改动的断言 | `tests/test_console_nav.py` 9 → **11** 条 |
| 全量 | **1681 passed / 0 failed**（读 junitxml 求和，不信退出码） |
| 反证 | 4 次全部变红，无假绿 |
| 类型检查 | `npx tsc --noEmit` 通过 |
| 生产构建 | `npm run build` 通过，21 个静态页全 prerender |

### 反证的 4 个方向

1. `--tabbar-h` 改回 60 但 tab 实际是 50 → `test_token_matches_the_tab_it_describes` 红
2. 删掉 `<CampusTabBar />`（只留 import）→ `test_tools_page_has_the_same_tabbar` 红
3. 删掉工具集页的让位 → `test_tools_page_makes_room_for_the_tab` 红
4. 让位里写死 `50px` 而不是变量 → 同一条红

★ 顺带修掉了旧断言的一个隐患：`test_token_matches_the_tab_it_describes` 原来写死
`item_h + 8`（上下各 4px），这轮 padding 改成 3 会红一次 —— 红得住，但下次再调
还得手改预期，改着改着就会有人把断言删掉。现在改成**从 CSS 里读 padding**。

## 四、没验到的 / 已知缺口

1. **仍然没上真机**。全程 Edge headless。iPhone 的 `env(safe-area-inset-bottom)`
   在模拟器恒为 0，那 34px 的真实效果没有数据。
2. **桌面端工具集仍然没有侧栏**。`/tools` 是独立板块（880px 版心、自己的视觉），
   塞进 ConsoleLayout 会两层滚动。桌面用户从侧栏进来后仍要点「← 回首页」。
   这一轮只解决手机。
3. **10px 的观感提升有限**，见上文。若用户仍觉得「占位置」，需要动输入区那一段。
4. 平板 900–1024 仍未单独确认（上一轮就欠着）：侧栏在 ≤900 隐藏、tab 在 ≤900 出现，
   **1000px 左右可能两边都没有导航**。

## 五、还能怎么走（若要继续压）

按「收益 / 代价」排序：

| 方案 | 收益 | 代价 |
|---|---|---|
| 去掉 tab 文字，只留图标 | 高度可到 ~40px | 5 个图标的辨识度下降，不符合主流习惯 |
| 内容向下滚动时收起 tab | 阅读时长内容占满 | 首页不滚动，对用户抱怨的「主界面」无效 |
| 把工具行 + 输入框 + tab 合成一块底板 | 视觉上从三层变一层 | 动的是首页聊天区的结构，风险最高 |
| 安卓/iOS 各自给不同高度 | 各平台都贴原生 | 多一套分支，验收成本翻倍 |

目前只做了第一列最保守的一行（压到 iOS 标准尺寸）。
