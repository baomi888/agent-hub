## 3. iOS 端功能矩阵（要你拍板）

### 3.1 核心发现：移动端导航与产品定位错配

`frontend/src/lib/nav.ts` 里，导航顺序是给**桌面侧栏**排的：

```
对话(1) 资料库(2) 论坛(3) 待办(4) 每日委托(5) 总结(6) 打卡(7) 四六级(8) 学习路径(9) 工具集(10) 设置(11)
```

而 `TAB_PRIMARY_COUNT = 4`，手机底部 tab **直接取前 4 个**。

⇒ **「学习路径」在手机上没有任何一级入口**，要进「更多」翻到第 9 项。而它的定位是「和对话平行」的核心（申报书 3.4）。

**这不是样式问题，是架构缺陷**：导航清单只有一个维度（桌面顺序），没有「移动端权重」。

### 3.2 建议的移动端结构

| 位置 | 模块 | 理由 |
|---|---|---|
| **tab 1** | 对话 `/` | 最高频 |
| **tab 2** | 学习路径 `/path` | 核心定位，必须一级可见 |
| **tab 3** | 论坛 `/forum` | UGC 浏览是手机原生场景 |
| **tab 4** | 打卡 `/checkin` | 轻交互、每天一次，最适合手机 |
| 「更多」 | 资料库 `/knowledge` | 检索型，手机可用但非高频 |
| 「更多」 | 待办 `/reminders` | 3769 行最重的页面，需真机重点验 |
| 「更多」 | 工具集 `/tools` | 独立单页，不套外壳 |
| 「更多」 | 设置 `/settings` | 低频 |
| **移出移动端** | 每日委托 `/delegate` | 1072 行，任务生成后实际看的是对话，手机无独立场景 |
| **移出移动端** | 总结 `/report` | 报表型，需横向对比，窄屏体验差 |
| **移出移动端** | 四六级 `/cet` | 长周期备考，主要在电脑做计划；单词卡已在工具集里 |
| 恒隐藏 | 工作流 `/flow`、看板 `/dashboard` | 已是 `adminOnly`，手机上永不需要 |

> **重要：「移出移动端」= 只删导航入口，不删代码、不删路由。**
> 桌面侧栏照旧能进，后端接口不动，代码零删除。这是一条可逆的改动。

### 3.3 实现方式（改 `lib/nav.ts` 的模型，不是改顺序）

```ts
export interface NavItem {
  href: string;
  icon: string;
  label: string;
  adminOnly?: boolean;
  /** 手机底部 tab 是否出现（不填 = 不进 tab） */
  mobileTab?: boolean;
  /** 完全不进移动端：侧栏可见，「更多」里也不出现（桌面仍可用） */
  desktopOnly?: boolean;
}
```

然后 `ConsoleTabBar` 从 `mobileTab === true` 取，不再按 `slice(0, TAB_PRIMARY_COUNT)`。
**这样桌面顺序可以继续为桌面服务，移动端有自己的排序**——两个维度解耦。

⚠️ 落地时必须同步 `tests/test_*` 里对 `TAB_PRIMARY_COUNT` / `visibleNav` 的断言，否则会出现「源码改了测试还绿」的假象（本项目踩过，见 `topics/05`）。

## 4. 技术改动清单

### P0（不做内测就不成立）

#### P0-1 `viewport-fit=cover` 缺失 → 刘海/灵动岛遮挡

**问题**：全站写了大量 `env(safe-area-inset-*)`，但 `layout.tsx` 的 `viewport` **没有设 `viewportFit: "cover"`**。
在 iOS 上，没有 `viewport-fit=cover` 时 `env(safe-area-inset-*)` **恒为 0** —— 也就是说那些安全区代码从来没生效过。

这直接解释了「论坛线未上真机」这个欠账的后果：**这套 PWA 从没在 iPhone 独立窗口里打开过。**

**改法**（`src/app/layout.tsx`）：
```ts
export const viewport: Viewport = {
  width: "device-width",
  initialScale: 1,
  viewportFit: "cover",        // ← 新增，safe-area 才会生效
  themeColor: [...],
};
```

**判据**：真机添加到主屏后打开，页头顶部不被刘海压住、底部 tab 不被 Home 指示条压住。

#### P0-2 暗色模式状态栏黑字不可见

**问题**：`appleWebApp.statusBarStyle: "default"`（黑字）。暗色模式背景是 `#1A1610`，状态栏黑字 = 看不见。

**改法**：改 `statusBarStyle: "black-translucent"`，配合 P0-1 的 safe-area padding 让内容延伸到状态栏下。
**副作用**：所有页面顶部必须有 `padding-top: env(safe-area-inset-top)`，否则内容被状态栏盖住。
**判据**：浅色 + 暗色两种模式下，状态栏文字都清晰可读。

#### P0-3 移动端导航重排（§3）

**改法**：`lib/nav.ts` 加 `mobileTab` / `desktopOnly`，`ConsoleTabBar.tsx` 改用筛选。
**判据**：手机上 tab 是「对话 / 学习路径 / 论坛 / 打卡」；「更多」里没有每日委托/总结/四六级。

### P1（内测体验，建议本周做）

- **启动屏缺失**：没有 `apple-touch-startup-image`，iOS 启动会白屏 1–2 秒。用品牌纸色 `#EDE4C8` + 居中 logo 生成 6 个主流尺寸的 PNG（iPhone SE / 13 / 14 Pro / 15 Pro Max 等），写进 `<link rel="apple-touch-startup-image">`。
- **iOS 专属安装指引**：现有 `/install` 是三端通用教程。iOS 上真正卡人的是：**必须用 Safari**（微信内置浏览器打不开）、**必须点分享→添加到主屏幕**。这两句要在检测到 iOS 且未 standalone 时置顶。
- **首次打开的网络依赖**：内测时如果有人用 4G，`/api` 全部走线上域名，确认 `myzhisui.cn` 的证书链在 iOS 上没问题（ATS 强制 HTTPS，自签证书会直接拒绝）。

### P2（可延后）

- 离线兜底页文案针对 iOS 优化
- 主屏图标在暗色模式下的变体（iOS 18 支持 `theme_color` 变体图标）
- 快捷方式（shortcuts）在 iOS 上的验证——iOS 对 manifest shortcuts 支持有限，可能需要改用 URL Scheme

## 5. 内测分发流程（不写下来就会乱）

PWA 没有安装包，所以「分发」= 教会每个人装。**必须写成可转发的文档**，不能口头教。

1. 用 **Safari** 打开 `https://myzhisui.cn`（不能是微信/QQ 内置浏览器，不能是 Chrome iOS）
2. 点底部**分享**按钮 → 向下滑 → **「添加到主屏幕」**
3. 桌面出现「知穗Agent」图标 → 从图标打开（此时无地址栏 = standalone 生效）
4. 登录
5. 验证是否真的进了 App 模式：**从屏幕底部上滑，看不到 Safari 的地址栏**

⚠️ 常见失败：从微信里点链接打开 → 无法添加到主屏幕。这是最高频的失败原因，文档第一句就要写。
