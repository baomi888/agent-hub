# 纸张到边：把 14px 的桌面边收掉（第九批，2026-11-15 跨零点）

用户原话：

> 将当前样式调整为纸张背景延伸至边缘的效果，即背景色与纹理需铺满至容器边界、
> 不留内边距留白；同时将该容器整体尺寸在现有基础上适当放大一些，
> 保持原有布局结构与视觉比例协调，仅做尺寸微调。

这一批接着第八批（底部留白 54 → 34）的尾巴：当时留了一句话——
「如果 34px 还嫌多，我可以再试把输入框做成纸边到底的样式，
让那 26px 视觉上归给输入区，而不是空白」。用户选的正是这条路，并且往外扩了一层：
不只是输入框，整张纸都到边。

---

## 一、先把"纸"和"容器"分清楚

首页的层次原来是三层：

```
body            桌面 → 桌面渐变（desk-0 → desk-1）
  main.workbench-main   14px 外边距 / 圆角 / 外投影 / 纸色 + 左上受光
    .book-spine         --bg-canvas + --noise（纤维噪点）
      .chat-measure     内容版心 --measure
```

所以用户看到的"内边距留白"不是某一处的 padding，而是 `main` 那圈 14px（窄屏 8px）的
外边距——它让 body 的桌面色露出来，观感是"一张纸放在桌上"。要"铺满至容器边界"，
动的就是这一圈，而不是任何一个 `--chat-px`。

`main.workbench-main` 只有一个消费者（`app/page.tsx:910`），控制台 8 个页面走
`.console-shell`，所以这一改只影响首页。

## 二、改了七处

| 文件 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| `base.css` `main.workbench-main` | `margin: calc(14px + env(top)) 14px 14px`；`height: 100dvh - 28px - env(top)`；`radius: --radius-lg`；外投影 + 1px 描边 | `margin: env(top) 0 0`；`height: 100dvh - env(top)`；`radius: 0`；只剩 `inset` 书脊凹影 | 贴边后没有"外面"，圆角会切出四个角的桌面底，外投影没有落点只会在屏幕四边压出暗边 |
| `base.css` 纸面 | `background: 受光渐变, var(--bg-canvas)` | `background-color: var(--bg-canvas)` + `background-image: 受光渐变, var(--noise)` + `size/position/repeat` 分层写 | 纹理上移到 main，才能"从边到底连续" |
| `fx.css` 窄屏档 | `margin: calc(8px + env(top)) 8px 8px` 等 | 同上归零 | 两档必须同时改，否则手机上仍露 8px |
| `layout.css` `.book-spine` | 自己铺 `--bg-canvas` + `--noise` | 只留 `position: relative` | 两层噪点叠在一起会显脏，且侧栏与对话区会出现两种白 |
| `fx.css` ≤899 档 | 还藏着一条 `.book-spine { background-image: var(--noise) }` | 删除 | **线上探针抓到的**：390/768 的 `.book-spine` 仍有 `background-image`，1440 是 `none` |
| `tokens.css` `--measure` | 720 / 宽屏 800 | **736 / 816** | 纸宽多了 28px，栏宽按「内容宽 / 纸宽」之比守恒跟上：720 / 1412 ≈ 736 / 1440 |
| `chat.css` `--app-edge-y` | 14 / 8 | **0 / 0** | 卡片不再有外边距，安全区不需要再扣一截（否则 iPhone 上输入框会压到 home 条） |

`--app-edge-y` 的公式本身没动，仍是

```css
padding-bottom: max(var(--chat-dock-pb), calc(env(safe-area-inset-bottom) - var(--app-edge-y)));
```

值为 0 时它退化成 `max(12px, 34px) = 34px`，与第八批的结果**逐像素相同**：
第八批是「卡片外 8 + 卡片内 26」，现在是「卡片外 0 + 卡片内 34」。
也就是说这一批没有让底部留白变多或变少，只是把那 8px 从"屏幕外的桌面"
划进了"纸内"——这正是第八批结尾说的那件事。

## 四、纹理单层的证明（这一批真正的收获）

第一版改完，探针一跑就露了：

```
390  spine: {"bgColor":"rgba(0,0,0,0)","bgImage":"url(\"data:image/svg+xml,..."}
768  spine: {"bgColor":"rgba(0,0,0,0)","bgImage":"url(\"data:image/svg+xml,..."}
1440 spine: {"bgColor":"rgba(0,0,0,0)","bgImage":"none"}
```

桌面是对的、窄屏不是——因为 `fx.css` 的 `@media (max-width: 899px)` 里还躺着一条
`.book-spine { background-image: var(--noise) }`。它写在「窄屏收紧版面留白」那段注释下面，
和留白毫无关系，属于历史遗留。

这件事暴露的是**断言的扫描范围问题**：第一版 `test_paper_texture_lives_on_main_only`
只读了 `layout.css` 的那条规则，`fx.css` 完全没扫。已改成两个文件全文扫：

```python
for name, css in (("layout.css", layout), ("fx.css", fx)):
    stray = re.findall(r"\.book-spine\s*\{[^}]*background", css)
    assert not stray
```

改完复测，三个视口的 `bgImage` 全部 `none`。

## 六、这一批自己踩的四个坑

1. **`Path.read_text(newline=...)` 又是 3.13 的 API**。本地 3.12 直接 `TypeError`，
   反证脚本第一轮打印「0/1 真红，异常 1」。上一批已记过一次，这次换成
   `open(..., newline="")` 并写进脚本注释——同一个坑连踩两次，说明"记住"不够，得写进代码。
2. **反证节点名又拼错**：`f"::{test}"` 里 test 已含 `test_` 前缀，我写成 `::test_{test}`
   → `no tests ran`，pytest 返回 5，11 条全"红"。这次的修法不是记住前缀，而是让
   `red()` 主动识别 `no tests ran` 并返回"未变红"——**让失误以"没验证"的形状暴露，
   而不是伪装成"验证通过"**。
3. **替换锚点撞到别处**：layout.css 里有 3 个以 `position: relative;\n}` 结尾的规则，
   反证用例替换第一处会改错对象（改了个无关地方还假红）。锚点补上选择器名。
4. **注释让断言变红**：我在 `fx.css` 里把删掉的旧规则原文写进注释留档，
   结果 `\.book-spine\s*\{[^}]*background` 扫到了注释。修法是给测试加 `_css()`
   剥注释，而不是改注释措辞——**注释能红也能绿，只有剥掉注释的断言才可信**。

## 八、未验

- **真机**：`env(safe-area-inset-top)` 在刘海机上是否真的把纸推到状态栏之下；
  贴边后 iOS 的橡皮筋回弹会不会露出 body（`overscroll-behavior` 未单独处理）。
- **横屏**：安全区左右各 44px（横屏刘海）时纸仍然铺满，内容会不会被刘海压住——
  现在只让了 top，**没让 left/right**。竖屏无影响，横屏有可能。
- **居中折叠屏 / 超宽屏**：`--measure` 736 在 2560 以上是否该继续加宽，这轮没碰。
