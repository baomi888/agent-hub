## 2. 最终用户行为

### 2.1 注册

- 保留用户名、密码及现有“注册并登录”行为。
- 在密码下面增加必填邮箱和邮箱验证码。
- 用户必须验证邮箱后才能注册成功；后端同样强制验证，不能只靠界面限制。
- 不提供手机号输入框、手机号验证或短信发送。
- 邮箱变更后，旧验证码和已验证状态不能用于新的邮箱。
- 同一个安全邮箱只能绑定一个账号。
- 保留现有用户名保留规则、密码规则、账号状态和关闭注册的开关。

### 2.2 登录和密码显示

- 继续使用用户名和密码登录，不增加邮箱验证码免密码登录。
- 登录、注册及重置密码框右侧提供“小眼睛”。
- 默认隐藏密码；切换显示不改变内容，也不提交表单。
- 登录页密码一行右下方提供“找回密码”入口。
- 不提供手机找回或手机/邮箱选择器。

### 2.3 找回密码

1. 打开找回密码页面，输入账号已绑定的安全邮箱。
2. 请求真实邮件验证码，输入并验证。
3. 验证成功后取得短期、一次性重置凭证。
4. 输入两次新密码。
5. 前后端都检查两次一致，并使用现有密码规则。
6. 成功后旧密码、旧登录会话和其他未消费的找回凭证失效。
7. 清除页面密码、验证码和临时凭证，跳转登录页重新登录；不自动登录。
8. 发送阶段不明确暴露邮箱是否注册，避免被用来查询用户。
9. 未绑定邮箱的历史账号不能通过该流程找回密码。

### 2.4 设置中的安全邮箱

- 新增“账号安全 / 安全邮箱”区域，显示脱敏邮箱及验证状态。
- 历史用户没有安全邮箱时，可以验证新邮箱并绑定。
- 已绑定用户可以换绑；不允许解绑后让账号没有安全邮箱。
- 原先的“解绑必须验证、至少保留一种联系方式”在仅邮箱版中落实为：
  验证旧邮箱和新邮箱后，一次性换绑，不暴露单独清空邮箱的操作。
- 旧、新邮箱证明必须属于同一用户和同一换绑流程。
- 换绑失败保留旧邮箱；成功后旧邮箱不能继续用于找回该账号。
- 无法收取旧邮箱验证码时，本版不提供绕过验证的换绑或人工申诉入口。

### 2.5 历史账号与邮件提醒兼容

- 不强制历史账号立即绑定邮箱，也不阻止其正常登录和使用。
- 设置中提示补绑，以获得密码找回能力。
- 现有“邮件提醒邮箱”和“安全邮箱”保持独立，复用发送底层，不复用验证码或绑定状态。
- 不自动把提醒邮箱迁移为安全邮箱；不读取真实用户数据进行自动补绑。
- 原邮件提醒的启停、验证、删除不应改变账号安全邮箱。
- “不能留空”的规则适用于已经绑定安全邮箱的账号，不要求历史空邮箱账号先绑定才能登录。

## 5. 数据与接口设计

### 5.1 数据结构

沿用 SQLite，优先新增专用表，不修改旧账号字段含义。

| 表（建议名） | 关键内容与约束 |
| --- | --- |
| security_emails | user_id 唯一、标准化邮箱唯一、验证时间、绑定版本/记录标识 |
| verification_requests | 流程标识、用途、目标邮箱、关联用户/注册上下文、验证码摘要、有效期、错误次数、状态 |
| verification_grants | 一次性凭证摘要、用途、账号/邮箱/绑定版本、流程、期限、消费时间 |
| verification_rate_limits | 接收方、IP、账号、全局发送限制与时间窗口 |

要求：

- 明确邮箱标准化策略，前后端一致；不擅自合并不同邮箱的点号或加号别名。
- 邮箱格式与最大长度在后端验证；唯一性由数据库约束兜底。
- 未验证邮箱不算绑定，不永久占用地址。
- 验证码与凭证只保存受服务端秘密保护的摘要；不记录明文验证码或密码。
- 绑定、换绑、账号创建或密码重置，与凭证消费在同一事务完成。
- 迁移幂等，不自动把真实历史邮箱标为安全邮箱。
- 迁移代码仅在临时库和合成历史库验证，不能因 import、启动或测试触碰真实用户库。
- 记录脱敏安全审计；日志不包含完整邮箱、验证码、凭证或密码。

### 5.2 验证码和凭证默认规则

| 项目 | 第一版默认值 |
| --- | --- |
| 邮件验证码 | 6 位安全随机数字 |
| 验证码有效期 | 10 分钟 |
| 同一流程重发冷却 | 60 秒 |
| 每个验证码错误上限 | 5 次 |
| 同一邮箱每日发送上限 | 10 次，按 Asia/Shanghai 日期统计 |
| 重置/换绑凭证有效期 | 5 分钟，一次性 |
| IP 与账号短时限额 | 初始建议每 10 分钟 20 次，独立于邮箱限额 |
| 全局发送预算 | 可配置，真实服务接入时按额度设置 |

这些限额是待实现的配置默认值，不表示现有提醒邮件限额同步改变。
无效或未注册邮箱请求也纳入接口限流。服务重启不能重置发送次数。

用途严格隔离：register_email、bind_email、change_email_old、change_email_new、reset_password。
各用途不能互用；绑定/换绑校验当前登录身份。
发送网络请求不放在长数据库事务中；预留、发送、激活状态分离，失败不能生成有效绑定。
重发成功后旧验证码作废，异步迟到的发送结果不能覆盖新请求。
验证成功只发放特定操作的证明，不生成通用登录令牌。
换绑或改密时检查账号鉴权代数/绑定版本，拒绝已经过时的凭证。

### 5.3 接口草案

| 方法和路径 | 功能 | 鉴权 |
| --- | --- | --- |
| POST /api/auth/email/code/send | 按用途发送邮件验证码 | 注册/找回公开；绑定/换绑需登录 |
| POST /api/auth/email/code/verify | 验证验证码，签发短期用途凭证 | 按用途判断 |
| POST /api/auth/register/ | 用户名、密码、邮箱及验证证明，原子注册绑定 | 无需登录 |
| GET /api/auth/security-email | 脱敏邮箱与绑定状态 | 需登录 |
| POST /api/auth/security-email/bind | 历史账号首次绑定 | 需登录 |
| POST /api/auth/security-email/change | 使用旧、新邮箱证明原子换绑 | 需登录 |
| POST /api/auth/password/reset | 重置证明、两次新密码 | 无需旧登录态 |
| GET /api/auth/config/ | 扩展注册需邮箱、邮件服务能力等配置 | 公开 |

没有手机号接口，没有单独删除唯一安全邮箱的接口。
旧邮箱接收地址必须从当前账号绑定记录取得，不由前端任意指定。
禁止前端指定目标 user_id；账号来源于服务端会话或一次性证明。
响应保留已有兼容字段，不返回密码散列或服务凭证。
找回发码对“未注册”和“已注册”返回相同业务文案；故障采用不暴露账号存在性的提示。
