这两个问题都是当下正在演进的产品机制，我先查证具体实现细节，避免凭印象讲。
这两题都查到了实质细节，其中 DeepSeek 的情况跟你的预期可能不一样。我先把机制画出来。
Hermes 的关键在于：**它进化的不是模型层，是 agent 层**——不微调、不训练，只在模型外面裹一层记忆和技能。三层分别是工作记忆（上下文压缩+会话血缘）、陈述记忆（`MEMORY.md` 存环境事实、`USER.md` 存用户画像，靠 FTS5 全文检索跨会话召回）、程序性记忆（Skills）。

真正值得抄的是**提炼门槛**——它明确规定只有三类事才配被写成技能：需要 5 次以上工具调用的复杂任务、反复修改才过关的任务、以及反复出现的有价值工作流。而且是agent 自我评估后才创建，不是每轮对话都提炼。技能被调用时若被发现过时或不好使，它会用 patch 工具自己打补丁。

这套结构完全可以迁移到「对话提炼到个人知识库」，但需要加一道 Hermes 没有明说的约束。
再看第二个问题。这里有个反直觉的发现：**DeepSeek 恰恰是没有做个性化的那一个**。四家的路线差异极大，我按「推断强度」和「用户可控度」给它们定了个位：
## 一、Hermes 的自进化

**核心定位**：Nous Research 出品的开源 Agent。它最反直觉的一点是——**进化的不是模型层，是 agent 层**。不微调、不训练，只是在模型外面裹一层「记忆 + 技能 + 验证习惯」。所以你在任何 LLM 上都能跑。

**三层分工**（对应认知科学）：

| 层 | 载体 | 关键设计 |
|---|---|---|
| 工作记忆 | 上下文压缩 + 会话血缘 | 防止长任务断线 |
| 陈述记忆 | `MEMORY.md`（环境/项目事实）+ `USER.md`（用户画像） | **边界策展**：只把最关键的注入系统；FTS5 全文检索跨会话召回 |
| 程序性记忆 | Skills | 自动沉淀 + 使用中自修复 |
| （可选）训练数据 | 任务轨迹 → Atropos RL | 反哺下一代模型 |

**最值得抄的一条：提炼是有门槛的。** 它明确规定只有三类任务才配被写成技能：

- 需要 **≥5 次工具调用**的复杂任务
- **反复修改才过关**的任务
- 反复出现的有价值工作流

而且要经过 agent **自我评估**后才创建。对比绝大多数系统的「每次对话都总结一遍」，这恰恰是 Hermes 不产生垃圾的原因。

**第二个是「用中自修复」**：技能不是写死的。调用时若被发现过时或命令失效，它会**主动打补丁**。所以技能的价值边缘在于器 step + 踩过的坑 + **验证方法** + 环境路径——注意它把「验证方法」写进了技能定义里，这很少见。

底层还有三个原则：**Prompt Stability**（稳定前缀保缓存与行为一致）、**Frozen Snapshot**（按节奏批量更新，不是每轮改——这正好就是你「每日夜间处理」的形态）、**Profile Isolation**。

它自己也承认失败模式：**存太多 / 存错东西 / 不验证就宣称成功**。

## 二、能不能迁移到「对话提炼到个人知识库」

能，但**必须补一道 Hermes 没有明说的约束：溯源**。

这道约束正是昨天我们给 agent-hub 判的那条：**总结会放大幻觉**。如果被提炼的源对话本身含幻觉，提炼就等于把幻觉固化成一条看起来很确定的知识——图和文本只是形态不同，机理完全一样。所以「不可指回原文的话不许入库」不是洁癖，是防污染。

另外三条建议：

1. **门槛照抄**：不要每轮都提炼。`重复≥2次` 或 `你手动修正过它` 才入库。后者是极强的信噪信号——用户动手改的地方，才是真正该记住的地方。
2. **必须挂元数据**：来源指针 + `last_verified` + 衰减权重，并在再次命中时重新校验。没有衰减机制的知识库会**越用越僵化**，把某次偶然的偏好固化成永久规则。这正好是 Hermes 列的第一条失败模式。
3. **别只做向量库**。见下文——四家里赢的都是可读可改的文本文件。

顺带一提：**你自己那个 `daily-review-loop` skill 其实就是「程序性记忆」的雏形**。它已经是一份「把一次成功经验变成可复用能力」的技能文件了——你要做的不是从零设计，而是把这个模式自动化。

## 三、大厂 Personal Agent 怎么做个性化

**先说结论：这三家里，DeepSeek 恰恰是没做个性化的那一个。**

| | 记忆形态 | 可见可控 | 「个人风格」从哪来 |
|---|---|---|---|
| **DeepSeek** | **无跨会话记忆**。每次新对话归零，无偏好存储、无管理界面、甚至没有对话全文搜索（只按标题列） | 无功能故无控制 | 靠 128K 长上下文在**单次会话**内维持；2026-01 的 Engram 是「conditional memory」，仍只在会话内 |
| **Grok** | 双 tier：128K 上下文 + 持久记忆（把「你是素食者/你写 Python」蒸馏成事实存向量，语义检索注入） | **最高**：回答里 book icon 显示引用了哪段记忆、可单条删、总开关、Private Chat 不入库 | ①用户自定义指令（~4000字符）②Custom Agents（≤4 个，各自 system prompt）③**Grok Skills**——关键是**可以直接让 Grok「把从你身上学到的存成 skill」**，和 Hermes 几乎同构 |
| **Meta Muse** | **每联系人一页 dossier，每小时更新**；含 args 你们的相遇、共同兴趣、**「争执与结盟」** | 较弱：VM 隔离/导出/forget，但**「forget」不删原始聊天记录** | **推断你「没有说出口的」目标**。每晚分析当日对话；内部示例原话：「该用户晚上 10 点后对短提示的反应更好」 |

### 三条共性

**1. 赢的不是向量库，是可读可改的文本文件。** Muse 是「每联系人一页结构化文本」，Hermes 是 `MEMORY.md`/`USER.md` 明文。向量只负责检索，**事实放在人类能编辑的地方**才谈得上可控。

**2. Muse 是 Hermes 第三层的激进产品化版。** 它的内部指令写明各 VM 之间通过**去标识化的共享学习互相教**——这就是 Hermes「轨迹反哺模型」的消费版。区别在于一个对象楼盘性能 Teach with unverified inferred data。

**3. 透明度是分野，不是能力。** Grok 与 Muse 在「能推断出什么」上差距没那么大，真正的差别是：一个给你看 book icon 让你逐条删，一个把推断沉在你看不见的地方，还连你没注册的朋友一起建档（例如苹果ွ在 Marketplace 交流中泄露用户家庭住址）。

### 给你的一点判断

如果你要做「对话提炼到个人知识库」，**别学 Muse，学 Grok + Hermes 的混合**：

> 提炼结果落在**明文文件**（可读可改可控）→ 提炼有**明确门槛**（不是每轮都做）→ 条目**必须可溯源**（防幻觉固化）→ 带**衰减与重校验**（防越用越僵化）→ 用户**能逐条删**。

这五条每一条都能直接对应到你昨天那份 agent-hub 判定里的 P0/P2，而且成本低——不需要训练模型，只需要在模型外面加一层存储纪律。
