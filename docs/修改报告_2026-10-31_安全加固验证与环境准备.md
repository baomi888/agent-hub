### 1.1 S-03 注册与登录防滥用

注册新增三道闸（`api/auth.py::register`）：

| 维度 | 配置项 | 默认 | 落库键 |
|---|---|---|---|
| 同 IP 每分钟 | `SIGNUP_IP_PER_MINUTE` | 10 | `signup:ip:<ip>` |
| 同 IP 每日 | `SIGNUP_IP_PER_DAY` | 50 | `signup:ip:<ip>` |
| 全站每日 | `SIGNUP_GLOBAL_PER_DAY` | 500 | `signup:global` |

- IP 取值优先 `X-Forwarded-For` 首个地址，回退直连地址（`_client_ip`）。
- 每日计数走 `core/quota.py::consume_key`：任意维度记账、不豁免管理员、超限不计数。
- 默认值偏宽松，避免误伤本机演示与自动化测试；公网建议收紧到 3 / 10 / 50。

登录新增失败锁定（`core/account.py`）：

- `users` 表幂等补列 `failed_count`、`lock_until`，老库自动迁移。
- 连续失败 `AUTH_MAX_FAILS`（默认 5）次后锁 `AUTH_LOCK_MINUTES`（默认 15 分钟）。
- 锁定期内不再执行 PBKDF2 校验；登录成功清零；锁到期自动恢复。
- 登录提示改为“账号已被停用或锁定”，可区分停用与临时锁定。

### 1.2 S-06 / S-07 上传配额

| 位置 | 改动 |
|---|---|
| `api/chat.py::upload_attachments` | 补 `Depends(get_current_user)`；落盘前校验 `UPLOAD_TOTAL_MB`（默认 200MB）；落盘后按实际字节扣 `upload` 日额度，超限删除刚落的文件 |
| `api/kb.py::upload_and_build` | 同样的单次总大小校验；落盘后按实际字节扣同一张 `upload` 日额度，超限清理本次落盘文件 |
| `core/quota.py` | 新增 `upload` 配额类型（`DAILY_UPLOAD_MB`，默认 2000MB/人/日） |

记账单位为 MB、向上取整、最小 1MB；聊天附件与知识库文档共用同一张日账。

### 1.3 S-08 防火墙

`deploy.sh` 的 firewalld/ufw 分支只放行 `FRONT_PORT`；`BACK_PORT` 仅监听 `127.0.0.1`，不再开公网入方向。同步修正“后端没有任何鉴权”的过时注释，并说明放行 8000 会让 XFF 可伪造。

### 1.4 S-09 / S-10 跨域与信息泄露

- `main.py` 仅在 `CORS_ALLOW_LOCALHOST=1` 时注册 localhost CORS；生产同源部署应设 0。
- `/health` 默认只返回 `{"status":"ok"}`；版本号与 `llm_gate` 快照仅在 `HEALTH_DETAIL=1` 时返回。
- `kb/rag_core.py::describe_api_error` 未知异常不再回显类名与原文，原始异常写 warning 日志；已知 401/402/404 文案保持不变。

### 1.5 S-11 依赖上界与 SCA

- `requirements.txt` 为 fastapi / uvicorn / sse-starlette / python-multipart / pypdf / sqlalchemy / httpx / python-dotenv / pydantic / pillow 增加主版本上界。
- `.github/workflows/ci.yml` 增加 `pip-audit -r requirements.txt`，当前为 `continue-on-error`。
