## 3. 当前仍打开的洞（已逐条核实到代码）

### 🔴 P0-1　`X-Forwarded-For` 第一跳可伪造（**两个分支都有**）

**证据链**（两边都在仓库里）：

```
https/agent-hub.conf.template:73,93,105,121
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;   ← 追加，不覆盖
api/auth.py:116
    raw = (request.headers.get("x-forwarded-for") or "").split(",")[0].strip()   ← 取第一跳
```

即：客户端自带 `X-Forwarded-For: 1.2.3.4`，nginx 追加真实 IP，后端取到 `1.2.3.4` → 伪造成立。

**影响**：`SIGNUP_IP_PER_MINUTE=10`、`SIGNUP_IP_PER_DAY=50`、`login:ip:<ip>` 的 30 次/分钟
**全部可被旋转 header 绕过**；任何"按 IP 风控"的后续设计都会继承这个洞。

**修法（两处必须同时改，只改一处无效）**：
1. nginx：`proxy_set_header X-Forwarded-For $remote_addr;`（覆盖）；
2. 后端：只信"最后一跳"或仅在可信代理（回环）时才读 XFF。

### 🔴 P0-2　注册先扣额度、后建号（**两个分支都有**）

**证据**（`api/auth.py`，dev 与 main 行号一致）：

```python
L251  quota.consume_key(f"signup:ip:{ip}", "signup_ip", config.SIGNUP_IP_PER_DAY)
L252  quota.consume_key("signup:global", "signup_global", config.SIGNUP_GLOBAL_PER_DAY)
...
L257  user = account.create_user(body.username, body.password)
```

**影响**：409（重名）/ 400（校验失败）**也会消耗** `signup_ip` 与 `signup_global`。
攻击者不用真的注册成功，只要反复提交重名请求就能**打满全站注册额度**（`signup_global`），
合法用户当天注册不了——这是可用的拒绝服务面，不只是"口径偏差"。

**修法**：`consume_key` 移到 `create_user()` 成功之后；或失败路径显式退还。

### 🔴 P0-3　`dev` 缺「删号墓碑」闸门（main 已修，dev 从未合入）

**证据**：

| 位置 | main | dev |
|---|---|---|
| `core/session.py` 建 `deleted_users` 表 | ✅ | ❌ |
| `core/auth.py`：`if row is None and account.is_deleted(uid): 401` | ✅ | ❌ |
| `core/account.py::is_deleted` | ✅ | ❌ |
| `tests/test_deleted_user.py` | ✅ | ❌ |

引入提交是 `99d4249`「fix: 手机端资料预览交系统阅读器；删号吊销令牌；看板解释人数变化」，
`git branch -r --contains` 确认**只在 origin/main**。

**影响**：在 dev 的代码上，账号被 `DELETE` 之后，其签名合法的 cookie（7 天有效）**仍然通过鉴权**——
因为 `row is None` 时会按「鉴权代数 0」处理，而令牌里的 `af` 也是 0，比较相等即放行。
这正是 `security/` 报告里 75 个"幽灵身份"的成因；main 已经封堵（墓碑 2 → 77），dev 没有。

**为什么这条要单独标红**：它不是"dev 少个功能"，而是 **`dev → main` 合并时的回退风险**——
如果合并时整文件取 dev 的 `core/auth.py` / `core/session.py`，这个闸门会被静默删掉，
而账面上"合并成功、测试全绿"（因为 dev 没有对应测试）。
