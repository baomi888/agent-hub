## 1. 改了什么

### 1.1 路由：删规则层，只问模型

| 文件 | 改动 |
|---|---|
| `core/router.py` | 删除 `_STRONG/_MID/_SEQ/_OPEN/FLOW_MIN_SCORE/score_flow()/classify_flow_open()`；`decide()` 改为一次轻量 LLM 输出 `workflow` / `agent`；任何失败兜底 `agent` |
| `hybrid/switcher.py` | 删除 `classify_task()`（原先把规则层包一层同步壳），留下说明注释 |
| `api/chat.py` | 混合分支不再自己判起跑方向，直接用路由结果 `plan.route` |

**为什么删规则层**，写进了 `core/router.py` 的模块文档，三条：

1. 中文不分词，「先生 / 优先 / 最后一个问题」会被「先 / 最后」按子串命中——24 条真实问句里误判 4 条；
2. 规则只认字面，认不出「把这三篇论文对比着列个表」这种没有顺序词但明确要多步的任务；
3. 误判代价两边都不可接受：多步被当闲聊=泛泛而谈，闲聊被当多步=白跑一次规划加一整轮智能体。

**兜底为什么是 `agent` 而不是 `workflow`**：工作流要多跑一次规划 + 一串节点，兜底时最该省的就是这段；智能体在没有工具时就是一次普通问答，退化成本最低。副作用是 `ROUTER_ENABLED=0` 的语义变干净了——关掉路由 = 永远走智能体。

### 1.2 请求契约：两个开关 + 旧 mode 兼容

`ChatRequest` 新增 `use_kb` / `use_web`，类型是 `bool | None`。用 `None` 而不是 `False` 做默认值，是为了区分两种情况：

- `None` = 调用方没传这个字段（旧前端 / 内部脚本）→ 回落到 `mode` 兼容映射
- `False` = 明确关掉

映射表（`api/chat.py::_resolve_switches`，唯一翻译处）：

| 旧 mode | use_kb | use_web | 说明 |
|---|---|---|---|
| `rag` | True | False | 用户明确只检索 |
| `llm` | False | False | 明确什么都不用 |
| `agent` | has_kb | True | 旧 agent 本来就绑了全部工具 |
| `hybrid` | has_kb | True | 工作流里也能检索/联网 |
| `auto` | has_kb | True | 绑库仍会检索（与旧 auto 一致），无库时保留联网 |
| 脏值 | has_kb | True | 按 auto 处理，不让它穿透 |

### 1.3 执行分支：`_pick_mode` → `_plan_route`

`_pick_mode` 返回一个字符串，信息不够（后面要用开关、要知道路由结果）。换成 `PlannedRoute` 数据类：

```python
mode    # hybrid | agent | rag | llm —— 决定进哪个分支
route   # workflow | agent —— hybrid 分支内的起跑方向
use_kb  # 是否使用知识库
use_web # 是否允许联网
source  # fields / mode:xxx / router —— 只进日志
```

分支选择规则：

```
显式 mode=rag/llm/agent  → 直通对应分支，不问路由（零行为变化的兼容口）
其余（auto / 新契约）    → 问路由：
    workflow → hybrid（引擎关了退 agent）
    agent    → 有任一开关进 agent；两个都关进 llm（省掉一层 ReAct 循环）
```

最后这条是有意的：两个开关都关意味着没有工具可绑，再套一层智能体循环只是多花 token 和延迟。

### 1.4 工具集：删算数、留天气、按开关绑定

| 文件 | 改动 |
|---|---|
| `agent/tools.py` | 删除 `calculator` 函数与 `_CALC_*` 常量（63 行）；`AGENT_TOOLS` 变为 `[kb_search, web_search, get_weather, download_file]`；文件头与段落编号重排 |
| `core/tool_registry.py` | 删除 `TOOL_META["calculator"]` 与 `TOOL_PLAYBOOK["calculator"]`；两处「5 个工具」注释改为 4 个 |
| `agent/builder.py` | 新增 `_tool_allowed()`；`build_agent()` 加 `use_kb` / `use_web`；`_cache_key()` 加两个开关维度（改成 keyword-only，避免调用方传错位置） |

绑定规则（`_tool_allowed`）：

| 工具 | 生效条件 |
|---|---|
| `kb_search` | `use_kb and 会话有库` |
| `web_search` / `download_file` | `use_web`（下载依赖搜索产出的允许清单，同开同关） |
| `get_weather` | **无条件常驻** |

字段 `get_weather` 不挂开关：它是只读感知工具，问天气才调，不会增加无谓开销。

### 1.5 提示词：从「五个能力并列」改成「开关决定能力」

`SYSTEM_PROMPT` 重写要点：

- 开头改成「本轮实际可用的能力由用户开启的开关决定」，逐条标注生效条件；
- 第 1 条从「自主选择工具」升级为「工具清单里没有的能力就是本轮没开——如实说明，不要假装调用，也不要绕道实现」；
- 第 2 条写明「资料类问题优先查知识库，库里确实没有且允许联网时再上网」——这就是决策表说的「库优先、联网其次」；
- 删掉「数学计算必须用 calculator」整条，改为第 9 条尾巴「算术、换算、日期差自己算，但要复核进位和运算优先级」；
- **保留原第 8 条 grounding 约束原文**（10-17 那次修复的核心，不能动）。

`build_agent` 里的动态段落也按开关分了三支：已绑库 / 开了检索但没库 / 没开检索；再单独一段说明「本轮未开启智能联网」。

### 1.6 检索前置（决策表 D5）

`api/chat.py` 的 agent 分支新增：`use_kb && 有库` 时**先跑一轮检索**，把片段拼成 `【参考资料】` 插进最后一条用户消息，同时发 `sources` / `grounding` 帧。

为什么不让模型自己调 `kb_search` 了事：

1. 用户明确开了「检索」，期望是"用了我的资料"，不能靠模型自觉；
2. 先检索才能把 `sources` / `grounding` 赶在正文前发给前端；
3. 片段已在上下文里，模型想补检索还能再调一次。

抽出 `_references_text()` 让 rag 分支和预检索共用一份拼装口径——两处各写一遍的话，引用卡片和正文里的 `[1]` 迟早指的不是同一段。

检索失败不阻断：降级为"没有参考资料"，并发一条 status 说明，模型照常作答。

### 1.7 混合引擎的开关透传

`AgentEngine` 和 `HybridOrchestrator` 加了 `use_kb` / `use_web`，一路透传到工作流 `execute` 节点里的 `build_agent`。不透传的话会出现「用户关了联网，工作流里仍在联网」。

`ctx.agent_state["kb_id"]` 与 agent 分支的 `configurable["kb_id"]` 都改成「没开检索就不注入」，避免模型绕过开关拿到本不该用的资料。

### 1.8 模板推荐模式

`api/templates.py::apply` 增加 `use_kb` / `use_web` 两个派生字段；`recommended_mode` 保留原值但标注废弃。推导口径与 `_resolve_switches` 一致。

`core/templates_catalog.py` 的 8 处数据**没动**——前端这轮不改，两套字段并存一个版本，等前端切到新字段后再删旧值。

## 3. 前端不改会怎样（重要）

这轮不动前端，所以线上仍会发 `mode`。逐档说明行为变化：

| 前端现状 | 后端行为 | 变化 |
|---|---|---|
| 点「检索」→ `mode:"rag"` | 直通 rag 分支 | **无变化** |
| 点「纯对话」→ `mode:"llm"` | 直通 llm 分支 | **无变化** |
| 点「自动」→ `mode:"auto"` + 绑库 | 映射 use_kb=True/use_web=True → 判 workflow/agent | **有变化**：从「纯检索」变成「先检索 + 智能体（可补检索/可联网）」 |
| 点「自动」→ `mode:"auto"` + 无库 | 映射 use_web=True → agent | **轻微变化**：工具从 5 个减为 4 个（少算数），多了预检索尝试（无库时跳过） |
| 任何触发工作流的请求 | 路由判 workflow → hybrid | **有变化**：不再由关键词决定，改由模型判 |

`done.mode` 仍回 `rag` / `llm` / `agent` / `hybrid`，前端轨迹渲染逻辑不用改。

## 5. 前后端对接（给接手前端的人）

### 5.1 请求体

```http
POST /api/chat/stream
Content-Type: application/json

{
  "sid": "会话 id",
  "question": "用户问题",
  "use_kb": true,      // 可选，不传 = 按 mode 兼容映射
  "use_web": false,    // 可选
  "top_k": 5,
  "scenario": null,
  "attachments": [],
  "location": { "lat": 23.1, "lon": 113.3 }
}
```

- `use_kb` / `use_web` **不传**时才会读 `mode`；两个都不传等价于 `mode:"auto"`。
- `mode` 请尽快停止发送，但后端会继续接受一个版本周期。
- 两个都不传（或都 `false`）= 纯大模型，不查库不联网。

### 5.2 SSE 帧（只列变化）

| 帧 | 变化 |
|---|---|
| `sources` | agent 分支现在也会发（预检索命中时），字段不变：`{items:[{...}]}` |
| `grounding` | 同上，`{weak: bool, ...}`，仍赶在正文前 |
| `done.mode` | 取值不变（`rag/llm/agent/hybrid`），可继续用于 `hybrid.onDone()` |
| `status` | 新增两类文案：`知识库检索不可用：…`（预检索失败）、`检索到 N 条片段`（预检索命中） |

### 5.3 待前端改造的点（板块 C）

1. 模式条（自动/检索/纯对话）→ 两个 toggle：「检索」「智能联网」，默认都关；
2. 请求体 `mode` → `use_kb` / `use_web`；
3. 顶栏「能力」弹层整块删除（四卡假选择，算数/天气卡随之消失）；
4. 设置页工具表去掉「数学计算」，保留天气；
5. 引导文案改为「直接问；需要资料就开检索，需要最新信息就开智能联网」；
6. `usePrefs` 旧值迁移：`auto`/`agent`/`hybrid` → 两个开关都关；
7. 模板跳转 `?mode=` 停止传递，改读接口返回的 `use_kb` / `use_web`。
