## 2. 新增文件详细

### 2.1 `core/sediment_store.py`

- `ensure()`：`CREATE TABLE IF NOT EXISTS user_prefs / kb_proposals / sediment_batches`（DDL 见接口文档 §10）。
  - 模式照抄 `core/user_feedback.py:118-142`：`from core import session as store; with store._get_conn() as conn: ...`，模块级 `_READY` 按库路径缓存。
- `get_prefs(owner)` / `set_prefs(owner, **fields)`：无行时返回默认 `{auto_sediment: True, auto_create_kb: True}`。
- `create_proposal(owner, sid, topic, source, payload, ttl_hours)` / `get_proposal` / `update_proposal`。
- `topic_of(owner, sid)`：优先 `store.get_conversation(owner, sid)["title"]`；无标题取首条 user 消息前 24 字；再兜底「未命名对话」。
- `add_batch(...)` / `find_batch(...)`；`(owner_id, sid, content_hash)` 唯一索引做入库幂等。
- 单测可直接 monkeypatch `core.session._db_path` 到临时目录（参考 `tests/test_compress_v2.py` 的 `setUp`）。

### 2.2 `core/kb_proposals.py`

- `maybe_propose(owner, sid, *, use_kb, use_web, kb_bound, web_sources)` → `dict | None`
  - `no_kb_retrieval`：`use_kb and not kb_bound and prefs.auto_create_kb`
  - `web_search`：`use_web and web_sources`
  - 冷却：同会话同 source 10 分钟内已有 pending → 返回 None
  - 返回字段与 SSE `data` 完全一致（接口文档 §5.1）
- `confirm(owner, proposal_id, name=None, bind=True)` → 业务实现：建库/复用 → 入库 → staged → 绑会话 → 更新状态。
  - 复用/抽库名：`kb_hint` 默认「对话沉淀·{topic}」；同 owner 同名库存在 → 复用（`pipelines.list_all(owner)` 匹配 name）。
- `dismiss(owner, proposal_id)`。

### 2.3 `service/sediment.py`

```python
JOB_KEY = "sediment.dialogue"

def enqueue(owner, sid, boundary_id) -> bool      # core.scheduler.enqueue_job(...)
def run_one(job_key, subject_id, planned_at) -> dict
def ingest_candidates(owner, sid, kb_id, indexes=None, *, source="manual") -> dict
```

- `run_one`：偏好 → 消息 → `dialogue_import.extract_candidates` → `topic_of` → 复用/建库 → `quota.guard("embed")` → `pipe.add_chunks` → `mark_segments_staged` → `add_batch` → `bump_usage` → `{"tokens_out": n}`。
- `ingest_candidates`：手工 API / worker / B 的工具三条路共用；内部做候选重提取（防伪造）与下标校验。
- 全部同步函数（worker 线程里跑），不引入 async。

### 2.4 `api/kb_proposals.py`

- `prefix="/api/kb"`（与现有 kb router 同前缀、不同文件，`main.py` 直接 include 即可，路径不冲突：`/proposals/...`）。
- `POST /proposals/{id}/confirm`、`POST /proposals/{id}/dismiss`、`GET /proposals/{id}`。
- 依赖：`Depends(get_current_user)`；所有业务逻辑委托 `core.kb_proposals`，HTTP 层只做状态码映射（404/409/410/400）。

### 2.5 `api/prefs.py`

- `prefix="/api/prefs"`：`GET ""`、`PUT ""`；请求模型 `PrefsUpdate`（字段可选 bool）。
- 未登录 401；非 bool 422（Pydantic 自动）。

### 2.6 `kb/admin.py`

- `list_documents(owner, kb_id)`：复用 `pipelines.get_status` + `api/kb.py::list_files` 的底层逻辑（把该端点里的循环抽成函数，端点改为调用它 —— 只动 `api/kb.py` 的 `list_files` 函数体，不动契约）。
- `delete_documents(owner, kb_id, names)`：复用 `api/kb.py::delete_file` 的逻辑（同样抽函数）。
- `create_kb(owner, name)`：`pipelines.create_kb` 薄封装。
- 目的：B 的工具函数直接调这层（同步），不再复制一遍端点代码。

### 2.7 测试

- `tests/test_sediment.py`：
  - 建表/默认偏好；
  - `maybe_compress` 成功后 `job_runs` 出现 `sediment.dialogue` pending（monkeypatch `session._db_path`，`force=True`）；
  - `run_one` 全链路（FakeEmbedding）：入库数量 >0、`staged=True`、batch 写入、同 content_hash 第二次跳过；
  - 偏好关：不建库；
  - `enqueue` 同一 boundary 两次只有一行。
- `tests/test_kb_proposals.py`：
  - 偏好 API（200/401/422）；
  - proposal：pending → confirm → 200 且库存在、可检索；重复 confirm 409；dismiss 后再 confirm 409；越权 404；过期 410；
  - `maybe_propose` 两种来源与冷却。
- 可离线：embedding 用 `DeterministicFakeEmbedding`；不调 LLM（`topic_of` 用标题，不生成）。

## 8. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 自动沉淀噪声入库 | 默认用户可关；`SEDIMENT_MIN_SALIENCE` 可调；入库内容只来自本会话消息（防注入）；batch 可审计 |
| 每压缩一次入队一次 | 幂等键 = 压缩边界 `new_upto`；同边界只跑一次 |
| 一个用户建库过多 | `SEDIMENT_MAX_TOPIC_KBS` 上限 + 同名复用 |
| worker 未起 | pending 堆积在 job_runs，不报错；`/health` 有 worker 心跳可见 |
| 与 A/B/C 改同一文件 | 本文 §1「不改」清单 + 联调点只加 2~3 行 |
| 撤销需求 | 首版不做删批次接口；`sediment_batches` 已记录 refs/chunk 数，后续可补 `DELETE /api/kb/{kb_id}/sediment/{batch_id}` |

**回滚**：撤销 6 个修改文件的 diff + 删除 8 个新文件即可；新表保留不影响旧功能（不删也行）。
