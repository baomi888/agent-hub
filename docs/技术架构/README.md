## 怎么重新渲染（改完 `.mmd` 之后）

```powershell
# 依赖：本机 mermaid（脚本里已指向 mewcode 的 node_modules）+ 无头 Edge
node docs\技术架构\render_mmd.mjs docs\技术架构\整体设计架构图.mmd docs\技术架构\整体设计架构图
```

> **为什么不用 CDN**：本机到 jsdelivr / GitHub 的连接被阻断（实测超时），
> 所以脚本把 `mermaid.min.js` 内联进临时页面再交给无头 Edge 渲染。
> 同样原因，**当前网络下无法 `git push`**，见下方"推送"一节的替代方案。

## 讨论会先看这三件事

1. **申报书那句「资料不出校」还保不保留？** 现状 embedding 走阿里百炼（数据出校），
   与这句话**直接冲突**。保留就要换本地 embedding，不保留就要改文案。
2. **院赛要不要多副本？** 要，就得在院赛前把 SQLite 换成 PostgreSQL（并连带动向量库选型）。
3. **谁负责运维新增的 worker 进程？** 本轮把定时任务做成了独立进程（故障隔离），
   代价是多一个进程要管。没人负责的话，任何"加服务"的方案都该先否掉。

## 一句话结论

技术栈本身**不需要推翻**：Next.js 16 + FastAPI + SQLite + Chroma + LangGraph + DeepSeek
这套组合在 Demo 与校赛阶段是合适的，真正的决策点集中在
**"要不要为院赛提前换掉存储层"** 与 **"要不要为合规换掉 embedding"** 这两件事上。
