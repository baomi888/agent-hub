## 2. 昨天版本的工作流程（摘要，全文见配套文档）

### 2.1 五档版（删模式选择之前）

```text
用户点模式 → ChatRequest.mode → api/chat.py::_pick_mode
  auto   : 绑库 → rag，无库 → agent
  rag    : RAG 检索链（改写/增强/RRF/过滤/MMR）→ 带引用生成
  agent  : create_agent + 5 工具（kb_search/web_search/calculator/get_weather/download_file）
           ReAct 循环，recursion_limit=10
  hybrid : 关键词规则 classify_task 判 flow/open → 工作流 plan→execute 或 Agent 裸跑，
           运行中按切换规则换手（最多 5 次、冷却 30s），轨迹靠 SSE 事件上屏
  llm    : 纯对话，不检索不工具
```

要点：**工作流选择从未交给 LLM**——由关键词词表决定；工具选择在 agent 段由模型自主，但次数被常量封顶。

### 2.2 三档版（昨天收尾 0ecc803）

```text
auto → ① 规则（强/中/配对/开放词，阈值 2 分）命中 flow → 直接工作流起跑（不问模型）
       ② 否则一次轻量模型判断 → rag / agent / llm
          硬约束：无库判 rag → 改判 agent；有库判 llm → 改判 rag
```

与五档版的差异只在入口路由与 hybrid 收尾；执行链、检索链、5 个工具、全部超参完全没动。

## 3. 问题 1：联网搜索失败（已定位 + 已修复）

**根因（100% 可复现）**

```python
def web_search(query, max_results=5, config: RunnableConfig = None):
    try:
        from core import config          # ← 把形参 config 覆盖成 core.config 模块
        ...
        allow = _configurable(config).get("download_allowlist")  # ← 对模块调 .get()
    except Exception:
        return "联网搜索暂时不可用，请稍后再试或换个问法。"   # ← 吞掉 AttributeError
```

- 引入提交：`cf49ef2`（2026-10-29 20:02 安全修复）给 `web_search` 加了 `config` 形参，函数体旧导入未改。
- 后果：只要配了 `SERPER_API_KEY`，Serper 请求发出 → 结果被丢弃 → 每次搜索都失败（扣额度但用户拿不到结果）。
- 离线复现：伪造 Serper 返回 200 + organic，`web_search` 仍返回失败；`_configurable` 收到 `<module core.config>`。

**已修复**：`agent/tools.py:135` 改为 `from core import config as _cfg`，与 `download_file` 的同款写法一致；新增 `tests/test_web_search_tool.py`（4 条回归：成功返回+允许清单回填/无 config 不崩/缺 key 文案/空结果文案）。

**验证**：新测试 4 passed；关联既有套件（安全加固/天气工具/工具 playbook/路由）78 passed。

**仍需你确认的生产侧信息**：① 生产 `.env` 是否配了 `SERPER_API_KEY`（没配会显示"需要 SERPER_API_KEY"，属于配置缺失）；② 服务器部署的代码是否包含 `cf49ef2`（含才踩到这个 bug）；③ 部署更新后实际问一句联网问题验证。

## 6. 新目标（定稿，详见决策表）

- **删「自动」**：改为两个能力开关「检索」「智能联网」，默认都关（= 纯大模型）。
- **开关语义**：只勾检索 = 先自动检索一轮（引用卡片）→ 模型决定补检索/联网；只勾联网 = 模型自主联网；两个都勾 = **先库后网**。
- **工作流/智能体**：一次轻量 LLM 判定，关键词规则层删除。
- **工具**：算数/天气前后端删除；感知工具只剩知识库检索/联网搜索；交互工具 = 下载、写入知识库、知识库文档管理、修改画像标签（模型自主调用，改状态的需确认/预授权）。
- **长对话沉淀**：压缩时 worker 默认按主题自动建个性化知识库；用户可关（关掉只做正常压缩）。
- **建库确认制**：检索无库、或智能联网回答后，都**先问用户**再按主题建库。

## 7. 风险与验收

完整清单见决策表 §9–§10。三条最需要盯：

1. **自动沉淀 vs 10-26 报告红线**：原设计是"不做自动入库、必须人工确认"；本次按你的决定默认开，用「可关 + 可预览/撤销 + 只沉淀高置信句 + staged 回写」降低不可逆污染风险。
2. **延迟**：每轮多一次 LLM 判定；绑库且勾检索时多一轮检索。都是结构成本，需压测 P95，>15% 再优化。
3. **删除工具的影响面**：`calculator/get_weather` 被多处引用（工具表、前端标签、测试），需全仓 grep 后一并清理。
