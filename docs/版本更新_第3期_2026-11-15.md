## 二、强制浏览机制：触发条件与流程（保留，未改）

### 1. 形态

整页纸，不是"卡片 + 半透明遮罩"。理由写在 `AnnounceModal.tsx` 顶部：既然用户没有关掉的
途径，就没必要露出背后那层点不动的界面 —— 那只会让人反复去点它。

### 2. 触发条件（四个条件同时成立才弹）

| # | 条件 | 代码依据 | 不满足时 |
|---|---|---|---|
| ① | 客户端已挂载 | `mounted`（`useSyncExternalStore`） | SSR 阶段不渲染，避免水合不一致 |
| ② | 有已登录用户 | `userId` 非空 | 未登录不弹（记不住已读，会每次进来都拦一次） |
| ③ | 本期没读过 | `localStorage["baomi.announce.v1.<uid>.<期号>"] !== "1"` | 读过就不再弹 |
| ④ | 四步引导已读完 | 挂载时读 `baomi.guide.v1.<uid>` 的快照 | 新用户先看引导，公告顺延到下次进入 |

> ④ 用的是**挂载那一刻**的快照，不是实时值：否则用户在本次会话里刚关掉引导，
> 实时值一变，公告会紧接着弹出来，等于连着被拦两次。

**例外通道**：URL 带 `?ann=<期号>`（`?ann=1` 等价于最新一期）→ 忽略已读、忽略登录，
直接以预览态打开。用途是给没账号的人看版式、以及"我想再看看那期公告"能靠一个链接复现。

### 3. 流程

```
进入首页或控制台
      │
      ├─ 未登录 ────────────────────────────► 不弹
      │
      ├─ 引导没读完 ────────────────────────► 不弹（顺延到下次）
      │
      ├─ 本期已读 ──────────────────────────► 不弹
      │
      └─ 四个条件都成立
             │
             ▼
    全屏公告页（无关闭按钮、点空白不关、Esc 无效）
             │  顶部金线 = 阅读进度（scaleX 直接写 style，不 setState）
             │  焦点锁在内容区，键盘可 PageDown
             ▼
    滚到底（scrollTop ≥ max − 4px）──► 解锁
      或 内容不足一屏（max ≤ 4px）──► 直接解锁
             │
             ▼
    按钮由「还没读完（灰）」变成「开始使用」
             │  点按钮 或 按 Esc
             ▼
    写入 baomi.announce.v1.<uid>.2026-11-c = 1
             │
             ▼
    关闭，焦点归还给进来时的元素；本期不再弹
```

### 4. 四条边界（每条都想清楚了才写）

1. **没有关闭按钮、点空白不关、Esc 在读到底之前静默无效**（不是报错提示，是彻底不响应）。
2. **但滑到底一定能关**：解锁条件是「滚到内容底部」或「内容不足一屏」，两条必有一条成立。
   不留死路 —— 用户被彻底困住时唯一的出路是关标签页，那就连"下次再弹"的机会都没有了。
3. **解锁之后不回锁**：往回滚一点又给锁上，是拿用户的手势惩罚用户。
4. **内容不足一屏直接解锁**：大屏常见，否则会出现"没东西可滚、按钮永远灰着"。

### 5. 这一期为什么还敢用强制

因为篇幅守住了。代价写在代码注释里：**强制的前提是文案必须短**。
这一期 5 条正文 + 6 处细修，手机上四五屏；如果哪天涨到需要读五分钟，
该改成"首屏强制 + 其余折叠"，而不是继续往这一篇里加字。

### 6. 机制本身现在有测试守着

新增 `tests/test_announcements.py`（15 条），其中 6 条钉机制、9 条钉内容纪律：

| 断言 | 防的是什么 |
|---|---|
| 期号不复用（`USED_IDS = {2026-11, 2026-11-b}`） | id 复用**不会报错**，只会让读过的人永远看不到 |
| 按钮必须 `disabled={!unlocked}`（排除 `aria-disabled`） | 被"顺手优化"成随时可关 |
| 存在 `max <= BOTTOM_EPS` 与 `scrollTop >= max − BOTTOM_EPS` | 大屏上按钮永远灰 / 触底判定失效 |
| 未解锁时 Esc 必须被吃掉 | 键盘绕过强制 |
| 不存在 `setUnlocked(false)` | 回锁 |
| `!dismissed && guideDone` | 公告不给引导让路，新用户连拦两次 |
| 已读键里必须含 `${ann.id}` | 换一期不重弹 |
| 首页与控制台都挂、都传 `userId` | 少挂一处，从那里进来的人看不到 |

反证 5/5 全部真红（改坏 → 对的那条测试红 → `shutil.copy2` 逐字节还原 → sha256 一致）。

> ★ 反证第 1 条第一版是**假绿**：断言写的是裸子串 `disabled={!unlocked}`，
> 而下一行 `aria-disabled={!unlocked}` 也含这串 —— 把 `disabled` 去掉也能绿。
> 改成 `(?<!aria-)disabled=\{!unlocked\}` 才真红。子串断言在本仓库已经是第三次栽跟头。

5. **旧 HTML 里引用的 chunk 会 404**：每次 `mv .next` 重建后旧 hash 全没了，
   拿上一次抓下来的 html 复验静态资源必然报 404 —— 要重新抓页面再验。
