# 支付宝 / 微信 登录与支付接入开发指南

> 面向后续接手这块的开发者。本文把「支付宝登录 / 支付宝支付 / 微信扫码登录 / 微信支付」四条链路的接口契约、验签规则、与 agent-hub 现有体系的对接方式，一次性讲清楚。
>
> 文档生成日期：2026-11-25　|　技术栈：**Java（Spring Boot）**　|　对接后端：agent-hub（FastAPI + SQLite + 自研 JWT）

---

## 0. 先说清楚三件事（动手前必读）

### 0.1 为什么这块可以用 Java 单独写

agent-hub 现有登录是**自研 JWT + 邮箱密码**（`core/auth.py`），`users` 表里**没有任何**第三方登录字段，代码里**没有任何**支付宝/微信相关引用。也就是说，第三方登录支付是一块**从零开始的全新功能**，不存在"覆盖既有代码"或"与现有核心不适配"的问题。

用 Java（Spring Boot）写一个独立服务（例如 `auth-gateway` / `pay-service`），通过下面两种方式之一与 agent-hub 的 Python 后端协作即可：

- **方式 A（推荐，解耦）**：Java 服务独立部署，通过 HTTP 内部接口 / 共享数据库与 agent-hub 交互。
- **方式 B（内嵌）**：Java 服务只负责「对接支付宝/微信」这一薄层，拿到 openid/user_id/手机号后，回传 agent-hub 的 `/api/auth` 完成真正的账号体系接入。

**唯一的硬约束**：第三方登录最终必须把 `openid` / `unionid` / `user_id` / 手机号 **映射回 agent-hub `users` 表的 `uid`**，才能复用 agent-hub 现有的 JWT 鉴权链路（`get_current_user` → `current_user_id`）。这是整个对接的锚点，后文 §5 展开。

### 0.2 支付宝与微信的"易混点"对照（先建立心智模型）

| 维度 | 支付宝 | 微信 |
|---|---|---|
| 登录协议 | OAuth2（授权码模式） | OAuth2（授权码模式） |
| 登录授权 URL | `openauth.alipay.com/oauth2/publicAppAuthorize.htm` | `open.weixin.qq.com/connect/qrconnect` |
| 授权码参数名 | `auth_code` | `code` |
| 换 token 接口 | `alipay.system.oauth.token` | `/sns/oauth2/access_token` |
| 用户唯一 ID | `user_id`（部分场景 `open_id`） | `openid`（跨应用统一用 `unionid`） |
| 签名算法 | RSA2（SHA256withRSA） | APIv3：RSA-SHA256（WECHATPAY2-SHA256-RSA2048） |
| 金额单位 | **元**（两位小数，字符串） | **分**（整数） |
| 支付回调形态 | POST 表单（明文 + `sign` 验签） | POST JSON（业务体 AES-GCM 加密 + 头验签） |
| 网关地址 | `openapi.alipay.com/gateway.do` | `api.mch.weixin.qq.com` |

> 最常踩的坑：**金额单位**。支付宝 `total_amount` 单位是元（字符串），微信 `amount.total` 单位是分（整数），两个字段都叫 total，不仔细看会差 100 倍。§7 有专门提醒。

### 0.3 需要的账号与前置准备

| 事项 | 支付宝 | 微信 |
|---|---|---|
| 开发者账号 | 开放平台企业/个体户账号，完成认证 | 微信开放平台账号（网站应用需审核 3~7 工作日） |
| 应用 | 建"网页/移动应用"，过审拿 `app_id` | 建"网站应用"，过审拿 `AppID` + `AppSecret` |
| 密钥 | 下载密钥工具，生成应用私钥 + 支付宝公钥 | AppSecret（登录）、商户 API 证书 + APIv3 密钥（支付） |
| 回调配置 | 授权回调地址、应用网关、服务器 IP 白名单 | 授权回调域名（只填域名，不带路径/协议） |
| 支付签约 | 签约"电脑网站支付" / "当面付" | 开通 Native / JSAPI 产品权限，绑定商户号 |

## 1. 支付宝登录（网页授权 / OAuth2）

### 1.1 流程四步

```
1. 拼授权 URL，引导用户跳转
2. 用户授权后，回调地址带上 auth_code
3. 用 auth_code 调 alipay.system.oauth.token 换 access_token + user_id
4. （可选）用 access_token 调 alipay.user.info.share 拿昵称/头像
```

### 1.2 第一步：拼接授权 URL

```
https://openauth.alipay.com/oauth2/publicAppAuthorize.htm
    ?app_id=APPID
    &scope=SCOPE
    &redirect_uri=ENCODED_URL
    &state=STATE
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `app_id` | 是 | 应用 APPID |
| `scope` | 是 | 只支持两个值：`auth_base`（静默授权，拿不到用户信息）或 `auth_user`（弹确认页，可拿用户信息） |
| `redirect_uri` | 是 | 回调地址，需 URL 编码，且必须与后台配置一致 |
| `state` | 否 | 自定义参数，回调原样带回，用于防 CSRF（建议传随机串 + session 校验） |

**scope 的关键区别**：
- `auth_base`：静默授权，登录成功直接跳回调，**换到的 access_token 不能调 `alipay.user.info.share`**（会报 `aop.invalid-auth-token`）。
- `auth_user`：用户会看到授权确认页，确认后才跳回调，换到的 access_token **可以**调用户信息接口。

> 要拿昵称/头像，`scope` 必须用 `auth_user`。

### 1.3 第二步：拿 auth_code

用户授权后，支付宝跳回：

```
redirect_uri?app_id=xxx&source=alipay_wallet&scope=auth_user&auth_code=ca34ea491e7146cc87d25fca24c4cD11
```

从 query 里取 `auth_code`。**注意**：`auth_code` 只能使用一次，一天未使用自动过期。

### 1.4 第三步：换 access_token + user_id

接口：`alipay.system.oauth.token`，`grant_type` 传 `authorization_code`。

### 1.5 第四步（可选）：拿用户信息

接口：`alipay.user.info.share`，返回昵称、头像等（仅 `scope=auth_user` 时可调）。

### 1.6 Java 实现要点（Spring Boot）

```java
// 1. 拼授权 URL 并重定向
String redirect = "https://openauth.alipay.com/oauth2/publicAppAuthorize.htm"
    + "?app_id=" + appId
    + "&scope=auth_user"
    + "&redirect_uri=" + URLEncoder.encode(callbackUrl, StandardCharsets.UTF_8)
    + "&state=" + state;   // state 存 Redis，回调时校验

// 2. 回调拿 auth_code，换 token（用官方 SDK）
AlipayClient client = new DefaultAlipayClient(
    "https://openapi.alipay.com/gateway.do",
    appId, privateKey, "json", "UTF-8", alipayPublicKey, "RSA2");
AlipaySystemOauthTokenRequest req = new AlipaySystemOauthTokenRequest();
req.setGrantType("authorization_code");
req.setCode(authCode);
AlipaySystemOauthTokenResponse resp = client.execute(req);
String userId = resp.getUserId();        // 这就是支付宝用户唯一 ID
String accessToken = resp.getAccessToken();

// 3. 拿用户信息（可选）
AlipayUserInfoShareRequest infoReq = new AlipayUserInfoShareRequest();
AlipayUserInfoShareResponse info = client.execute(infoReq, accessToken);
```

**关键提醒**：
- 私钥/公钥用官方 SDK 管理，`sign_type` 固定 `RSA2`。
- `state` 建议存 Redis（短期），回调时校验一致性，防 CSRF。
- 换到的 `user_id` 就是你要**映射回 agent-hub `users.uid`** 的锚点。

## 2. 支付宝支付（电脑网站支付 + 当面付）

### 2.1 电脑网站支付（`alipay.trade.page.pay`）

适用：PC 网页下单，跳转支付宝收银台，用户扫码/输密码支付。

**流程**：
```
1. 服务端调 alipay.trade.page.pay 下单，拿到一段 HTML form
2. 前端把 form POST 到支付宝网关 → 用户进收银台
3. 用户支付后：return_url（同步跳转）+ notify_url（异步通知）
4. 以 notify_url 验签为准更新订单；return_url 仅做展示
```

**关键业务参数**（放在 `biz_content`，JSON 编码，不转义中文）：

| 参数 | 必填 | 说明 |
|---|---|---|
| `out_trade_no` | 是 | 商户订单号，64 位内，字母/数字/下划线，**商户端唯一** |
| `total_amount` | 是 | 订单总金额，**单位元**，两位小数，范围 [0.01, 100000000] |
| `subject` | 是 | 订单标题，不可用特殊字符 `/`, `=`, `&` |
| `product_code` | 是 | 固定 `FAST_INSTANT_TRADE_PAY` |
| `body` | 否 | 订单描述 |
| `timeout_express` | 否 | 最晚付款时间，`1m`~`15d`（不支持小数，如 `90m`） |

**公共参数**：`app_id`、`method=alipay.trade.page.pay`、`charset=utf-8`、`sign_type=RSA2`、`timestamp`、`version=1.0`、`notify_url`、`return_url`、`sign`。

**返回**：一段 HTML `<form>`，SDK `pageExecute()` 拿到后直接输出，前端自动 POST 到网关。

### 2.2 当面付 / 扫码支付（`alipay.trade.precreate`）

适用：服务端生成二维码，用户支付宝扫一扫付款。

**流程**：服务端下单拿 `qr_code` → 生成二维码展示 → 用户扫码支付 → 异步通知确认。

**业务参数**（在 `biz_content`）：

| 参数 | 必填 | 说明 |
|---|---|---|
| `out_trade_no` | 是 | 商户订单号，唯一 |
| `total_amount` | 是 | 金额，**单位元**，两位小数 |
| `subject` | 是 | 订单标题 |
| `product_code` | 否 | 当面付快捷版传 `OFFLINE_PAYMENT`；其它传 `FACE_TO_FACE_PAYMENT`（默认） |

**返回**：`qr_code`（二维码码串，如 `https://qr.alipay.com/xxx`），有效期 **2 小时**，用二维码工具转图。

### 2.3 异步通知验签（支付宝唯一真相源）

```
1. 支付宝 POST 到 notify_url（表单：out_trade_no、trade_status、total_amount、sign 等）
2. 用支付宝公钥验 sign（SDK 提供验签方法）
3. 核对 app_id / out_trade_no / total_amount 与下单时一致
4. trade_status == TRADE_SUCCESS 才改订单状态
5. 幂等处理（支付宝会重试 24 小时）
6. 返回纯文本 "success"（不带 HTML），否则支付宝继续重试
```

> **铁律**：支付结果**只能以异步通知或 `alipay.trade.query` 查询为准**，`return_url` 同步跳转**不能作为记账依据**（用户可能关页面、断网）。

## 3. 微信扫码登录（网站应用 / OAuth2）

### 3.1 流程

```
1. 前端跳授权 URL（或内嵌二维码），用户微信扫码
2. 用户确认后，微信重定向到 redirect_uri，带上 code + state
3. 后端用 code + AppID + AppSecret 换 access_token + openid + unionid
4. （可选）用 access_token 调 /sns/userinfo 拿昵称/头像
```

### 3.2 第一步：请求 code

```
https://open.weixin.qq.com/connect/qrconnect
    ?appid=APPID
    &redirect_uri=REDIRECT_URI      // 必须 urlEncode
    &response_type=code
    &scope=snsapi_login             // 网站应用固定这个值
    &state=STATE
    #wechat_redirect                // 末尾固定带这个锚点
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `appid` | 是 | 应用唯一标识 |
| `redirect_uri` | 是 | urlEncode；域名必须与审核时填写的授权域名一致 |
| `response_type` | 是 | 填 `code` |
| `scope` | 是 | 网站应用仅 `snsapi_login` |
| `state` | 否 | 防 CSRF，回调原样带回 |

**两种实现方式**：
- **方式一：页面重定向**（简单），整页跳到微信域。
- **方式二：内嵌二维码**（体验好），引入 `http://res.wx.qq.com/connect/zh_CN/htmledition/js/wxLogin.js`，`new WxLogin({...})` 把二维码嵌进 iframe。

### 3.3 第二步：拿 code

用户授权后跳回：`redirect_uri?code=CODE&state=STATE`。`code` **有效期 10 分钟，只能换一次**。

### 3.4 第三步：换 access_token

```
GET https://api.weixin.qq.com/sns/oauth2/access_token
    ?appid=APPID&secret=SECRET&code=CODE&grant_type=authorization_code
```

返回：`access_token`、`expires_in`（2 小时）、`refresh_token`（30 天）、`openid`、`scope`、`unionid`（**仅当应用获得 userinfo 授权时才返回该字段**）。

### 3.5 第四步（可选）：拿用户信息

```
GET https://api.weixin.qq.com/sns/userinfo?access_token=ACCESS_TOKEN&openid=OPENID
```

返回昵称、头像等。

### 3.6 Java 实现要点

```java
// 1. 跳转授权
String url = "https://open.weixin.qq.com/connect/qrconnect"
    + "?appid=" + appId
    + "&redirect_uri=" + URLEncoder.encode(callbackUrl, StandardCharsets.UTF_8)
    + "&response_type=code&scope=snsapi_login&state=" + state
    + "#wechat_redirect";

// 2. 回调拿 code，换 token（务必后端做，secret 不能进前端）
String tokenUrl = "https://api.weixin.qq.com/sns/oauth2/access_token"
    + "?appid=" + appId + "&secret=" + secret
    + "&code=" + code + "&grant_type=authorization_code";
// 解析 JSON 得到 openid、unionid、access_token、refresh_token

// 3. 拿用户信息（可选）
String infoUrl = "https://api.weixin.qq.com/sns/userinfo"
    + "?access_token=" + accessToken + "&openid=" + openid;
```

**安全提醒**（官方原文）：
- `AppSecret`、`access_token`、`refresh_token` **绝不能放前端**，放客户端可能被反编译窃取。
- 建议 secret 和用户数据放云端，由云端中转调用。
- 换到的 `openid`（或 `unionid`）就是映射回 `users.uid` 的锚点。

## 4. 微信支付（APIv3 · Native + JSAPI）

### 4.1 先搞清三套凭证（最容易乱）

| 凭证 | 从哪拿 | 用途 |
|---|---|---|
| 商户号 `mchid` | 商户平台「账户中心」 | 所有接口都要 |
| 商户 API 证书私钥 `apiclient_key.pem` + 证书序列号 | 证书工具本地生成 | **请求签名** |
| APIv3 密钥（32 位串） | 商户平台「API安全」设置 | **解密回调**（AES-GCM） |
| 微信支付公钥 / 平台证书 | 「API安全」 | **验签回调**（新商户默认"微信支付公钥"模式，没有平台证书） |

> **关键**：新申请商户号默认「微信支付公钥」验签模式，**没有平台证书**，调 `/v3/certificates` 拿不到。接入前先确认验签模式。

### 4.2 Native 下单（扫码支付）

**接口**：`POST https://api.mch.weixin.qq.com/v3/pay/transactions/native`

**请求体**：

| 参数 | 必填 | 说明 |
|---|---|---|
| `appid` | 是 | 公众号/应用 AppID |
| `mchid` | 是 | 商户号 |
| `description` | 是 | 商品描述 |
| `out_trade_no` | 是 | 商户订单号，数字/字母/`_-*`，商户号下唯一 |
| `notify_url` | 是 | 回调地址，公网 HTTPS，**不能带参数** |
| `amount.total` | 是 | 金额，**单位分，整数** |
| `amount.currency` | 否 | 默认 `CNY` |
| `time_expire` | 否 | RFC3339 格式，如 `2015-05-20T13:29:35+08:00` |
| `attach` | 否 | 附加数据，回调查询原样返回（别放敏感信息） |

**返回**：`{"code_url": "weixin://wxpay/bizpayurl?pr=xxx"}`，用 `code_url` 生成二维码（有效期 2 小时，过期需重新下单）。

### 4.3 JSAPI 下单（公众号/小程序内 H5 支付）

**接口**：`POST https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi`

比 Native 多一个 `payer` 字段：

```json
{
  "appid": "wx...", "mchid": "1900...", "description": "订单描述",
  "out_trade_no": "订单号", "notify_url": "https://域名/回调",
  "amount": { "total": 100, "currency": "CNY" },
  "payer": { "openid": "用户 openid" }
}
```

**返回**：`prepay_id`（预支付会话标识，有效期 2 小时）。前端用它调起支付：

```js
wx.requestPayment({
  timeStamp: payParams.timeStamp,
  nonceStr: payParams.nonceStr,
  package: 'prepay_id=xxx',
  signType: 'RSA',        // v3 必须 RSA，不能 MD5
  paySign: payParams.paySign,
})
```

### 4.4 请求签名（APIv3）

签名串是**五行，末尾换行**，漏一个 `\n` 验签就失败（最常见错误）：

```
HTTP方法\n
URL路径\n         // 只写路径，不带域名！如 /v3/pay/transactions/jsapi
时间戳\n
随机串\n
请求体\n
```

```
message = method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + body + "\n"
signature = RSA-SHA256(message, 商户私钥)  → base64
```

请求头：

```
Authorization: WECHATPAY2-SHA256-RSA2048 mchid="...",nonce_str="...",
               signature="...",timestamp="...",serial_no="商户证书序列号"
Content-Type: application/json
Accept: application/json
```

### 4.5 回调验签 + 解密（支付结果唯一真相源）

```
1. 微信 POST 到 notify_url，body 是 JSON：
   { "resource": { "ciphertext": "AES-GCM 加密的业务数据", ... }, ... }
2. 从 HTTP 头读 Wechatpay-Signature / Wechatpay-Timestamp / Wechatpay-Nonce / Wechatpay-Serial
3. 按 Wechatpay-Serial 找对应平台证书/公钥 → 验证签名
   （证书轮换时新旧同时有效，必须按 Serial 选证书，不能固定一张）
4. 验签通过后，用 APIv3 密钥 AES-256-GCM 解密 resource.ciphertext 得明文
5. 明文里拿 out_trade_no / trade_state / amount，核对金额
6. trade_state == SUCCESS 才改订单
7. 幂等处理（微信会重试）
8. 返回 {"code": "SUCCESS", "message": "成功"}，否则微信重试
```

**回调验签字符串是三元组**（`时间戳\n随机串\nbody\n`），与请求签名（五元组）不同，别搞混。

### 4.6 Java 实现要点

```java
// 下单（用官方 wechatpay-java SDK 或自实现签名）
String path = "/v3/pay/transactions/native";
String body = objectMapper.writeValueAsString(Map.of(
    "appid", appId, "mchid", mchId,
    "description", "测试订单", "out_trade_no", orderNo,
    "notify_url", notifyUrl,
    "amount", Map.of("total", 100, "currency", "CNY")
));
String auth = buildAuthHeader("POST", path, body);  // 五行签名串 + 商户私钥
// POST https://api.mch.weixin.qq.com/v3/pay/transactions/native
// 返回 code_url → 生成二维码
```

> 强烈建议用官方 SDK 管理平台证书的**自动轮换更新**——见过团队自研请求层、证书到期没人管、所有验签失败、线上支付瘫痪 3 小时的案例。

## 5. 与 agent-hub 现有体系的对接（关键锚点）

无论用 Java 还是 FastAPI，第三方登录最后都要落到 agent-hub 的账号体系。现状：

- 登录：`api/auth.py`，邮箱 + 密码，自研 JWT（`core/auth.py`），`users` 表。
- 鉴权：`get_current_user` 从 JWT 解 `uid`，`current_user_id` 查用户。
- 数据库：SQLite（`core/session.py`），`users` 表有 `id`(uid)、`username`、`status` 等。

### 5.1 核心方案：openid/user_id/手机号 → uid 映射

新增一张绑定表（或给 `users` 表加字段），把第三方身份映射到 agent-hub 的 uid：

```sql
-- 建议新增（由第三方登录模块维护）
CREATE TABLE IF NOT EXISTS third_party_bindings (
    provider     TEXT NOT NULL,   -- 'wechat' | 'alipay'
    provider_id  TEXT NOT NULL,   -- openid / unionid / user_id / 手机号
    uid          TEXT NOT NULL,   -- 关联 agent-hub users.id
    created_at   INTEGER NOT NULL,
    PRIMARY KEY (provider, provider_id)
);
```

**登录逻辑**：
```
1. 第三方回调拿到 provider_id（openid / user_id / 手机号）
2. 查 third_party_bindings：已绑定 → 直接拿 uid，走 agent-hub 发 JWT 的流程
3. 未绑定 → 引导用户「绑定已有账号」或「注册新账号」，写入绑定表
4. 绑定成功后，生成 agent-hub 的 JWT 返回前端
```

### 5.2 两种落地方式的取舍

| 维度 | Java 独立服务（推荐） | FastAPI 直接写 |
|---|---|---|
| 语言 | 你更熟的 Java/Spring Boot | 与现有后端一致 |
| 部署 | 多一个进程，需配置反代 | 复用现有 uvicorn |
| 好处 | 可独立演进、可复用到其他项目 | 少一层网络跳转 |
| 代价 | 要维护进程 + 内网通信 | 混入现有代码，边界需小心 |

**结论**：Java 独立服务负责「对接支付宝/微信」这一层（授权跳转、换 token、下单、验签），拿到 `provider_id` 后，通过**内部 HTTP 接口**调用 agent-hub 完成账号绑定 + 发 JWT。这样两边职责清晰，agent-hub 核心不被第三方 SDK 污染。

### 5.3 对接时的安全铁律

1. **secret/私钥/APIv3 密钥不进代码仓库**，走环境变量或配置中心（agent-hub 现有 `.env` 体系同理）。
2. **回调地址必须公网 HTTPS**，回调端点**不加登录态校验**（微信/支付宝服务端不会带你的 session）。
3. **支付结果只信异步通知 + 主动查单**，前端跳转永远不用于记账。
4. **回调必须幂等**（第三方会重试），建议 `out_trade_no + event` 建唯一索引，冲突即返回成功。
5. **金额单位在两侧统一**：支付宝元 / 微信分，入库、展示、回调校验保持同一套。

## 6. 手机号一键登录（补充）

### 6.1 微信手机号快速验证（小程序）

> 适用于 agent-hub 的 `mobile/` 或小程序端。

**新版流程**（基础库 2.21.2+，推荐，不再依赖 `wx.login`）：

```
1. button 组件 open-type="getPhoneNumber"，用户点击同意
2. bindgetphonenumber 回调拿到动态令牌 code（e.detail.code）
3. 后端用 code 调微信接口 phonenumber.getPhoneNumber 换手机号
4. 根据手机号找/建用户，下发登录态
```

- **接口**：`POST https://api.weixin.qq.com/wxa/business/getuserphonenumber`，用 `code` + access_token 换手机号。
- `code` 有效期 **5 分钟**，只能消费一次。
- **注意**：`getPhoneNumber` 返回的 code 与 `wx.login` 的 code **不能混用**；要 openid 仍需单独 `wx.login` + code2session。
- **门槛**：仅非个人主体、完成认证的小程序开放；新方式收费（有 1000 次体验额度）。

### 6.2 支付宝手机号

支付宝登录走 OAuth2 `auth_user` 后，可结合 `alipay.user.info.share` 或专门的手机号授权接口获取；手机号作为 `provider_id` 映射回 uid（见 §5.1）。

## 7. 避坑清单（按踩坑概率排序）

1. **金额单位**：支付宝元、微信分，字段都叫 total/total_amount，差 100 倍。
2. **微信签名串漏换行**：APIv3 请求签名是五元组、回调验签是三元组，末尾 `\n` 不能丢。
3. **微信签名只写路径不带域名**：`/v3/pay/transactions/jsapi`，不是完整 URL。
4. **JSAPI 调起 signType=RSA**：v3 下前端调起支付必须 `RSA`，不能用老的 `MD5`。
5. **回调不幂等**：微信/支付宝都会重试，重复通知不处理会重复发货/重复入账。
6. **新商户用公钥验签没有平台证书**：别照抄"下载平台证书"的老文档。
7. **证书轮换按 Serial 验签**：不能固定用一张证书，否则轮换期回调全挂。
8. **支付宝 return_url 不能记账**：只做展示，记账靠 notify_url / 查单。
9. **out_trade_no 必须唯一**：支付宝/微信都按它关联单据，重复会关联到原订单。
10. **secret 进前端**：AppSecret/私钥/APIv3 密钥放前端会被反编译窃取。
11. **code 一次性**：auth_code/code 都只能用一次，重复换报错。
12. **回调地址不匹配**：授权回调域名/redirect_uri 与后台配置不一致会导致登录/支付直接失败。

## 9. 建议的开发落地顺序（给后续开发者）

1. **先跑通登录**（依赖少、无资金风险）：微信扫码登录 → 支付宝登录 → 手机号一键登录。
2. **再做支付**（有资金风险，需沙箱/小额真实验证）：
   - 先做**下单 + 回调验签 + 主动查单**（结果认定三件套），再考虑退款、账单。
   - 金额单位统一写一个校验函数，两侧换算集中一处。
3. **账号映射**：优先做 `third_party_bindings` 表 + 绑定流程，这是登录与 agent-hub 的对接点。
4. **联调环境**：支付宝用沙箱，微信支付用测试商户号 + 小额真实验证（覆盖退款全链路）。
5. **上线 checklist**：私钥/密钥走配置中心、回调 HTTPS、幂等唯一索引、对账脚本、日志脱敏（不打印完整密钥与敏感字段）。
