# 移动端 UI 评审：与成熟原生软件差在哪

> 对象：知穗（`myzhisui.cn`）在 iPhone / Android 上的界面，即 `mobile/App.tsx` 那个 Expo WebView 壳所承载的同一套页面。
> 日期：2026-11-16｜方式：线上登录态 + CDP 真视口取证，不看代码猜结论。
> 本文只做评审与方案，不改产品代码。

## 0. 一句话结论

**不是一个"丑"的问题，是一个"外壳没有立住"的问题。**

这套界面是「桌面工作台 + 手机降级」拼出来的：能力强、信息全，但**外壳（导航、返回、弹层、加载、尺寸）仍然是网页的习惯**。成熟软件在这五件事上是稳定契约，用户不需要每次重新学；这里每一件都要重新判断一次。

三个可量化的根因：

1. **导航模型分裂** —— 5 个一级入口里，2 个（对话、论坛）没有底部导航。
2. **尺寸按桌面做** —— 13px 是主导字号，39px 是主导按钮高度，两者都低于 iOS HIG 的 17pt / 44pt。
3. **页内自带说明书** —— 每个页面标题下 2–3 行解释文字，占掉约 60px，且每次都要读一遍。

## 1. 取证条件

| 项 | 值 |
| --- | --- |

## 2. 差距清单（按影响排序）

### A. 外壳与导航一致性

**A1 · 一级入口里有两个没有底部导航**（P0，最重）
- 观察：`/checkin`、`/reminders`、`/knowledge`、`/settings` 都有 `.tabbar`（top 767 / h 85）；`/`（对话）与 `/forum` 实测 `.tabbar` 为 `null`。
- 依据：`.tabbar` 由 `components/console/ConsoleLayout.tsx` 渲染，而这两个页面不在 `(console)` 路由组里。
- 影响：用户在「对话」要用 `☰` 抽屉，在「论坛」要用左上角「工作台」返回，在其余页用底部 tab —— **三种导航模型**，且这两页进不去打卡/设置。这是"像网页"的第一观感来源，比任何配色都强。

**A2 · App 里在教用户"把知穗装到桌面"**（P0）
- 观察：iOS 视口首屏截图顶部就是「把知穗装到桌面 / 点一下装到桌面 / 安装 ×」横幅，压在标题栏位置。
- 依据：`lib/pwa.ts` 的 `isInstalled()` 只判 `display-mode: standalone` 与 `navigator.standalone`。WKWebView 两者都为假 → 横幅在原生壳里照样出现，而"安装"在壳里没有 `beforeinstallprompt`，点了只会跳教程页。
- 影响：用户已经装了 App，App 却让他再装一次。这类自相矛盾的提示，比缺功能更伤信任。

**A3 · 「更多」面板不接管系统返回键**（P1）
- 依据：`ConsoleTabBar.tsx` 只监听 `keydown` 的 Escape（第 62 行），没有 `pushState` / `popstate`；外壳 `App.tsx` 的 `BackHandler` 只做 `webRef.goBack()`。
- 影响：App 里打开面板后按安卓返回，页面会整页后退，面板留在屏幕上。这是 WebView 壳最典型的"手感不对"。

**A4 · 加载态是文字，不是骨架**（P1）
- 依据：全站 `grep skeleton` 为 0；加载态写的是「正在加载…」「正在加载话题」。
- 影响：切换一级 tab 时，屏幕先出现一行小字再跳成内容，视觉上"闪一下"，原生 App 用骨架屏把这一步藏掉。

**A5 · 没有原生转场方向**（P2）
- 依据：`console.css` 只有 `.page-enter` 0.18s 淡入，没有 push/pop 的方向感。
- 影响：进二级页与切一级 tab 观感一样，用户分不清"我进去了"还是"我切换了"。

### B. 尺寸与可点性

**B1 · 触控目标普遍低于 44pt**（P0）
实测（iPhone 393 宽，单位 CSS px ≈ pt）：

| 元素 | 实测 | 位置 |
| --- | --- | --- |
| 全局 `.btn` | **39 高** | 各页主按钮（修改密码、保存这张图…） |
| `.tb-new` 发帖 | 40 高 | 论坛顶栏 |
| `.tb-bar` 分类 chip | **31 高** | 论坛分类行 |
| `.kbp-new` 新建 | 31 高 | 资料库 |
| 会话「改名 / 删除」 | **18×18** | 对话页会话列表 |
| `×` 关闭 | 26×26 | 公告条、安装横幅 |
| 「改」改登录名 | **18×23** | 设置页 |
| `.rem-pritag` 普通 | 54×24 | 待办卡片 |
| 时间轴点 `.rem-ev` | **14×18** | 待办时间轴 |

iOS HIG 要求 44×44，Material 要求 48dp。18×18 的删除按钮意味着**误触率不可控**，而删除会话是不可撤销操作。

**B2 · 字号整体小一号**（P0）
- 实测首页文本节点：`13px` 出现 **102 次**，`16px` 30 次，`14px` 12 次；设置页 `13px` 44 次。
- iOS 正文 17pt、次要 15pt、说明 13pt。这里把 13px 当正文用 —— 在 6.1 寸屏上相当于把桌面 13px 直接搬过来。

**B3 · 圆角没有系统**（P1）
实测首页圆角值：`8px`×100、`4px`×68、`999px`×13、`12px`×11、`16px`×4、`50%`×4。六种并存，其中 4px 与 8px 在同屏相邻出现（卡片 vs 卡内小按钮），看不出是两档还是随手写的。

### C. 层级与信息密度

**C1 · 首页有 162px 空白**（P1）
- 实测：「常去的地方」那一行底边到输入区顶边 **162px**，占 852 屏高的 19%。输入区本身 60px。
- 感觉：内容像是没加载完。原生 App 这个位置通常是"最近会话 / 继续上次"，而不是空气。

**C2 · 论坛顶栏常驻 116px**（P1）
- 实测 `.tb-top` sticky，高 **116**（含安全区 59），占屏高 13.6%，滚动时不收。
- 内含三行：标题+搜索+发帖、分类 chip、公告卡。原生列表页通常滚动即收起分类，只留 56。

**C3 · 每页自带说明书**（P1）
- 待办：「设了提醒时间，到时会通知你；课表、打卡的提醒会自动排好。」
- 打卡：「把今天的总结变成一张只讲知识结构、不露个人内容的图……」
- 资料库：「课件、笔记、论文都可以放进来……」
- 设置：「改登录名要先验证一次密码。」「当前重心：语言考证（权重 70）……权重来自手选（每次 +3）……」
- 影响：每屏约 60px 用于解释"这页是干什么的"，而这是首次进入该讲一次的事。设置页那段权重算法更是**把内部模型讲给用户听**。

**C4 · 资料库把桌面两栏竖着堆**（P1）
- 观察：上面是库列表（5 行），下面紧接着同一个库的详情卡，标题重复出现（「数据采集与·处理·作业·」出现两次）。
- 影响：手机上要滑过一遍列表才能看到详情，且分不清"我在列表里还是在库里"。

**C5 · 「更多」面板 7 项两列**（P2）
- 观察：6 项排成 3 行，第 7 项「设置」单独一行居中偏左，右下空出一格。
- 观感：像没做完。改 3 列×2 行 + 设置放顶栏，或最后一项跨两列。

**C6 · 首页两组三列权重相同**（P1）
- 「每日委托/每日总结/打卡记录」是带底卡的模块，「待办/公开知识库/论坛」只有图标无底框，但两组视觉重量接近；两个小标题都用"细线压字"的样式，把一屏切成 5 段横线。

### D. 文本与状态完整性

**D1 · 帖子标题被后端硬切 24 字，且切在词中间**（P0）
- 现象：公告条显示「第 3 期 · 十一月更新：AI 待办、论坛与公」，到此为止，**没有省略号**。
- 根因：`core/forum.py:78` 的 `title_of()` 对**所有**标题都做 `t[:24]`。数据库里第 40 号帖标题是完整的「……论坛与公开知识库」（已在服务器 `kb_posts` 表核对）。
- 为什么连省略号都没有：字符串在到达 CSS 前就已经是 24 字，`.tb-notice-t` 的 `text-overflow: ellipsis` 永远不触发。
- 影响：这是"内容被截断"里最糟的一种 —— 用户以为标题就是这么写的。

**D2 · 内部标识出现在界面上**（P1）
- 设置页：「账号 ID 96308855」（裸 ID）；「权重 70 / 22 / 13」；打卡页按钮「SVG」；打卡卡徽章「演示数据」。
- 影响：`SVG` 是给开发者的词（应写「下载矢量图」或收进更多）；裸 ID 没有任何用户价值；「演示数据」说明这张卡还没接真实数据 —— 这类话应写在交付说明里，不该印在界面上。

**D3 · 首页顶部 chip 被截成「未绑定资料库 · 点…」**（P2）
- 观察：虚线框里塞了一句状态说明，宽度不够，用省略号收尾。原生做法是一行 subtitle 或干脆不显示。

## 3. 我原以为有问题、实测不成立的（避免误导）

评审最怕把"看着像"写成"就是"。这三条查过，不成立：

1. **内容被底部 tab 遮挡** —— 不成立。`.console-scroll` 的 `padding-bottom: 96px` > tabbar 85px；滚到底后最后一个文本元素底边 715 < tabbar 顶边 767。截图里"卡片被切断"只是**当前滚动位置**造成的，不是遮挡。
2. **对比度不足** —— 不成立。带 alpha 合成后实测深色模式关键文字对比度 **5.2–13.1**（最低是任务卡副标题 5.20:1，仍过 AA 4.5）。问题不在对比度，在字号。
3. **横向溢出** —— 不成立。6 个页面 × 2 个视口，`scrollWidth == clientWidth`，无溢出元素。

> 附带一条方法论：第一版对比度脚本把 `rgba(61,47,26,0.035)` 当成不透明底色，算出 1.0–1.55 的假红。半透明底必须逐层合成再算。

## 4. 优化方案

### P0：先让外壳立住（4 项，其中 1 项是结构调整）

| # | 改什么 | 怎么改 | 验收 |
| --- | --- | --- | --- |
| P0-1 | 底部导航常驻 | `/` 与 `/forum` 改用 `(console)` 外壳，或至少在页内渲染 `<ConsoleTabBar />`；对话页的 `☰` 抽屉降级为"会话历史"入口，不再是主航 | 任意页面 `.tabbar` 存在且 `aria-current` 正确；从论坛能一步到打卡 |
| P0-2 | 触控目标 ≥44 | `.btn{min-height:44}`；`.tb-bar` 31→36 可视 + 44 热区（`padding:6px 0` 或 `::after` 扩热区）；`.tb-new`/`.kbp-new` 统一 44；图标按钮保持 24 视觉 + 44 热区；会话「改名/删除」18×18 → 44 热区 | 扫描脚本：`button,a,[role=button]` 中 `h<44 或 w<44` 的数量为 0（时间轴点可用父级热区豁免，需白名单） |
| P0-3 | 标题不再硬切 | `core/forum.py:78` 改为：有真标题就原样返回，只在**标题为空**时用正文前 24 字兜底；`.tb-notice-t` 改两行 `-webkit-line-clamp:2` | 第 40 号帖在公告条显示到「公开知识库」或带省略号截断，不再出现「与公」 |
| P0-4 | App 内不弹安装横幅 | `isInstalled()` 增加壳判定：`!!window.__ZHISUI_APP__`（壳里 `injectedJavaScriptBeforeContentLoaded` 注入），或 UA 里加 `ZhisuiApp/0.1.0` 后缀 | 在壳里打开首页，安装横幅不出现；Safari 里仍出现 |

> 成本提醒：P0-1 是唯一会动路由结构的，预计 1–2 天且要回归一遍导航相关断言（`tests/` 里 `visibleNav` 那组）。其余三项各半天内。

### P1：让尺寸和信息层级像原生（6 项）

1. **字号升一档**：正文 `13 → 15`，元信息 `13 → 14`，页标题 `20 → 22`，行高 `1.5 → 1.6`。改的是 token（`--fs-sm` 等）而非逐处硬写；改完必须逐页看**行尾孤字**（19.4 字/行、海报 14 字/行的老坑）。
2. **圆角收敛到三档**：卡片 12、控件 10、胶囊 999。删掉 4px / 8px / 9px / 16px / 50% 的散值。
3. **漏斗页说明文下沉**：首屏保留一句不超过 20 字的主张（如「课表、打卡、作业，到点提醒你」），其余移进首次进入的 coach mark 或标题右侧 `ⓘ`。省下 40–60px 给真实内容。
4. **论坛顶栏可收**：滚动超过 80px 后把分类行淡出并压到 56 高；公告卡改成一行（图标 + 标题 + 时间），高度从 99 压到 56。
5. **资料库改 push**：列表点进库 = 整屏切换 + 左上角「‹ 我的资料库」，不再竖排堆两道。删除重复的库名标题。
6. **首页补空白**：162px 空白区放「继续上次」——最近 3 条会话 + 最近一个库，两行列表，顺带把对话入口从 `☰` 里救出来。

### P2：可延后

- 骨架屏替代「正在加载…」（3 条灰条，200ms 后淡入）。
- 「更多」面板改 3 列×2 行 + 设置进顶栏；或最后一项 `grid-column: span 2`。
- 面板接管返回键：打开时 `history.pushState`，`popstate` 里关闭（网页侧做，壳不用改）。
- 原生转场：进入二级页 8px 横向位移 + 淡入 180ms；切一级 tab 只淡入。
- 触觉反馈：壳里在切 tab / 完成待办时 `Haptics.selectionAsync()`。
- 内部信息清理：裸 ID 移进「关于」；「演示数据」徽章改成真实数据或不上线这一块。

## 5. 不建议做的

- **不要为了"原生感"重写一遍原生 UI**。壳的 220 行是有理由的（5 人团队、双份维护）。差距里 90% 可以靠上面这些 CSS 与外壳动作补上。
- **不要加大面积深色、玻璃拟态、粗描边**。当前米黄纸墨的基调是对的，问题在尺寸与结构，不在风格。
- **不要一次性全局换字号**。先在一个页面（建议待办）试，量一遍行尾孤字再铺开。
