# 苞米 Agent · 前端视觉审查报告

- **审查对象**：`frontend/`（Next.js 16 + React 19 + Tailwind v4 + 手写 CSS 分层）
- **对标基线**：`苞米地笔记本_设计提示词.md`（尤其是 2.2 色彩、2.4 组件规格、2.6 质感、2.7 禁忌清单）
- **审查日期**：2026-09-27

## 0. 一句话结论

**不是难看，是有两套视觉语言在同一个界面里打架。**

一套是你想要的那本"温暖的纸质笔记本"：暖米白纸底、深棕墨字、成熟玉米金点缀、线描玉米穗、极淡投影、统一小圆角。这套做得相当到位。

另一套是通用 SaaS 组件的默认装饰习惯：高光白边（`inset 0 1px 0 rgba(255,255,255,.5)`）、彩色投影（`0 8px 20px var(--glow)`）、hover 一律上浮 2px、6 属性全包的长过渡、无限脉冲动画、3D 渐变高光球。这套每一条都写进了你的禁忌清单，但代码里到处都是。

**现在观感上的所有"不够高级"，几乎都不是配色问题，是第二套语言没清干净。**

## 2. P0 · 直接破坏"纸"的隐喻（建议首批清理）

### P0-1 · 拟物层叠加太厚，纸变成了塑料片

你的规范 2.6 写的是 `0 2px 8px rgba(61,47,26,0.06)`。实际代码：

| 位置 | 实际堆叠层数 | 具体 |
|---|---|---|
| `layout.css:87-127` `.bubble-user` | **5 层** | 线性渐变底 + 3 重 box-shadow + `::before` 斜向金色渐变 + `::after` 顶部 1px 白色渐隐高光 |
| `components.css:28-79` `.btn-new` | **5 层** | 同上整套再来一遍 |
| `fx.css:3-42` `.thinking-dot` | **4 层** | radial 高光 + 静态投影 + inset 阴影 + `::before` 白色高光点 |
| `chat.css:114-165` `.send` | **4 层** | radial 金球 + 投影 + `::before` radial 反向高光 + hover scale 1.06 |
| `interactions.css:70-116` `.plan-card` | **5 层** | 顶部 3px 渐变条 + `inset` 白线 + 双层投影 + 斜向渐变背景 |

其中 **`inset 0 1px 0 rgba(255,255,255,0.5)` 这一条是重灾区**——它是 2012 年前后 Web 2.0 玻璃按钮的招牌手法，在一张"纸"上出现会立刻把材质变成塑料。全文出现了 **8 次**（`layout.css:96`、`components.css:42/188/265`、`chat.css:188/285`、`interactions.css:81/265`、`kb.css:553`）。

**改法**：删掉所有 `inset 0 1px 0 rgba(255,...)` 白线和所有 `radial-gradient(circle at 30% 30%, ...)` 高光点。阴影统一收敛到一个令牌：

```css
/* tokens.css —— 只留两级，够用就够了 */
--shadow-1: 0 1px 2px rgba(80,60,30,.06);   /* 贴在纸上的薄卡 */
--shadow-2: 0 2px 8px rgba(80,60,30,.10);   /* 抬起 / hover / 浮层 */
```

`--shadow-soft` 现在写的是 `0 2px 10px rgba(80,60,30,0.08)`，和上面两条几乎重合，合并即可。

### P0-2 · hover 上浮泛滥，失去层级重点

统计：`.ability-card`(welcome.css:204) `translateY(-2px)`、`.welcome-eg`(:101) `-1px`、`.bubble-user`(layout.css:119) `-2px`、`.input-row`(chat.css:78) `-1px`、`.attach-item`(kb.css:313) `-1px`、`.msg-file`(:423) `-1px`、`.plan-card`(interactions.css:103) `-2px`、`.btn-new`(components.css:65) `-2px`、`.msg-img`(kb.css:402) `scale(1.02)`、`.feed-btn`(components.css:139) `-1px`……

**10 个组件在 hover 时做同一件事。** 结果是：鼠标扫过欢迎页时整片纸都在往上跳，用户的注意力反而没有落点。

**改法**：保留 **2 个** hover 位移——`.ability-card`（这是主转化入口）和 `.send`（这是唯一的主操作按钮）。其余全部改成 **静态** 反馈：换边框色 + 换背景，不加位移、不加额外阴影。

```css
/* 其余组件的统一 hover 形态 */
.xxx:hover { border-color: var(--accent); background: var(--accent-soft); }
```

纸不会被鼠标顶起来。这是最直白的一条"到底像不像纸"的判定线。

### P0-3 · 9 处 `infinite` 动画同时跑，页面永远在动

| 位置 | 动画 | 周期 |
|---|---|---|
| `welcome.css:22` `.hero-logo` | `heroFloat` 浮息 | 7s |
| `components.css:346` `.status .dot` | `statusPulse` 呼吸 | 2s |
| `components.css:386` `.kb-chip .dot` | `dotPulse` 呼吸+缩放 | 2s |
| `chat.css:232` `.kb-row.bound::after` | `boundGlow` 呼吸 | 2s |
| `kb.css:514` `.cursor::after` | `blink` | 0.9s |
| `chat.css:24` `.thinking-dot` ×6 | `thinkingPulse` | 1.5s |
| `interactions.css:21` `.tool-spin` | `toolSpin` | 0.7s |
| `fx.css:206` `.skel-line` | `skelPulse` | 1.4s |

规范要的情绪是"温暖、安静"。首屏常态下（hero logo + 状态点 + 绑定呼吸 + 打字光标）就有 **4 组动画同时进行**，边界还在闪。这是"廉价感"的第一来源。

**改法**：把 `hero-logo` 的浮息、`status .dot`、`kb-chip .dot`、`boundGlow` 全部删掉，只保留加载态（thinking / tool-spin / skeleton）和打字光标——它们是"有事在发生"的信号，不是装饰。

### P0-4 · 两处直接违反禁忌清单的直角

规范 2.7 明确写「❌ 不要直角」，但：

- `components.css:354-366` `.kb-chip`（顶栏"已绑定：xxx"胶囊）→ **无 border-radius**，实际渲染为直角描边矩形，而同行的 `.ability-trigger`/`.theme-chip` 都是 999px。三者挨在一起，形态互相打架。
- `interactions.css:214-225` `.plan-export`（"导出"按钮）→ **无 border-radius**，直角大按钮。
- `chat.css:266-279` `.check`（自定义复选框）→ **无 border-radius**，15px 直角小方块，和旁边 6~10px 圆角的组件完全不是一个族。

**改法**：`.kb-chip` → `border-radius: 999px`；`.plan-export` → `var(--radius-md)`；`.check` → `4px`。

## 3. P1 · 系统层不严谨（让"精致"无法成立）

### P1-1 · 明度阶梯缺失，中间和边上的纸几乎同色

实测五个米色令牌的 L\*（CIE 明度）：

| 令牌 | 色值 | L\* | 与上一级的 ΔL\* |
|---|---|---|---|
| `--bg` | `#F4EDD8` | 93.8 | — |
| `--bg-canvas` | `#F5F0E1` | 94.8 | **+1.03** |
| `--panel` | `#F9F3E0` | 95.8 | **+1.03** |
| `--card-bg` | `#FDFAF2` | 98.3 | **+2.46** |
| `--bg-sidebar` | `#EDE4C8` | 90.6 | （对 canvas）**−4.18** |

ΔL\* < 2 时人眼基本分不出层次。也就是说：**侧栏以外的"纸—面板—卡片"三级，视觉上是同一张平涂米色**，卡片只能靠 1px 边框勉强撑起来。这就是"远看是一片平米黄、缺立体感"的根因。整张页面里唯一有真实层次的一跳，是侧栏到主画布（−4.18）。

**改法**：把五个收敛成 **三级，每级 ΔL\* ≈ 4**：

```css
--step-0: #EDE4C8;  /* L*=90.6  纸底 / 侧栏   （沿用现 --bg-sidebar） */
--step-1: #F5F0E1;  /* L*=94.8  面板          （沿用现 --bg-canvas）  ΔL*=+4.2 */
--step-2: #FDFAF2;  /* L*=98.3  抬起的卡片    （沿用现 --card-bg）    ΔL*=+3.5 */
```

三个色值你项目里已经有了，只是没被排成阶梯——这一步几乎是零成本调整。

> 顺带解决令牌冗余：`--panel`/`--surface`/`--paper` 三个名字同一个值，`--ink`/`--text-1`/`--solid` 三个名字同一个值——注释里你自己也承认了。合并时一并做干净。

### P1-2 · 深色模式是"把浅色值算暗"，不是设计出来的

`.dark` 块（`tokens.css:76-110`）整体依赖在浅色平缓\:=\:\;之上叠 alpha 面板：

```css
.dark .plan-card  { background: rgba(68,55,40,0.55); }   /* interactions.css:106 */
.dark .theme-chip { background: rgba(68,55,40,0.5); }    /* interactions.css:342 */
.dark .fs-picker  { background: rgba(68,55,40,0.5); }    /* interactions.css:316 */
```

半透明暖褐色压在 `#1E1A12` 上会得到一坨**没有色相、发浑发脏的棕**，而且因为 alpha 不同，三个组件叠在同一张纸上却是三种不同的灰。另外 `.dark` 里还有 4 处硬编码 hex（`--red: #D9705A`、`--accent: #E0A03A` 等），没有进 `@theme inline`，Tailwind 侧拿不到。

**改法**：深色模式的 `--panel` / `--card-bg` / `--veil` 应写成**不透明实色**（如 `#262018` / `#2C2418`），不要用 alpha 叠加；`.dark` 里新增的色值要同步补到 `@theme inline` 块。

### P1-3 · 23 种圆角取值，令牌只用了 11 次

实测分布（全文 `border-radius` 硬写 **71 次**，令牌 `var(--radius-*)` 仅 **11 次**）：

```
999px ×13 | 6px ×9 | 8px ×8 | 10px ×7 | 50% ×5 | var(--radius-md) ×4
12px ×4 | var(--radius-lg) ×3 | 16px ×3 | 4px ×2 | 14px ×2 | 20px/11px/5px/2px ×1各
特殊: 16px 16px 4px 16px | 0 0 10px 10px | 14px 0 0 14px | 0 14px 14px 0
```

`--radius-xs/sm/md/lg/xl` 五个令牌定义了，但大多数组件绕过它们直接写数字。同一屏能看到 5px（`.ref-note`）、6px（`.ref-idx`）、8px（`.attach-item`）、10px（`.kb-row`）、12px（`.toast`）、14px（`.ability-card`）、999px（`.theme-chip`）七种——**这是"不精致"最容易被感知的来源**，比配色更致命。

**改法**：定 **4 档就够**，然后把 71 处硬写全部替换：

```css
--r-xs: 4px;   /* 复选框、小标签 */
--r-sm: 8px;   /* 按钮、输入框、chip */
--r-md: 12px;  /* 卡片、便签、浮层 */
--r-lg: 16px;  /* 主输入框、计划卡 */
/* 999px 只保留给真正的胶囊：theme-chip / ability-trigger / tool-bar */
```

### P1-4 · 21 处复制粘贴的六属性过渡

```css
transition: transform .25s ease, box-shadow .25s ease, background-color .2s ease,
            border-color .2s ease, color .2s ease, opacity .2s ease;
```

这段在 `components.css`/`chat.css`/`kb.css`/`interactions.css` 里出现 **21 次**，部分变体 duration 是 .22/.18。两个问题：

1. **维护**：改一次节奏要动 21 处，必然漏。
2. **质感**：同时过渡 6 个属性，任何 hover 都会呈现一段"什么都在一起糊"的中间态。**真正让交互显得干脆的，是只对真正变化的那一两个属性做过渡。**

**改法**：把所有动的时间里缩到 2 个，其余瞬时：

```css
--t-color: 140ms ease;   /* 颜色类：背景/边框/字色 */
--t-move:  220ms cubic-bezier(.4,0,.2,1);  /* 位移类：只留给那 2 个组件 */
```

### P1-5 · 三处硬写字体族，与 `--font-serif` 不一致

`--font-serif` 已定义为 `"LXGW WenKai Screen", "Noto Serif SC", "Songti SC", "SimSun", serif`，但下面三处绕开了它直接写 `"Noto Serif SC", "Songti SC", "SimSun", serif`：

- `interactions.css:134` `.plan-title`
- `interactions.css:186` `.plan-idx`
- `welcome.css:121` `.welcome-eg-hint`

结果：**同一个界面里同时渲染两种衬线字体**（计划卡/示例卡 用 Noto Serif，侧栏品牌名/会话选中项/预览标题 用 LXGW WenKai）。中文尤其明显——文楷的骨架窄而长，思源宋体扁阔，混排在视觉上就是两套东西。

另外，`LXGW WenKai Screen` 只有 regular 一档字重，你在 `.plan-idx`、`welcome-eg-hint`、`pv-title`、`session.active .session-name` 上用了 `font-weight: 700`，浏览器会**合成假粗体**——中文古文笔画多，合成粗体直接糊成一团。

**改法**：三处改为 `font-family: var(--font-serif)`；需要强调的地方改用 `--ink` 色 + 字号/字距区分，而不是加粗；必须加粗时把该元素切回 `"Noto Serif SC"`（它有 700 真字重）。

### P1-6 · 低对比度的错误提示（这是安全问题，不只是美观）

实测：

| 场景 | 色值组合 | 实测对比度 | WCAG AA(4.5:1) |
|---|---|---|---|
| `--accent` 对纸底 `#F5F0E1` | `#C8892A` / `#F5F0E1` | **2.61 : 1** | ✗ |
| `.warn` 错误条正文 (`kb.css:436-439`) | `#C8892A` / `#FFF8E6` | **2.80 : 1** | ✗ |
| `.ref-note` 角标 (`refs.css:11-12`) | `#C8892A` / 浅金底 | **2.66 : 1** | ✗ |

你已经意识到这个问题并加了 `--accent-ink`（4.99:1，✓），但**只覆盖了 10-12px 的眉题**。

其中 `.warn` 最严重：它是一个包裹错误详情的 `<details>`，是全应用里语义权重最高的文字，却用了 **2.80:1** 的金色放在浅米底上——比正文弱了整整 4 倍。

**改法**：

```css
.warn { color: var(--red); background: rgba(180,71,47,.06); border-color: rgba(180,71,47,.22); }
.ref-note { color: var(--accent-ink); }   /* 有背景块，实在要用金也得是可读版本 */
```

顺手全线排查：凡是 ≥12px 且承担信息职责的文字，一律不许用 `--accent`，改用 `--accent-ink`。

## 4. P2 · 完成度与收边

### P2-1 · 四项收边瑕疵

- **未定义令牌**：`--accent-line-strong` 在 `components.css:127` 和 `welcome.css:205` 被引用，**但全项目从未定义**，永远走 fallback。要么定义它，要么删掉写法。
- **焦点样式缺失**：全文 `:focus-visible` 只出现在 4 个 CSS 文件里的 17 处。`btn-new`、`btn-import`、`feed-btn`、`send`、`icon-btn`、`check`、`session`、`welcome-eg`、`kb-file-name` 都只能依赖浏览器默认轮廓，而 `underline-input` / `search input` / `textarea` 又写了 `outline: none` —— 键盘用户会彻底失去焦点位置。建议全局兜底：

  ```css
  :where(a,button,[role="button"],input,textarea,select,summary):focus-visible {
    outline: 2px solid var(--accent); outline-offset: 2px; border-radius: var(--r-xs);
  }
  ```

- **没有 favicon / OG**：`layout.tsx` 里只有 `title` 和 `description`，没有 `icon`、`openGraph`、`twitter`、`theme-color`。浏览器标签是空白的，分享出去没有卡片。加入一行 `<link rel="icon" href="/icon.svg">`。
- **嵌套可聚焦**：`Sidebar.tsx:182-238` 的 `.session` 是 `div role="button" tabIndex={0}`，内部还嵌了"重命名""删除"两个真实 `<button>`。键盘用户要 Tab 三次才能过一条会话，且 `Escape` 在两层里各处理一次。建议外层改为 `<div>` + 内层真实 `<button>` 承担点击，或用 roving tabindex。

photo-desk.jpg         454,345 B   ← 未使用

### P2-3 · 排版尺度没有谱系

实测：`line-height` **13 种**（1/1.2/1.3/1.4/1.45/1.5/1.6/1.65/1.7/1.78/1.9/15……），`letter-spacing` **9 种**（0.02~0.22em）。

正文、预览、标注、标题各行一套，垂直节奏不成立。

**改法**：行高收到 **3 档**，字距收到 **3 档**：

```css
--lh-tight: 1.35;  /* 标题、按钮 */
--lh-body:  1.75;  /* 正文、AI 回答 */
--lh-loose: 1.9;   /* 长段落阅读 */

--ls-normal: 0;       /* 正文 */
--ls-meta:   0.04em;  /* 按钮、元信息 */
--ls-eyebrow:0.18em;  /* 眉题（统一现有的 .22em/.16em 两档） */
```

### P2-4 · 布局没有利用宽屏，字号不流式

- 内容区写死 `max-w-[720px]`（`ChatArea.tsx:438/553/584`），在 2560px 宽屏上左右各留一大片空白，疏密失控。建议 `clamp(640px, 60ch, 860px)`。
- 标题写死 `--hero-fs: 34px`（`tokens.css:61`），但在 1366px 和 4K 上完全一样大。建议 `clamp(26px, 2.4vw, 38px)`。
- 断点只有 899 / 1279 两档，中间没有 ≥1600 的处理，也没有 container query。

### P2-5 · 细节质感逐项清理

| 位置 | 现象 | 建议 |
|---|---|---|
| `kb.css:489-500` | 滚动条用 `linear-gradient` 到玉米金 —— 高饱和拉丝，和纸的安静感正面冲突 | 改为纯色 `var(--line-strong)`，hover 略深 |
| `chat.css:118` `.send` | `radial-gradient(circle at 32% 30%, #d7b263, var(--accent))` 3D 高光球 | 改为平涂 `var(--accent)` + 单色投影 |

## 6.5 第四批：把对照出的三处缺口补齐

对照 LobeHub `DESIGN.md` 之后留下三处真缺口（填充阶梯、字号阶梯、语义色），这一轮全部补齐。执行细节与数据记在 `docs/设计令牌对照_LobeHub.md` 第 5 节，这里只记判断。

**填充：金不再用来表示"鼠标在上面"。** 之前 hover 淡底散着 `--accent-soft`（金 .10）、`--bg-subtle`（金 .08）和各家自写的 `rgba(61,47,26,.06)`，同一张纸上 hover 出来的颜色深浅不一，金底还会把纸染黄。现在四级中性填充只做一件事——表示深浅，不表示情绪；金色留给"这一项是选中的"和"这是主操作"。分界线画在**瞬时 vs 持久**上：hover / focus / 按下走中性，`.on` / `.active` / `:target` 与主按钮走金。这样全站只剩两种底色语言，看一眼就知道是"能点"还是"就是这个"。

**字号：14 种 → 5 档 + 2 个例外。** 过去 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 相邻差 0.5px，纯粹是"当初手写的那个数"。收档后 CSS 与 tsx 里共 85 处声明全部落位，其中 `text-[15px]` 那 3 处是写死的正文字号——用户把字号调到"大"档，正文和输入框纹丝不动，是个真 bug，现在走 `--text-msg: var(--msg-fs)`。

**语义色：从两个变五个。** 之前只有 accent（金）和 red，success 硬写在 toast 里，info 没有独立色，warning 跟 accent 混用。现在 success / warning / info 各带本体（实心、压白字）与 `-ink`（纸底文字）两态，浅深两套值都验过 AA。另外补了 `--red-solid`：深色 `--red` 提亮成 `#D9705A` 后压白字只剩 2.9:1，实心底得换它。

**没动间距。** 对照表里它是"斟酌项"：中文小控件密排时 4px 步长偏粗，`gap: 6px` 与 `10px` 都是高频真实需求，硬套会变糙。留到下一轮单独决定要不要 2px 半档。

## 7. 最后一句

这套设计的底层判断是对的：暖米纸 + 深棕墨 + 克制玉米金 + 线描图标，这个组合在中文 AI 应用里很少见，有辨识度。**现在缺的不是"加更多的效果"，而是"把多余的效果删掉"。**

每次准备加一个 `inset 白线`、`box-shadow: 0 8px 20px`、hover `translateY(-2px)` 或 `infinite` 脉冲之前，先问一句：**这张纸上会发生这件事吗？** 答案是不会的时候，删掉它，质感就往前走一步。
