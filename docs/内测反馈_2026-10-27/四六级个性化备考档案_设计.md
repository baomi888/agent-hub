# 四六级工作区 · 个性化备考档案 设计方案

> 触发：内测反馈「不是想取消，是这根本就没有指定计划就有个很模板化的备考区了……
> 连选四级还是六级都不能选，时间啥的也不能选」。
> 结论：**问题不在缺按钮，在于「计划」这个对象本身没有可配置项。**

---

## 一、现状为什么会变成"模板"

| 位置 | 现状 | 后果 |
|---|---|---|
| `service/cet.py:27 _MODULES` | 5 个模块、任务文案**全部写死** | 谁打开都是同一套任务 |
| `service/cet.py:36 api/cet.py:36` | 默认 title = `"六级 54 天备考计划"` | **所有人默认都是六级**，四级考生没法选 |
| `api/cet.py:38` | `days = body.get("days") or 54` | 只能填天数，不能填考试日；前端也只有一个数字输入框 |
| `service/cet.py:120` | `exam_date = _add_days(start, days-1)` | 考试日是**反算**出来的，不是用户选的 |
| `cet_plans` 表 | 列只有 `title/start_date/exam_date/total_days` | **没有 exam_type、没有目标分、没有模块选择** |
| `cet_scores` 表 | 反倒有 `exam_type` 和 `target` | 分数分四级六级，计划却不分 —— 数据模型自相矛盾 |

所以用户看到的"模板化工作区"，本质是：**系统替他决定了考几级、考多久、每天练什么、目标多少**。
按钮点下去的那一刻，这四件事就已经写死了。

---

## 二、目标：从「计划」升级为「备考档案」

把 `plan` 从"一次生成的结果"改成"一份可编辑的档案（profile）"：

```
备考档案 (cet_plans)
├── 考哪一级     exam_type   CET4 / CET6
├── 什么时候考   exam_date   官方日期候选 + 自定义
├── 每天练什么   modules     听力 / 词汇 / 阅读 / 写作翻译 / 真题（多选，≥1）
├── 练多少       intensity   light / standard / heavy
├── 目标多少分   target_score 425 / 500 / 550 / 自定义
└── 档案状态     archived_at  NULL = 生效中
        ↓ 按上面五项生成
   每日任务 (cet_tasks)  ← 可勾选、可算进度
```

关键变化：**任务变成档案的"产物"，而不是唯一存在的东西**。
改档案 → 重算任务；档案归档 → 任务保留但不再显示。

## 三、数据模型（幂等迁移，不重建表）

`cet_plans` 增加 5 列，全部带默认值，老数据打开即是合理初值：

```sql
ALTER TABLE cet_plans ADD COLUMN exam_type    TEXT    NOT NULL DEFAULT 'CET6';
ALTER TABLE cet_plans ADD COLUMN target_score INTEGER;
ALTER TABLE cet_plans ADD COLUMN modules      TEXT    NOT NULL DEFAULT '听力,词汇,阅读,写作翻译,真题';
ALTER TABLE cet_plans ADD COLUMN intensity    TEXT    NOT NULL DEFAULT 'standard';
ALTER TABLE cet_plans ADD COLUMN archived_at  INTEGER;
```

**迁移方式**：照 `service/daily.py` 给 `delegations` 补 `last_error` 的现成写法 —— 在
`_ensure_cet_tables()` 里 `PRAGMA table_info` 查一遍，缺哪列补哪列。**幂等，不写迁移脚本，旧库免停机。**

`modules` 用逗号分隔而不是 JSON：这里只用于"回填勾选状态"和"决定生成哪些任务"，
不参与 SQL 查询，逗号串足够，且 ALTER 的默认值能直接写。

## 四、接口设计

### 4.1 `POST /api/cet/plan` —— 建立档案（扩展入参，向后兼容）

```jsonc
{
  "exam_type": "CET6",              // 可选，默认 CET6
  "exam_date": "2026-12-12",        // 优先。给了就按它算天数
  "days": 54,                        // 只在没给 exam_date 时用（兼容旧调用）
  "modules": ["听力", "词汇", "阅读"],
  "intensity": "standard",
  "target_score": 500
}
```

- `exam_date` 与 `days` 的优先级：**exam_date 优先**，`total_days = exam_date - start + 1`。
  只给 days 时才反算 exam_date（保持旧行为）。
- `modules` 至少 1 个，最多 5 个；不在目录里的名字直接忽略（不报错，防脏数据）。
- 已有生效中的档案时：**旧档案自动归档**（不是硬删），再建新档案 —— 这正好解决
  「重复生成写 230 条垃圾任务」的隐患。

### 4.2 `PATCH /api/cet/plan` —— 改设置（新增）

```jsonc
{ "exam_date": "2026-12-12", "modules": ["听力","真题"], "intensity": "heavy", "target_score": 550 }
```

**改动的语义要分清两类**（这是本设计最关键的一条规则）：

| 改的是什么 | 怎么处理 | 为什么 |
|---|---|---|
| 考试日 / 目标分 / 考试类型 | **只更新档案字段**，任务不动 | 已经勾过的任务不该消失 |
| 模块 / 强度 | **重建「今天及以后」的任务**，今天之前的保留 | 模块变了任务就对不上；但历史打卡不能丢 |

重建范围写死在 `task_date >= today`，昨天之前的一条不碰。
`total_days` 随 exam_date 重算；如果新 exam_date 已经过去 → 返回 400「考试日不能早于今天」。

### 4.3 `DELETE /api/cet/plan` —— 归档（新增）

不物理删除。`archived_at = now()`，`_latest_plan` 加 `WHERE archived_at IS NULL`。

**为什么归档而不是删**（核实过代码）：

- `service/cet.py:151 _streak_days` 从 `cet_tasks` 里 `done=1` 的日期算 → 硬删会让**连续天数归零**
- `service/path.py:223/236` 学习路径的关卡要数 `cet_plans` 和 `cet_tasks` → 硬删会让**关卡倒退**

归档两边都不动，用户点"结束计划"不会掉进度。（这也解答了上一轮反馈里"取消"的真实诉求：
用户要的是"别再给我看这个模板"，不是"把我学过的抹掉"。）

### 4.4 `GET /api/cet/overview` —— 返回档案明细

`plan` 增加 `exam_type / target_score / modules / intensity`，
另外加 `subtitle`（`六级 · 2026-12-12 · 还剩 46 天`），前端不用自己拼日期。

## 五、任务生成规则

`_MODULES` 常量升级为**模块目录**，按强度给不同任务量：

| 模块 | light（≈30 分钟） | standard（≈1 小时） | heavy（≈2 小时） |
|---|---|---|---|
| 听力 | 精听 1 组（10 分钟） | 同义改写第 {day} 组（10–15 组） | 精听 2 组 + 复盘错题 |
| 词汇 | 高频词 15 个 | 高频词 30 个 + 昨日错词 | 高频词 50 个 + 错词复盘 |
| 阅读 | 真题阅读 1 篇 | 真题阅读 2 篇 + 长难句 3 句 | 阅读 3 篇 + 长难句 6 句 |
| 写作翻译 | 作文或翻译（二选一） | 作文 1 篇 或 翻译 1 段 | 作文 1 篇 + 翻译 1 段 |
| 真题 | 真题 1 套（按周） | 真题限时 1 套 | 真题 1 套 + 错题精析 |

**只生成被勾选的模块**。强度只影响任务文案，不影响天数 —— 天数由考试日决定。

`exam_type` 影响：默认目标分推荐（四级 425 / 六级 500）、档案标题、以及分数趋势图只画同级。

## 六、交互设计

### 6.1 空状态 = 配置向导（不再是"输个天数点按钮"）

见附图 `cet_wizard.png` 的线框。四组选择 + 实时天数反馈：

```
考哪一级     [ 四级 ] [ 六级 ]                     ← 默认六级
考试日期     [2026-12-12 ▾]  或自填 [____]         ← 内置官方日期候选
             → 还剩 46 天，每天 5 个任务
每天练什么   ☑听力 ☑词汇 ☑阅读 ☐写作翻译 ☑真题
练多少       [ 轻 30min ] [ 中 1h ] [ 重 2h ]
目标分       [500]  参考：425 及格 · 500 良好 · 550 优秀
                                  [ 建立我的备考档案 ]
```

要点：
- **天数不再是输入项，而是考试日的推导结果**（"还剩 46 天"即时显示）。
  这直接消掉用户的困惑：他关心的是"12 月 12 号考试"，不是"我要 54 天"。
- 模块用勾选，至少 1 个，全不选时按钮置灰并提示。
- 每个选项下面一行小字解释（不靠 tooltip，用户不会去悬停）。

### 6.2 有计划时：顶部一行档案摘要 + 「调整设置」

```
六级 · 2026-12-12 · 还剩 46 天 · 目标 500        [ 调整设置 ⌄ ]
```

点开是**同一个向导**（预填当前值），底部多两个按钮：
`[ 保存修改 ]` `[ 结束这个计划 ]`。结束要二次确认，文案写清
「结束不会删掉你已完成的记录，只是不再显示这个计划」。

### 6.3 考试日已过

`today > exam_date` 时，今日任务区显示：「这场考试已经结束了」+ 两个出口：
`[ 开始新的备考 ]` `[ 回顾这次的完成情况 ]`。不再是现在那句干巴巴的"今天不在计划区间内"。

## 七、兼容与迁移

| 场景 | 处理 |
|---|---|
| 老档案（迁移后 `exam_type` 默认 CET6、modules 全选） | 打开设置面板即看到合理初值，用户一改就保存 |

| 线上已有测试数据 | 不删。归档机制只在用户主动点「结束」时触发 |

## 八、需要你拍板的 4 件事

1. **改模块/强度时，历史任务保留吗？** 推荐"只重建今天起，昨天之前不动"（打卡不丢）。
2. **"练多少（强度）"要不要做？** 不要的话就只留"选模块"，界面更简单，但少一层个性化。
3. **考试日期给不给官方候选？** 推荐给（如 2026-06-13 / 2026-12-12）+ 允许自填，
   大部分学生记不住确切日期。
4. **要不要支持"每个模块自写任务"**（如把"听力同义改写第 N 组"改成"精听 BBC 1 篇"）？
   这是"完全自定义"的最后一层，但要给每个模块一个可编辑文本框，成本和维护都高一档。
   建议**这期不做**，先做模块级选择。

## 九、工作量与验收

**后端**：表迁移 + 3 个接口（1 改 2 增）+ 任务生成器改造 ≈ 4 小时
**前端**：向导组件（空状态与设置面板复用）+ 摘要行 + 已过期状态 ≈ 4 小时
**测试**：8–10 条（含迁移幂等、归档后 streak 不变、改模块只动今天起）≈ 2 小时

**验收标准（每条都能自动化）**
- 建档案时选四级 → `overview.plan.exam_type == "CET4"`，任务里没有未勾选的模块
- 只勾 2 个模块 → 每日任务正好 2 条/天，`progress.total == days × 2`
- 改模块为 3 个 → 今天起每天 3 条，**昨天之前的任务条数不变**
- 结束计划 → `overview.plan == null`，但 `streak` 与 `/path` 关卡**保持不变**
- 新建第二份档案 → 旧档案 `archived_at` 非空，任务行仍在库里（不是垃圾，是历史）
- 老库（缺 5 列的）→ 启动后 `PRAGMA table_info(cet_plans)` 有 5 个新列，**跑两次不报错**

### 两个踩过的坑（留给以后的自己）

1. **"还剩 N 天"有两个口径**：向导里算任务要用"含今天"（47），摘要行显示"距考试"（46）。
   一开始混用，出现"向导说还剩 47、摘要行说 46"的自相矛盾。现在向导改用
   `共 N 天（含今天）`，摘要行保留`还剩 N 天`，两个数字不再互相打架。
2. **探针的 `includes` 会点错按钮**：找「保存修改」时先命中了
   「← 返回工作区（不保存修改）」，于是编辑态被关掉、什么都没存，
   日志上却显示"点了保存"。改成**精确匹配优先、包含匹配兜底**才抓到真问题。
