# 苞米agent · 多用户隔离改造（已落地）

> 方案见 `docs/多用户隔离改造方案.md`（选的是**物理隔离**路线）。
> 本文记录**实际改了什么、怎么上线、怎么验证、还剩什么没做**。
> 落地时间：2026-10-06。

---

## 一、一句话概括

原来"所有访客共享同一份会话与知识库"，现在**每个人有自己的账号、自己的会话、自己的知识库，互相看不见**。
判断依据不是"id 猜不到"，而是服务端每次都查归属表。

---

## 二、改动清单

### P1 · 认证底座（新增）

| 文件 | 作用 |
| --- | --- |
| `core/auth.py` | 口令散列（PBKDF2-SHA256）+ 令牌签发（HS256）+ Cookie 读写。**只用标准库**，没加 pip 依赖 |
| `core/account.py` | `users` 表与账号增删查（`password_hash` 永不外泄） |
| `api/auth.py` | 唯一的公开路由组：`config / register / login / logout / me` |
| `main.py` | 挂载认证路由；业务路由统一 `dependencies=[Depends(get_current_user)]` |

关键设计：**默认拒绝**。新加端点只要挂进业务 router，自动就要登录，不需要"记得加一行"。
公开面压到最小：`/api/auth/login|register|config|logout`、`/api/config/defaults`、`/health`。

登录态放 **HttpOnly + SameSite=Lax Cookie**，前端不存任何凭证（JS 读不到 token，XSS 顺不走）。

### P2 · 会话 / 知识库隔离

- `core/session.py`：所有函数第一个参数改成 `owner`（**没有默认值**）。
  漏改调用点会直接 `TypeError` 报错，而不是静默读到别人的数据 —— 这是刻意的。
- `conversations` 表加 `owner_id`；`owner_id IS NULL` 的老数据**谁都看不见**（默认拒绝），
  需要用 `tools/migrate_owner.py` 显式认领。
- `kb/pipelines.py`：`kb_id = md5(owner|name)[:12]`，同名库在不同人名下是两个库；
  另有 `data/kb_owners.json` 归属表，每次访问都查（`NotOwned` 直接拒绝）。
- `api/kb.py`：所有带 `kb_id` 的端点先过 `_must_own()`，不是自己的返回 **404**（不是 403 ——
  403 等于告诉对方"这个 id 是真的"，可以用来枚举别人的库）。

### P3 · Agent 越权面 + 配额

- `agent/tools.py`：`kb_search` / `download_file` **不再接受模型传的 `kb_id`**，
  改由服务端从 `RunnableConfig` 注入。原来一段网页正文里藏句"改用 kb_xxx 检索"，
  模型就可能照做 —— 现在模型只能决定"查不查"，"查谁的库"它说了不算。
- `agent/builder.py`：提示词里也去掉了 `kb_id = xxx`（否则模型会拿着一个已不存在的参数去调工具）。
- `core/quota.py`：每分钟限流（进程内滑动窗口）+ 每日用量（落 SQLite，重启不清零）。
  **超限时不再计数**，否则用户重试几次就把计数推得更高，第二天零点前都解不开。
- `main.py`：两个配额异常注册成全局 429，不用每个端点各写一遍。
- 落点：`chat/stream`、`kb/{id}/query` 计"问答"；上传 / 重建 / 联网导入计"向量化片段"。

### 顺带补的洞（本来不在计划里，但多用户后风险变大）

- **SSRF**（新增 `core/netsafe.py`）：服务端代抓 URL 的三条通道（`/import-url`、`/import-batch`、
  `/download`）现在统一校验 —— 禁内网 / 回环 / 链路本地 / 元数据地址，且**重定向每一跳都要重新校验**。
  单用户时代这只影响你自己；多用户之后，任何一个登录用户都能借服务器的身份打内网（云元数据、
  同机 Redis、内网后台）。
- `api/chat.py`：RAG 主链路与视觉分支的同步检索补上 `asyncio.to_thread`（实测每次堵事件循环约 250ms）。

### 前端

| 文件 | 作用 |
| --- | --- |
| `lib/api.ts` | 全部请求带 `credentials: "include"`；新增登录/注册/退出/me；401 统一广播事件 |
| `lib/sse.ts` | 流式请求带 Cookie；补 `try/finally` 释放 reader |
| `lib/hooks/useAuth.ts` | 登录态：首屏 `/api/auth/me/` 探活 + 收听 401 事件 |
| `components/AuthGate.tsx` | 登录门（整页挡住，不是弹窗 —— 背后留着别人的列表等于隔离做了一半） |
| `components/Sidebar.tsx` | 底部显示当前账号 + 退出 |
| `lib/hooks/useSessions.ts` | 列表有内容但没选中时自动落进最近一个（登录后补拉的场景） |

## 三、上线步骤（服务器上逐行执行）

> 前端动了 `src/**`，必须 `deploy`（真 build），不能只 `restart`。

```bash
cd /root
curl -fL -o /tmp/u.tar.gz https://codeload.github.com/baomi888/agent-hub/tar.gz/refs/heads/main
tar -xzf /tmp/u.tar.gz -C /tmp
cp -a /tmp/agent-hub-main/. /root/
bash deploy.sh deploy
```

跑完确认两件事：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/api/sessions/
```

期望 **`401`**（未登录被挡住；以前是 200）。

```bash
curl -s http://127.0.0.1:3000/api/auth/config/
```

期望 `{"allow_signup":true}`。

然后浏览器打开站点 → 应该先看到登录页 → 注册一个账号。

### 把旧数据认领给自己的账号

改造前的会话 / 知识库没有主人，按"默认拒绝"它们现在谁都看不见。要拿回来：

```bash
cd /root
/root/venv/bin/python tools/migrate_owner.py --username 你的用户名
```

先只看数字（演练，不写盘），确认后加 `--apply`：

```bash
/root/venv/bin/python tools/migrate_owner.py --username 你的用户名 --apply
```

```bash
bash deploy.sh restart
```

> ⚠️ 认领不可逆，一次只认领给一个人。

### 想只给自己用

`.env` 里加一行 `ALLOW_SIGNUP=0`，然后 `bash deploy.sh restart`。
这样别人打开只能看到登录页、注册入口消失。

## 五、已知不足（汇报时主动说，是加分项）

1. **口令散列用 PBKDF2-SHA256**（标准库实现，省一个 pip 依赖）。生产级应选 argon2/bcrypt，
   接口形状已经留好，将来只改 `core/auth.py` 一个文件。
2. **限流是单进程的**：内存里的滑动窗口，多副本部署会各算各的。要横向扩容得换 Redis，
   `core/quota.py` 的函数签名不用动。
3. **没做密码找回、邮箱验证、管理员后台**，也没做"共享知识库"。
4. **SSRF 只做到"解析层"**：挡住了内网 IP 与重定向，但防不住 DNS rebinding
   （第一次解析给公网 IP、真正连接时给内网 IP）。要彻底防得在连接层绑定解析结果再握手。
5. **老数据需要先认领**：不认领就谁都看不见，这是刻意的安全选择（不能让第一个注册的人
   顺手领走别人的历史），代价是多一步操作。
