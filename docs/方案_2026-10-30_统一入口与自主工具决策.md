## 1. 已锁定决策

| 编号 | 决策项 | 结论 |
|---|---|---|
| D1 | 「绑库」定义 | 知识库（上传的资料/文档库）；业务数据库不在本轮范围 |
| D2 | 删除「自动」 | 用户不再看到「自动」；改为两个显式能力开关 |
| D3 | 两个开关 | 「检索」「智能联网」（原「纯对话」改名）。**默认两个都不勾**；可同时勾选 |
| D4 | 开关语义 | 都不勾 = 纯大模型（不查库、不联网）；勾检索 = 查知识库；勾智能联网 = 允许联网；两个都勾 = **先库后网** |
| D5 | 勾「检索」时的执行 | **结构上先自动检索一轮**（RAG 检索链 + 引用卡片），结果交给模型；模型再决定补不补检索 / 补不补联网 |
| D6 | 勾「智能联网」时的执行 | 把 web_search 工具交给模型，**模型自主决定搜不搜、搜几次** |
| D7 | 检索 + 会话无库 | 按对话主题建新库（D9 的个性化库体系），**先询问用户确认**，确认后建库、入库、再检索回答 |
| D8 | 算数 / 天气 | **UI 与后端一起删除**。感知工具只剩：知识库检索、联网搜索 |
| D9 | 工作流 vs 智能体 | **一次轻量 LLM 判定**（workflow / agent），**删除关键词规则层** |
| D10 | 长对话 → 个性化知识库 | 压缩时由后端 worker 沉淀；**默认开启、按主题自动建多个库**；用户可关（关掉只做正常压缩） |
| D11 | 智能联网结果 → 建库 | 收集信息并回答后，**问一次「要不要建知识库」**；确认后按主题建库 |
| D12 | 工具权限模型 | 所有工具都由模型自主决定调不调、调几次；**用户不逐个选工具**。只读感知工具直接执行；改状态的交互工具执行前需确认，或在设置页预授权 |
| D13 | 交互工具清单 | 下载文件、写入知识库（对话沉淀）、知识库文档管理（列表/删除/改名）、修改用户画像/标签 |

## 2. 目标架构

```text
POST /api/chat/stream
  请求能力：use_kb（检索开关） / use_web（智能联网开关）   ← 默认都为 false
  兼容：旧 mode 字段（auto/rag/llm/agent/hybrid）按映射降级，前端不再发
        │
        ├─ ① 轻量 LLM 判定：workflow | agent（替代原 keyword 规则层）
        │      workflow → 混合引擎 plan→execute（轨迹照旧）
        │      agent    → ② 统一智能体
        │
        └─ ② 统一智能体（工具由模型自主决定）
              ├─ use_kb && 已绑库：先自动检索一轮（sources/grounding）
              │     → 片段进上下文 → agent 循环（kb_search 可补检索）
              ├─ use_kb && 无库：询问按主题建库（D7）
              ├─ use_web：绑定 web_search（+ 下载），模型自主搜
              └─ use_kb && use_web：先库后网（D4）
                   → 回答后按 D11 询问是否把结果沉淀为知识库
```

**决策权归属**

| 决策 | 谁决定 | 依据 |
|---|---|---|
| 用不用知识库 / 用不用联网 | 用户（两个开关） | D3/D4 |
| 工作流还是智能体 | LLM（一次轻量判定） | D9 |
| 用哪个工具、用几次 | 模型（ReAct 循环） | D12；`recursion_limit=10` 仅防跑飞的硬上限 |
| 先库后网顺序 | 系统结构（开关都开时） | D4/D5 |
| 查哪个库 / 下载白名单 | 服务端注入（模型不能改） | 既有安全边界，保留 |

## 5. 长对话 → 个性化知识库（D10）

| 项 | 设计 |
|---|---|
| 触发 | 压缩触发时（`core/context_compress.py::maybe_compress`）登记待沉淀；由后台 worker 异步执行 |
| 抽取 | 复用 `kb/dialogue_import.py::extract_candidates()`（规则分流 + salience + 纠正抑制） |
| 入库 | `RagPipeline.add_chunks()`；`source`=「对话·<会话标题>」+ message_id 溯源 |
| 库形态 | **按主题自动建多个库**（LLM 生成库名，同主题复用/合并，防重复建库） |
| 回写 | `mark_segments_staged()` 标 staged；已备份段才允许被折叠 |
| 用户开关 | 设置页「自动沉淀到个性化知识库」，默认开；关闭 = worker 不建库，只做普通压缩 |
| 安全 | owner 隔离；可预览/撤销；幂等（同 message_id 不重复入库）；入库内容只来自本会话消息，不接受模型构造内容 |

## 6. 显式检索无库 → 按主题建库（D7）

| 项 | 设计 |
|---|---|
| 触发 | use_kb=true 且会话无可用库 |
| 交互 | 先问「当前会话没有知识库，是否按本次对话主题新建一个？」→ 确认后建 |
| 内容 | 本次对话知识候选 + （若 use_web）模型联网补充 |
| 回答 | 建库+入库后走 RAG 检索回答，带引用；仍无内容则如实说明 |
| 防滥用 | 同主题复用已有库（主题指纹幂等）；按 owner 隔离；可删除 |

## 8. 失败兜底

| 场景 | 行为 |
|---|---|
| LLM 判定超时/非法 | 默认走 agent（无工具即纯 LLM 作答），不阻断请求 |
| 检索失败/空结果 | 模型收到弱依据提示；use_web 时可转联网；仍失败如实说明 |
| web_search 失败 | 区分「未配置/额度/网络」并如实告知；`core/serper.py` 补错误码日志 |
| 工作流失败 | 沿用 `HYBRID_LLM_FALLBACK=1` |
| 建库失败（D7） | 回落到直接作答并说明原因 |
| 沉淀失败 | 不阻塞压缩，只记失败日志，下轮可重试（幂等） |

## 9. 可观测与验收

**日志**：`route=<workflow|agent> source=model`、`use_kb/use_web`、`tools=[…] count=<n>`、`sediment=<ok|skip|fail>`；不向前端展示判断理由（沿用 10-29 决策）。

**验收**

1. 两开关都关：不查库、不联网，直接 LLM 回答（无 tool 帧）。
2. 只勾检索 + 有库：先出 sources/grounding，答案带引用；模型可补检索。
3. 只勾检索 + 无库：弹「是否按主题建库」，确认后建库+检索；取消则直接作答。
4. 只勾智能联网：模型自主联网（可能 0 次或多次），不编造实时信息。
5. 两开关都勾 + 有库：先库后网；库结果弱时模型自主补联网。
6. 联网回答后询问「是否建知识库」，确认后按主题建库可检索。
7. 长对话触发压缩：默认自动沉淀（按主题多库）；设置关掉后只压缩、不建库。
8. 规则层删除后：原 24 条样本不再被规则截走，全部走 LLM 判定；单测改断言。
9. 算数/天气前后端无残留（grep `calculator|get_weather|数学计算|查天气` 仅剩历史文档）。
10. 全量 pytest 无回退；`ruff check` 0；`tsc --noEmit` + `npm run build` 通过。

## 10. 风险登记

| 编号 | 风险 | 缓解 |
|---|---|---|
| R1 | 自动沉淀与 10-26 报告「不做自动入库」红线冲突，噪声/错误中间态入库 | 默认开但可关；只沉淀高置信知识句；可预览/撤销；幂等与 staged 回写 |
| R2 | 每轮多一次 LLM 判定 + 绑库先检索 → 首字延迟 | 2s 超时兜底；检索与判定可并行；压测 P95 >15% 再优化 |
| R3 | 删算数/天气影响既有测试与用户预期 | 全仓 grep 调用点；测试改断言；文案说明 |
| R4 | 自动建库/沉淀带来 embedding 成本与垃圾库 | 主题指纹复用、确认制、可删除、限每用户库数 |
| R5 | 交互工具（写库/改画像）被提示词注入利用 | 入库内容只来自本会话 + owner 隔离 + 确认/预授权 |
| R6 | 删除规则层后 LLM 判定误判多步任务 | prompt 示例 + 单测样本；误判只影响形态/速度 |
