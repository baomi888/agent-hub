## 二、三个设计决定（都有代价，写下来免得后人改回去）

### 1. 压缩块放在历史最前面，不塞 system prompt

Agent 路径的 system prompt 在 `agent/builder.py::build_agent` 里**随图编译固化**，图按
`(has_kb, 场景, 激活集)` 做 LRU 缓存（32 槽）。把压缩块塞进 system，等于给缓存键多一个
随会话变化的维度 —— **每个会话都编译一张新图**，缓存直接失效，而编译是纯 CPU 开销。

而压缩块本身是**稳定前缀**：只在压缩事件时**增长**（增量分段，不改旧段），两次压缩之间
逐字节不变。所以放在历史最前面同样不破 KV 缓存，还没碰缓存的键。

### 2. 用一对 `human → ai` 包住，不裸插一条 human

- 部分 chat template 对"连续两条 human"敏感（P0-1 移定位时踩过）；
- 必须显式写明**"这不是用户的新提问"**，否则模型会把摘要里的内容当成本轮诉求去执行
  （摘要里必然带着用户以前的问句）。

`PRELUDE_HEAD` / `PRELUDE_ACK` 写死在代码里，是行为契约，不做成配置项。

### 3. 没有压缩块时必须**原样直通**

这是最容易写错的地方。`plan_context()` 无条件按最近 K 轮截断；若在"还没压缩过"的短会话上
也套 K 轮窗口，等于把 `MAX_HISTORY_TURNS=30` 悄悄改成 6 轮 —— **功能倒退**，而且没有任何报错。

所以 `assemble_history()` 先判 `summary_text` 为空就整段直通。回归测试 `[K]` 专门盯这一条。

## 三、读写两侧各改了什么

| 侧 | 位置 | 改动 |
|---|---|---|
| 读 | `api/chat.py` 五处 | vision / hybrid / agent / rag / llm 全部改走 `ctxcompress.assemble_history()`；五处规则只有一份实现，避免日后漏改其中一处 |
| 写 | `api/chat.py` 两处收尾 | 回答落库后 `_schedule_compress()` 起后台任务跑 `maybe_compress()`（fire-and-forget，不拖慢 `done` 帧）；vision 分支有自己的收尾，单独接 |
| 配置 | `core/config.py` | `COMPRESS_ENABLED` 等 6 个开关（此前 `context_compress` 读的是 `getattr(config, ...)` 的兜底默认值，运维**改不了**） |

写入侧的顺序约束（写进代码注释了）：**必须在 assistant 消息落库之后**再压缩。否则本轮这一问一答
会被算进"旧轮次"，刚回答完就被压成摘要，下一轮追问细节时模型已经看不到原文。

## 四、一个接线时才暴露的坑

`should_compress()` 的字符数必须按**全量历史**算，不能按 `get_messages()` 的窗口算。
窗口被 `MAX_HISTORY_TURNS=30` 封顶后字符数恒定，**永远到不了 80% 阈值 —— 压缩永远不会触发**。
所以 `maybe_compress()` 用 `limit_turns=None` 取全量。

## 五、验证

| 验证 | 结果 |
|---|---|
| `python tests/test_compress_wiring.py` | **31 项全过**（K/L/M/N/O/P/Q/R/S 九组） |
| `python -m pytest -q`（排除并发会话的 WIP 测试） | **254 passed, 19 subtests**（与 `dev` 基线一致，零回归） |
| `python tests/test_context_compress.py` | 原算法自测不受影响 |

新增测试 `tests/test_compress_wiring.py` 覆盖的九组：

- **K** 无压缩块原样直通（防窗口悄悄缩短）
- **L** 有压缩块：前置一对 + 最近 K 轮，被压缩原文不再重复进上下文
- **M** 前置说明含"不是用户的新提问 / 不要编造"
- **N** 两次组装逐字节一致（稳定前缀）
- **O** 未到阈值不写库 / 到阈值写库且 `compressed_upto` 前进
- **P** 二次压缩只追加不改旧段
- **Q** L1 回退：新压缩丢实体且有上一版 → 不写库、库里不被污染
- **R** `COMPRESS_ENABLED=0` → 读写两侧退回旧行为（一键回滚开关）
- **S** 压缩层抛异常 → 降级为原样返回，不抛给对话

## 六、上线怎么回滚

只改环境变量，不动代码、不回滚版本：

```bash
COMPRESS_ENABLED=0        # 读写两侧同时退回"滑动窗口 + 无压缩块"
COMPRESS_KEEP_TURNS=12    # 或只把尾巴放大（更保守，仍走压缩）
```
