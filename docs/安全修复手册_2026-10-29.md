把本次改动同步到服务器（`git pull` 或重新打包上传）。涉及文件见第 5 节，**不要只传单个文件**：`agent/tools.py`、`api/chat.py`、`hybrid/*`、`core/*` 之间有联动。


预期：`15 passed`。

### 2.2 配置 `.env`

编辑 `<项目根目录>/.env`，逐项确认：

```ini
# 管理员：优先用 uid（不可猜、不可抢注）
ADMIN_UIDS=<管理员的 uid>
ADMIN_USERNAMES=

# 下载闸门：只允许下载本轮搜索/用户原话里的链接
DOWNLOAD_ALLOWLIST_ENABLED=1

# 单次工作流 tool 节点调用上限
HYBRID_MAX_TOOL_CALLS=20

# 注册策略：建议关闭；若要保留开放，见 4.1
ALLOW_SIGNUP=0
```

**取管理员 uid**：

```bash
# 账号已存在（推荐）：只查 uid
venv/bin/python tools/create_user.py 苞米呀 --show-uid

# 账号不存在：先建号（会交互式输入两遍密码）
venv/bin/python tools/create_user.py 苞米呀
```

把输出的 `uid` 填进 `ADMIN_UIDS`，并**清空**原来的 `ADMIN_USERNAMES`。
如果 `.env` 里还留着 `ADMIN_USERNAMES=苞米呀`，代码仍兼容，但不如 uid 安全。

> 为什么改：原默认管理员名写在公开仓库里，账号未创建时第一个抢注的人会直接变成管理员。现在这个名字在注册入口被保留，只能由 `tools/create_user.py` 创建。

### 2.4 SSH 加固（S-01，最高优先级）

**推荐用阿里云 Workbench 执行**（不需要 SSH）：控制台 → ECS → 实例 → 远程连接 → Workbench → root 登录。

第一次（不会关密码通道，不会锁死）：

```bash
cd <项目根目录>
cat ~/.ssh/id_ed25519.pub        # 若用 Workbench，先在本地取自己的公钥粘进来
bash hardening/fix-s01-ssh.sh --pubkey "ssh-ed25519 AAAA... 你的公钥注释"
```

它做的事：建 `deploy` 用户 → 配 NOPASSWD sudo → 把公钥写入 `deploy` 和 `root` → 装 fail2ban → `PermitRootLogin prohibit-password` → `sshd -T` 校验生效值。

**验证**（不要关当前 Workbench/SSH 会话）：另开一个终端：

```bash
ssh deploy@8.163.62.25
sudo -v          # 应直接通过
```

第二次（彻底关密码、禁 root）：

```bash
bash hardening/fix-s01-ssh.sh --i-verified --disable-password --disable-root
```

其他命令：

```bash
bash hardening/fix-s01-ssh.sh --status     # 看生效值
bash hardening/fix-s01-ssh.sh --rollback   # 恢复发行版默认密码登录
```

**安全组**（脚本改不到，必须手动）：阿里云控制台 → 安全组 → 入方向 → 22 端口授权对象改成**你的出口 IP/32**，不要 `0.0.0.0/0`。

> 如果 SSH 锁死：用 Workbench 登录 → `bash hardening/fix-s01-ssh.sh --rollback`。
> 如果 Workbench 也进不去：控制台「重置实例密码」后重启，再用新密码进 Workbench。

`deploy.sh` 第 8 步会同时放行 3000 和 8000。**每次部署都会把 8000 重新打开**，所以要改脚本：

```bash

#   firewall-cmd --permanent --add-port=${BACK_PORT}/tcp
#   ufw allow ${BACK_PORT}/tcp
```

同时：阿里云安全组删除 `8000/8000` 入方向。后端本来就是 `127.0.0.1:8000`，关掉不影响前端。

## 8. 常见问题

**Q1：SSH 报 `Permission denied (publickey,password)`，是服务器不通吗？**
不是。22 端口可达，是认证没过。用 root 密码登录，或走 Workbench 装公钥。

**Q2：Workbench 也进不去？**
控制台「重置实例密码」→ 重启实例 → 用新密码进 Workbench。重置会重启，选低峰期。

**Q3：`https://myzhisui.cn` 打不开，但 IP:3000 能开？**
说明 HTTPS/nginx 还没接管，或备案未通过被拦。**不要关 3000**；先确认备案状态与 443 监听。

**Q4：改了 sshd 后新终端登不进？**
当前会话别关，用 Workbench 执行 `--rollback`；或从 `/etc/ssh/sshd_config.bak.<时间戳>` 还原。

**Q5：管理员账号找不到？**
先 `venv/bin/python tools/create_user.py <名字> --show-uid`；没有就建号。建完把 uid 填 `ADMIN_UIDS`，重启后端。

**Q6：为什么不能把 `ADMIN_USERNAMES` 留着？**
兼容，但名字可猜。推荐 `ADMIN_UIDS`；两者都填时 uid 优先。
