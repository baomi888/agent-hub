# 调研报告：模型选型（性价比 · 各自擅长什么 · 哪个适合我们）

> 日期 2026-10-15 · 面向：标签钩子 C 方案（第 3、4 点调研之一）
> 结论先行：**不要"一个模型打天下"**。按 4 类任务分工——便宜的干抽取、贵的只干对话，
> 并用**准入门槛 + 自家任务基准**决定谁上，而不是看榜单。

## 1. 先说方法：这个项目该怎么选模型

你本机那本书里有一段方法论，比任何榜单都更适用：

> `chapter6.md:491`：**"此时你面临的问题不是『Gemini 是否比 Claude 强』，而是『在我的特定任务上，
> Gemini 是否比 Claude 好？好多少？切换成本是什么？』"**

> `chapter6.md:429`：**"成本不应孤立评估——一个便宜但成功率低的模型，因为需要频繁重试，
> 实际花费可能反而更高。需要计算每个任务的平均成本和成本-性能比。"**

**所以本报告分三步**：① 把我们的任务拆开（§2）②给各档位的真实价格（§3）③给准入门槛与自家基准怎么建（§5）。
**不给"谁最强"的结论**——那个结论在你的任务上没有意义。

## 2. 我们的四类任务，需求完全不同

| 任务 | 频率 | 输入规模 | 对模型的要求 | **关键约束** |
| --- | --- | --- | --- | --- |
| **A. 对话问答** | 每次提问 | 中（RAG 片段 + 历史） | 语言质量、推理、工具调用 | 用户**直接感知质量**，最不能省 |
| **B. 标签抽取** | 每轮 / 每天 | **小**（一轮对话） | **结构化输出、限定词表、低温度** | 量大，**最该省** |
| **C. 每日总结** | 每天 1 次/人 | **大**（当天全部会话） | 长上下文、归纳、**结构化** | 注意"长输入"的阶梯定价 |
| **D. 向量化** | 每次入库 | 中（按切片） | embedding 专用 | 已有选型，见 §4 |

> 关键洞察：**B 和 A 的需求几乎相反**。A 要"聪明"，B 只要"听话+便宜+稳定"。
> 把它们绑在同一个模型上，等于让最贵的那档去干最不需要智商的活。

## 4. 各模型"擅长什么"（按我们的任务说，不按通用能力说）

| 任务 | 推荐档 | 理由 |
| --- | --- | --- |
| **A. 对话问答** | DeepSeek `deepseek-chat`（现状） | 已跑通、中文好、OpenAI 兼容、支持 function calling（Agent 链路依赖）。**别为了省这点钱动它** |
| **B. 标签抽取** | **`qwen-flash` 或 `qwen3.7-flash`**（$0.028/$0.110 级） | 任务本质是"从封闭词表里选 + 输出 JSON"，**不需要推理能力**；小模型更快更稳更便宜 |
| **C. 每日总结** | `qwen3.7-plus` 级 或 DeepSeek；**务必走 Batch** | 输入大（全天会话），需要归纳与结构化；Batch 半价 + 错峰折扣 |
| **D. 向量化** | 百炼 `text-embedding-v3`（现状） | 已在用；换模型要整库重建，**非必要不动** |
| **E. 视觉（图片理解）** | `qwen-vl-plus`（现状） | 已是低成本档 |
| **F. 蒸馏提炼（全量回溯）** | 与 B 同档 + **Batch** | 一次性全量，量大且非实时，**Batch 是必选** |

**一句话**：**A 保持现状不动；B/F 换成 flash 档；C 走 Batch + 错峰。**
这样"模型选型"就变成了"按任务分工"，而不是"换一个更好的模型"。

## 5. 怎么决定"哪个够用"：准入门槛 + 自家基准

### 5.1 抽取任务的准入门槛（可用指标，不是感觉）

标签抽取可以被**客观打分**，因为它有标准答案结构：

| 指标 | 定义 | 门槛建议 |
| --- | --- | --- |
| **JSON 合法率** | 输出能被 `json.loads` 的比例 | ≥ 99% |
| **词表命中率** | 抽出的标签能命中受控词表的比例 | ≥ 85% |
| **一致性** | 同一段对话抽两次，标签集合重合度 | ≥ 90%（低温度下） |
| **空输出率** | 正确地输出 `[]` 的比例 | 不设上限（宁可空，不可凑） |
| **P95 延迟** | 单次抽取耗时 | ≤ 3s（异步可放宽） |

**用 100 轮真实对话做基准集**（你已有的数据就够），让候选模型各跑一遍，谁过门槛用谁。
这张表本身就是**答辩材料**：它证明我们不是"凭感觉选模型"。

### 5.2 别踩的坑

| 坑 | 为什么 |
| --- | --- |
| 只看榜单选模型 | `chapter6.md:491`：榜单不回答"在我的任务上好不好" |
| 只看单价 | `:429`：便宜但成功率低的模型，重试后总成本更高 |
| 抽一次就定论 | 抽取有随机性，**同一批样本跑 2~3 次**看稳定性 |
| 忘了切换成本 | 换 embedding 要**整库重建**；换对话模型要重测 Agent 工具调用（function calling 支持度不一致） |

## 6. 结论与行动项

### 结论

1. **任务分工，不搞一刀切**：A 对话保持 DeepSeek；B/F 抽取换 flash 档；C 总结走 Batch + 错峰
2. **省钱靠杠杆不靠降级**：Batch 半价 + 缓存 10% + 错峰折扣，比换便宜模型更确定
3. **用自家基准选型**：100 轮真实对话 + §5.1 的五个指标，谁过门槛用谁
4. **不动 embedding**：换它要整库重建，收益不成比例
