## P0 · 高收益、低风险，建议先做

### 1. 拆分 ChatArea.tsx → `components/chat/`
纯移动文件，不改逻辑。拆成：

```
components/chat/
  constants.ts    # MODE_LABELS / EXAMPLES / TOOL_META / ABILITIES
  content.tsx     # URL_RE / splitByUrl / renderContent / cleanLine（纯函数，可单测）
  plan.tsx        # PLAN_KEYWORDS / isPlanRequest / PLAN_TOPICS / parsePlan / PlanCard
  Bubble.tsx      # 消息气泡（含操作条 hover 逻辑）
  Field.tsx       # 设置项控件
  HubMark.tsx     # 品牌 icon
  index.tsx       # ChatArea 主组件（拆完剩约 500 行）
```

收益：Bubble 是渲染热路径（memo 过），独立文件后边界清晰；plan/content 纯函数拆出后**可以补单测**。

### 2. 抽取重复的复制逻辑 → `useCopy()`
`ChatArea.tsx` 第 392、471 行有两份一模一样的 `const [copied, setCopied] = useState(false)` + 复制 + 定时还原。抽成 `lib/useCopy.ts`（copy + toast + 1.5s 还原），两处共用。

### 3. CSS 死代码清理（已核实引用）
- 删除 `--spine-ink` / `--spine-hair`（:root 与 .dark 共 4 行）：书脊中缝删除后全库无引用，grep 已验证。
- `.brand-sub` 仍在用（Sidebar），**保留**。
- 顺带把 2.4k 行以后的历史注释块里已失效的描述清一遍。

### 4. 令牌去重（项目记忆里的 P2 待办）
`--paper/--panel/--surface` 同值、`--ink/--text-1` 同值。保留一个事实来源，其余改为 `var()` 别名（现有注释已写明这个意图，但只做了一半）。防"改一处漏三处"。

### 5. globals.css 按域拆分
3033 行按域拆成多文件，主文件 `@import`（Tailwind v4 原生支持，编译产物不变）：

```

  base.css        # body、focus-visible、滚动条、toast
```

纯移动，风险最低；拆完后"改欢迎页只看 welcome.css"。

## P1 · 中收益，P0 完成后做

### 6. page.tsx 编排层拆 hooks
会话增删改查、知识库绑定/解绑、预填同步混在 693 行里。抽 `lib/hooks/useSessions.ts`、`useKnowledge.ts`，page 只剩"组合 + 布局"。这是后续任何功能开发（如多人协作、会话搜索）的前置条件。

### 7. 消息渲染 ErrorBoundary
Bubble 直接渲染模型输出的解析结果，一条坏消息抛错会白屏整个会话。给 Bubble 包一层 ErrorBoundary，降级显示"这条消息渲染失败 + 重试"。改动小、价值高。

### 8. API 层类型收口
`lib/api.ts`（139 行）里返回值标注不全，靠调用方推断。把返回类型对齐 `lib/types.ts` 已有定义，消除隐式 any。

### 9. 消息列表虚拟化（先量化再决定）
会话超过 ~100 条消息时滚动会卡。**建议先不实现**，等真实使用中出现卡顿再加 `@tanstack/react-virtual`——现在加是过度设计。

## P2 · 锦上添花 / 需要后端配合

### 10. 计划卡片解析改结构化
`isPlanRequest` / `PLAN_TOPICS` 靠前端关键词硬编码猜"是不是计划请求"。正确做法是后端在响应里给结构化 plan 字段，前端只负责渲染。需后端配合，单独立项。

### 11. 最小单测
`parsePlan` / `splitByUrl` / `renderContent` / `cleanLine` 都是纯函数，P0 拆出来后用 vitest 覆盖边界（嵌套 URL、坏 markdown、空行）。成本低，防回归价值大。

### 12. KnowledgePanel 进料状态机
上传/联网两种进料的展开-校验-进度逻辑（约 300 行）可抽 `useIntake()` 或拆子组件。优先级低于以上所有项。

---

## 明确不建议做的

- **不引入组件库**（shadcn/radix 全家桶）：设计体系已调好且高度定制，引入只会打架。
- **不重构设计令牌语义**：金只点缀、暖纸底这套约束是资产，不是负债。
- **不上状态管理库**（zustand/jotai）：现有 props + hooks 规模完全可控，page.tsx 拆完 hooks 后问题就消失了。
