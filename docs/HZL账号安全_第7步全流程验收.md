### B. 真实 QQ SMTP、隔离账号、实际注册与找回 API

工具：tools/check_account_recovery_live.py。
用户明确确认沿用此前配置，仅向发件邮箱自身发送两封邮件。

流程：
- 隐藏输入取得凭证，仅保留在进程内，不读取真实 .env。
- 新建独立临时数据目录和账号，不查询既有用户库。
- 经真实注册发码 API → QQ SMTP → 验证 → 原子注册和绑定 → /me 成功。
- 按真实时间等待至少 60 秒发送冷却，没有推进真实验收时钟绕过限制。
- 真实找回发码 → QQ SMTP → 验证 → 重置 → 确认未自动登录。
- 旧密码被拒绝，新密码登录成功。
- 验证码从本次发送器内存取得用于接口验收，不读取用户邮箱其他邮件。
- 用户随后明确确认：“两封均收到，内容正常”。

凭证未写入源码、报告、命令行参数、配置文件或 Git 文件，未回显。

## 本步发现并修复的问题

### SMTP 错误响应的敏感内容回显

新增回归用合成错误响应模拟 SMTP 回显凭证、验证码和账号，原代码测试失败。
修复 core/mailer.py：
保留原错误分类、重试判断和脱敏收件地址，
只输出固定安全说明，不再记录或返回 SMTP 原始异常内容。
旧测试要求错误详情保留脱敏地址，该断言完整保留并通过，没有降低标准。

### 介绍页注册说明过时

实际退出登录后发现：
首页首屏仍称“不用邮箱验证”，FAQ 仍称邮箱和手机号都不需要。
仅调整两个说明字符串：
- 注册时需要验证邮箱，登录仍用登录名和密码；
- 不需要手机号，可通过绑定邮箱找回密码。

位置：
frontend/src/components/landing/Landing.tsx
frontend/src/lib/landingContent.ts
真实联调中对修正后的页面文案做了断言，未改布局或其他页面业务。

### 联调工具自身的定位与修正

- 空路由播报被误当成错误提示：改为等待明确的发送失败文案。
- 邮件异步到达前提前读取：按本次新增邮件数量等待，而不是立即读取旧结果。
- 按钮变为“请稍候”被误认为成功：改为等待真实登录跳转完成。
- 退出后实际进入介绍页：按实际退出路径等待，不假定有登录表单。
- 版本公告遮挡：按正常阅读、关闭流程处理。
- 既有通用 401 文案转换：保留原产品行为，同时检查真实登录 HTTP 状态。
- 清理诊断代码时发生脚本维护错误，产生空运行；未计为通过。
  完整恢复测试后增加语法、场景数量及精确请求数量检查，全部断言重新执行。
- 未保留输出验证码、证明或请求体的临时诊断代码。
