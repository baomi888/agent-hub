## 一、后端可更新点

### ★★★ 1. Agent 记忆从未持久化——`SqliteSaver` 导入失败被静默吞掉
**文件**：`agent/builder.py:67-84`

```python
def _make_checkpointer():
    try:
        from langgraph.checkpoint.sqlite import SqliteSaver
        ...
    except Exception:          # ← 这里吞掉了 ModuleNotFoundError
        return MemorySaver()
_CHECKPOINTER = _make_checkpointer()
```

**为什么值得改**：这是全项目最高价值的单点。表现是"多轮对话在重启后失忆"，但
用户看到的现象是"它好像记不住我上面说过什么"，而代码里完全看不出异常——`except Exception`
连一条日志都没留。硬证据：`data/agent_memory.sqlite` **从未被创建过**（09-29 报告曾误判为已落盘，
09-30 已更正，本轮再次确认）。

**怎么改**（两步，都是加法）：
1. `pip install langgraph-checkpoint-sqlite`（3.1.1，dry-run 已确认可拉），并在 `requirements.txt`
   的 LangGraph 段落补一行 `langgraph-checkpoint-sqlite>=3.1`。
2. `except Exception` 里补 `logging.warning("SqliteSaver 不可用，降级为 MemorySaver：%s", e)`，
   并把 `MemorySaver()` 分支的降级事实记进 `/health`（见第 6 条）。**同类静默降级一律补日志。**

### ★★★ 2. 前端丢弃了后端全部 `status` 进度事件——十几秒的 Agent 等待是黑屏
**文件**：`frontend/src/app/page.tsx:192-259`（SSE switch）

后端在长流程里主动推了 6 条人话进度（"Agent 模式，正在规划任务…"、"检索到 N 条片段"、
"正在生成答案…"），前端 switch **没有 `case "status"`**，这些帧全部落进 `default` 被丢掉。

**为什么值得改**：Agent 模式首次响应常 10~20 秒。现在用户盯着一颗转圈的玉米，不知道卡没卡；
接上以后同一份等待时间会变成"看得见的进度"。改动量：**加一个 case + 一个 state 字段**。

**怎么改**：
```ts
case "status": {
  setStatusText(ev.data.text ?? "");
  break;
}
```
在 `sendMessage` 开始时 `setStatusText("")`、`done`/`error` 时清空；渲染处复用一个已有的
低调文案位（不要新造 loading 组件，也不要加 `infinite` 动画——记忆里那条约定仍然有效）。

### ★★ 3. `retry` 只截前端、不删后端——库里攒重复提问
**文件**：`frontend/src/app/page.tsx:296-307` + `api/chat.py:242`

```ts
// 现在
const start = i > 0 && list[i - 1].role === "user" ? i - 1 : i;
setMessages(list.slice(0, start));
void sendMessage(question);
```
`chat.py:242` 的 `store.add_message(req.sid, "user", req.question)` **无条件新增**。
重试 N 次，库里就多 N 条同题，`MAX_HISTORY_TURNS = 10` 的窗口会被稀释掉。

**零件全部现成，只差接线**：`api.ts:50-54` 已有 `deleteMessageTurn(sid, msgId)`，
`api/sessions.py:80-91` 的 `DELETE /{sid}/messages/{msg_id}/` 已存在，
`useSessions.ts:108-120` 的 `deleteTurn` 已经走通了这条路。

**怎么改**：`retryMessage` 在 `setMessages(...)` 之前，先 `await api.deleteMessageTurn(sid, 被撤回那条的 dbId)`
（连带其后消息），再 `sendMessage`。注意 `dbId` 为 undefined 的本地消息跳过。

### ★★ 4. `delete_conversation` 不清 `feedbacks`——删库留孤儿行
**文件**：`core/session.py:157-163`

```python
def delete_conversation(sid: str) -> bool:
    conn.execute("DELETE FROM messages WHERE conversation_id = ?", (sid,))
    cur = conn.execute("DELETE FROM conversations WHERE id = ?", (sid,))
```
`messages` 表有 `ON DELETE CASCADE`（`:72`），`feedbacks` 表**没有外键**（`:76-82`）。
对照 `delete_messages()`（`:344-346`）——那里**已经**显式清了 feedbacks，说明作者知道该清，
`delete_conversation` 只是漏写。

**怎么改**：在删 conversations 之前补一行
`conn.execute("DELETE FROM feedbacks WHERE conversation_id = ?", (sid,))`。
更彻底的做法是给 feedbacks 加 `FOREIGN KEY ... ON DELETE CASCADE`（需一次性迁移）。

### ★★ 5. `/api/kb/download` 是开放 SSRF 代理，且前端把它做成了用户可点的按钮
**文件**：`api/kb.py:400-432` + `frontend/src/components/KnowledgePanel.tsx:383`

后端只校验 `url` 以 http/https 开头，然后就 `httpx.get(url, follow_redirects=True)` 原样返回内容。
没有内网地址黑名单、没有域名白名单、没有大小上限、`follow_redirects=True` 还能绕过 IP 校验。
前端 383 行直接 `href={/api/kb/download?url=${encodeURIComponent(r.href)}}` 暴露给用户。

**为什么值得改**：单机自用风险低，但这是**唯一一个能被外部输入驱动的服务端出网请求**。
一旦分享给人用（或哪天部署到公网），就是标准的 SSRF 面。

**怎么改**（最小版，半天）：
- 限制目标必须命中搜索结果里出现过的域名（服务端存一份近期搜索来源域名的集合）；
- 解析出的 IP 落在私网段（10./172.16-31./192.168./127./169.254.）直接拒；
- 加 `Content-Length` 上限（比如 50MB）与 `Accept` 白名单（pdf/txt/md）。

### ★ 6. `/health` 是假探针 + 三处 `detail=str(e)` 裸异常
**文件**：`main.py:76-79`、`api/kb.py:372 / 382 / 397`

```python
@app.get("/health")
def health():
    return {"status": "ok", "version": "0.3.0 (W3)"}
```
永远 ok，不看 DB、不看 Chroma、不看 checkpointer 是内存还是落盘——**不能用来判断服务是否真的可用**。

三处 `detail=str(e)` 把原始异常字符串直接抛给前端（含内部路径、库名、堆栈片段）。

**怎么改**：
- `/health` 做成真实探针：`{sqlite: bool, chroma: bool, checkpointer: "sqlite"|"memory", llm_configured: bool}`，
  任一硬依赖失败返回 503。顺带把第 1 条的降级事实暴露出来。
- 三处改为 `logging.exception(...)` + 对外统一文案（如 `detail="知识库操作失败，请查看服务端日志"`）。

---

### ★ 7. `top_k` 无下界 + 上传 `Form` 字段无校验
**文件**：`api/kb.py:124`、`api/kb.py:45-47`

`top_k: int = 3` 没有 `ge=1`/`le=20`，传 0 或 -5 会走到 `select_diverse` 的分支里产生空结果或异常；
上传接口的几个裸 `Form(...)` 字段（kb_id / name 等）没有长度和字符校验。

**怎么改**：用 `Query(3, ge=1, le=20)` 与 `Form(..., min_length=1, max_length=128)`。
顺手把 `kb_id` 限制成 `^[A-Za-z0-9_-]{1,64}$`。

## 二、前端可更新点

### ★★★ 8. `submit()` 不释放已发送附件的 blob URL——长会话内存泄漏
**文件**：`frontend/src/components/ChatArea.tsx:294-312`（`submit`）

同一个文件里另外两条路径**都**规规矩矩 revoke 了：
- `removeAttachment`（`:249`）— `URL.revokeObjectURL(t.url)`
- Esc 清空（`:796`）— `prev.forEach((a) => URL.revokeObjectURL(a.url))`

**唯独发送路径漏了**：`submit` 把 `attrs` 交给 `onSend` 之后既不清空也不 revoke，
blob URL 一直挂到页面卸载。连着发几十张图的长会话会稳定涨内存。

**怎么改**：`submit` 里在 `onSend` 之后（或 `sendMessage` 拿到 attrs 后）对每张图的 `url`
调 `URL.revokeObjectURL`。注意**不能在 onSend 之前 revoke**——fetch 还在读它。

---

### ★★ 9. 删知识库后不解绑会话——静默降级成 agent 模式
**文件**：`frontend/src/lib/hooks/useKnowledge.ts:84-92`，关联 `page.tsx:346-355`

`deleteKb` 删掉库之后，重拉列表**但不碰任何会话的 `kb_id`**。
下次打开那个会话，`exists(kb_id)` 返回 False → 悄悄退回 agent 模式，
用户看到的是"知识库问答怎么不检索了"，没有任何提示。

**怎么改**：`deleteKb` 成功后，遍历 `sessions` 把 `kb_id === 被删库` 的会话一并解绑
（调已有的 unbind 接口），并 `toast("已删除知识库，N 个会话已解除绑定")`。

---

### ★★ 10. 会话搜索只搜标题——"我记得问过 XXX"搜不到
**文件**：`frontend/src/components/Sidebar.tsx:94-100`

```ts
sessions.filter((c) => c.title.toLowerCase().includes(q))
```
标题是后端自动生成的（`_generate_title`），经常与用户记忆里的措辞不一致。搜正文一个都搜不到。

**怎么改**：两条路，成本差很多——
- 轻：搜索框为空时也把**当前会话的消息**纳入匹配（仅当前会话，零后端改动）；
- 重：后端加 `GET /api/sessions/search?q=`，SQLite `LIKE` 扫 `messages.content`，前端 debounce 调。

---

### ★★ 11. 外链第三方 CDN 字体、无 `next/font`——首屏字体闪烁
**文件**：`frontend/src/app/layout.tsx:41-49`

字体走 `cdn.jsdelivr.net` 与 `miaoda.feishu.cn` 两处外链。首屏会先渲染 fallback 字体再切换（FOUT），
且依赖一个非标准的内部域名——对方一变，字体就没了。

**怎么改**：`next/font/google` 接不住 LXGW WenKai（不在 Google Fonts），实际做法是把 woff2
自托管到 `public/fonts/` + `@font-face` + `font-display: swap`（子集化后体积可控）。
这与记忆里"线上有文楷"那条不冲突——那条说的是"能显示"，这条说的是"能稳定且不闪"。

---

### ★ 12. `TOOL_META` 缺 `download_file`——第 5 个工具显示英文原名
**文件**：`frontend/src/components/chat/constants.tsx:22-58`，对照后端 `agent/tools.py`

后端有 5 个工具，前端 `TOOL_META` 只有 4 个（kb_search / web_search / calculator / get_weather），
漏了 `download_file`。`toolLabel()`（`:60`）的 fallback 是 `?? name`，所以该工具一旦被调用，
聊天里就会出现一行英文 `download_file`，没有图标、没有中文标签。

**怎么改**：补一条 `{ label: "下载文件", icon: <DownloadIcon/> }`。改动量 3 行。

---

### ★ 13. `pendingOtherCount` 提示分支是死代码
**文件**：`frontend/src/components/KnowledgePanel.tsx:702-705`

文案是"另有 N 个非图片附件未显示"，但文件选择器的 `accept="image/*"`（`:752`）
根本放不进来非图片文件，这个分支**永远不触发**。留着会让后来者以为支持文档附件。

**怎么改**：要么删掉分支，要么把 `accept` 放宽到 `.txt,.md,.pdf,image/*` 让分支活过来。
取决于产品意图，**两个方向都行，但别保持现状**。

---

### ★ 14. 会话列表删除后不重拉 + 硬编码模型名
**文件**：`frontend/src/lib/hooks/useSessions.ts:94-105`、`frontend/src/components/Sidebar.tsx:328`

- `deleteSession` 只在前端数组里移除，不重新拉取列表。与同文件里 `deleteTurn`（`:108-120`，删完重拉）
  的做法不一致——网络抖动或服务端有额外删除逻辑时，前端状态会和后端错位。
- Sidebar 底部写死 `在线 · deepseek-chat`。换模型（`core/config.py` 才是真源）后这行字就在骗人。

**怎么改**：`deleteSession` 删完调 `refresh()`；模型名从 `GET /api/defaults`（已有）取。
