# 思考流接口说明（给前端）

> 日期 2026-10-14 · 后端已完成 · 本文是**前端照做就能实现的接口契约**，不含推测
> 对应端点：`POST /api/chat/stream`（SSE）· 验证：`tests/test_reasoning_stream.py` 16 项全过

---

## 0. 给前端的三句话

1. **多了一个事件类型**：`event: reasoning`，只在服务端配置了思考模型时出现。
2. **`done` 事件多了一个字段** `reasoning`（完整思考文本，未启用时为 `""`）。
3. **行为向后兼容**：没配置思考模型的部署，事件序列与现在**完全一致**，前端不改也能跑。

**要做的改造就一件事**：把回答气泡分成上下两块 —— 上方可收纳的「思考过程」块，下方正文流式。

---

## 1. 后端到底改了什么（为什么必须改）

`DEEPSEEK_MODEL` 默认是 `deepseek-chat`，**它按定义不产出思考内容**。所以要让"思考块"有内容，
必须换成 `deepseek-reasoner` 这类思考模型。

但光换模型还不够。以下是实打实的取证结果：

> `langchain_openai/chat_models/base.py:1-12` 的原文：
> *"Non-standard response fields added by third-party providers (e.g., `reasoning_content`,
> `reasoning_details`) are **not** extracted or preserved. If you are pointing `base_url` at a
> provider such as ... **DeepSeek**, use the corresponding provider-specific LangChain package instead
> (e.g., `ChatDeepSeek`)."*

**即：用原来的 `ChatOpenAI` 指向 DeepSeek，思考内容会在 LangChain 这一层被静默丢弃**，
前端一个字都收不到——不管模型是不是 reasoner。

后端已改为：
- 装上 `langchain-deepseek` 并改用 `ChatDeepSeek`（它会转发 `additional_kwargs["reasoning_content"]`）
- `_stream_llm` 把思考增量转成 `event: reasoning`
- **出口剥离**：`reasoning_content` 绝不会被写进会话历史、也不会回灌进下一轮请求体
  （DeepSeek 官方口径是不回传；部分版本直接 400）

## 2. 事件契约（照这个实现）

帧格式与现有完全一致：`event: <name>\ndata: <单行 JSON>\n\n`（`api/chat.py:87-88`）。

### 2.1 新增：`reasoning` 事件

```
event: reasoning
data: {"text": "先看清问题"}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `text` | string | **思考增量**（delta），不是累计全文。前端自己累加 |

> 沿用现有 `token` 事件的约定：只发增量，不发累计值。早期每帧发全文会让千 token 回答产生 O(n²) 传输量。

### 2.2 变化：`done` 事件新增 `reasoning` 字段

```
event: done
data: {"answer": "...", "refs": "...", "title": "...", "mode": "rag", "message_id": 123, "reasoning": "先看清问题：用户想验证思考流。那么分两步走。"}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `reasoning` | string | **完整思考文本**。未启用思考模型时为 `""`。断线重连/刷新后靠它拿回完整思考块 |

其余字段（`answer` / `refs` / `title` / `mode` / `message_id`）**一个都没改**。

### 2.3 完整事件序列（实拍，非示意）

后端测试里对一次思考模型回答抓到的真实序列：

```
reasoning  ×3   ← 思考增量（累加得「先看清问题：用户想验证思考流。那么分两步走。」）
token      ×2   ← 正文增量（累加得「思考流已经打通。这是正文部分。」）
done       ×1   ← 含 answer + reasoning 全文
```

**顺序保证**：思考一定在正文之前（模型先想后说）。但**不要假设** `reasoning` 一定出现——
未启用思考模型时它完全不出现，事件序列就是现在的 `token ×N → done`。

## 3. 前端要做什么

### 3.1 状态机（照 DeepSeek 网页版的行为）

```
收到首个 reasoning 帧  → 创建思考块，展开，开始流式追加
收到首个 token 帧      → 思考块开始「自动收起」（若用户在流式期间手动展开过，则不再自动收起）
收到 done              → 用 done.reasoning 校正全文（防丢帧），状态置为已完成
流式结束               → 思考块可点击展开/收起，默认收起
```

### 3.2 三条容易做错的细节

1. **思考块要有独立的流式光标**，不能和正文共用——否则用户会看到思考文本在正文区域闪。
2. **自动收起只在用户没手动干预时发生**。用户中途点开看了，就别再自动收起（这是 DeepSeek 网页版的实际行为，照抄即可）。
3. **`done.reasoning` 要覆盖本地累加值**，不要只依赖逐帧累加：中途丢帧（网络抖动）时，
   本地累加会缺字，而 `done` 拿到的是服务端的完整值。**以 done 为准。**

### 3.3 渲染建议

- 思考块用 `details/summary` 或受控折叠面板，标题给「已深度思考（用时 N 秒）」这类提示
- 思考文本用弱化样式（更小字号、次要色、可换行），与正文明确区分
- 思考块内不需要 Markdown 富渲染，纯文本换行即可（思考内容常含未闭合标记，富渲染会闪）

## 4. 后端配置（要真正看到思考流，必须做这一步）

`.env` 里加一行：

```ini
DEEPSEEK_REASONER_MODEL=deepseek-reasoner
```

- **留空 = 关闭思考流**，走原来的 `DEEPSEEK_MODEL`，行为与改造前完全一致
- 填上 = 每次问答都走思考模型（**注意：思考模型单价更高、首字延迟更长**）
- 依赖：`langchain-deepseek` 已加进 `requirements.txt`

> 为什么不做成前端参数：同一部署里"有的用户看到思考块、有的看不到"会让演示很难讲清。
> 要关就整个部署关。若确实需要逐请求开关，后端可以加，但要先定谁来决定。

## 5. 如何自查（前端联调时用）

后端提供了一个**不花钱、不联网**的验证脚本：

```powershell
cd C:\biancheng\agent-hub
& 'C:\biancheng\.scratch\ifdoc\venv312\Scripts\python.exe' tests\test_reasoning_stream.py
```

它会起一个假的 OpenAI 兼容服务端，模拟 reasoner 吐思考+正文，验证：
- `reasoning` 事件序列正确
- 思考不污染正文（`acc.text` 只含正文）
- `reasoning_content` 不被回灌进请求体

**前端联调时也可以用同样的办法**：把 `DEEPSEEK_BASE_URL` 指到一个本地假服务端，
就能稳定复现思考流，不用烧真实 token。假服务端的实现可以直接抄那个测试文件里的 `Handler`。

## 6. 边界与已知限制

| 项 | 现状 |
| --- | --- |
| 思考内容是否落库 | **不落库**。`done.reasoning` 只在本次流里给，刷新页面后历史消息里没有思考块 |
| 是否需要后端再改 | 若要求"刷新后仍能看到思考过程"，需要新增存储与读取接口 —— **当前没做，需要你确认要不要** |
| 视觉理解路径 | 不发 `reasoning`（该路径走视觉模型，不产思考内容） |
| Agent 模式 | 当前 agent 路径未接思考流（它的中间过程已由 `tool` / `status` 事件表达） |
| `reasoning` 与 `token` 谁先 | 一定先 reasoning。若模型只给正文，则只有 token |

## 7. 后端改动清单（供 review）

| 文件 | 改动 |
| --- | --- |
| `core/config.py` | 新增 `DEEPSEEK_REASONER_MODEL`、`REASONER_ALLOW_OVERRIDE` |
| `core/llm.py` | 改用 `ChatDeepSeek`；新增 `has_reasoner()` / `get_reasoner_llm()` / `pick_llm()`；key 为空时传占位串 |
| `api/chat.py` | `_stream_llm` 支持 `emit_reasoning`；新增 `_strip_reasoning()`；`done` 增 `reasoning` 字段 |
| `requirements.txt` | 新增 `langchain-deepseek` |
| `tests/test_reasoning_stream.py` | 16 项端到端验证（新增） |
| `pytest.ini` | 该脚本式自测加入 ignore 列表 |

**顺手修掉的一个既有隐患**：`langchain_openai` / `langchain_deepseek` 的 `validate_environment`
都会用 `api_key_env="OPENAI_API_KEY"` 兜底 —— **本项目的 `DEEPSEEK_API_KEY` 为空时，
会静默拿环境里的 `OPENAI_API_KEY` 去请求**，既不报错也不走 DeepSeek。现在改为显式传占位串，
"没配 key" 就等于请求时 401，不会再串到别处。
