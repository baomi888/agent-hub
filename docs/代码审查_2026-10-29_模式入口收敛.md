🟠 Major（2 项）

**[M-01] `api/chat.py:1062-1065` 兜底判据会被 `shared` 里的中间产物污染**

```python
acc_text = full_text or str(ctx.shared.get("agent_result") or "")
if not acc_text and ctx.shared:
    acc_text = str(next(reversed(ctx.shared.values())))   # ← 这里
```

若工作流写完 `plan` 后 `execute` 节点失败，`shared` 里只有规划文本：
- `agent_result` 为空 → 走到 `next(reversed(...))` 取到 **plan**；
- `acc_text` 非空 → 新加的 LLM 兜底不触发；
- 用户拿到一段"任务规划"，却被当成答案渲染。

影响：本次新增的兜底在**最需要它的场景下失效**（流程跑了一半就断）。这不是本次引入的问题（`next(reversed(...))` 是既有代码），但兜底的价值被它抵掉了。

修复建议：兜底判据不要看"`shared` 里有没有东西"，只看"有没有真正的产出"：

```python
answer = full_text or str(ctx.shared.get("agent_result") or "")
used_shared_fallback = bool(answer)
if not answer and ctx.shared:
    # 仅当 shared 里最后一个值是产出型键时才当答案，plan 不算
    answer = str(ctx.shared.get("agent_result") or "")
```
或给 `shared` 的键加白名单（`agent_result` / `final` 才算产出）。

状态：**待你确认后修改**（会改变既有 hybrid 行为，不擅自改）。

**[M-02] 每个 auto 请求多一次 LLM 往返，尾延迟与吞吐需要评估**

- 位置：`core/router.py::decide` → `_ask_model`
- 影响：非 flow 的 auto 请求每次多 300–600ms（上限 `ROUTER_TIMEOUT=2s`）。路由调用在**已持有的闸位内**执行，不会二次抢闸、无死锁风险，但单请求占用上游的时间变长，同并发下吞吐会下降。
- 已做的缓解：2s 硬超时、`max_tokens=48`、规则命中不问模型、抢不到闸/异常立即回落。
- 建议：上线前用 `tools/loadtest_concurrency.py` 对 `/api/auth/me` 与真实对话各跑一组，对比 P95；若 P95 上升超过 15%，把 `ROUTER_TIMEOUT` 降到 1.0，或对长度 ≤ 4 字的追问直接走规则（目前会走模型）。

## 三、值得肯定的设计（评审记录）

- 路由**只吃 `has_kb` 布尔值**，不吃 `kb_id`：与 Agent 侧 `configurable` 注入同一条安全边界，模型没有机会改检索目标。
- 两条硬约束写在代码里而不是提示词里（`rag && !has_kb` → agent、`llm && has_kb` → rag）：提示词只能"劝"，代码才能"拦"。
- 规则与模型的分工按**代价不对称**设计（漏判几百毫秒 vs 误判几秒 + 数倍 token），有明确取舍而不是拍脑袋。
- `_plain_llm_messages` 把"llm 模式"与"hybrid 兜底"的上下文拼装合成一份：兜底最容易漏压缩块，这一步避免了两套口径。
