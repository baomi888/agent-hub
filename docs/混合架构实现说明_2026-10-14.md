# 混合架构实现说明：工作流 × 自主 Agent（2026-10-14）

> 依据 `docs/混合架构系统研讨报告.md` 的推荐方案（三个决策点全选 A）落地。
> 本文档对照需求 1~8 说明实现位置与关键取舍。

---

## 总览

新增 `hybrid/` 引擎层（8 文件）+ `api/hybrid.py` 管理面（12 端点），并预留前端对接接口
（SSE 事件契约 + REST 端点，见下文「前端对接接口」）。前端 UI 实现不属于本模块职责范围，
`frontend/` 保持改动前状态，留待前端团队按契约对接。既有 39 项基线测试保持绿色，
新增 25 项混合架构用例，全量 64 项通过。

```
api/chat.py  mode=hybrid（复用 SSE 协议，新增 3 类事件）
api/hybrid.py  工作流 CRUD / 切换规则 / 执行记录 / 人工切换
hybrid/
  context.py       TaskContext + ExecEvent（统一上下文，要求 4）
  store.py         hybrid.db 四张表（独立库，WAL 不与 sessions.db 争抢）
  expr.py          受限表达式求值（条件边/规则条件，拒绝任意 eval）
  workflow.py      WorkflowEngine（节点/条件分支/超时/重试/on_fail，要求 2）
  agent_engine.py  AgentEngine（包装 build_agent()，步数/token/时长预算，要求 3）
  switcher.py      SwitchEngine（规则链 + 人工指令插队 + 防抖，要求 1/5）
  orchestrator.py  HybridOrchestrator（执行循环 + 事件落库 + SSE 翻译）
```

## 需求对照

### 1. 无缝切换与动态融合

- 编排器驱动执行循环：当前引擎产出事件 → 切换判定 → 必要时在安全点
  （节点边界 / 事件边界）让出并移交，不是硬切。
- 三种融合形态全部落地：
  - **降级接管**（工作流→Agent）：节点失败且无 `on_fail` 分支时，
    已完成节点产物 + 失败原因打包为 Agent 初始任务描述；
  - **收编回归**（Agent→工作流）：预算耗尽或子目标完成，Agent 产出写回
    `shared`，工作流从断点的下一节点续跑（`wf_state.next_node`）；
  - **流程内嵌**：`agent` 类型节点、`requires_agent=True` 节点是融合的一等公民，
    不需要切换规则介入。

### 2. 工作流标准能力

- 节点类型：`llm / tool / agent / condition / human`；节点级
  `timeout_seconds`（`asyncio.wait_for`）、`retry`、`on_fail` 跳转、
  `requires_agent` 声明。
- 条件分支：边上挂表达式（如 `shared.score > 0.8`），经 `expr.py` 受限求值
  （白名单 AST 节点，沿 calculator 的思路，拒绝任意 eval）。
- 流程级总时长护栏 `timeout_seconds`；超时按节点失败进入切换判定。
- 可视化编排：后端已提供编排所需的完整结构化定义读写能力
  （工作流 CRUD 端点，`definition` 为节点 + 边的 JSON 图），交由前端按该契约实现
  表单与拓扑视图。

### 3. 自主 Agent 能力

- `AgentEngine` 直接复用 `agent/builder.py build_agent()`（图编译缓存沿用），
  动态规划 / 工具调用 / 流式 token 原样保留；`owner_id/kb_id` 仍由服务端经
  `RunnableConfig.configurable` 注入，安全边界不变。
- 预算护栏：步数 / token / 时长三维（`HYBRID_AGENT_MAX_STEPS` 等配置），
  任一触顶上报 `budget_exhausted` 信号进入切换判定。

### 4. 统一任务上下文

- `TaskContext`：`goal / current_mode / workflow_state / agent_state / shared /
  mode_trace / version`。**`shared` 是唯一跨模式数据交换通道**，杜绝模式私有状态隔空引用。
- 切换即快照：每次切换把 `TaskContext` 整体序列化落 `workflow_runs` 表，
  `version` 乐观锁校验移交一致性。

### 5. 切换规则配置 + 人工干预

- `switch_rules` 表：信号（`requires_agent / node_failed / budget_exhausted /
  goal_satisfied`）+ 可选条件表达式 + 动作（`to_agent / to_workflow / terminate`）
  + 决策理由 + 优先级 + 防抖冷却。
- 归属模型与知识库一致：系统默认规则（owner NULL）删不掉，用户同名覆盖、删覆盖恢复默认。
- 4 条系统默认规则随库初始化种子（降级接管 / 收编回归 / 节点声明移交 / 预算收编）。
- 人工入口：`POST /api/hybrid/runs/{run_id}/switch`（`action ∈ to_agent / to_workflow /
  terminate`，仅 running 允许，否则 409）。人工指令优先级高于一切自动规则；
  前端可在运行中据此端点提供接管入口。
- API 层对规则条件做语法级校验（`ast.parse` mode=eval），存不住的表达式直接 400。

### 6. 统一监控与日志

- `exec_logs` 表：`run_id / event_type / mode / node_id / decision / payload / ts`，
  payload 摘要截断 2000 字符防大文本撑库。
- SSE 新增三类事件（`api/chat.py` 头注释有完整协议说明）：
  `hybrid_start {run_id, mode}` / `workflow_node {phase, node_id, ...}` /
  `mode_switch {rule, reason, from, to}`；`done` 事件新增 `run_id` 键。
- 轨迹数据源：流式执行由 `hybrid_start / workflow_node / mode_switch` 事件驱动，
  历史执行可由 `GET /api/hybrid/runs/{id}/logs` 全量补查；前端按这两条通道渲染时间轴。
- 本轮修复：`orchestrator._switch_event` 现在同时写 exec_logs
  （此前 switch 只发 SSE 不落库，监控链路会缺切换记录）。

### 7. 可扩展性

- `HybridOrchestrator` 持有引擎注册表（`{"workflow": WorkflowEngine, "agent": AgentEngine}`），
  新增执行模式 = 实现 `ExecutionEngine` 协议（`stream() / result`）+ 注册一行。
- 两种核心模式各自独立：WorkflowEngine 不 import AgentEngine，反之亦然，
  唯一耦合点是 `TaskContext` 与 `ExecEvent`。
- 持久化独立成 `hybrid.db`：聊天会话与混合执行两套生命周期，备份/清理分开做。

### 8. 测试验证

新增 25 项用例（pytest 风格，可独立 `python` 运行），全量 64 项绿：

| 文件 | 覆盖 |
|---|---|
| `test_hybrid_context.py` | TaskContext 快照/恢复、shared 交换、version 乐观锁 |
| `test_hybrid_expr.py` | 受限表达式：合法求值 / 危险语法拒绝 / 名字缺失 |
| `test_hybrid_workflow.py` | 节点顺序、条件边路由、on_fail、重试、超时、孤儿节点报错 |
| `test_hybrid_switcher.py` | 规则优先级、条件求值、防抖冷却、人工指令插队、terminate |
| `test_hybrid_orchestrator.py` | 端到端：起跑模式选择、降级接管、收编回归、断点续跑、事件序列 |

## 前端对接接口（预留契约）

> 交付给前端同学的完整接口文档另见 `docs/前端对接接口文档_混合架构_2026-10-14.md`
> （含逐字段说明、节点 config 逐类型约定、内置样例与联调清单）；本节为简版摘要。

前端 UI 实现按职责边界未纳入本次改动：`frontend/` 已回退到改动前状态，
交互层留待前端团队按下列契约实现。

**1. 聊天请求**

- `POST /api/chat/stream` 请求体新增 `workflow_id`（hybrid 专用；缺省 = 后端按任务分类自动选流程，
  指定但不存在或无权限时回 `error` 事件）。
- `mode` 取值新增 `hybrid`；`HYBRID_MODE_ENABLED=0` 时静默回退 `agent`。

**2. SSE 事件（既有协议上新增三类，`api/chat.py` 头注释为准）**

| 事件 | payload |
|---|---|
| `hybrid_start` | `{run_id, mode}`：起跑即发，`mode` 为初始模式（`workflow` / `agent`） |
| `workflow_node` | `{phase: "enter" \| "exit", node_id, ...}`：enter 附 `{type, name}`，exit 附 `{status, on_fail?, error?}` |
| `mode_switch` | `{rule, reason, from, to}`：切换决策依据（规则名 / 理由 / 切换前后模式） |
| `done` | 新增 `run_id` 键：人工切换与执行日志查询均按它寻址 |

**3. REST 管理面（前缀 `/api/hybrid`，12 端点，整组需登录）**

- 工作流：`GET /workflows`、`POST /workflows`、`GET /workflows/{wf_id}`、
  `PUT /workflows/{wf_id}`、`DELETE /workflows/{wf_id}`
  （系统内置 `builtin_plan_execute` 只读，列表项带 `builtin` 标记）
- 切换规则：`GET /rules`、`PUT /rules/{name}`、`DELETE /rules/{name}`
  （同名覆盖系统默认；删用户覆盖 = 系统默认重新生效；系统行删不掉 → 404）
- 执行记录：`GET /runs?limit=`、`GET /runs/{run_id}`、`GET /runs/{run_id}/logs?limit=`
- 人工干预：`POST /runs/{run_id}/switch`，body `{action}`，
  `action ∈ to_agent / to_workflow / terminate`；仅 `running` 允许，否则 409

**4. 数据形状**

- `WorkflowIn`：`{name, description, definition}`；`definition` =
  `{id, name, version, entry, nodes[{id, type, name, config, timeout_seconds, retry, on_fail,
  requires_agent}], edges[{source, target, condition?}], timeout_seconds}`，
  节点 `type ∈ llm / tool / agent / condition / human`。
- `RuleIn`：`{signal, condition, action, reason, priority, enabled, cooldown_seconds}`；
  `signal ∈ requires_agent / node_failed / budget_exhausted / goal_satisfied`，
  `condition` 为空表示不看条件，非空须能通过 `ast.parse(mode="eval")`（否则 400）。
- 兼容性：不传 `workflow_id`、不改 `mode` 的既有前端请求行为完全不变。

验证：后端全量 64 项 pytest 绿；`frontend/` 回退后 `tsc --noEmit` 通过。

## 配置面（core/config.py 新增 HYBRID_* 段）

- `HYBRID_MODE_ENABLED`（默认 1；置 0 时 hybrid 请求静默回退 agent 模式）
- Agent 预算：`HYBRID_AGENT_MAX_STEPS` / `HYBRID_AGENT_MAX_TOKENS` / `HYBRID_AGENT_MAX_SECONDS`
- 切换防抖默认值、日志截断长度等见 config 注释

## 内置资产

- 工作流 `builtin_plan_execute`（规划→执行）：LLM 节点把目标拆成 3~5 步
  （非流式进 `shared.plan`）→ Agent 节点按规划自主执行（流式）。
  系统内置只读，前端可见不可改删。
- 4 条系统默认切换规则（见需求 5）。

## 已知边界

- 执行轨迹不随聊天历史持久化：`exec_logs` 按 run 归档，历史消息若要回显轨迹，
  需前端按 `run_id` 调 `GET /api/hybrid/runs/{id}/logs` 补查。
- 并行节点未实现（研讨报告中标记为可后置项）；条件分支 + 顺序执行已覆盖
  当前需求。
